Lesson shape

A lesson is a list of sections. Each section holds blocks, and every block carries one role tag. The allowed roles are exactly these fifteen: routine_heading, teacher_talk, sample_response, callout_purpose, callout_say, callout_watch, support_table, cfu_item, quick_write, text_evidence_needed, excerpt_slot, teacher_tip, homework, paragraph, list.

Section names and minutes come from the template in the context block. Keep them in order and do not add or rename sections.

Each section must include the roles the template requires for it. A sample_response goes right after the question it answers. A Flex Day or Assessment lesson also needs a sample_response in Launch, and in Learning in Action a routine_heading that names the activity and a teacher_tip that tells the teacher what to choose or prepare.

Part roles. When a template line lists "Part A roles" or "Part B roles", each part must hold every role listed for it, inside that part (part field set to that label). A placeholder role in that list (text_evidence_needed or excerpt_slot) is written as described next.

Placeholders. A placeholder stands in for words you were not given, so a person can supply them; it is never filled by you. Never write a quotation, an excerpt or a paraphrase presented as a quotation from the anchor novel or from any text whose words are not in the data blocks. Use exactly these placeholders, and no others, and never more than two blocks of these two roles in one lesson:
- text_evidence_needed: in a Reading lesson, write exactly one in Learning in Action Part A, at the point where the students would look at one sentence of the anchor novel (its text begins with the words Reviewer to insert, then says which sentence is needed and what it must show, using only the pages the card states). Do not write a text_evidence_needed in a lesson of any other type, and not more than one in any lesson.
- excerpt_slot: stands for a whole passage of a separate short text that students read. In a Writing lesson, write exactly one in Learning in Action Part A, for the passage students read and write to (name the text and the moments the card states; add nothing else about it). In a Reading lesson, write one excerpt_slot in the Homework section only when the card's homework asks students to read a separate named text or excerpt that is not given in the data blocks; otherwise write none. A Writing lesson never gets a second placeholder, and its sample answers and tips paraphrase only what the card states.
- A Flex Day, Assessment, Spark or any other type with no worked pair has no placeholder unless the card itself asks students to read a text that is not in the data blocks; then write one excerpt_slot in the section where they read it.
Everywhere else, refer to a text by title and chapter or pages only as the card states them, and describe the students' evidence in your own words without quotation marks.

Parts. Only a section whose template line lists parts uses them; never invent Part A or Part B elsewhere. When a template line lists parts (for example parts: Part A, Part B), every block in that section carries its part label in the part field, written exactly as listed: a capital P, a space and a capital letter, nothing else. Put all Part A blocks before the Part B blocks. A descriptive phrase is never the label. To give a part a title, make the first block of that part a routine_heading holding the title. In a section whose template line lists no parts, part is null.

A check for understanding uses the cfu_item role, with one question and its expected response as a single item. Every cfu_item block must also fill its cfu field: the question in stem, the answer options in options (at least two), key_index for the correct option, one entry in rationales for each option, and standard_code. A cfu_item whose cfu field is null is invalid.

Every focus code on the lesson card must be checked. The usual check is a cfu_item whose standard_code names the code, spelled exactly as listed on the card (or the sub-code that replaces it, see Sub-codes below). A quick_write that lists the code in its standard_codes also counts as a check of it. One cfu_item, or one quick_write, may name up to two codes, only when its question or task really checks both; for more codes, write more items. A code that is an ELD code does not count toward that limit of two. Listing every code on one item checks none of them. For a cfu_item, standard_codes either stays empty or lists the same codes as its standard_code. If the lesson card lists no standard codes (a Flex Day), do not choose standards yourself: set standard_code to null on every cfu_item and keep standard_codes empty; never write N/A, none or the lesson id as a code.

Every focus code must also be taught. In each section or part where a focus code is taught, the routine_heading that opens it lists that code in its standard_codes, with teacher_talk or paragraph blocks under it. The lesson adds the brackets itself, so never type brackets or codes inside block text. A code written only on a teacher_talk or paragraph block does not count as teaching: it must be on the routine_heading that opens the teaching, and those blocks leave standard_codes empty. Teaching under that heading may be teacher_talk, paragraph or callout_say text. A quick_write may list in standard_codes the codes it practises; that does not replace a cfu_item. Only routine_heading, quick_write and cfu_item carry standard_codes.

Sub-codes. When the card lists a code that has sub-codes (for example L.6.4 has L.6.4.a and L.6.4.b), the standard data blocks also show those sub-codes. You may teach and check a sub-code instead of the listed code when the lesson card's own plan or notes point to it. Then use the sub-code everywhere you would have used the listed code, spelled exactly as the data block spells it, and give it narrowed in code_origins. A sub-code is a proposal that a reviewer must confirm before the lesson is approved. Use only sub-codes of a code that is on the card, and only codes that appear in the standard data blocks; never invent a code.

code_origins has exactly one entry for each entry of standard_codes: outline for a code listed on the card, narrowed for a sub-code of a listed code. The lesson re-derives each origin from the card, so a wrong entry is replaced, but the number of entries must match. When standard_codes is empty, code_origins is empty.

Minutes go in the minutes field of the blocks. Within each section the minutes of its blocks must add up to exactly the minutes the template gives for that section, and the Homework section is 0. A block that takes no class time has minutes null.

Every Learning in Action section needs a callout_purpose, a callout_say, a callout_watch and a cfu_item, and its first teaching block comes before the check.

Use quotation marks only around words copied from the lesson card or the data blocks. Write teacher prompts, questions and student sentence frames without quotation marks. Name only people, characters, authors, places, organizations and works that appear on the lesson card or in the data blocks, spelled as there. A name from your own knowledge (a myth figure, an author, a historical person, a place) is checked against the lesson card and the data blocks, and it blocks the lesson even when it is correct; if you are not sure a name is on the cards, leave it out and write the character, the author or the text instead. Do not add example names for students or teachers.

Mention a page or chapter only when the lesson card gives a page or chapter range, and keep every number you write inside that stated range (for example p. 233 only if 233 falls within the pages given). If the card gives no pages or chapters, write none. If you are unsure of a page or chapter number, leave the number out.

Use only the allowed roles. Output must match the schema exactly.
