The story so far

Newsela is entering California's core English classes (ELA/ELD). It needs about 180 lessons per grade, in its own lesson shape, good enough for state reviewers. The brief asks for a tool that turns a designer's unit outline into lessons. Then staff review, edit and approve them.

Stage 1 found that review time is the real cost, so our north star is reviewer minutes per approved lesson. Stage 2 worked five outline rows through the tool by hand (the worked pairs). Every place that needed judgement became a card. A system-design walk added HP-10 and two addenda.

HP-1 · Orchestration: the shape of the generation pipeline Chosen: A · 2026-10-25

Journey steps 3–5

Where this comes up in the project

The author presses Generate on a 47-day outline. Row 8, Lesson 4, is the test. Its teacher edition must reach Newsela's size: a median of 3,306 words [M]. Its homework names an excerpt that Lesson 5 has not chosen yet, so one lesson waits on another (WP-1, WP-2, U3).

The problem we're solving

Turn one outline into 47 valid drafts that follow the unit's arc, at a bounded cost. A model must never run the workflow.

In

Row 8: focus RL.6.1, RL.6.2, L.6.4.b, Ch. 1 pp. 1–8.

Out

One typed LessonDraft. Code turns it into Launch 5 · Literacy Lab 10 · Learning in Action 15 + 15 · Look Back 5 · Homework. The Homework links to Lesson 5's excerpt slot and blocks until it is filled.

Why it's hard

  1. Size. A draft is about 5,500–7,000 output tokens [C on A]. A cut-off answer is broken JSON.
  2. The arc. Lessons written alone all open the same way. Written one after another, the run takes about 2 hours.
  3. Links. If Lesson 4's link lives only in its text, nothing clears it when Lesson 5 changes.
  4. "Agent". A free-running loop has no cost limit, no replay and no reliable stop.

The options

A · One typed call per lesson chosen

UnitPlan call → LessonDraft call → code compiles → checks → store or 1 repair.

Fits blocks 3–4 as planned (~9 h). Carries the cut-off risk SP-1 measures.

B · One call per section fallback

5–6 section calls → assemble → compile → checks.

Cut-offs nearly vanish. About +2 h [A].

C · Model writes editor JSON

1 call → raw ProseMirror JSON → checks.

Saves 1–2 h [A]. Output 2–3× bigger [A]; risks unsafe markup.

D · Agent loop with tools

model picks a tool → result → model says done.

+4–8 h [A]. Can't be replayed. Contradicts PD-3 and AD-7.

Your decision Option A, with B as the switch if SP-1 fails.

  • The model fills typed slots only. Code decides "what next" and "am I done".
  • Brakes include 1 repair round, a 10-minute job limit and a spend check before each call.
  • Code writes lesson_link rows at intake. A new block: "an unresolved cross-lesson link".

Proposal SP-1 tests this. Not yet run; see the spikes.

Evidence: WP-1, WP-2, WP-3; U3 · Status: Innocent ✓ 2026-10-25, recommendation accepted. If SP-1 fails, B is the choice. · Changes: PD-4; R-8, R-19 · Full card

HP-2 · Grounding and quotes without the source texts Chosen: B · 2026-10-25

Journey steps 5 and 7

Where this comes up in the project

Lessons discuss The Lightning Thief, "The Hare and the Lion" and the Iliad. We were given none of these texts. The model will "remember" lines anyway. Lesson 4 needs "one sentence from Ch. 1, pp. 1–8, where Percy's sarcastic word choice sets the tone" (WP-1). The reviewer must trust every quote.

The problem we're solving

A lesson may repeat what the row says about a text. It must never state a quote, page or plot fact the row does not give.

In

Row 8 → Lesson 4, Part A.

Out

Right: "Reviewer to insert: one sentence from Ch. 1, pp. 1–8…". Wrong: a short line the model wrote from memory as Percy's words.

Why it's hard

  1. The 12-word rule misses short quotes. R-19 flags quoted runs of 12+ words, so any made-up quote of 11 words or fewer gets through.
  2. Not every quotation mark is a quote. Flag them all, and reviewers stop reading flags.
  3. Made-up plot facts carry no quotation marks. "The hare tricks the lion into a pit" reads like normal text.
  4. A cell can ask for a quote. SYN-1 plants one such order. A prompt rule alone promises nothing.

The options

A · PD-5 as written

draft → 12-word check → page check → reviewer.

0 extra hours. Misses short quotes and plot facts.

B · No quote type, three scans chosen

draft with no quote type → quote scan → page scan → name scan → reviewer adds quotes.

~3 h [A]. A plot fact with no name in it is left to the reviewer.

C · A model judge

draft → judge: in the row? → advisory flags.

~4–5 h [A] plus ~30 labels. Advisory only; may answer from memory.

D · Fetch the public-domain texts

listed source → code copies span → hash check.

~3–4 h [A]. Does nothing for the novel.

Your decision Option B. The draft has nowhere to put a quote.

  • Blocking scans: a quoted span of 3+ words [A] not in the lesson's own row or standards; a page or chapter outside the row's range; a name not in those sources (inside checks; elsewhere SP-3 decides).
  • U6: a reviewer supplies the excerpt. U10: a reviewer slot that blocks.

Proposal SP-3 tests the scans. Not yet run; see the spikes.

Evidence: WP-1, WP-2, WP-4; control WP-3; U6, U10 · Status: Innocent ✓ 2026-10-25, recommendation accepted. · Changes: PD-5; R-12, R-19 · Full card

HP-3 · Proving alignment to standards Chosen: B · 2026-10-25

Journey steps 3–9

Where this comes up in the project

Every standard a lesson lists is a claim to the state. A reviewer opens Lesson 4. It shows L.6.4.b, but the outline wrote the parent L.6.4. The tool chose .b from a note: "think about using morphology" (WP-1). The first flex day has no codes at all (WP-3).

The problem we're solving

Each standard must say who claimed it. A named person must confirm any claim the outline did not make.

In

Row 8's L.6.4 plus the note.

Out

L.6.4.b, origin narrowed → a blocking "confirm" item → the reviewer reads the official text → "confirmed by <name>, v2".

Why it's hard

  1. "Aligned" is never defined. Code can prove each code is taught and checked somewhere. It can't prove the teaching is real.
  2. Most lists need a human choice. 23 of 41 lessons carry 27 bare parent codes [C].
  3. Empty lists are real. 6 flex rows have no codes; R-19 as written blocks them all.
  4. Too many confirmations and people click without reading.

The options

A · Labels only

tool picks codes → "AI-proposed" label → one tick.

0 extra hours. AI-chosen codes can pass unread.

B · Confirm what the outline didn't say chosen

codes + origin → tool narrows or adds → confirm items block → reviewer confirms.

~2.5 h [A]. About 2–4 confirmations per lesson [C].

C · Author picks all codes

parent or empty = error → author picks → Generate.

~2 h [A]. 27 picks plus 6 flex rows [C] at the busiest step.

D · Judge is the gate

draft → judge per activity → "no" blocks.

~5 h [A] plus ~30 labels. Against PD-17.

Your decision Option B. A person checks exactly where the outline stopped making the claim.

  • Every code carries an origin: outline, outline-fixed, narrowed or added. The last two block Approve.
  • WP-1 changes: L.6.4.b becomes a blocking confirmation. Confirmations count in neither V-1 nor G-1.
  • U1 → L.6.4.b. U5 → a, b, f, with "add?" for c, d. U7 → (b).

Evidence: WP-1, WP-2, WP-3; control WP-5; U1, U5, U7 · Status: Innocent ✓ 2026-10-25, recommendation accepted. · Changes: PD-6; R-19, R-20 · Full card

HP-4 · Which copy of a lesson is canonical Chosen: A · 2026-10-25

Journey steps 7–9

Where this comes up in the project

A lesson lives in three copies. The live one is a Y.Doc, a shared Yjs document that merges everyone's typing. The stored one is ProseMirror JSON. At 14:02:01 a reviewer types a sentence into Lesson 4's "Reviewer to insert" slot (WP-1). Checks, approval and export must all read it.

The problem we're solving

Every reader gets the lesson the editors last stored, and the stored record can always be rebuilt from the live copy.

In

The edit at 14:02:01.

Out

By 14:02:03 one Postgres row holds the Y.Doc bytes, the JSON, its hash and its state vector (a list of which edits it holds). By 14:02:06 the placeholder block is gone.

Why it's hard

  1. Two stores written by separate code drift apart.
  2. The live copy runs ahead of the stored one by up to 2 s.
  3. Round trips can change bytes. Then the hash changes with no edit, and every approval pin fails.
  4. Rebuilding duplicates. A fresh Y.Doc beside the old one makes Yjs merge both, so text appears twice.

The options

A · Y.Doc is the master chosen

edit → Y.Doc in memory → store ≤ 2 s → one transaction → readers read the row.

About +1.5 h [A]. Only the collaboration server writes content.

B · JSON is the master

JSON row → Y.Doc per version → edit → back to JSON.

About +1 h [A]. Text duplicates; edits at risk.

C · Store only Yjs updates

append updates → reader merges → derive JSON.

Same time as A, no saving. Two readers can disagree.

Your decision Option A, plus the front matter in the same Y.Doc.

  • Each store writes bytes, JSON, hash and state vector in one transaction.
  • Standards and minutes live in the Y.Doc too.

Addendum: the batch run comes before the editor

The 47-lesson run starts Sunday ~18:00; the editor schema comes later, in blocks 6–7. ProseMirror drops unknown nodes silently. Rule: one schema module, written in block 3, shared by compiler, editor and server. Each lesson stores schema_version. A lesson the schema can't read fails loudly.

Evidence: WP-1, WP-2 · Status: Innocent ✓ 2026-10-25, recommendation accepted. SP-2 checks the round trip. · Changes: PD-7 (first half); R-11, R-26, R-28, R-29, R-35, R-42 · Full card

HP-5 · Approval integrity under live co-editing and AI edits Chosen: B · 2026-10-25

Journey steps 7–9

Where this comes up in the project

"Approved" must mean a named person approved exactly the text they saw. Reviewer A clicks Submit on Lesson 4; reviewer B's last keystroke lands 300 ms later. Ten minutes on, the approver opens it. And Lesson 4's homework waits on Lesson 5's excerpt (WP-1, U3).

The problem we're solving

The server refuses any approval that does not match, edit for edit, the version the approver loaded.

In

The approver loaded Lesson 5 at v4. A request-changes cycle made v5. The old tab sends approve(v4 hash, v4 state vector).

Out

409 "this lesson changed since you opened it". Nothing changes.

Why it's hard

  1. Yjs never reports a conflict. A late edit just merges in, so what the approver saw must be captured on purpose.
  2. The stored row lags by up to 2 s, so an edit still in memory can slip in.
  3. AI rewrites written straight into the text mix with a co-editor's typing.
  4. Four-eyes needs a name on each edit, and Yjs updates carry none.

The options

A · Live pin at approval

approve → lock → flush → compare with live → read-only.

About 4 h [A]. A race against live typing on every click.

B · Submit freezes the lesson chosen

submit → lock + flush → read-only snapshot → approve = snapshot?.

About 3 h [A]. A typo fix needs a withdraw first.

C · Compare with stored row

approve → compare with stored row → edits still land.

About 1.5 h [A]. Fails R-33's test under load.

Your decision Option B. A submitted lesson can't change, so "approved what was seen" holds by design.

  • AI suggestions wait in a side panel; a pending one blocks Submit and Approve. Regenerate never touches the current version.
  • U3: Lesson 4 blocks until Lesson 5 is approved with its slot filled.

Proposal SP-2 tests this. Not yet run; see the spikes.

Addendum: reopening a lesson another one needs

If Lesson 5 is reopened, Lesson 4 is flagged, and export holds Lesson 4 back until Lesson 5 is approved again. Nothing reopens on its own.

Evidence: WP-1, WP-2, WP-4; U3 · Status: Innocent ✓ 2026-10-25, recommendation accepted. If SP-2 fails, close all connections at Submit. · Changes: PD-7 (second half); R-19, R-29, R-31, R-33, R-34, R-42 · Full card

HP-6 · Outline normalization: codes, ELD labels, notes and unit-wide rules Chosen: A · 2026-10-25

Journey steps 1–2

Where this comes up in the project

An author uploads the outline, and the report opens on row 8. Its focus cell reads RL.6.1, 6.2 L.6.4. Its plan cell holds a reviewer's note: "Instead, think about using morphology…". Its 10 words break a 6-word cap written on row 9. Row 39 lists a code that does not exist (WP-1, WP-2, WP-4).

The problem we're solving

Turn a messy outline into typed rows the generator can trust, and decide which problems must be settled before Generate.

In

Row 8, focus RL.6.1, 6.2 L.6.4.

Out

RL.6.1 OK · 6.2 error, fix RL.6.2 proposed · L.6.4 warning. Generate stays off until the author settles the fix.

Why it's hard

  1. Plan and comment share a cell. Only formatting tells them apart.
  2. A rule on one row rules others. "Across Investigation 1" on row 9 means rows 8–23.
  3. Fixes are guesses. 6.2 could be RL, RI or W. Only the author knows.
  4. Too many questions fail too. One ELD code sits on 20 rows: 20+ clicks [C].

The options

A · Code-only, safe defaults chosen

find header → split cells → look up codes → errors gate → Generate.

About 5.5 h [A]. Free, exact, testable.

B · A model reads each row

parse → model call per row → author confirms.

About 8–9 h [A]. Costs money; SYN-1 reaches a model first.

C · Pass cells straight through

parse → errors gate → whole cells to prompt.

About 2.5 h [A]. Fails R-6: row 8 ships 10 words.

D · A, confirm every warning

clean as A → confirm every line → Generate.

About 5.5 h [A]. A gate people click through proves nothing.

Your decision Option A. Ask a person only where a wrong guess would be silent and costly.

  • Model at generation: the sub-part a note points at, which 6 of 10 words. Labelled "AI-proposed".
  • Person before Generate: each error; 5 on the issued sheet [C]. Everything else has a stored default.

Evidence: WP-1 … WP-5; SYN-1…3; U1, U2, U4, U5, U8 · Status: Innocent ✓ 2026-10-25, recommendation accepted. · Changes: new PD-27; R-3–R-6, R-11, R-19 · Full card

HP-7 · Long jobs: rate limits, truncation, resume, spend Chosen: B · 2026-10-25

Journey steps 3 and 5

Where this comes up in the project

On Sunday evening the author starts the full 47-day run. Midway, a push to the mirror redeploys the app and restarts the worker. The same machinery runs the live demo on rows 8, 9 and 25 (WP-1, WP-2, WP-3).

The problem we're solving

Survive restarts, 429s (the provider saying "slow down"), cut-offs and a spend cap, storing each lesson once.

In

The worker dies while drafting Lesson 23. Lesson 22's draft has just come back, not yet stored.

Out

After the restart, Lesson 23 carries on. Lesson 22 is built from its saved output, no second call. The run ends "46 of 47 ready, 1 failed: truncated".

Why it's hard

  1. "No job billed twice" can't hold literally. A worker can die after the provider answers but before we store.
  2. A cap checked per call overshoots. With 6 calls in flight, by up to 6 × one call's top cost [C].
  3. A cut-off looks like a schema failure and would waste the one repair round.
  4. 429s arrive together, so plain retries hit the limit again.

The options

A · pg-boss plus our tables

enqueue → worker → copy status → board reads copy.

About 2 h [A]. State in two places can drift.

B · One lesson_job table chosen

claim with lease → reserve spend → call → save raw output → store once.

About 2–2.5 h [A]. The board reads the same rows.

C · Jobs in the web app

request → call → restart: run lost.

About 1 h. Any deploy kills the run.

D · Provider batch API

47 requests → batch → poll → repair batch.

+2–3 h [A]. No live progress; two paths.

Your decision Option B. One table is both the queue and what the board shows.

Workers claim rows with SKIP LOCKED, so no two hold the same row. A lease is a claim that runs out unless renewed.

  • Each call reserves its top cost first; a call that would pass the cap is refused.
  • R-16 reworded: no lesson stored twice, no completed call paid again, lost calls counted.

Unknown Still Innocent's to answer: the failure to survive (SD-7.2) and the spend ceiling (SD-1.6).

Evidence: WP-1, WP-2, WP-3 · Status: Innocent ✓ 2026-10-25, recommendation accepted. SP-1 sets the caps. · Changes: PD-13; PD-14; R-16, R-48 · Full card

HP-8 · Measuring the north star honestly Chosen: B · 2026-10-25

Journey steps 6–9

Where this comes up in the project

Our headline number is reviewer minutes per approved lesson. Lower is better, so skimming "wins". On Monday Innocent reviews Lesson 4 (WP-1). A second account approves, and the server writes the frozen metrics row. The demo ends on the north-star tile.

The problem we're solving

Count active review minutes so that skimming, idle tabs, scripted sessions and tiny samples can't flatter the number.

In

Reviewer 14 active minutes; approver 9; a Claude-driven test 3.

Out

active_minutes = 23, synthetic_minutes_excluded = 3. Tile: "Reading median 23 min, n = 1 · G-2 0% · approved 1 of 47".

Why it's hard

  1. No baseline (AQ-14). Any figure is a measurement, not an improvement.
  2. Skimming wins. G-2 must flag approvals faster than reading, and today it has two thresholds.
  3. Our reviewers are us. Claude-driven sessions send machine-speed heartbeats.
  4. Tiny samples. With one reviewer, every total is one person's number.

The options

A · Wall clock

open → close → sum.

About 0.5 h [A]. Counts idle tabs.

B · Heartbeats with honesty rules chosen

heartbeat 15 s → merge per user → row at first approval → tile with n.

About 2 h. Rules out claiming any saving.

C · B plus a with/without test

6 lessons → 3 with, 3 without → two medians.

Plus ~2.5 h of Innocent's time. n = 3 is an anecdote.

D · No number

define metric → no tile.

0 h. Contradicts PD-17.

Your decision Option B, with honesty rules.

  • Count only a focused tab with input in the last 60 s [A].
  • synthetic sessions are left out. Count to the first approval only.
  • One G-2 threshold: under half the version's own read time.

Evidence: WP-1 … WP-4 · Status: Innocent ✓ 2026-10-25, recommendation accepted. AQ-14 stays open. · Changes: PD-1, PD-25; R-36, R-49, R-52; GR-15 · Full card

HP-9 · Content-safety notes and teacher-only text Chosen: A · 2026-10-25

Journey steps 1–2, 5, 7–8

Where this comes up in the project

Row 39's Homework cell says "Warn students about potentially triggering scene in tonight's reading (references to domestic abuse)". Copied as written, that line would land in the students' homework list (WP-4).

The problem we're solving

A sentence written to the teacher is never shown to students. Approval waits until a named person has handled it.

In

Row 39 Homework: the reading plus the warning.

Out

Student homework: "Read and annotate The Lightning Thief Chapter 21 (pp. 344–353)". A teacher_tip with the warning. An open flag that blocks Approve.

Why it's hard

  1. The column and the sentence disagree about who reads it.
  2. One real case in 620 cells [M]. A tight keyword list flags exactly 1. A broad one flags 30, and 29 are false [M].
  3. A model must not clear a flag, or a cell can talk it out of asking a human.
  4. Disclosure prompts such as "Describe a time you felt left out" are harmful next to this chapter.

The options

A · Rules propose, author confirms chosen

patterns → author confirms → code places tip + flag → reviewer clears.

About 2 h [A]. Free at intake. May miss reworded warnings.

B · A model sorts every cell

classifier call → author confirms → tip + flag.

About 3.5 h [A], 47 calls.

C · Author tags by hand

author picks kind → tip + flag.

About 1 h [A]. 38 cells to read [M]; misses leak.

D · At generation only

draft call → maybe a flag.

About 1 h [A]. The model decides when to ask a human.

Your decision Option A. On the issued sheet it finds the one real case with no false alarms [M].

  • The draft may add a flag but never remove one.
  • Disclosure prompts are blocked in the flagged lesson and the next.
  • U9: any named reviewer or approver may clear a flag, only with a note.

HP-10 · Is the generated teaching any good? Chosen: A · 2026-10-25

Journey steps 7–8

Where this comes up in the project

A lesson can pass every check and still teach badly. Lesson 4's draft is about 3,300 words the model wrote from two bullets and a note (WP-1). A weak draft costs more review minutes than it saves, yet every quality signal in the plan can be cut.

The problem we're solving

Get a measured signal of draft quality for each lesson, with no expert rubric and no second model.

In

Lesson 4 approved after 22 active minutes.

Out

The record also holds the approver's one-click rating, "usable with edits". The report says "of n approved lessons, k were usable with edits or better".

Why it's hard

  1. No rubric. Newsela's checklist is unknown (AQ-20).
  2. No expert. A judge tuned by a non-expert is provisional.
  3. Time. A judge needs a second provider and ~30 labels.
  4. A model checking itself shares its own blind spots.

The options

A · Approver rates each draft chosen

approve → one-click rating → metrics row → unit report.

About 0.5 h. A number with n from day one.

B · Yes/no judge

draft → judge → advisory flags.

About 3 h plus ~30 labels. Stays at cut #2.

C · Arc checks in code

all drafts → unit checks → advisory issues.

About 1 h. Kept at cut #3.

D · Self-critique

draft → critique call → store.

+1 call per lesson. Rejected.

Your decision Option A now; C stays at cut #3 and B at cut #2.

  • New R-60: Approve needs a rating: usable as drafted, usable with edits or rewritten.
  • Target: 2 of 3 demo lessons rated "usable with edits" or better [T].

Evidence: WP-1, WP-2, WP-3 · Status: Innocent ✓ 2026-10-25, recommendation accepted. · Changes: new PD-28; new R-60 · Full card
