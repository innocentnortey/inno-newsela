## 5. Steps (build order)

Interfaces: implements `CollabCommands.lock_and_snapshot` (DO-4); consumes `FrozenDocs`, `LessonPersistence`, `AckBroadcaster`, `LessonDocReader`, `LessonStateRepo`, `LessonVersionRepo`, `IssueRepo`, `SubmitLoader` through `CollabCommandHandlerDeps` (dependency inversion: no `@ls/db` import in `commands/`; `shells.test.ts` scans for it).

1. **Types and wiring.** Edit `types.ts` (four members, `export type SubmitLoader`). Edit `wiring/commands.ts`: import `PgOutlineRepo` (`@ls/db/repos/outlines`, with the existing `PgStandardRepo`), `PgSuggestionRepo, PgSafetyFlagRepo, PgAlignmentRepo` (`@ls/db/repos/review-extras`), `PgIssueRepo` (`@ls/db/repos/issue-repo`), `CheckContextLoader` (`@ls/core/checks/context-loader`), `CHECK_RULES` (`@ls/core/checks/registry`), `CHECK_POLICY` (`@ls/core/checks/policy`). Build, with `deps = { db, ids: d.ids, clock: d.clock }` (already there): `standards = new PgStandardRepo(deps)`, `reader = new PgLessonDocReader({ db })`, `loader = new CheckContextLoader(new PgOutlineRepo(deps), standards, states, reader, new PgSuggestionRepo(deps), new PgSafetyFlagRepo(deps), new PgAlignmentRepo(deps), d.clock)` (same argument order as `apps/web/src/server/wiring/review.ts` line 94; `states` is the `PgLessonRepo`, which is also the `LessonGraphRepo`), `issues: new PgIssueRepo(deps)`, `rules: CHECK_RULES`, `policy: CHECK_POLICY`, `tx: db`. The pool stays lazy; the existing wiring test "builds with no database reachable" must still pass.

2. **Entry and the atomic freeze (`lock-and-snapshot.ts`).** Invariant: the check-and-freeze has no `await` between its read and its write, and we only ever release a freeze we took.
   a. `const id = cmd.lesson_id`. `const row = await deps.states.get(id)`; null -> `DomainRefusal("NOT_FOUND", "Lesson not found", {})`. (A read before the freeze is allowed: it only seeds the flag. Every *write or state change* comes after the freeze.)
   b. `const pre = decide_transition({ action: "submit", role: "reviewer", from_state: row.state })`; `!pre.allowed` -> `DomainRefusal(pre.refusal!, "This lesson cannot be submitted from its current state", { state: row.state })`. (Role is fixed to `"reviewer"`: the web side already authorised the person, as in `apply_edit`.) This runs before the frozen check so a lesson that is already `submitted` answers `INVALID_TRANSITION`, not `LESSON_LOCKED` (AC-7).
   c. Synchronously, no await between these three lines: `deps.frozen.seed(id, row.state); if (deps.frozen.is_frozen(id)) throw new DomainRefusal("LESSON_LOCKED", "This lesson is locked", { state: row.state }); deps.frozen.freeze(id);` Setting `took_freeze = true` here. A caller that finds the lesson already frozen (another Submit in flight, or `set_mode read_only`) refuses and **must not unfreeze** (never release a freeze you did not take).
   d. Everything after (c) runs in `try { ... } catch (e) { await release(...); throw e }`, `finally` closes the connection (step 8).

3. **Hold the live document, yield, store at once.** `const live = await open_live_doc(deps, id, { actor: cmd.actor, request_id: cmd.request_id })` (new `live-doc.ts`; copy `HasDirect`, `DirectConn`, `has_direct` from `apply-edit.ts`; not ready -> `DomainRefusal("COLLAB_UNAVAILABLE", ...)`; null document -> same). **Keep this connection open until after the commit and the release/broadcast (step 8).** Why: `conn.disconnect()` unloads an unconnected document, and `afterUnloadDocument` calls `frozen.forget(id)`; a socket that connected in that gap would seed from the database state (still `in_review`) and be allowed to write after the snapshot. Then `await new Promise<void>((r) => setImmediate(r))`: updates that passed `beforeHandleMessage` just before the freeze are applied in the same tick chain, so this lets them land before the encode and be part of the snapshot (the alternative is the update sitting in the live doc, unstored, which a debounced `onStoreDocument` would persist after Submit returned). Then `const stored_ack = await deps.persistence.store("lesson:" + id, Y.encodeStateAsUpdate(live.doc), null, cmd.request_id)`. `last_editor` is `null` on purpose: Submit is not an edit, and `record_last_editor` would corrupt four-eyes (`last_editor_id`). Then `const stored = await deps.reader.latest_derived(id)` (null -> `NOT_FOUND`); this serves both the `store -> null` case and gives the `lesson`, `content_hash`, `state_vector` of the stored row. All later steps use `stored`, never the live document.

4. **Cover check.** `try { ok = covers(stored.state_vector, cmd.client_state_vector) } catch (e) { if (e instanceof StateVectorError) throw new DomainRefusal("INVALID_REQUEST", "The state vector is not valid", {}) ; throw e }`. `!ok` -> `DomainRefusal("NOT_STORED", "Your latest changes were not received; reload and submit again", {})`. Invariant: the approver reads at least everything the submitter saw.

5. **Checks and gate on the stored row (`submit-gate.ts`).** Export `async function evaluate_submit_gate(deps: Pick<CollabCommandHandlerDeps,"loader"|"rules"|"policy"|"issues">, lesson_id, stored: { lesson; content_hash }): Promise<void>` which throws `DomainRefusal` or returns:
   - `ctx = await deps.loader.load(lesson_id, stored.lesson, stored.content_hash)`
   - `findings = run_checks(ctx, deps.rules, deps.policy).findings`
   - `issues = merge_resolutions(findings, await deps.issues.resolutions_for(lesson_id))`
   - `state: GateState = { action: "submit", issues, pending_check: false, pending_suggestions: ctx.pending_suggestions.length, open_confirmations: issues.filter(i => i.level === "confirmation" && !i.resolved).length, last_editor_id: null, approver_id: null, four_eyes_enabled: false, dependencies: [] }` (the last four are unused by `submit_gate`; same shape `approve-service.ts` builds)
   - `g = submit_gate(state)`; `!g.allowed` -> `DomainRefusal(g.refusals[0] ?? "BLOCKED", "This lesson cannot be submitted yet", g.details)`. `submit_gate` already orders `SUGGESTION_PENDING`, `BLOCKED` (details list unresolved blocking AND confirmation issues), `CONFIRMATION_OPEN`. Do not re-implement the order.
   Nothing is written in steps 4-5, so a refusal here leaves no rows.

6. **One transaction.** `const result = await deps.tx.with_tx(async (tx) => { ... })`:
   a. `locked = await deps.states.lock_for_update(id, tx)`.
   b. `d = decide_transition({ action: "submit", role: "reviewer", from_state: locked.state })`; refuse as in 2b if not allowed (covers a state moved by someone else since the pre-read).
   c. `v = await deps.versions.write_snapshot({ lesson_id: id, kind: "submit", lesson: stored.lesson, content_hash: stored.content_hash, state_vector: stored.state_vector, dependency_record: [], created_by: cmd.actor.user_id }, tx)`; `cmd.actor.user_id` null -> refuse `INVALID_REQUEST` before step 2c (check at 2a; the HTTP schema allows null, `apply_edit` refuses it, so Submit must too). Hash equality: `v.content_hash` must equal `stored.content_hash`.
   d. `await deps.states.set_state(id, "submitted", locked.reviewer_id, tx)`.
   e. `ev = await deps.states.append_review_event({ lesson_id: id, version_id: v.version_id, from_state: locked.state, to_state: "submitted", actor_id: cmd.actor.user_id, reason: null, reason_tag: null, note: null, content_hash: v.content_hash, request_id: cmd.request_id }, tx)`. `note` stays `null`: nothing from the lesson text ever goes in it (AC-10).
   f. return `{ lesson_id: id, version_id: v.version_id, version_number: v.number, content_hash: v.content_hash, state_vector: stored.state_vector, review_event_id: ev.review_event_id, from_state: locked.state, to_state: "submitted" }`.
   Any throw rolls the whole tx back (one snapshot, one state, one event or none).

7. **After commit.** `try { deps.acks.mode(id, { mode: "read_only", state: "submitted" }) } catch { log warn "collab.submit_broadcast_failed" }`: never fail a committed Submit; the freeze flag already keeps writes out and a reconnecting socket seeds as read-only. Log once: `deps.logger.info("collab.submit", { request_id, lesson_id: id, extra: { version_number: result.version_number, outcome: "ok" } })` (ids and counts only). The freeze stays on (the lesson is `submitted`, not editable). Return `result`. Order is `commit -> broadcast`, never the reverse (ticket "Must not").

8. **Connection lifetime and the apply_edit race (NL-105 review Low note).** `finally { await live?.disconnect() }` runs *after* steps 7 and 9, so the freeze flag and the loaded document outlive the whole command. Separately, fix the edit/freeze race at its source in `apply-edit.ts`: after `const doc = conn.document` and its null check, and before `prepare_edit(...)`, add
   ```ts
   // The freeze may have landed while the direct connection was opening (SP-2: no edit may be applied after the lock).
   if (deps.frozen.is_frozen(id)) throw new DomainRefusal("LESSON_LOCKED", "This lesson is locked", { state: row.state });
   ```
   `DirectConnection.transact` runs the mutation synchronously, so the check and the transaction are in the same tick: either the edit is in the document before our freeze (and our yield-then-encode in step 3 stores it) or it is refused. The early check at the top of `apply_edit` stays. This does not change any NL-105 frozen assertion. Residual (accepted, recorded): an `apply_edit` that passed this check just before our freeze and then calls `persistence.store` after our store gets `null` (same hash) or stores the same content; both are rows that include only pre-freeze edits and are written before Submit returns only if they win the race; AC-3 measures `lesson_doc` seq *after* return.

9. **Release on any failure (`release`).** Used by the `catch` of 2d, only when `took_freeze` is true. `let state = row.state; try { const cur = await deps.states.get(id); if (cur !== null) state = cur.state } catch { /* keep the pre-read state */ }`; then `if (is_editable(state, "reviewer")) deps.frozen.unfreeze(id)` else leave it frozen. Why not a blind `unfreeze`: if the lesson moved to a non-editable state while we held the freeze (a concurrent Withdraw/other transition), unfreezing would reopen writes on a locked lesson. Never throw from `release`; log failures. On the success path nothing is released.
   Failure kinds to cover: refusal from steps 3-6 (`DomainRefusal`), tx error (AC-8: injected error after the checks), unexpected error (`from_unknown` maps it to 503 `COLLAB_UNAVAILABLE`; the rethrow keeps that).
