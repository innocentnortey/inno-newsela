## 3. Thresholds (single source `s10-verdict.ts`)

`rate = caught/n`. Verdict, in this order: wrong-code plant missed -> `fail(floor)`; rate < 0.70 -> `fail(guard)`; rate >= 0.90 -> `meets`; else `reported`. For n = 5: 5/5 meets, 4/5 reported (0.8), 3/5 and below fails. `floors.ts` S10 row: keep `0` (the CLI exit code is driven by `verdict`, not by `floor_met`); the s10 suite sets case `passed` = plant caught, and the CLI must exit 1 when verdict is `fail(*)`. Smallest change: `run_cli` computes `floor_met` as today, and S10's `score` throws nothing; the exit code for S10 comes from a new exported `s10_floor_met(passed,total,wrong_code_caught)` that `cli.ts` calls for S10 only. Pin this in `s10.test.ts -t thresholds_and_wrong_code_floor`.

## 5. Behaviour

Plant (`plant_all`):
1. Read key (`{plant_id, lesson_id, kind, locator, marker}[]`). Kinds: `wrong_standard_code`, `invented_quote`, `page_out_of_range`, `safety_in_student_block`, `missing_section` (maps to checks `code_not_allowed`/`standard_not_taught`, `quote_unmatched`, `page_out_of_range`, `safety_text_in_student_block`, `section_missing`).
2. Refuse (exit 2, write nothing) if any target unit is not the seeded unit (id constant `SEEDED_UNIT_ID`; tool creates the `unit` row if missing, grade synthetic) or if the planter account equals any account holding a reviewer role in `app_user`/`lesson.reviewer_id`.
3. Ensure the synthetic planter `app_user` (`synthetic = true`, role `author`-class, never a reviewer); in one transaction per plant: load the source lesson's latest `lesson_doc.derived_json`, `apply_plant` to a **copy**, insert a new `lesson` row in the seeded unit (new id) and `seed_initial(new_lesson_id, planted, actor{user_id: planter}, tx)`; write one `audit_event` (`action "eval.seed_plant"`, `target_kind "lesson"`, details `{planted_by: <planter id>, plant_ref: <opaque index>}`: NEVER `plant_id`, `marker` or kind).
4. The mapping `plant_id -> new lesson id/hash` stays in `evals/local/seed-state-<run>.json` (git-ignored), not in any table the review API reads. `eval_run` is started at plant time (run id printed; key contents never printed).

Score (`score_plants`): per plant, from stored rows, using the planted `content_hash` and marker text (read from the local key at score time):
- caught by check: an `issue` row with matching CheckKind on the planted hash;
- caught by reviewer: marker absent from every later `lesson_doc.derived_json`, or a `review_event` send-back with a note naming it;
- missed: marker still present in an `approved` state snapshot / lesson approved with it.
Write one `eval_case_result` per plant (`case_id = plant_id` hashed as `seed-<n>`, provenance `hand-written`, source = key id; `expected`/`actual` carry kind, how caught, never the marker string), then `evals/reports/seeded-<run_id>.md` via `merge_section`/report helpers in `evals/src/report.ts`: each plant, caught or not, by check or reviewer, labelled "our reviewers", git SHA, *n*. The runner's `make_leak_guard` already scans case data and reports for keys and tokens (AC-7).
