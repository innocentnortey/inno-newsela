3. **`use-suggestions.ts`** (`"use client"`): state machine `{ phase: "loading"|"idle"|"asking"|"pending"|"deciding"|"locked", suggestion: Suggestion|null, error: {code; text}|null }`.
   - On mount `api.GET("/lessons/{lessonId}/suggestions", ...)`; the first item with `status === "pending"` becomes `suggestion` (restore after reload, AC-2). Call timeout is the server's 20 s; no client-side timer. Success -> `pending`.
   - `decide(decision)`: `api.POST("/lessons/{lessonId}/suggestions/{suggestionId}/decision", ..., body: decision === "accept" ? { decision: "accept", anchored_text_now: selection?.text ?? null } : { decision: "reject" })`. **One request and nothing else**: no collab call, no document write, no other POST (AC-4). Success: toast `ACCEPTED_TOAST` / `REJECTED_TOAST`, `announce(...)`, clear suggestion, `onPendingChange(false)`, and on accept `onLessonChanged?.()` so a host can re-read.
   - Errors: `ANCHOR_CHANGED` -> text `ANCHOR_CHANGED_TEXT`, suggestion cleared (nothing applied; the user asks again); `MODEL_UNAVAILABLE` -> `MODEL_UNAVAILABLE_TEXT`, stays on the form with the note kept; `LESSON_LOCKED` -> `phase: "locked"`, nothing applied; `COLLAB_UNAVAILABLE` -> `COLLAB_TEXT`, suggestion stays `pending` with Accept and Reject still enabled (retry); `INVALID_TRANSITION` -> `MOVED_ON_TEXT` and re-read `listSuggestions` (the suggestion disappears if decided elsewhere); `NETWORK`/other -> `errorText`. Notify `onPendingChange(suggestion !== null)` whenever it changes.
