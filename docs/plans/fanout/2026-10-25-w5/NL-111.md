## 5. Steps
1. **`labels.ts`**: `parse_labels(text): LabelRow[]` (header exactly `pair_id,lesson_id,content_hash,address,code,question,label,labelled_by,labelled_at,split`; RFC-4180 quotes handled by a small parser, no new dependency; reject unknown `label`/`split`/`question` values with the row number). `LabelRow.question` is `teaches_standard|eld_keeps_task`.
2. **Preflight in `calibrate.ts` `run_calibration(deps)`** (runs before any DB write or judge call): file missing, `dev < 20`, or `holdout < 10` -> throw `CalibrationRefused` (exit 2) with a message naming the count. Also reject duplicate `pair_id`s. No `eval_run` exists yet at this point.
3. **Resolve inputs per pair** (before any call, so a missing lesson fails with zero calls): `PgLessonDocReader.latest_derived(lesson_id)`; its `content_hash` must equal the label's `content_hash` else refuse (`stale label`). `activity_text` = concatenate the `text` of all nodes in the `sections` entry whose `address` equals the label's `address`. `standard_text` = `StandardRepo.texts([code])[0].text`. Missing section/standard -> refuse. Pairs are processed dev first, then holdout.
4. **Judge dev pairs**: `rubric_version = "judge-rubric-v1"` (constant exported from calibrate.ts; the adapter's `JUDGE_RUBRIC_V1` is the text). Per pair: render nothing new; build `JudgeRequest`; in real mode reserve first (amount from `max_call_cost` using `price_for(model_id)`), `insert_sent` before the call, `complete` after, `settle`+`release`; in stub mode `insert_sent` with `reservation_id: null`, `complete` with cost 0, and **no spend row**. A `ProviderError` -> `fail`, release, count as disagree with `failure_category "provider_error"`, never retried.
5. **Write dev report section first**, then judge holdout pairs: `report.ts` exposes `write_dev_section(path, dev)` (writes the file with the dev numbers and the line `holdout: pending`) and `write_final(path, ...)`. Only after `write_dev_section` returns does the loop touch holdout rows. `add_case_result` for dev rows happens with dev; holdout rows after the dev section is written. No function takes holdout labels as input to a prompt, rubric or threshold.
6. **Evidence**: after step 3 passes, `start_eval_run({suite:"S12", git_sha, provider_mode, models:{judge: model_id, rubric_version}, case_set:"labels.csv", run_id:null, prompt_version_id:null})`; one `add_case_result` per pair (`provenance:"issued"`, `source:"labels.csv:<pair_id>"`, `guards:"R-23"`, `expected:label`, `actual:verdict`, `passed: agree`); `finish_eval_run(id, agreed, 30, "evals/reports/judge-calibration.md")`. The report states agreement and n, so M-34 is a query over `eval_case_result` where `eval_run.suite='S12'`.
7. **`main.ts`**: `run_judge_calibrate(argv, deps): Promise<number>` plus `main()` guarded like `cli.ts` (`import.meta.url === pathToFileURL(process.argv[1])`). Flags: `--real`, `--cap-usd <n>`, `--labels <path>` (default `evals/judge/labels.csv`), `--out <path>` (default `evals/reports/judge-calibration.md`). Default is stub: `deps.judge` is injected by tests; the CLI default stub answers `yes` to every pair (never built from the labels, which would leak them), so the script runs offline and the report says `provider stub: not a calibration` and `judge verdicts may be reported: no`. Real mode: `resolve_cap` (copy of driver/cap.ts rule), refuse before any request if no cap or cap above ceiling; build `OpenRouterJudgeAdapter` from `OPENROUTER_API_KEY` and `MODEL_JUDGE_ID`, naming the variable (not the value) in a `ConfigError`. Exit 0 ok, 2 refusal/usage/config. Provider keys come only through `/home/linuxuser/workspaces/bin/with-provider-env -- npm run eval:judge-calibrate -- --real --cap-usd 2`; never copy a key.
8. **`s12.ts`**: `make_s12(mode)` returns an `EvalSuite` named `"S12"` whose `cases()` reads `evals/judge/labels.csv` synchronously (empty list if missing, so `cli.ts golden --suite S12` exits 2 as every shell does) and whose `score` replays one pair through the same pure `judge_pair()` helper exported from calibrate.ts. It does not write the calibration report. The calibration report is only from the `eval:judge-calibrate` entry.
9. **Tests**, fixtures, devlog, area-map as in sections 2-3 and 6. End the reply with `Route facts:` lines (new exports `run_judge_calibrate`, `run_calibration`, `parse_labels`, `gate`; script-targets row repointed).
