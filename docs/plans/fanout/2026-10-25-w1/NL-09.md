### content-hash.ts
```ts
import { sha256 } from "@noble/hashes/sha2.js";
import { bytesToHex, utf8ToBytes } from "@noble/hashes/utils.js";
export function canonical_json(value: unknown): string   // exported for tests
export function content_hash(lesson: StoredLesson): Sha256
```
`canonical_json`: recursive; objects -> keys sorted by UTF-16 code-unit order (`Object.keys(o).sort()`), no whitespace, `JSON.stringify(key)`:value; arrays keep order; `null` -> `null`; primitives via `JSON.stringify`; a key with value `undefined` is omitted (so `null` vs missing differ: null emits `"k":null`, missing emits nothing); throw `TypeError` on non-finite numbers, bigint, function. Hash = `bytesToHex(sha256(utf8ToBytes(canonical_json(lesson))))`. Do NOT zod-parse inside (cost; callers hold a StoredLesson). Check `node_modules/@noble/hashes/package.json` exports for the exact subpath (`./sha2.js`, `./utils.js` exist; v2 requires the `.js` suffix).

## Edge decisions already made (do not reopen)
- Dates are ISO strings (`z.iso.datetime({offset: true})`), not `Date`, because these records are JSON on the wire and in the emitted schemas.
- `IdPrefix` enum includes `req` as DO-4 §2 lists it, but the "prefixed ULID" id schemas cover the 15 non-`req` prefixes ticket lists; `RequestId` has its own two-form regex.
- `.strict()` on intake/outline/export records; model-output schemas (`UnitPlanDraft`, `LessonDraft`) are NOT strict so extra model keys are ignored by parse (Zod default strips) but still visible in JSON Schema via `additionalProperties` default; if `z.toJSONSchema` emits `additionalProperties:false` for `.strict()` only, that is acceptable.
- No `Section.address` regex (OpenAPI says free `string`); no ELD/standard code regexes (belong to NL-12/standards).
