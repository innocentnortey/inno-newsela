## Writing each mirror (rules, same for all 102)
- Translate each YAML schema one-to-one: `type/format/enum/pattern/min*/max*/nullable/required/items/oneOf/allOf/$ref/additionalProperties`. `$ref` -> import the sibling mirror. Optional (not in `required`) -> `.optional()`; `nullable: true` or `type: [x, "null"]` -> `.nullable()`.
- Objects: response/value objects default to `z.object` per the YAML's `additionalProperties` (false -> `.strict()`). **Every `*Request` and `TransitionRequest` variant is `.strict()`** (AC-3). `ProseMirrorDoc` alone is `z.object({type: z.string() ...}).passthrough()`-style per `additionalProperties: true`. Read the YAML component itself; where this plan and the YAML disagree, the YAML wins.
- `Sha256 = z.string().regex(/^[0-9a-f]{64}$/)`; `Timestamp = z.iso.datetime({ offset: true })`; `StateVector = z.base64()`; `NullableText = z.string().nullable()` (confirm against YAML). `ErrorCode = z.enum([...36 codes in YAML order])`; `export const API_ERROR_CODES = ErrorCode.options` typed as a `readonly` tuple (write the tuple literal `as const` once, build `z.enum(API_ERROR_CODES)` from it).
- `TransitionRequest = z.discriminatedUnion("action", [StartReview, Submit, Withdraw, Approve, RequestChanges, Reopen])`, each variant `.strict()`.
- `TransitionRequestInput`: same union, but `Approve.rating`, `RequestChanges.note`, `Reopen.reason` become `.nullish()` in input variants (`ApproveInput = Approve.extend({ rating: Approve.shape.rating.nullish() })` etc., keep `.strict()`); all other fields unchanged. Header comment cites DO-4 §5, G-11.
- Each file starts with a one-line comment citing its card(s); no behaviour, no helpers beyond what mirrors need.
