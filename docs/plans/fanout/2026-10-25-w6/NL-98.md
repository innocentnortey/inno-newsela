## 5. Real service facts the seed must satisfy (copied from board-service.ts and the repos)

- Rows: `lesson` (id `G6.U4.L<n>`, `unit_id`, `number`, `type`, `title`, `state`, `reviewer_id`, `schema_version` NOT NULL). Reviewer name shown = `app_user.name` of `lesson.reviewer_id`. `last_change_at` = max of `review_event.at` and `lesson_version.stored_at`.
- Counts: `issue` rows whose `content_hash` equals the lesson's *checked hash* = the hash on the newest `issue` row (by `created_at`, `id`) or the newest done `check_job.finished_at`, whichever is later (`checked_hash_sql` in `packages/db/src/repos/issue-repo.ts`). Counted only if `resolved_at IS NULL`; `level` in `blocking|confirmation|advisory`. A new `lesson_version` with another `content_hash` and no new `issue`/`check_job` row does not move the counts (AC-2).
- Sort (UXQ-5): `generation_failed` first; then active states (`draft, in_review, submitted, changes_requested, reopened`) by blocking desc, advisory desc, confirmation desc, lesson number; then `approved`/`exported` by lesson number.
- Roll-up: counts per `LessonState` over every lesson of the unit, regardless of the `state` query.
- Dependency flags: only for lessons with a `lesson_link` (`outline_version_id` = the unit's newest `outline_version` by `number`, `from_lesson_id` waits on `to_lesson_id`, `slot_id`) whose source is not `approved|exported`. `slot_empty` when the source has no `lesson_doc.derived_json` section filling `slot_id` (`slot_is_filled`/`node_fills_slot` in `packages/db/src/repos/lessons.ts` near line 80-110: read that function once to build a filling `derived_json`); `waiting_for_source_approval` when the slot is filled but the source is not approved; `source_reopened` additionally when the source state is `reopened`.
- Send-back: newest `review_event` with `to_state='changes_requested'` for a lesson currently `changes_requested`; `reason_tag`, `note`, actor `app_user.name` becomes "by".
- Tile (CON-10): rows of `lesson_metrics` for the unit's lessons with `human_sessions > 0`: `n`, median of `active_minutes` (2 decimals), fast approvals = `active_minutes < g2_threshold_minutes` per row, `approved: { k: all lesson_metrics rows, total: all lessons }`, `segment_label` = null when n = 0 or when the distinct reviewer names (from `lesson.reviewer_id` of those lessons) number 3 or more, else `"one reviewer, n = <n>"` or `"<d> reviewers, n = <n>"`. `lesson_metrics` is append-only (triggers reject update/delete), so each tile case gets its own unit.
- `unit` (`id` `G6.U4`, `grade`, `title` "Grade 6 · Unit 4") and `outline_version` (`id` `G6.U4.ov1`, `number`, `sha256` 64 hex, `source_kind`, `source_name`, `uploaded_by`) rows are needed for `GET /api/units` and the dependency query.

If `board-routes.ts` is found to differ, fall back to asserting `request_id` and `duration_ms` from `route.done` and report `unit_id` as missing (do not edit `with-route.ts`). Add a unit assertion to `apps/web/app/api/units/[unitId]/board/route.test.ts` is not allowed (NL-54's file); put any unit check in `capture.spec.ts` only.

Decision: write the 8 PNGs with `page.screenshot({ path })` into `con-9/` instead of `toHaveScreenshot`; they are evidence for a human look-sheet check, not baselines. Report the config limitation as a Route fact.
5. **Stale test uses a real 11 s wait** (the product rule is time-based: polls failing > 10 s); every other wait is a locator or response wait, no sleeps.
6. **S-15 stays out.** The failed-row note is the fixed text "Generation failed" and there is no failure reason, "Approved · v2" or "Standard proposed" data on `BoardRow` (seam S-15, contract gap). The ticket may not fix it (contract change goes through `CHG-N`); the specs assert the fixed text and do not assert a reason.
