## 4. Design decisions (made here; ticket > DO-4 > DO-3)
1. **Clock.** The web container uses `SystemClock` (`container.ts` line ~84), so `heartbeat.at` and the merged seconds are SERVER time; `page.clock` moves only the browser. A 10-minute replay under `page.clock` alone yields ~0 stored minutes and cannot meet AC-1. The ticket forbids editing `container.ts`/`src/server/**`. Decision: **replay in real time with a compressed script** (below), use `page.clock` only where it helps the client side (idle: `last_input_at` staleness) and never to fake server time. This departs from "10 minutes" in AC-1; see Open items 1.
2. **Compressed S8 script** (`script.ts`, seconds of real time; all within one test so it fits `perl alarm 500`): lesson 1: reviewer A, tab T1, active 90 s; lesson 2: A, T1, active 90 s; lesson 3: A in two tabs T1+T2 both active 120 s (counts 120 not 240), plus reviewer B tab T3 idle (focused/visible but `last_input_at` older than 60 s) for 120 s. Events are `(tab, t, focused, visible, last_input_at)`; the replay drives real input (`page.mouse.move`) at scripted times and uses `page.context().newPage()` for the second tab, `bringToFront` / `page.evaluate` to flip focus is NOT reliable, so use `page.emulateMedia`-free approach: a hidden tab is simulated by not touching it and by `page.addInitScript` overriding `document.hasFocus`/`visibilityState` per script event. Keep tolerances: +/- 1 minute (60 s) per lesson, as the AC says.
3. **Oracle** `oracle.ts`: `expected_active_seconds(script, lesson, user)` = union of 15 s-beat intervals per user across tabs where each beat is active and at least 10 s from the previous kept beat of that tab, gaps <= 60 s; pure function of the script, never reads the database. Also `expected_idle_add(script) <= 60`.
4. **Seeding** `seed.ts` (repo helpers, no UI, no collab): `seed_standards(db)` and `seed_users` from `@ls/db/testing/outline-seed`; unit/outline/lesson rows via `insert_row` from `@ls/db/testing/insert-row` and `PgLessonRepo.ensure_lessons` + `write_generated_version` / `write_snapshot` for WP-1, WP-3, WP-4 drafts (compiled stub drafts; `StubJudgeClient` is in `packages/llm/src/stub.ts`, not needed here). Three lessons editable (state with a generated version), one `submitted` lesson with snapshot for approval; the last stored editor (`record_last_editor`) is a reviewer who is not the approver. Users: reviewers A and B (`synthetic: false`), approver, author, synthetic reviewer.
5. **Approval** through SCR-14 UI (click rating "Usable with edits", submit); the API call is `transitionLesson` (CON-18). Matrix beyond AC-5/6/9 is NL-115.
6. **S8 result** (AC-7): use `PgEvidenceRepo` against the stack DB (NL-49 evidence repo is merged): `start_eval_run` suite S8, one `add_case_result` (`case_id` `s8-3-lesson-review`, `expected_json` script minutes, `actual_json` stored minutes + pass/fail vs 1 min), `finish_eval_run`. The spec reads the row back from `eval_case_result`.
7. **No-name walker** (AC-4): record every JSON response via `page.on("response")` for the lesson read, board, metrics, heartbeat routes; walk objects, fail on any object holding a name-like key (`name|display_name|user|email|reviewer`) and a minutes-like key (`minutes|active_minutes|seconds`); also assert the reviewer display names never appear in the metrics response text.
8. **Versions.** `workspace-screen.tsx` sends `versionId: "lv-" + version_number`, not the real `version_id`. Sessions are keyed by (user, lesson, version) and `sessions_for` reads all versions, so totals still merge. Fix it only if the lesson read exposes the real `version_id` on the same object (check `components["schemas"]["Lesson"]`); otherwise leave and record it in the dev log as a finding.
9. **Disclosure**: `DISCLOSURE` exists in `copy.ts`; AC-2 asserts it is visible on SCR-9 and SCR-14; if SCR-14 does not render it, add the single line there (heartbeat part, allowed by the ticket) and log it.

## 7. Risks
1. Real-time script is slow (~6 min) and flaky if the host is loaded: no retries, one test per AC token except AC-1/AC-7 sharing the run output file (`con-20/.script-result.json` under `test-results/`, not committed).
2. Focus/visibility simulation: use the init-script override of `document.hasFocus` / `visibilityState` rather than real window focus (headless has no focus).
3. `HeartbeatService.last_kept` is in-process memory; restarting the stack between tests resets it (fine). One `startStack` per run, so tests share the server: use a fresh lesson and fresh users per test.
4. Role/page access: the SCR-14 path needs lesson `submitted` with snapshot; seed it exactly like NL-68's mock data (`e2e/approval`).
