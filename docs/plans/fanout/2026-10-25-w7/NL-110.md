## 1. Goal (what it does)

After a lesson is stored AND its deterministic checks have finished for that exact `content_hash`, a separate worker loop (the judge lane) finds the hash that has no
`judge_verdict` rows, runs `JudgeJob.run(lesson_id, content_hash)` (one stub or real verdict per (activity address, standard code) alignment pair), then writes one
advisory `judge_no` issue per "no" verdict. Nothing in the gates reads it: `judge_no_rule.run` returns `[]` and `submit_gate`/`approve_gate` work from re-run findings, so Approve never waits.

## 2. Findings that shape the plan (read before coding)

1. **Pairs = the `alignment_link` rows of that hash** (written by the check runner: `derive_alignment`, roles I/P/A, one row per (code, address)). The pair source reads
   them, so "WP-1 Lesson 4 yields its focus-standard pairs" holds with no new derivation. Because pairs exist only after the checks wrote links, the claim query also needs
   the hash to be **already checked** (see 4.2); this also avoids the `replace_for_hash` same-hash trap (finding 2).
2. **`PgIssueRepo.replace_for_hash` cannot add rows to a hash that already has issue rows** (`same_hash` branch only touches `created_at`), and the port is frozen by
   `packages/core/src/ports/ports-surface.test-d.ts:56` (exact key list). So "through IssueRepo" is not possible without breaking that test. Ruling (ticket > DO-4 > DO-3 order cannot satisfy it; least invasive): a **worker-local writer**
   `PgAdvisoryIssueWriter` in an owned file that inserts into the existing `issue` table; `IssueRepo` and `issue-repo.ts` stay untouched. Recorded as Open item 1.
3. **Ordering hazard**: `checked_hash_sql` takes the newer of the newest `issue.created_at` and newest done `check_job.finished_at`. A slow judge inserting a `judge_no` row for old hash H1 with `created_at = now()` after H2 was checked would make `current()` report H1. The writer therefore (a) inserts only if H is still the latest `lesson_doc` hash of the lesson, in the same tx, and (b) sets `created_at` to the hash's own done-check time, never `now()`.
4. **Claim without a table**: no `judge_job` table exists and DDL is NL-08's. Claim = `SELECT ... FOR UPDATE OF d SKIP LOCKED` over `lesson_doc` (rows are append-only, store inserts new seq rows and never updates, so the lock blocks nobody), held in a `TxRunner.with_tx` for the duration of the job. Idempotence = "no `judge_verdict` row for (lesson_id, content_hash)".
5. **Prices**: `JudgeJob.run` calls `prices.price_for(config.judge_model_id)` before reserving; `PRICE_TABLE` has only `claude-sonnet-5-5`, and `packages/llm/src/prices.test.ts` (NL-32 frozen) asserts the id list equals `["claude-sonnet-5-5"]`. Stub mode has `model_judge_id === null`.
6. **S-26 / AC-10**: `OpenRouterJudgeAdapter.verdict` ignores the rendered prompt (sends `JUDGE_RUBRIC_V1` + a JSON blob), so `model_call.rendered_prompt` is not what is sent and the locked injection guard never leaves the box. `JudgeJob` also releases the reservation only on the client-error paths, not when `calls.complete`/`insert_verdict` throws.
7. **No test double produces a "no" in a running stack** (`StubJudgeClient` throws `unscripted stub judge call` when its queue is empty).

### 4.2 `judge/claim-loop.ts`

```ts
export interface JudgeJobPort { run(lesson_id: LessonId, content_hash: Sha256): Promise<JudgeRunReport>; }
export interface ClaimedJudge { lesson_id: LessonId; content_hash: Sha256; }
export class JudgeClaimLoop {
  constructor(db: TxRunner, job: JudgeJobPort, issues: AdvisoryIssueWriter, clock: Clock, logger: Logger,
              opts: { poll_ms: number; backoff_ms: number; backoff_max_ms: number });
  /** claims at most one pair of (lesson, hash), runs it, writes advisory issues. null = nothing to do. */
  run_once(): Promise<JudgeLoopReport | null>;
  run_until(stop: { is_set(): boolean }): Promise<{ judged: number }>;
}
export interface JudgeLoopReport { lesson_id: LessonId; content_hash: Sha256; pairs: number; verdicts_no: number; issues_written: number; skipped: number; failed: number }
```
`run_once` inside one `db.with_tx` (this is the lock holder; the job uses its own connections through the repos):
```sql
SELECT d.lesson_id, d.content_hash
  FROM lesson_doc d
 WHERE d.seq = (SELECT max(seq) FROM lesson_doc x WHERE x.lesson_id = d.lesson_id)
   AND EXISTS (SELECT 1 FROM alignment_link a WHERE a.lesson_id = d.lesson_id AND a.content_hash = d.content_hash)
   AND (EXISTS (SELECT 1 FROM check_job j WHERE j.lesson_id = d.lesson_id AND j.content_hash = d.content_hash AND j.status = 'done')
        OR EXISTS (SELECT 1 FROM issue i WHERE i.lesson_id = d.lesson_id AND i.content_hash = d.content_hash))
   AND NOT EXISTS (SELECT 1 FROM judge_verdict v WHERE v.lesson_id = d.lesson_id AND v.content_hash = d.content_hash)
 ORDER BY d.stored_at ASC, d.lesson_id ASC
 LIMIT 5
 FOR UPDATE OF d SKIP LOCKED
```
(`FOR UPDATE ... LIMIT` with a subquery in WHERE is allowed; if Postgres rejects the correlated max(seq) form with FOR UPDATE, select ids first then `SELECT ... FOR UPDATE SKIP LOCKED` on the picked keys.) Skip candidates still in the in-memory backoff map (`Map<"lesson|hash", { next_at: number; fails: number }>`). Only the **latest** hash of a lesson is judged (an older stored hash is superseded).
Then `report = await job.run(lesson, hash)`. After it: read the "no" verdict rows (`SELECT address, code, question FROM judge_verdict WHERE lesson_id=$1 AND content_hash=$2 AND verdict='no' ORDER BY address, code`) and call `issues.append_advisory(...)` once (4.3). Outcomes:
- `report.pairs > 0 && report.failed + report.skipped === report.pairs` (judge unavailable: provider error/timeout, spend refusal): no verdict rows exist so the pair stays claimable; record backoff `min(backoff_max_ms, backoff_ms * 2^fails)`; log exactly one line `judge.unavailable` with `{ lesson_id, extra: { content_hash, failed, skipped } }`. No issue written. Reservation was released by the job (AC-4).
- some verdicts written: normal path; if `report.failed + report.skipped > 0` log one `judge.partial` line (those pairs are not retried; advisory, Open item 3).
- `JudgeJob.run` throws (unexpected client error): catch in `run_once`, log `judge.failed` with `name` only (never `e.message`), apply backoff, return null. The loop never calls `exit` for a judge failure.
`run_until(stop)`: while `!stop.is_set()`: `run_once`, `clock.sleep(poll_ms)` when null (copy `CheckLane` shape). `JudgeLane` may simply be `JudgeClaimLoop.run_until`; the wiring field `lane` is that object so `loops.ts` calls `h.judge.lane.run_until(stop)`. Own poll, no generation semaphore, no check-queue interaction (AC "never shares a lane").
Poll settings: reuse `settings.check_poll_ms` (no new setting; settings are not owned). `backoff_ms` 30000, `backoff_max_ms` 600000 constants in wiring.

### 4.3 `judge/advisory-issue-writer.ts`

```ts
export interface AdvisoryIssueWriter {
  append_advisory(lesson_id: LessonId, content_hash: Sha256, nos: readonly { address: string; code: string; question: string }[]): Promise<number>;
}
```
`PgAdvisoryIssueWriter(deps: { db: PgDatabase; ids: IdGenerator; clock: Clock })`, one `with_tx`: (1) `SELECT content_hash FROM lesson_doc WHERE lesson_id=$1 ORDER BY seq DESC LIMIT 1 FOR SHARE`; if it differs from `content_hash` return 0 (superseded, finding 3). (2) for each no, skip if `issue` already has `(lesson_id, content_hash, kind='judge_no', address, code)`; else insert `id = ids.new_id("iss")`, `level='advisory'`, `kind='judge_no'`, `address`, `code`, `span_anchor=null`, `related_lesson_id=null`, `created_at = COALESCE((SELECT max(finished_at) FROM check_job WHERE lesson_id=$1 AND content_hash=$2 AND status='done'), $now)`. Returns rows inserted. Idempotent. "blocks: []" is the `IssueRow` shape's absence of any blocking field: advisory level only; the API's `blocks` is derived in `issue-service` (verify `blocks: []` for `level: advisory` in the route test, do not edit the service).
Message (provisional label, fixed text, no model rationale, no quote from the lesson): `Provisional: the judge says this activity may not teach ${code}. Advisory only; it does not block Submit or Approve.` Put the template in `packages/core`? No: keep local, exported as `judge_no_message(code)`.
