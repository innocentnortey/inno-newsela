## 4. Design decisions (ticket > DO-4 > DO-3)
1. **Collab reachability (the main seam).** The shared stack web (`startStack({web:true})` in global-setup) gets no `COLLAB_INTERNAL_URL`; its default `http://collab:1234/internal` does not resolve, so `submit/withdraw/request_changes/reopen` return `COLLAB_UNAVAILABLE` there. `support/**` is read-only. Decision: `con-18/stack.ts` starts, in `beforeAll`, (a) a real collab process `npx tsx apps/collab/src/main.ts` (repo root cwd) with the global stack's `DATABASE_URL`, `COLLAB_INTERNAL_TOKEN=e2e-token-00000000000000000`, `AUDIT_HASH_SALT`, `SESSION_COOKIE_NAME=ls_session`, `PORT=COLLAB_PORT=<free>` (same env keys as `startStack`'s collab branch; copy them), and (b) a second `npx next start -p 3134 -H localhost` from `apps/web` (reuses the existing `.next`; build first with `E2E_SKIP_BUILD` logic: if no `.next/BUILD_ID`, run `next build`) with the same env plus `COLLAB_INTERNAL_URL=http://127.0.0.1:<collab>/internal` and `APP_ORIGIN=http://localhost:3134`. All specs that submit/withdraw/send back/reopen use this web2 base URL (absolute URLs, `Origin` header = web2 origin). Approve-only cases may use seeded `submitted` lessons (no collab), same web2. Teardown kills only these two children (`detached` + process-group kill like `real-stack.ts kill`). Fallback if a second web is unworkable: the in-spec collab from `con-12/helpers.ts startCollab()` does not serve `/internal`, so it is not a substitute; stop and report.
2. **Browser to collab.** Call `bridgeCollab(page, collabPort)` on every SCR-9 page that opens the live editor.
3. **Two accounts, two contexts.** Reviewer R and approver A each in their own `browser.newContext()`; `createUser("reviewer", {synthetic:false})`, `createUser("approver", {synthetic:false})`; a second approver A2 for FOUR_EYES/precedence variants. Last-editor fixture rows are set by direct SQL on the test DB only (AC-4): `update lesson set last_editor_id = $approver where id = $1`.
4. **Folder names.** Ticket says `actions/submit/**`; the submit code lives directly in `actions/` (see section 2). Do not create a new `submit/` folder or move files (NL-113/114 edit neighbours). Record the typo in the dev log.
5. **SCR-15 reachability (AC-16, duplicate AC number in ticket; call the second one AC-17 in the dev log).** Entry point stays NL-68's `DecisionCard`. Wire in `approval-screen.tsx`: `onStale` -> `action.markStale()` (add a small `markStale` to `use-approve-action.ts` that sets `view = { kind: "stale" }`) then close the dialog, so the SCR-14 stale banner shows (not the form's own toast); `onDone` -> close and `data.reload()` (state reads `changes_requested`/`reopened`). Add unit tests beside (`apps/web/tests/unit/features/approval/` pattern). On SCR-9 for the author/reviewer the new state must show after reload; assert in e2e.
6. **Seeding** (`seed.ts`, wraps NL-99's): WP-1 Lesson 4 (`content: "wp1"`, id `<unit>.L4`) and Lesson 5 as the linked lesson. Create the Lesson 4 -> Lesson 5 dependency with a `lesson_link` row on the unit's outline version (`from_lesson_id` L4, `to_lesson_id` L5, `kind` as in `packages/db/migrations/0002_intake.sql` / `packages/db/src/repos/lessons.ts` ~line 357; copy real values from there). Check `ensureOutline` copies links; if not, insert the row in `seed.ts`. WP-1 holds the confirmation code `L.6.4.b`: leave it unconfirmed for the precedence case, insert resolved `issue` rows (as NL-99 `resolveBlocking`) for the happy path. WP-4 (Lesson 31 flag) is used only for the safety-flag blocking case in the precedence test if cheap; otherwise log as not covered. Distinctive heartbeat: seed a `review_session` for the reviewer with `active_minutes` 7.77 minutes (`active_seconds` 466.2 is not an integer: use 466) and heartbeat rows; assert the string `7.77` and `466` never appear in the three captured outputs (AC-11 evidence also checks `7.77`).
7. **Counts helper** (`counts.ts`): `snapshot(lesson_id)` returns counts of `lesson_version`, `review_event`, `audit_event`, `lesson_metrics`, `lesson_doc` and `lesson.state`, `lesson.current_version_id`; `expectUnchanged(before, after)`. Used by every refusal case.
8. **Logs for AC-11.** Capture `getStack().logs()` is for web1 only; web2 and collab pipe their lines into an array in `stack.ts` and the test scans it. Scan responses via `page.on("response")` for approve/transitions, `audit_event` rows via SQL (`json` text), and the log array.
9. **request_id** (AC-12): assert each `audit_event` written by the flow has non-null `request_id` equal to the `x-request-id` response header of the call (read the header name from an existing route test; do not invent one; if the response has none, assert audit `request_id` non-null and log the finding).
10. **Perf/timing**: single run under `perl alarm 500`; tests use fresh units/lessons/users; one `beforeAll` stack start.

## 7. Risks
1. Second web + collab startup adds ~1-2 min; cap with `waitFor200` on `/sign-in` and collab `/healthz`; no retries.
2. NOT_STORED/stale races: after the editor types, wait for the "stored" status chip (as `con-12/states.ts`) before Submit; poll `lesson_doc` count rather than sleeping.
3. Cookie jar: `localhost` cookies are shared across ports in one context, so use one context per account and never sign two accounts into one context.
4. STALE_PIN scenario needs a real edit after withdraw: use the NL-105 apply-edit internal route (token header) or the editor; whichever is reachable, not both.
5. Reopen metrics wording ("new row on next first-approval path") is ambiguous against NL-48; assert only what the writer does and record the behaviour.
6. `lesson_link` may not be copied to the seeded unit's outline version; that would make the dependency case a no-op: assert the link exists before the approve calls.
