Input type `S3Observed` (produced by `s3-observe.ts`, also built by hand in tests):

```ts
export interface S3Observed {
  run_state: string;                        // lesson_job.status for the lesson
  lesson_stored: boolean;
  draft: { blocks: {role:string; section:string; part:string|null; standard_codes:string[]; code_origins:string[]; minutes:number|null; cfu: unknown}[] } | null;
  schema_valid_first_pass: boolean | null;  // first draft model_call parsed by LessonDraft (M-31 numerator)
  repairs_used: number;                     // lesson_job.repairs
  truncation_retries: number;
  sections: { name: string; part: string|null; minutes: number }[];   // from lesson_json
  minutes_total: number | null;
  node_types: Record<string, number>;       // counts of excerpt_slot, quote_placeholder, quote in lesson_json
  codes: { code: string; origin: string | null; taught: boolean; checked: boolean }[];
  link: { present: boolean; blocks: string[] } | null;               // WP-1 only
  failure_reasons: string[];                // lesson_job.failure_reasons_json[].check
  brakes: string[];
  calls: { purpose: string; attempt: number; status: string; stop_reason: string|null; served_model: string|null; requested_model: string; input_tokens: number|null; output_tokens: number|null; cost_usd: string|null }[];

```
Export `run_assertions(expected: S3Expected, o: S3Observed): AssertionResult[]` where `AssertionResult = { name: S3AssertionName; passed: boolean; fc: FcId | null; detail: string }` (detail uses names, counts and addresses only, never draft text). Order and FC mapping (the order is also the step order used for `first_failing_step`):

| name | passes when | FC on fail |
|---|---|---|
| `draft_stored` | `lesson_stored` and `draft !== null` | FC-2 if no draft parsed or truncated (`failure_reasons` has `schema_invalid`/`truncated` or `brakes` has `truncation_retry`); FC-3 when the compile failed; FC-6/FC-4 mapped from the first blocking `failure_reasons` kind via the table `FAILURE_KIND_TO_FC` (see below); else FC-2 |
| `required_blocks` | for every expected section, every `required_roles` role occurs among `draft.blocks` with that `section` (+`part` when given) | FC-3 |
| `section_minutes` | every expected section exists in `sections` with `abs(minutes - expected) <= 5`, and `minutes_total` in `[45, 55]` | FC-3 |
| `placeholder_count` | `node_types.excerpt_slot + node_types.quote_placeholder === expected.placeholders.exact` | FC-7 |
| `no_quote_node` | `node_types.quote ?? 0 === 0` | FC-6 |
| `origin_present` | every `codes[]` entry has `origin` in `outline|outline-fixed|narrowed|added`, and the codes named in `expected.focus_codes[].origin_expected !== "outline"` are not `outline` | FC-4 |
| `taught_and_checked` | every expected focus code has `taught && checked` | FC-5 |
| `lesson_link_blocking` | only when `expected.lesson_links` is non-empty: `link.present` and `blocks` contains both `submit` and `approve` | FC-9 |

`FAILURE_KIND_TO_FC` (keys are `FailureReason["check"]` values from `packages/schema/src/api/runs.ts`; implementer reads that union and maps each: schema/truncation -> FC-2; structure/timing -> FC-3; code/standards kinds -> FC-4; alignment -> FC-5; grounding/quote/pagenum kinds -> FC-6; placeholder kinds -> FC-7; safety -> FC-8; cross-lesson -> FC-9; anything unmapped -> `FC-3` plus the detail "unmapped failure kind"). One test enumerates every union member and fails if one is unmapped.

Trajectory (`first_failing_step`): `derive_trajectory(o, results): { first_failing_step: "normalize"|"plan"|"draft"|"compile"|"checks"|"repair"|null; fc: FcId|null; steps: {step; ok}[] }`. Rule, in step order: `normalize` fails if `run_state` is missing (run never started / row refused); `plan` fails if no `unit_plan` call completed; `draft` fails if the first `lesson_draft` call errored, was truncated twice, or returned schema-invalid output; `compile` fails if `compile_error`-style failure reasons exist; `checks` fails if the first check pass had blocking findings (any `repairs_used >= 1` means checks failed first time); `repair` fails only if a repair was used and the lesson still ended `generation_failed`. A case that passes all assertions but needed a repair has `first_failing_step: "checks"` recorded with `repair_recovered: true` (information, not failure). `first_failing_step` and `fc` are placed in `CaseOutcome.actual.trajectory`.

`CaseOutcome` mapping: `passed = results.every(r => r.passed)`; `failure_category` = the `FC-n` of the first failing assertion, or `null`; `actual = { assertions: [{name, passed, fc, detail}], trajectory, counts: {placeholders, minutes_total, sections}, schema_valid_first_pass, repairs_used, tokens: {input, output}, served_models: [...], requested_models: [...], calls: [...], pair: "WP-n" }`; `cost_usd` = sum of `model_call.cost_usd` of the run as `Decimal`. `actual` must contain no draft text, no prompt, no cell text (AC-7); the draft's text stays in the discarded test database.

## 5. Cost guards and CLI flags (AC-5, AC-6; `s3-guards.ts`, `cli.ts`, `types.ts`, `runner.ts`)
