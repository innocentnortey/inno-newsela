## 1. What to build
Route `/prompt-guidance` (program-wide, UXQ-3; replaces the NL-24 placeholder). `h1` "Prompt guidance". `?version=<version_id>` selects a guidance version (default: the latest). Two panes (`TwoPane` with `rail` = versions list):

**Left (rail) "Guidance versions"**: `<ul aria-label="Guidance versions">`, newest first; each item is a `Link` to `?version=<id>` with "v{number}", author, time (`toLocaleString("en-GB",{timeZone:"UTC"})`), reason; the selected item has `aria-current="true"`. Unknown `?version=` falls back to the latest silently.

**Right**:
1. Role note (reviewer/approver): "Only authors edit guidance." (`RoleNote`); no editor, no **Save as new version**, no **Try on one lesson** in the DOM.
2. **Selected version**: heading "Guidance v{n}", its text, and **"Changes from v{n-1}"** diff. The contract has no per-version full text, only `diff` (text) per version and the locked layer; so the version's text IS its `diff`... see Section 6 item 1 (decision made there): render `diff` line by line in a `<pre aria-label="Changes from v{n-1}">`, each line a `<span>`; lines starting `+` get a `data-diff="add"` marker and tokens (`text-success`/ semantic token classes only), `-` get `data-diff="remove"`. v1 (empty diff) shows "First version." Text is always a React text node (never HTML, R-58).
3. **Locked layer**: section titled "Locked rules (read-only)" showing `locked_layer.text` in a `<pre>` (plain text node). Never input/textarea/contenteditable; no edit control (R-38).
4. **Editor** (author only): `Textarea` label "Guidance text" (maxLength 8000, show remaining count), `TextInput` label "Reason" (required), **Save as new version** (primary). The textarea is pre-filled with the latest guidance text reconstructed per Section 6 item 1; typed text lives in `useDraft("guidance")` and `useDraft("reason")` from `@/lib/draft-memory` (UXQ-1: survives re-sign-in on the same page, lost on reload). Blank reason: client does NOT pre-block; the call is made and the server answers `REASON_REQUIRED` (so the named error is proved), but the button is disabled while a save is in flight (single POST).
5. **Try on one lesson** (author only): `Select` label "Lesson" listing the board rows of unit `g6-u4` ("Lesson {number}: {title}", only rows with a non-null `number`), button **Try on one lesson**. Starts the trial (Section 2). One in-flight at a time.
6. Messages (`role="status"`, one at a time): save 201 -> "Guidance v{n} saved. Runs already going keep v{n-1}." (n-1 = base number). Trial -> "Candidate made on Lesson {number}, not adopted." plus a `Link` "Compare the candidate" to `/units/g6-u4/lessons/{lesson_key}/candidates/{candidate_id}` (SCR-12). While the candidate is being found: "Making a candidate on Lesson {number}…".
7. Errors: `REASON_REQUIRED` -> field error on Reason "A version needs a reason." and text kept. `STALE_BASE` (409, `details.latest_version_id`) -> `Banner level="blocking"` "Someone saved a newer version first. Review it below, then save again." the list is refetched, the newer version is selected and its diff shown, the typed Guidance text and Reason kept verbatim, base switches to the newer version. `ROLE_FORBIDDEN` on save/trial -> read-only view with "Only authors edit guidance.". Network/other save error -> `Banner level="blocking"` "Nothing was saved. Try again." text kept. Trial errors (`DAY_CAP_REACHED` -> "The day's spend cap would be passed. Remaining: ${remaining_usd}." when `details.remaining_usd` is a number else generic; anything else -> "No candidate was made. Try again.") text and selection kept. `listPromptVersions` fails -> `CantLoad thing="prompt guidance"` with Retry. Board list fails -> only the Lesson select shows "Couldn't load lessons. Retry"; the rest of the page works.
8. Cut #7: `PromptGuidanceGate({fired = FIRED_CUTS, children})`: `fired.includes(7)` renders `<NotFound what="page" />` else children; the screen wraps itself in it. The nav entry and the NL-55 ghost link already follow `FIRED_CUTS` (verified in `nav.ts` `buildNav`, `units-home-screen.tsx`), nothing to edit there.
9. Must not: render the locked layer in an editable control, send locked-layer text in any request body, render guidance as HTML (no `dangerouslySetInnerHTML`, no markdown).

## 6. Decisions made (ticket > DO-4 > DO-3) and risks
1. **Version text.** CON-24 `listPromptVersions` returns per guidance version only `diff` (text), not the full text. Decision: the "selected version's text" = the lines of its `diff` that survive (`+` and unchanged lines, markers stripped) is NOT reconstructible in general, so the screen shows the version's `diff` as the "Changes from v{n-1}" view and the editor's starting text is `latestText(versions)` = the `+`/unmarked lines of the LATEST version's diff joined with newlines (for v1 the fixture diff is `''`, so the textarea starts empty with placeholder "Write guidance for the generator"). If the real server's diff is a full-text diff against the previous version this is exact; NL-103 verifies on the real route and raises a `CHG-N` (add `guidance_text` to `GuidanceVersion`) if it is not. Do not invent a field client-side. Record in devlog.
2. **Read access.** Page is open to every role (CON-24 read); `view_prompt_guidance` in `roles.ts` is author-only and only drives the nav entry. Not edited (NL-24 file).
3. **`prompt_version_id` for a trial** uses `current_prompt_version_id`; trying an older version is disabled with a reason (no combined-id rule in the contract). Raise to the batch if Innocent wants older-version trials (needs a `CHG-N`).
4. **Candidate id resolution** goes through `getLessonHistory` (Section 2); it is not in the `startRun` response. If NL-103 finds the real route stamps `provenance.run_id` differently, it fixes it there. The Prism history example has no candidate with `run_id: "run-trial-1"`, so `serveTrial` supplies it.
5. Risks: (a) Next dev server runs effects twice: guard save and trial starts with a ref so a double click posts once (AC-2 counts POSTs). (b) `apiGlob` also matches page navigations: keep `?view=1`. (c) `useDraft` keys by pathname, so `?version=` changes keep drafts; the draft is cleared only after a successful save. (d) The `Select` from `@/components/ui/select` needs a visible label "Lesson".
