### Step 1. The Sheets base-URL seam (production code, with unit tests)

Design (decided, do not reopen): the base origin is a setting that defaults to Google and can be moved to a loopback address only in stub-model mode; the allow-list stays exact-origin.

1. `packages/config/src/settings.ts`: in `WebSettings` add `sheets_base_url: string` (read the interface at the top of the file and add the field next to `sheets_fetch_timeout_ms`). In `load_web_settings`, after `sheets_fetch_timeout_ms`, add `sheets_base_url: load_sheets_base_url(env, model.model_provider_mode)`. Add this private function (same file, near `nonempty`):
   ```ts
   const DEFAULT_SHEETS_BASE_URL = "https://docs.google.com";
   function load_sheets_base_url(env: Env, mode: "real" | "stub"): string {
     const raw = read_url(env, "SHEETS_BASE_URL", ["https:", "http:"], { default: DEFAULT_SHEETS_BASE_URL });
     const origin = new URL(raw).origin;               // keeps scheme, host, port; drops any path
     if (origin === DEFAULT_SHEETS_BASE_URL) return origin;
     const host = new URL(origin).hostname;
     const loopback = host === "127.0.0.1" || host === "localhost" || host === "[::1]";
     if (mode !== "stub" || !loopback) throw new ConfigError("SHEETS_BASE_URL", "only the default Google origin is allowed unless MODEL_PROVIDER_MODE=stub and the host is loopback");
     return origin;
   }
   ```
   (`ConfigError(name, reason)` is already imported; `read_url` is already imported; `Env` is the same type the other loaders use.) Why both conditions: `MODEL_PROVIDER_MODE` defaults to `stub`, so stub alone is not a production guard; loopback alone would let a misconfigured deploy fetch from the host. A real deployment sets `MODEL_PROVIDER_MODE=real`, so a stray `SHEETS_BASE_URL` fails at boot with `ConfigError`, never silently.
