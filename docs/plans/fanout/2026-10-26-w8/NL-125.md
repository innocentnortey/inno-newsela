## 4. Design decisions (ticket > DO-4 > DO-3)
1. **Own Playwright config in the owned folder.** `apps/web/e2e/integrity/playwright.config.ts` copies `playwright.real.config.ts` (same `globalSetup` path `../integration/support/global-setup.ts`, `workers: 1`, `fullyParallel: false`, `retries: 0`, trace/screenshot/video off, `outputDir: ./test-results/integrity-out`, `testDir: "."`, `timeout: 120_000`, `reporter: [["list"], ["json", { outputFile: "test-results/integrity/report.json" }]]`, `E2E_PORT` default `3160`). `snapshotPathTemplate` not needed (no screenshots).
2. **The ticket's command cannot run as written** (`npm run test:e2e` is wired by `scripts/script-targets.json` to the mock config; `package.json` and that file are not owned). Decision: ship `apps/web/e2e/integrity/run.ts` and document the working command; record the mismatch in the dev log and add one row to `docs/plans/seam-followups.md` for the owner of `scripts/script-targets.json` ("`test:e2e -- integrity --trials n` should route to `e2e/integrity/run.ts`; NL-137 uses the `npx tsx` form until then"). Working commands (repo root):
   - `E2E_PORT=<free> perl -e 'alarm 1500; exec @ARGV' npx tsx apps/web/e2e/integrity/run.ts --trials 20 [--grep <token>] [--fault-fixture]`
   - `run.ts`: parses the three flags; sets `INTEGRITY_TRIALS`, `INTEGRITY_FAULT` env; truncates `apps/web/test-results/integrity/trials.jsonl`; spawns `npx playwright test -c apps/web/e2e/integrity/playwright.config.ts [--grep token]` with `stdio: inherit`; afterwards (also when playwright failed) runs the S5 scoring step `npx tsx evals/src/cli.ts integrity --repeat <trials>` (check `cli.ts parse_args`; if `integrity` is not a subcommand, call `run_cli(["golden","--suite","S5","--repeat",n], ...)` the same way `cli.ts` main does, or construct `EvalRunner` directly with `make_s5`); appends the store p95 and not-built lines (6.5); exits non-zero when playwright exited non-zero OR any case failed OR `floor_met` false. `--grep` runs only that assertion's file and scores only that case (see 6.2 `INTEGRITY_ONLY`).
3. **One scenario per assertion per trial, each on its own fresh clone.** Tests are generated in a loop `for (let t = 1; t <= TRIALS; t++) test("<token> trial <t>", ...)` so `--grep stale_approve` selects exactly that assertion's 20 trials. A scenario seeds a fresh unit and a fresh WP-1 Lesson 4 clone (`freshUnit()` + `seedLesson`), creates three fresh users (A reviewer, B reviewer, C approver, `synthetic:false`) and three `browser.newContext()` contexts signed in with `signInAs`; reviewer/approver rows are per trial so four-eyes state never leaks across trials. The trial driver `trial.ts` exports `runTrial(browser, stack, token, t, body)` which builds the world, runs `body`, always closes contexts, and appends one JSON line to `trials.jsonl` (`{ token, trial, passed, detail, ms, store_ms, request_ids, store_id, error? }`) in a `finally` so a thrown assertion is recorded as failed (not lost), then re-throws so Playwright also fails.
4. **No new product code and no collab fault hooks.** AC-7's "fixture that lets the post-lock write through" is a test-side fixture: with `INTEGRITY_FAULT=1`, in the trial number `ceil(TRIALS/2)` of `zero_edits_after_lock` only, `scenarios.ts` inserts one stray `lesson_doc` row for the locked lesson with plain SQL (`insert_row` from `@ls/db/testing/insert-row`, test DB only) after the lock; the "row count constant after the lock" check then fails for that trial only. Expect 19/20, exit non-zero, report names the trial. Never wire the fault into product code or collab.
5. **Counts, not just status.** Every refusal/invariant check compares `snapshot()` / `expectUnchanged()` from con-18 `counts.ts` (`lesson_version`, `review_event`, `audit_event`, `lesson_metrics`, `lesson_doc`, `lesson.state`) before and after, plus `docCount`/`auditCount` for the lock case.
6. **Store latency** (`store-latency.ts`): measure `store_ms` = time from the last keystroke in a trial's editing burst to the first new `lesson_doc` row for that lesson, polling every 25 ms with a 10 s cap; collab debounce is 500 ms (`STORE_DEBOUNCE_MS=500` in `con-18/stack.ts`), so also record `store_ms_net = max(0, store_ms - 500)`. The report states both; the verdict line uses `store_ms_net` (the store write itself, which is what SP-2's 500 ms target measures) and shows the raw p95 beside it. p95 = nearest-rank over all trials of all assertions that type (record the n). Choice made here, open item O-1.

## 5. Assertions and scenario bodies (all via real entry points; trial = `<token> trial <t>`)
Common setup `world(t)`: stack from `startCon18Stack()` once per file in `test.beforeAll` (closed in `afterAll`); lesson `in_review`, `last_editor_id = null`; A, B, C contexts each with `bridgeCollab(page, stack.collabPort)` and signed in; A and B open `lessonPath(lesson)`; wait `firstTextbox(page)` `aria-readonly=false`. C opens SCR-14 only where noted.
1. **`stale_approve`** (AC-1): A and B each type a unique token (`A-<t>-1`, `B-<t>-1`), wait for `savedState(..., "stored")`; A submits through the SCR-9 Submit action; C loads SCR-14 and records the pin from `latestSubmit(lesson_id)`; B withdraws (`transition(api, id, {action:"withdraw"})`), types `B-<t>-2` and resubmits (a new snapshot); C approves with the OLD pin (`approveBody(pin, "usable_with_edits")`) -> `status 409`, `errCode === "STALE_PIN"`; `expectUnchanged(before, after)`; reload SCR-14 shows the new snapshot hash (`latestDocHash`).
2. **`zero_edits_after_lock`** (AC-2): A types and waits stored; A submits; read `docCount` and `auditCount` and `lesson.state='submitted'`; A types `LATE-<t>` into the still-open editor (keystrokes after the freeze); expect the notice `Your last edits were not saved because` and `Removed text: “` visible and the editor `aria-readonly=true`/`read_only`; wait 2.5 s past the 500/1000 ms store debounce; `docCount` and `auditCount` equal their post-lock values (0 rows added); a `rawSocket(...)` write by B is refused (`LESSON_LOCKED`) and also adds no rows; the refused text is the text A typed (CON-12 `refused`, `refused_from`).
3. **`no_silent_loss`** (AC-3): A and B type 12 unique tokens (`A<t>-01..12`, `B<t>-01..12`, 6 keystroke bursts, no waits) concurrently; A clicks Submit while B is still typing so some tokens land at the lock boundary; collect `typed` (set of tokens), `in_snapshot` (tokens found in `latestDoc(lesson_id).derived_json` text) and `refused` (tokens found in the visible refused notice text of A's and B's pages, each page's own typed tokens); assert `in_snapshot ∪ refused ⊇ typed` and `|union| === |typed|` (store the counts in `detail`); never rely on timing guesses: if the editor refused nothing and the snapshot has all tokens that is a pass too.
4. **`four_eyes`** (AC-4a): B types a token, stored; `update lesson set last_editor_id = <C.user_id> where id = $1` (test DB only, as NL-115 does); B submits; C approves with the real pin -> `422 FOUR_EYES`, `expectUnchanged`. Then restore `last_editor_id` to B's id and C approves successfully (state `approved`), proving the refusal was the cause, not a broken fixture.
5. **`suggestion_blocks`** (AC-4b, NL-116 landed): A selects a passage and creates a pending suggestion through the real entry point `POST /api/lessons/{lessonId}/suggestions` (stub model; NL-116 route; copy body shape from `docs/contracts/INTERFACE.md` CON-16/CON-18 suggestion section or `apps/web/e2e/integration/con-16`); A submits; C approves with the real pin -> `422 SUGGESTION_PENDING` (first in precedence), `expectUnchanged`; then A rejects the suggestion (the real route) and C's approve proceeds past the gate.
6. **`round_trip`** (AC-5): A and B type tokens, wait stored; A reloads the page; read `latestDoc` (stored `content_hash`, `derived_json`); assert `content_hash(derived_json) === stored content_hash` and `content_hash(ydoc_to_lesson(lesson_to_ydoc(derived_json))) === stored content_hash`; from the reloaded editor read the page's own doc hash if exposed (reuse con-12 `round-trip-hash.spec.ts` approach) and compare. Then export half (NL-102 landed): A submits, C approves (restore last editor first), C `createExport(page, unit_key)` -> `download(...)` and assert the bundle's lesson hash equals the approval snapshot hash from `latestSubmit`/`lesson_version` (look at `con-23/schema-and-hashes.spec.ts` for the exact field; `bundleHash` hashes the whole bundle, use the per-lesson hash, not the bundle hash).
7. **`ids`** (AC-9): in `ids.spec.ts` (`--grep ids`): for one stale-approve-style trial, assert every `audit_event` row written by the flow has non-null `request_id`, equal to the `x-request-id` response header of the call that wrote it (read the header name from an existing route test; if absent, assert non-null and log), and each `lesson_doc` row carries the store id (`store_id`) per WF-9 capture; store them in `request_ids` on the trials line.

## 6. Suite `evals/src/suites/s5.ts` (WF-43)
6.1 `make_s5(provider_mode, deps?: S5Deps)`; `interface S5Deps { read_trials(): Promise<TrialLine[]>; available: { suggestion: boolean; export: boolean } }`; default `read_trials` parses `apps/web/test-results/integrity/trials.jsonl` (path resolved from the repo root via `import.meta.url`, like `git-sha.ts`); default `available` from `availability.ts`.
6.2 `cases()`: one `EvalCase` per assertion that is built: `stale_approve`, `zero_edits_after_lock`, `no_silent_loss`, `four_eyes`, `suggestion_blocks` (only if `available.suggestion`), `round_trip`. `provenance: "synthetic"`, `source: "DO-5 S5 / WP-1 Lesson 4 stub"`, `guards: "S5"`, `input_path: "n/a"`, `expected: { passed: true }`. When `INTEGRITY_ONLY=<token>` is set, only that case is listed.
6.3 `score(c, opts)`: per-case counter in the closure (`counters.get(c.case_id)` starting at 0, incremented each call) = trial number k; find the JSONL line `{token === c.case_id, trial === k}`; **no line => `passed: false, failure_category: "trial_missing"`** (a missing trial never passes; 20 of 20 means 20 lines passed). `actual` carries `{ trial: k, n: opts.repeat, store_ms, detail, git_sha }`, no cookies, no tokens (the runner leak guard scans it). `cost_usd: new Decimal(0)`.
6.4 not built: `availability.ts` reads `docs/plans/merged.txt` for `NL-116` and `NL-102`; if either is absent the matching assertion is excluded from `cases()` and the report gets the line `<token>: not built (cut #8)` (or `export hash: not built (NL-102)`) counted neither pass nor fail. Both are present today, so this path is covered by a unit test only (`s5.test.ts`, injected `available`).
6.5 report extras: after `EvalRunner.run`, `run.ts` appends to `evals/reports/integrity-<git-sha>.md` a section with: the three contexts (A reviewer editing, B second reviewer co-editing, C approver), `n` per assertion, model IDs `stub`, prompt version `none (stub)`, git SHA, `Store p95: <raw> ms raw, <net> ms net of the 500 ms collab debounce; target <= 500 ms [A] -> SP-2: MET|MISSED`, and the not-built lines. If `merge_section` already offers a notes field use it instead of appending.
6.6 `floors.ts`: change only `S5: 0` to `S5: 1.0`.
