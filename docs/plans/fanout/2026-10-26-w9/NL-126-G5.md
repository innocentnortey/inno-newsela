## 1. Per-issue fixes (all in `apps/web`; no server change, so CON-15, CON-9, CON-11 stay as agreed)

### #158 F-11: SCR-10 empty Insert shows the generic banner
Cause: `insert-quote-form.tsx` `onSubmit` posts empty text. The route's zod check returns `INVALID_REQUEST` with `details.fields:["body.text"]` (or `["text"]`); `fill-errors.ts` `mapFillError` has no case for it, so the `default` branch returns the banner `e.message`.
Fix (both layers, client first so no request is sent):
1. `insert-quote-form.tsx` `onSubmit`: before the POST, if `text.trim()===""` set `failure={target:"text", message:"Add the quote text."}`; else if title, chapter, pages and url (excerpt only) are all blank set `failure={target:"source", message: SOURCE_REQUIRED_MSG}`. If both are missing, text wins first (focus order), and the source message shows after the text is filled. Return without calling the API.
2. `fill-errors.ts` `mapFillError`: add `case "INVALID_REQUEST"`: read `e.details.fields` (array of strings); any field ending in `text` returns target `text` "Add the quote text."; any containing `source_ref` returns target `source` with the source message; otherwise the RETRY banner. Export `SOURCE_REQUIRED_MSG = "A quote needs a source: add the book and page, or the URL."` and use it in the existing `SOURCE_REQUIRED` case (same string, no copy change).
Acceptance: Insert with empty Text and Source shows the Text message under Text and focuses it, no banner "The request is not valid.", no network call. With Text filled and Source empty: the exact source sentence under "Book or title", focus there. A server `INVALID_REQUEST` with `fields:["body.text"]` maps to the Text field.

### #160 F-13: SCR-8 board for a unit with no outline
Cause: `board-screen.tsx` line 62: `NOT_FOUND` with no data returns `<NotFound what='unit "g6-u4"' where="Lesson Studio" boardHref="/units">` (the "Back to the board" link points at `/units`, and on the nav's board entry reads as a self link).
Fix: in that branch render the same page as the `total === 0` empty state (header + "No lessons generated for this unit yet." + "Lessons appear here as a run drafts them."), not `NotFound`. Extract the empty-state block into a small component `board-empty.tsx` (`BoardEmpty({role, unitKey, latestVersion, runId})`) used by both branches, so the copy lives once. In the NOT_FOUND branch there is no run and no version: author sees a link "Upload an outline" to the existing upload route (same href `board-screen`/`links-row` already uses for upload; implementer copies it from `links-row.tsx`); reviewer and approver see no link (FLOW-6 E1 "See the latest run" needs a run id that does not exist; recorded as a deviation in the devlog). `NotFound` stays for other screens (`conventions.tsx` unchanged).
Acceptance: empty database, reviewer lands on `/units/g6-u4/board`: sees the two sentences, no "There is no unit", no link to itself; author also sees "Upload an outline"; the north-star tile is not shown.

### #161 F-14: SCR-12 regenerate with no run says "Lesson not found."
Cause: `regenerate-panel.tsx` `errorText` falls through to `e.message` for `NOT_FOUND`; the server sends `details.reason:"no_generation_run"` (candidate-service line 176).
Fix: in `errorText` add `if (e.code === "NOT_FOUND" && e.details.reason === "no_generation_run") return REGEN_NO_RUN;`. Add `REGEN_NO_RUN = "This lesson has no generation run yet, so there is nothing to regenerate from. Start a run for this unit first."` to `features/workspace/actions/copy.ts` next to `REGEN_LOCKED`. Other NOT_FOUND keeps `e.message`.
Acceptance: the Regenerate dialog on a lesson with no run shows the new sentence, not "Lesson not found."; LESSON_LOCKED and DAY_CAP_REACHED texts unchanged.

### #162 F-15: two rail items selected
Cause: `features/frame/nav.ts` `buildNav` marks `current` by prefix, so `/units/g6-u4/board` matches both `/units` and `/units/g6-u4/board`.
Fix: compute `current` as "the single entry with the longest href that equals the path or is a path prefix of it" (ties: first). Keep the item shape. Result: board and approval pages (`/units/g6-u4/lessons/...`) light only the entry that fits best; `/units/g6-u4/lessons/L5/approval` still lights `Units` (only prefix match) which is acceptable; if the product wants "Unit board" for lesson pages that is a separate IA change, not in this slice.
Acceptance: on `/units/g6-u4/board` exactly one item has `aria-current="page"` (Unit board); on `/units` exactly one (Units).

### #163 F-16: SCR-1 demo accounts box missing
Cause (verified): the box exists (`features/sign-in/demo-accounts.tsx`) but `sign-in-screen.tsx` shows it only when `process.env.NEXT_PUBLIC_DEMO_ACCOUNTS === "1"`, a build-time value. `Dockerfile.web`, `docker-compose.yml` and `render.yaml` never set it, so deployed builds never show it. The decision the issue asks for is therefore: the spec stands, the page changes.
Fix (page only): make the flag a runtime server value. `app/sign-in/page.tsx` (server component) reads `process.env.DEMO_ACCOUNTS === "1" || process.env.NEXT_PUBLIC_DEMO_ACCOUNTS === "1"`, marks the page `export const dynamic = "force-dynamic"`, and passes `showDemoAccounts` to `SignInScreen`, which renders `<DemoAccounts />` from the prop instead of reading `process.env`. Playwright keeps working (its env sets `NEXT_PUBLIC_DEMO_ACCOUNTS`).
Handoff, not done here: set `DEMO_ACCOUNTS: "1"` on the `web` service environment in `docker-compose.yml` (G1 owns that file). Do not add it to `render.yaml` without the decision below.
Acceptance: with `DEMO_ACCOUNTS=1` at container start the sign-in page lists Author, Reviewer, Approver with emails (as `demo-accounts.tsx` already renders); without it the box is absent.
