## 1. Root causes (read from main)
- **F-5.** `ApiError(BLOCKED).details.issues` come from `packages/core/src/checks/gates.ts` `issue_json()`, which emits `kind, level, message, address, code, related_lesson_id, resolved` and **no `blocks`** (the contract `Issue` in `GET /issues` has it). `apps/web/src/features/approval/derive.ts` `checklistRows` runs `i.blocks.includes("approve")` over `[...issues, ...blockedIssues]`, so the first BLOCKED reply throws `TypeError` during render and Next's error screen replaces SCR-14. `viewFromError` casts the raw array `as Issue[]`.
- **F-6.** `apps/web/src/server/services/lesson-read-service.ts` returns `reviewer: row.reviewer_id` and `last_editor: row.last_editor_id` (user ids). The contract and board give names (`lesson.reviewer` "name or empty", UXP-1; INTERFACE example `last_editor: Reviewer A (demo)`). `send-back/copy.ts` `whoSeesIt` and SCR-14 `meta` ("by {lesson.reviewer}") print the field as is. `board-service` already uses `reviewer_name` (join `app_user.name`).
- **F-7.** Same file, `send_back` is built from `HistoryRow`: `tag: "other"` hard-coded, `note: newest.reason ?? ""`. But `transition-service.ts` line 146-148 stores a send-back as `review_event.reason_tag` + `review_event.note` (`reason` is only for reopen), and `audit_log_v` (migration `0008_review.sql`) exposes `reason` only. The board reads `review_event` directly (`board-extras.ts`), which is why the board is right.
- **F-10.** Server `build_checklist` marks "Standards confirmed" `ok` unless a standard has `confirmation === "open"`; the web `evidenceFor` (derive.ts) says "not all confirmed" whenever a focus standard is anything but `"confirmed"` (so `null` = not yet linked/checked). Row status and sentence disagree on the first load.
