## 1. F-2 (#149): COLLAB_INTERNAL_URL needs the `/internal` prefix

Cause (confirmed in code): `docker-compose.yml` line 114 sets `COLLAB_INTERNAL_URL: http://collab:1234`. The collab server only routes `/internal/...` as commands (`apps/collab/src/commands/routes.ts` `is_internal_path`); the bare host answers "Welcome to Hocuspocus!" and the web adapter (`apps/web/src/server/adapters/collab-commands.ts`, base_url joined with `/lessons/<id>/<command>`) cannot parse it. The code default in `packages/config/src/settings.ts` is `http://collab:1234/internal`.

Fix:
1. `docker-compose.yml` web service: `COLLAB_INTERNAL_URL: ${COLLAB_INTERNAL_URL:-http://collab:1234/internal}` (keeps the override possible, correct by default).
2. `render.yaml`: `ls-web` has no `COLLAB_INTERNAL_URL` entry and the code default host `collab` does not exist on Render. Add the key as a non-secret placeholder only if the render-yaml test allows `sync: false`; otherwise leave `render.yaml` untouched and record in Open items (deploy owner sets `https://<ls-collab host>/internal`). Implementer: read `tests/platform/render-yaml.test.ts` first and keep it green. Do not add a secret.
3. Guard so it cannot regress: a static test (below).

Tests (named):
- new `tests/platform/compose-collab-wiring.test.ts`, case `web COLLAB_INTERNAL_URL default ends with /internal` (parses `docker-compose.yml` with the `yaml` package already used by `tests/platform/render-yaml.test.ts`; verify import there).
- Existing `apps/web/src/server/adapters/collab-commands.test.ts` stays green (unchanged).

Acceptance: on the Compose stack as committed (no override file), quote insert (SCR-10) and send back (SCR-15) return 200 and the success toast shows; web log has no `collab.bad_body`.

## 2. F-3 (#150): the browser editor must reach collab on Compose

Cause: `apps/web/src/editor/collab-url.ts` uses `NEXT_PUBLIC_COLLAB_URL` (inlined at build) else `ws://<host>/collab`. Next serves no `/collab`; `Dockerfile.web` and Compose never set the variable. Collab is already published on `127.0.0.1:${COLLAB_PORT:-1234}`.

Fix (no code change in `collab-url.ts`; the unset fallback stays for the e2e bridges and `playwright.config.ts`, which sets its own value):
1. `Dockerfile.web`: in the `build` stage, before `RUN npm run build -w @ls/web`, add `ARG NEXT_PUBLIC_COLLAB_URL` and `ENV NEXT_PUBLIC_COLLAB_URL=$NEXT_PUBLIC_COLLAB_URL`. It is a public URL, not a secret (matches `.claude/rules/gauntlet-hosting-default.md`, which forbids secrets in ARG/ENV, not public URLs). Keep the runner stage free of it.
2. `docker-compose.yml` web `build.args`: `NEXT_PUBLIC_COLLAB_URL: ${NEXT_PUBLIC_COLLAB_URL:-ws://localhost:${COLLAB_PORT:-1234}}`.
3. `.env.example`: document `NEXT_PUBLIC_COLLAB_URL` (build time; set to the public `wss://` collab URL on Render).
4. Cookie check, no code expected: the session cookie is host-scoped, not port-scoped, so a cookie set by `localhost:3000` is sent to `localhost:1234`; `apps/collab/src/auth.ts` authenticates from that cookie only. Implementer must confirm in the live check that the collab upgrade has no Origin allow-list rejecting `http://localhost:3000` (a grep of `apps/collab/src` found none). If it does, STOP and report; that would change collab, not just wiring.
5. Docs: README and `docs/delivery/operating-instructions.md` one sentence each: the web image bakes the collab URL at build; changing `COLLAB_PORT` needs `--build`. (These two doc files are the only overlap risk with G5; edit only the Compose paragraph.)

Tests (named):
- `tests/platform/compose-collab-wiring.test.ts`, cases `Dockerfile.web declares NEXT_PUBLIC_COLLAB_URL before the build step` and `compose passes NEXT_PUBLIC_COLLAB_URL as a web build arg defaulting to the published collab port`.
- Existing unit tests for `collab_url` (search `apps/web/tests/unit/editor/`) stay green; if none covers env precedence, add `apps/web/tests/unit/editor/collab-url.test.ts` with `env wins over the same-origin fallback`.

Acceptance: on Compose, `/units/g6-u4/lessons/L4` shows "Connected" within seconds, text is editable, Submit is enabled (no bridge).
