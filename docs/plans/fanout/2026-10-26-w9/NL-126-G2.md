## 1. F-1 (#148): Confirm U4 sends `U4`, server wants `G6.U4`

**Cause (real code).** `apps/web/src/features/validation-report/errors-section.tsx`, `ActionCell`: for `unit_conflict` it builds `{ kind: "confirm_unit", value: report.unit.as_written }`. `report.unit.as_written` is the short form (`U4`; `packages/core/src/intake/normalize.ts` line 130 keeps `unit_as_written` short and builds `G${grade}.${unit_as_written}` separately). `validate_choice` in `apps/web/src/server/services/outline-choices.ts` (case `confirm_unit`) requires `UNIT_ID_RE` (`/^G\d{1,2}\.U\d{1,2}$/`, `@ls/schema/ids`) or an absent value (then it uses `ctx.unit_id`), so `U4` gets 422 "That is not a unit id such as G6.U4." The UX-5a mock accepted `U4`.

**Fix (frontend only, server unchanged; CON-4 says `value` is optional text for this kind and the server's omitted-value path is the contract-safe default).** Send the full unit id taken from the report, not the display text:
- In `report-model.ts` add `export function unit_id_of(report: Report): string | null` returning `report.outline_version_id.replace(/\.ov\d+$/, "")` when it matches `UNIT_ID_RE` (the QA walk shows ids like `G6.U4.ov1`), else `null`.
- In `errors-section.tsx` build the request as `value: unit_id_of(report) ?? undefined`. Because `ReportActions.choose` takes `ChoiceRequest` (`report-model.ts` line 23 area), make `value` optional for `confirm_unit` only if the type does not already allow it (check `ChoiceRequest`; the generated `IntakeChoiceRequest` in `apps/web/src/lib/api-types.ts` already has `value` optional). With `undefined` the server stores `ctx.unit_id`, which is the right unit.
- Display text (`The sheet says U4; every filename says U3`, button label `Confirm U4 for the unit`) stays unchanged: `as_written` is still right for reading.
- Do not change `outline-choices.ts` (server). Do not loosen `UNIT_ID_RE`.

**Owned files:** `apps/web/src/features/validation-report/errors-section.tsx`, `apps/web/src/features/validation-report/report-model.ts`.
**Tests:**
- unit: add to `apps/web/tests/unit/features/validation-report/report-model.test.ts`, `-t "unit_id_of"` (`G6.U4.ov1` gives `G6.U4`; junk gives null).
- unit (new): `apps/web/tests/unit/features/validation-report/confirm-unit.test.tsx`, `-t "confirm unit sends the full unit id"`: render `ErrorsSection` with a unit-conflict report (`as_written: "U4"`, `outline_version_id: "G6.U4.ov1"`), press `Confirm U4 for the unit`, assert `actions.choose` got `{ kind: "confirm_unit", value: "G6.U4" }` (or no short `U4`).
- e2e: extend `apps/web/e2e/validation-report/` (mock-backed) with a case whose mock rejects `U4`, same as the real route: `-g "confirm unit"`. Also keep the real-backend check: `apps/web/e2e/integration/con-3/` has helpers that confirm via the API; add the UI press in a new `apps/web/e2e/integration/con-4/confirm-unit-ui.spec.ts` only if the con-3 helpers can reach it cheaply, otherwise name it under Open items.
**Acceptance:** on an issued sheet the unit row shows "Confirmed by ..." after Confirm; no 422; Generate turns on after the last error (QA table row "unit-id error").

## 2. F-8 (#155): Confirm fix replaces a 13-code Focus cell with one code

**Cause (real code).** `packages/core/src/intake/normalize-codes.ts`, `check_standards_cell` line 49-51: for a `nonexistent_code` it pushes `{ original_text: cell, proposed_fix: res.suggestion }`, where `res.suggestion` (from `standards-index.ts`: the stripped code, e.g. `RL.6.9` for `RL.6.9.a`) is ONE code. The UI (`Proposed` and `What` in `errors-section.tsx`) prints `original_text` (whole cell) and `proposed_fix` as is, and `validate_choice` `confirm_fix` stores `f.proposed_fix`, so confirming stores the one code in place of the whole cell. The spec (`SCREEN_SPECS.md` lines 98, 133) proposes the cell minus only the bad code and names only that code.

**Fix (smallest layer that fixes the data; field names, types and findings counts do not change).** In `check_standards_cell`:
- For `nonexistent_code`: `original_text` becomes the invalid `code` (so "What" reads `RL.6.9.a does not exist`, matching the spec); `proposed_fix` becomes the cell's other codes in order, with the invalid one dropped, and `res.suggestion` appended only when it is not already in the list (`RL.6.9` already listed: drop only). If nothing is left, `proposed_fix` is `null`. Build the list from the `codes` array already collected in the function (the order of first appearance), so the code is computed after the token loop: collect `{code, suggestion}` for unknown codes during `consider`, then push the findings after the loop with the full `codes` array.
- `parent_code` findings keep `original_text: cell` and `res.resolved.join(", ")` (not in the filed finding; out of scope, note in devlog if the same single-code replacement applies).
- `finding_id` is `hash12(row|kind|ordinal)` (normalize.ts line 77), independent of `original_text`, so ids are stable. `check_eld_cell` is unchanged.
- "Row 30 appears twice with different cell texts": two findings per row is by design (one per distinct invalid code or one `malformed_code`); with `original_text` now the code, the two rows read differently and correctly. Do not merge them.
- Frontend `errors-section.tsx` `Proposed` already splits `proposed_fix` on commas into chips; no change there. For a `nonexistent_code` whose `proposed_fix` is `null`, it already prints "No fix proposed" (unchanged; the author uses Edit).
- `edit_fix` prefill is `f.proposed_fix ?? f.original_text`; with a non-null list that is now the corrected cell, which is what the spec's Edit example shows.

**Owned files:** `packages/core/src/intake/normalize-codes.ts`, `packages/core/src/intake/normalize.test.ts` (extend), `apps/web/e2e/validation-report/fixtures.ts` (only if its `nonexistent_code` fixtures hard-code the single-code proposal; update to the new shape).
**Tests:**
- unit: `packages/core/src/intake/normalize.test.ts`, `-t "nonexistent code proposes the cell minus the bad code"`: cell `RL.6.1, RL.6.2, RL.6.9, RL.6.9.a, L.6.4` gives one finding, `original_text: "RL.6.9.a"`, `proposed_fix: "RL.6.1, RL.6.2, RL.6.9, L.6.4"`; cell with a suggestion not yet listed appends it; cell with only the bad code gives `proposed_fix` of the suggestion or `null`. Keep the existing `distinct_rows(...)` expectation `[30, 34, 39]` (line 29) passing.
- unit (web): `apps/web/tests/unit/features/validation-report/cell-text.test.tsx` extend `-t "nonexistent"`: chips show the corrected list.
- e2e/integration: `apps/web/e2e/integration/con-3/` issued-sheet checks that count findings still pass; add an assertion that rows 30, 34, 39 `proposed_fix` contains more than one code (`-g "focus cell proposal keeps valid codes"`).
- evals: `evals/src/suites/s1-support.ts` reads `original_text`; grep it before editing and keep the suite green, report if it depends on the old value (Open items).
**Acceptance:** on `packages/core/tests/fixtures/outline/issued.xlsx`, rows 30, 34, 39 each name one bad code and propose the full cell minus it; confirming sends the stored list, not a single code; no valid code is lost.

## 3. F-12 (#159): unsupported file shows "Choose a file first." plus the type banner

**Cause (real code).** `apps/web/src/features/upload-outline/drop-zone.tsx` `accept()` calls `onReject()` for non-CSV/XLSX and never `onFile`, so `file` stays null. `upload-form.tsx` `reject()` sets the `UNSUPPORTED_FILE` banner; pressing Upload then runs `submit()`, hits `source === "file" && !file`, sets `fieldError "Choose a file first."` and returns before `setError(null)`, so the banner stays and both show.

**Fix (`upload-form.tsx` only).** In `submit()`, when `source === "file" && !file` and `error?.code === "UNSUPPORTED_FILE"`, do not set the field error; keep the banner and focus the zone (`zoneRef.current?.focus()`) and return. When the file is genuinely missing (no prior reject), keep "Choose a file first." and ensure `setError(null)` runs first so no stale banner coexists. The drop zone does not show a rejected file (nothing was chosen); that matches the type message. No change to `drop-zone.tsx` or `messages.ts`.

**Owned files:** `apps/web/src/features/upload-outline/upload-form.tsx`.
**Tests:**
- unit: `apps/web/tests/unit/features/upload-outline/upload-form.test.tsx`, `-t "unsupported file then upload"`: choose `bad.txt`, press Upload; banner `This file type isn't supported. Upload a CSV or XLSX file.` present, text `Choose a file first.` absent. Plus `-t "no file chosen"` still shows "Choose a file first." and no banner.
- e2e: `apps/web/e2e/upload-outline/upload-outline.spec.ts`, `-g "unsupported file"` (add the Upload press and the absence check).
**Acceptance:** the two messages never show together.
