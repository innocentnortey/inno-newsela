## 5. Steps and algorithms
**Time source.** Every timestamp written (`enqueued_at`, `claimed_at`, `finished_at`, `lease_until`, `issue.created_at`, `resolved_at`) is `this.clock.now().toISOString()` cast `::timestamptz`, never `now()`, so FakeClock tests and ordering stay consistent.

**A. enqueue (tx = DbTx).** Invariant: at most one queued row per lesson, oldest `enqueued_at` kept.
1. `UPDATE check_job SET content_hash=$2, store_id=$3 WHERE lesson_id=$1 AND status='queued'`.
2. If rowCount 0: `INSERT ... (lesson_id, content_hash, store_id, status, enqueued_at) VALUES (...,'queued',$now) ON CONFLICT (lesson_id) WHERE status='queued' DO UPDATE SET content_hash=EXCLUDED.content_hash, store_id=EXCLUDED.store_id` (covers the race between step 1 and 2; `enqueued_at` untouched).
3. `SELECT pg_notify('check_job', $1)` with lesson_id. Postgres delivers it only on commit; rollback drops it and the row.
A running row is never touched (step 1 filters on queued), so a new queued row follows it.

**B. claim(lease_ms)** inside `db.with_tx`:
1. `SELECT id FROM check_job WHERE status='queued' OR (status='running' AND lease_until < $now) ORDER BY enqueued_at ASC, id ASC LIMIT 1 FOR UPDATE SKIP LOCKED`. (Oldest first by enqueued_at; reclaimed rows keep their old enqueued_at so they sort first.)
2. None -> return null.
3. `UPDATE check_job SET status='running', claimed_at=$now, lease_until=$now+lease_ms WHERE id=$id RETURNING lesson_id, content_hash, store_id, lease_until`. Reclaim edge: if a lapsed running row is reclaimed while a queued row exists for the same lesson, there is no conflict (the partial index covers only `queued`). Return `ClaimedCheck`.
Concurrency test (AC-3): `await Promise.all([q.claim(60000), q.claim(60000)])` with pool_max >= 4; exactly one non-null. SKIP LOCKED means the loser sees no row (the first holds the row lock until commit).
Lease test: enqueue, claim with lease 1000, `clock.advance(1001)`, second claim returns same lesson (reclaimed); with `clock.advance(500)` instead, second claim is null.

**C. finish(check):** `UPDATE check_job SET status='done', finished_at=$now WHERE lesson_id=$1 AND content_hash=$2 AND store_id=$3 AND status='running'`. Never matches a queued row. (A running row is unique per lesson in practice; if two running rows match after a reclaim, update only the newest: add `AND id = (SELECT max(id) FROM check_job WHERE lesson_id=$1 AND status='running' AND content_hash=$2 AND store_id=$3)`.) rowCount 0 is not an error (lease lost; worker handles).

**D. pending_for(lesson_id)** (read-only, one `with_tx`):
1. `latest_stored_hash, latest_stored_at` = `SELECT content_hash, stored_at FROM lesson_doc WHERE lesson_id=$1 ORDER BY seq DESC LIMIT 1` (null/null if none).
2. `newest_queued_hash` = content_hash of the queued row (null if none).
3. `checked_hash` = the shared checked-hash rule (section "Checked-hash rule" below).
4. `pending` = (an open job `status IN ('queued','running')` exists with `content_hash IS DISTINCT FROM checked_hash`) **OR** (`latest_stored_hash` not null and `latest_stored_hash IS DISTINCT FROM checked_hash`). The second clause makes an unchecked store report pending even when its job vanished (AC-10). No stored doc and no jobs -> all-null, `pending false` (AC-4 third case).
Hashes are not ordered, so "newer than checked_hash" means "different from checked_hash".

**Checked-hash rule (decision; implement once as a private exported SQL string `CHECKED_HASH_SQL` / helper in `issue-repo.ts`, imported by `check-queue.ts`).** There is no `checked_hash` column and a run with zero findings leaves no `issue` rows, so the newest checked hash is: among (a) the hash of the newest `issue` row of the lesson by `(created_at DESC, id DESC)` with its `created_at`, and (b) the hash of the newest `done` check_job by `(finished_at DESC, id DESC)` with its `finished_at`, take the one with the later timestamp (tie -> the issue row). Null if neither exists. `checked_at` = that timestamp. Keep it a single parametrized SQL `SELECT content_hash, at FROM (...) ORDER BY at DESC, src_rank LIMIT 1` per lesson. Document this in a comment (it is a CON-13 interpretation; DDL belongs to NL-08).

**E. replace_for_hash(lesson_id, content_hash, findings, tx)** (DbTx required):
1. Load all existing issues of the lesson (`SELECT ... FROM issue WHERE lesson_id=$1`).
2. If rows already exist for `(lesson_id, content_hash)` (a retry after a lease reclaim, or an edit back to an earlier hash): do not insert; `UPDATE issue SET created_at=$now, cleared_by = CASE WHEN cleared_by='fix' THEN NULL ELSE cleared_by END WHERE lesson_id=$1 AND content_hash=$2` (same hash means same findings, so this just re-affirms them as newest), then jump to step 5. Never change `message`, `kind`, `content_hash`.
3. Resolution map: from the loaded rows with `resolved_at IS NOT NULL`, keep the latest per key `${kind}\u0000${address ?? "\u0001null"}\u0000${code ?? "\u0001null"}` (order by `resolved_at`, then `id`). Exact-key match only (kind, address, code all equal, null equals null); a different address or code gets nothing (AC-6).
4. For each finding in order: `id = ids.new_id("iss")`; INSERT with `created_at=$now`; if the key is in the map copy `resolved_by, resolution_reason, resolved_at` and set `cleared_by='resolution'`, else those four are NULL.
5. Fix-clearing: for rows of OTHER hashes with `resolved_at IS NULL AND cleared_by IS NULL` whose key is not among the new findings' keys: `UPDATE issue SET cleared_by='fix' WHERE id = ANY($1)`. Resolved earlier rows stay `cleared_by='resolution'`.
6. Return `IssueSet {lesson_id, checked_hash: content_hash, checked_at: now, issues: rows of (lesson_id, content_hash) ordered by created_at, id}` mapped to `IssueRow`.
Level/kind values come from the finding as given; do not validate rules (non-goal).

**E2. current(lesson_id):** `with_tx`; apply the checked-hash rule; none -> `{lesson_id, checked_hash: null, checked_at: null, issues: []}`; else the rows of that hash (all, resolved or not), ordered `created_at, id`.

**F. counts_by_lesson(unit_id):** one query: for each `lesson` with `unit_id=$1` (order by `number NULLS LAST, id`) compute its checked hash (rule above, as a lateral subquery) and `count(*) FILTER (WHERE level='blocking' AND resolved_at IS NULL)` etc. over that hash's issue rows. Lessons never checked -> zeros. Returns `LessonIssueCounts[]` for every lesson of the unit.

**G. resolutions_for(lesson_id):** `SELECT DISTINCT ON (kind, address, code) * FROM issue WHERE lesson_id=$1 AND resolved_at IS NOT NULL ORDER BY kind, address, code, resolved_at DESC, id DESC` (DISTINCT ON treats NULLs as equal). Map rows.

**H. get / resolve:** `get(id)` returns row or null. `resolve(r, tx)`: SELECT the row `FOR UPDATE`; missing -> `throw new DomainRefusal("NOT_FOUND", "no such issue", { issue_id: r.issue_id })`; already `resolved_at` not null -> return unchanged (no write); else `UPDATE ... SET resolved_by=r.by, resolution_reason=r.reason, resolved_at=$now, cleared_by='resolution'` and return the row. No method updates/deletes `message`, `kind`, `content_hash` (the immutable test inspects those columns before and after `resolve` and `replace_for_hash`; and a grep-free check: assert no exported method name contains delete).

**I. unchecked_stores(db: PgDatabase, now: Date, unchecked_after_s: number): Promise<Array<{lesson_id, content_hash, stored_at}>>** read-only. For each lesson's latest `lesson_doc` row: include when `stored_at <= now - unchecked_after_s`, there is no `issue` row for that `(lesson_id, content_hash)`, no `done` check_job with that hash, and no `queued`/`running` check_job for that lesson. Order by `stored_at`.

**Order of work:** (1) `check-queue.ts` A-D + helper; (2) `issue-repo.ts` E-H and the shared checked-hash helper (write helper first in `issue-repo.ts`, import into `check-queue.ts`: dependency direction check-queue -> issue-repo is acceptable; alternatively put it in `check-queue.ts` and import it the other way. Pick: helper lives in `issue-repo.ts`, exported as `checked_hash_for(tx: DbTx, lesson_id)`); (3) tests; (4) unchecked_stores; (5) area map + devlog.
