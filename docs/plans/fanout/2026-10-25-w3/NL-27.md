Decisions made here where the ticket text is silent or two parts disagree (ticket > DO-4 > DO-3):
- **D-1 Flag precedence in `derive_run_state`:** the build-section order wins: `cancelled` > `capped` > `paused`. (AC-9's phrase "capped/paused/cancelled flags win in that order" is ambiguous; the table test includes rows with two flags set and asserts this order.)
- **D-2 "Lesson row"** = `row.kind` is `"lesson"` or `"flex_day"` AND `row.lesson_id !== null`. (WP-3 row 25 is a flex day with id `G6.U4.FLEX-1a` and must be a lesson job; 41 lessons + 6 flex days = 47.)
- **D-3 Trial** (`mode "trial"`): `run.kind = "trial"`, one job of `kind "candidate"` created through `queue.create_run_jobs([job], tx)` (as the ticket says), no `unit_plan` row, no plan job.
- **D-4 `mode "run"`** always gets a plan job + a `unit_plan` row, for scope `all`, `rows` and `unfinished_of_run` (the new run has its own plan; otherwise it would sit in `planning` forever).
- **D-5 Unfinished lessons** = lesson ids of the old run's jobs (`queue.jobs_for_run(old)`) with `kind "lesson"` and `status !== "ready"`. Empty -> `INVALID_REQUEST`. No restriction on the old run's state.
- **D-6 `NOTIFY lesson_job`:** `PgRunRepo.insert_run` runs `SELECT pg_notify('lesson_job', <run_id>)` inside the tx; Postgres delivers it at COMMIT, which is exactly "after commit". The service has no other way (no notify port). Duplicate notifications from NL-28 are harmless.
- **D-7 Idempotency key storage:** column `run.idempotency_key` is NOT NULL with `unique (started_by, idempotency_key)` and no time window. `insert_run` stores `idempotency_key ?? run_id`, and first retires an *expired* holder of the same key (repo step R-3, which uses the repo's own `idempotency_window_h` constructor option).
- **D-8 Replay response `scope`** is rebuilt from the retried request (the port `RunRow` has no scope). `mode` = `row.kind === "trial" ? "trial" : "run"`.
- **D-9 Validation order** inside `start` (after ROLE_FORBIDDEN): idempotency replay -> INVALID_REQUEST -> NOT_FOUND -> VALIDATION_INCOMPLETE -> DAY_CAP_REACHED (ticket order; CON-5 card order).
- **D-10 Job `priority`** is `0` for every job (FIFO and plan-before-lessons are the queue's job, NL-28).
- **D-11 Whole `start` body runs in one `tx.with_tx(fn, lock)`** with `lock = "run:start:" + user_id + key` when a key is present (else `null`), so a concurrent twin waits on the advisory lock until the first commits and then finds its run. Reads use the pool, writes use `tx`.

### Step 1 — `packages/core/src/lifecycle/run-machine.ts` (pure; imports only `@ls/schema/*` types and core port types; no clock, no I/O)

```ts
import type { ErrorCode } from "@ls/schema/api/common";
import type { TileState } from "@ls/schema/api/runs";
import type { JobKind, JobStatus, RunStateName } from "../ports/common.ts";
export type RunControlAction = "cancel" | "retry_failed" | "resume";
export interface JobStatusView { status: JobStatus; tile_state: TileState; kind: JobKind; failure_check: string | null }
export interface RunStateInput { current: RunStateName; plan_stored: boolean; cancelled: boolean; capped: boolean; paused: boolean }
export interface RunControlDecision { allowed: boolean; to_state: RunStateName | null; refusal: Extract<ErrorCode, "INVALID_TRANSITION"> | null; requeue_failed: boolean; cancel_jobs: boolean }
export function derive_run_state(jobs: readonly JobStatusView[], run: RunStateInput): RunStateName;
export function tile_state(job: JobStatusView): TileState;
export function decide_run_control(current: RunStateName, action: RunControlAction): RunControlDecision;
```
Algorithms:
1. `derive_run_state`: (a) `run.cancelled` -> `"cancelled"`; (b) `run.capped` -> `"capped"`; (c) `run.paused` -> `"paused"` (D-1); (d) `!run.plan_stored` -> `"planning"`; (e) `work = jobs.filter(kind !== "unit_plan")`; if `work.length === 0` -> `"running"` (guard: `every` on empty is true and would say complete); (f) if any work job has status `queued` or `running` -> `"running"`; (g) all terminal: if every status is `ready` -> `"complete"`; else (some `generation_failed` or `cancelled`) -> `"partial"`.
2. `tile_state`: `queued`->`queued`; `running` -> `job.tile_state` if it is one of `planning|drafting|checking|repairing`, else `job.kind === "unit_plan" ? "planning" : "drafting"`; `ready`->`ready`; `generation_failed` and `cancelled`->`failed`.
3. `decide_run_control` (table; `INVALID` = `{allowed:false,to_state:null,refusal:"INVALID_TRANSITION",requeue_failed:false,cancel_jobs:false}`): `cancel` from `planning|running|paused` -> `{allowed:true,to_state:"cancelled",refusal:null,requeue_failed:false,cancel_jobs:true}`; `retry_failed` from `partial` -> `{allowed:true,to_state:"running",refusal:null,requeue_failed:true,cancel_jobs:false}`; `resume` from `paused` -> `{allowed:true,to_state:"running",refusal:null,requeue_failed:false,cancel_jobs:false}`; every other pair (including every action on `cancelled|capped|complete`) -> INVALID.

Test `run-machine.test.ts` (both names must appear as `it(...)` or `describe(...)` titles so `-t` matches): `derive_and_tile` — 14 table rows (no plan; running jobs; queued job; all ready; one failed; one cancelled; ready+failed; empty jobs; only unit_plan job pending; capped flag; paused flag; cancelled flag; cancelled+capped -> cancelled; capped+paused -> capped) plus one assertion per `JobStatus` -> `TileState` (5) and the `running` step passthrough. `run_control_matrix` — loop 3 actions x 7 states = 21 cases against an explicit expected-allowed set. Command: `npx vitest run packages/core/src/lifecycle/run-machine.test.ts`.

### Step 2 — `packages/db/src/repos/runs.ts`: `export class PgRunRepo implements RunRepo`, `constructor(deps: PgRepoDeps)` (same field pattern as `PgAuditLog`).

- R-3 key retirement (D-7), done in `insert_run` before the INSERT when `run.idempotency_key !== null`: `UPDATE run SET idempotency_key = idempotency_key || '~' || id WHERE started_by=$1 AND idempotency_key=$2 AND created_at <= $3` with `$3 = now - window`. The repo does not know the window, so give `insert_run` a **file-level constant** `IDEMPOTENCY_WINDOW_H_DEFAULT = 24` ONLY IF the settings value is not passed; to keep the port unchanged, add an **optional constructor field** `idempotency_window_h?: number` to `PgRunRepo`'s constructor (`constructor(deps: PgRepoDeps, opts: { idempotency_window_h?: number } = {})`, default 24) and use it both here and nowhere else (`find_by_idempotency_key` uses its `within_hours` argument). - `get(run_id)`: select by id, `null` if none.
- `find_by_idempotency_key(user_id, key, within_hours)`: `WHERE started_by=$1 AND idempotency_key=$2 AND created_at > $3` with `$3 = clock.now() - within_hours*3600*1000 ms`; most recent first; first row or `null`. Runs in its own `db.with_tx`.
- `lock_for_update(run_id, tx)`: `SELECT * FROM run WHERE id=$1 FOR UPDATE`; none -> `throw new DomainRefusal("NOT_FOUND", "Run not found.")`.
- `set_state(run_id, state, paused_check, tx)`: `UPDATE run SET state=$2, paused_check=$3, finished_at = (TERMINAL has state ? now : NULL) WHERE id=$1 RETURNING *`.
- `mark_capped(run_id, capped_by, tx)`: one statement `SET state='capped', capped_by=$2, finished_at=now`.

Return the `UnitPlanRow` (`plan` parsed with `UnitPlanDraft.parse` from `@ls/schema/unit-plan`).

'failed'`, `lost=...
