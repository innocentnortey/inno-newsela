## 1. Goal and sources

Deliver `SuggestionService` (list pending / request an AI rewrite of a selection / accept or reject) and its three HTTP operations (`listSuggestions` GET, `requestSuggestion` POST 201, `decideSuggestion` POST 200). Nothing AI-written enters a lesson until a reviewer accepts; the accept is applied by the collaboration server against the live document using the STORED selected text, never the browser's.

## 4. Decisions already made (do not reopen)

- D-1 Roles: `request` and `decide` are `reviewer` only (service AND route spec, both layers, since AC-2 calls the service directly). `list_pending` allows `author`, `reviewer`, `approver` (ticket restricts only "the writes"; a pending suggestion blocks Approve, so approvers must see it). Wrong role -> `DomainRefusal("ROLE_FORBIDDEN", "Your role cannot do this.")`.
- D-2 Order in `request`: role -> input validation (INVALID_REQUEST, `details.fields`) -> lesson `NOT_FOUND` -> `LESSON_LOCKED` -> render -> `PaidCaller.call` -> parse -> insert -> audit. Order in `decide`: role -> lesson `NOT_FOUND` -> suggestion `NOT_FOUND` (also when `row.lesson_id !== lesson_id`, so a suggestion id from another lesson never works through this lesson's path) -> `INVALID_TRANSITION` -> in-flight guard -> action.
- D-3 Input limits (hardening; CON-17 gives only the 2,000 on `selected_text`): `selected_text` 1..2000 chars and no `\u0000`; `note` at most 2000 chars and no `\u0000`; `anchor.start` and `anchor.end` each 1..1024 chars. Violation -> `INVALID_REQUEST` with `details: { fields: ["selected_text"] }` (or `note`, `anchor`). The route schema `SuggestionRequest` only checks 1..2000 on selected_text; the service re-checks everything. List `note` cap and anchor cap under Open items for NL-72.
- D-4 Model output: parse `recorded.raw_output` with `JSON.parse` then `AssistRewrite.safeParse` (`@ls/prompts/assist-rewrite`, strict `{ suggested_text: string }`). Invalid JSON, invalid shape, empty/whitespace-only `suggested_text`, `suggested_text` longer than `SUGGESTED_TEXT_MAX_CHARS = 8000`, or containing `\u0000` -> `DomainRefusal("MODEL_UNAVAILABLE", ..., { reason: "bad_output" })`, nothing stored, no audit. Otherwise `suggested_text` is stored and returned verbatim (no trimming, no HTML handling; `<script>alert(1)</script>` stays that exact string).
- D-5 `MODEL_UNAVAILABLE` reasons: `SpendRefused` -> `{ reason: "spend_cap" }`; `ProviderError` (any kind, including `timeout`) -> `{ reason: "provider_error" }`. Message text is the fixed phrase `"The AI assist is unavailable right now. Nothing was changed."`. Any other error (e.g. `UnpricedModelError`, `LockedLayerMismatch`, `InvariantViolation`) is rethrown unchanged.
- D-6 `decide` accept error mapping: collab `DomainRefusal` code `ANCHOR_CHANGED` -> close (below) then throw our own `DomainRefusal("ANCHOR_CHANGED", "The text changed since the suggestion was made. Ask again.", { suggestion_id })`; `CollabUnavailable` (from `@ls/core/errors`) -> `DomainRefusal("COLLAB_UNAVAILABLE", "The editing service is busy. Try again.", {})`, suggestion stays pending, no audit; any other `DomainRefusal` from collab (`LESSON_LOCKED`, `NOT_FOUND`) is rethrown as is, suggestion stays pending; non-refusal errors rethrown.
- D-7 Closing on `ANCHOR_CHANGED`: `tx.with_tx(t => suggestions.decide(id, "closed", user.user_id, t))`, no audit row (the ticket asks for none). If that `decide` throws `InvariantViolation` (already decided/expired meanwhile) swallow it and still throw `ANCHOR_CHANGED`.
- D-8 Double-decide guard: `private readonly in_flight = new Set<string>()` keyed by suggestion id; a second concurrent `decide` on the same id throws `INVALID_TRANSITION` without any collab call. Add in `try/finally`. (Process-local; the app runs one web instance. The port has no row lock.)
- D-9 No dependency on unmerged code. `PaidCaller` (NL-33), `ModelCallRecorder`, `StubModelClient` (NL-32), `next-adapter.ts` (NL-25) are NOT on main. The service depends on local structural interfaces (below) that the real classes satisfy (DIP), and `http.ts` carries its own tiny `to_http_request` / `to_response` (same pattern as NL-26's `outline-versions/http.ts`). Do not import from any `.worktrees` path or `@ls/llm/*`.
- D-10 `section_name`: anchors are opaque Yjs positions, so resolve by text. `reader.latest_derived(lesson_id)` -> flatten each `sections[i].content` (ProseMirror JSON) to plain text by concatenating `text` nodes, joining block nodes with a single space, collapsing all whitespace runs to one space and trimming; same normalisation on `selected_text`; `section_name` = the `name` of the first section whose text contains the normalised selection. No derived row or no match -> `"Lesson"`. Only this string, `selected_text` and `note` reach the model (no other lesson text, no student work).
- D-11 `max_output_tokens: 2048` (`ASSIST_MAX_OUTPUT_TOKENS`), `effort: null`, `temperature: null`, `output_mode: "schema_enforced"`, `output_schema_name: "AssistRewrite"`, `output_json_schema: new SchemaRegistry().json_schema("AssistRewrite")` (module-level constant from `@ls/prompts/schemas`).
- D-12 Audit actions: request `suggestion.request`; accept `AI_ACCEPT_ACTION = "suggestion.accept"` (exact string; NL-44's branch defines the same constant in `lesson-read-service.ts` and counts it for "AI-assisted spans"; do NOT import it, export your own constant with the same value); reject `suggestion.reject`. `target_kind: "suggestion"`, `target_id: suggestion_id`, `actor_id: user.user_id`, `request_id: user.request_id`, `reason: null`; `details` ids and codes only (never text): request `{ lesson_id, model_call_id }`, accept `{ lesson_id, model_call_id }` with `version_hash: ack.content_hash` and `store_id: ack.store_id`, reject `{ lesson_id }`; `version_hash: null` and `store_id: null` otherwise.
- D-13 API mapping (`Suggestion` from `@ls/schema/api/lessons`): `{ suggestion_id, status, anchor: { start: anchor_start, end: anchor_end }, selected_text, suggested_text, requested_by: row.requested_by, expires_at: row.expires_at.toISOString(), decided_by: row.decided_by, content_hash }`. `content_hash` is `null` except in the accept response (`ack.content_hash`). `requested_by` / `decided_by` are user ids (no name lookup port exists; see Open items).
- D-14 The service writes no logs (the DO-4 constructor has no logger). The only log lines in the request path are `with_route`'s `route.refused` / `route.done` (codes, ids, status). Do not add a logger parameter.
