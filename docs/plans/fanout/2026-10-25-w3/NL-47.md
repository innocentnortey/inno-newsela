### 5.1 Interfaces declared in `candidate-service.ts` (export them)

**Candidate id decision (made here).** `candidate_id` in every response and path is the candidate **run id** (`RunRow.run_id`). A trial candidate (CON-5) works the same way (its job has kind `candidate`). ### 5.2 Private helpers
1. `candidate_cap(): Usd` = `cost.max_call_cost(prices.price_for(settings.model.model_generation_id), EST, DRAFT_CAP)` `.plus(cost.max_call_cost(<same price>, EST, TRUNCATION_CAP))` `.plus(cost.max_call_cost(prices.price_for(settings.model.model_repair_id), EST, REPAIR_CAP))`. Invariant: one lesson can never reserve more than the cap, so the worker's run-cap check passes and the candidate never draws on the original run's cap.
2. `job_key(run_id, lesson_id, prompt_version_id): string` = sha256 hex of `[run_id, lesson_id, prompt_version_id, String(SCHEMA_VERSION)].join("\n")` (identical to `job_key` in NL-27's `run-service.ts`; it is not on main yet, so keep a private copy).
3. `current_hash(row: LessonRow): Promise<string>`: `row.current_version_id === null ? NO_CURRENT_HASH : (await versions.version(row.current_version_id))?.content_hash ?? NO_CURRENT_HASH`.
4. `sections_of(v: LessonVersionRow): Section[]` = `v.lesson.sections.map(s => ({ address: s.address, name: s.name, minutes: s.minutes, content: s.content }))`.

### 5.3 `regenerate(user, lesson_id, req)`; order is the precedence
1. `user.role !== "reviewer"` -> `DomainRefusal("ROLE_FORBIDDEN", "Your role cannot do this.")`.
2. `row = await states.get(lesson_id)`; null -> `DomainRefusal("NOT_FOUND", "Lesson not found.", { lesson_id })`.
3. State not in `ALLOWED_STATES` -> `DomainRefusal("LESSON_LOCKED", "This lesson cannot be regenerated in its current state.", { lesson_id, state: row.state })`. (`draft` = review not started, so it is locked; `submitted`, `approved`, `exported` too.)
4. `inflight = await lookup.in_flight_run(lesson_id)`; if not null return `await this.view(lesson_id, row, inflight)` (5.4). No writes, no ledger call.
5. `parent_id = await lookup.latest_lesson_run(lesson_id)`; null -> `NOT_FOUND` with details `{ lesson_id, reason: "no_generation_run" }`. `parent = await runs.get(parent_id)`; null -> same NOT_FOUND.
6. `cap = candidate_cap()`; `d = await spend.check_day_cap(user.user_id, cap)`. If `!d.allowed` -> `DomainRefusal("DAY_CAP_REACHED", "Today's spend limit would be passed.", { scope: d.scope ?? (d.refused_by === "project_cap" ? "project" : "user"), remaining_usd: d.remaining_usd === null ? null : d.remaining_usd.toNumber() })` (same shape as `RunService.start`).
7. Read the parent's pinned data outside the tx: `choices = await runs.pinned_choices(parent.run_id)`; `plan = await runs.unit_plan(parent.run_id)`; `links = plan?.lesson_links ?? []`.
8. `note = req.note?.trim() ? req.note.trim() : null`.
9. One transaction: `tx.with_tx(async (t) => { ... }, \`candidate:${lesson_id}\`)` containing, in order:
   a. `run = await runs.insert_run({ unit_id: parent.unit_id, outline_version_id: parent.outline_version_id, kind: "candidate", prompt_version_id: parent.prompt_version_id, cap_usd: cap, scope_rows: null, started_by: user.user_id, parent_run_id: parent.run_id, eval_run_id: null, choices, choices_hash: parent.choices_hash, lesson_links: links, idempotency_key: null }, t)` (reuses the parent's plan via `parent_run_id` and its pinned prompt).
   b. `await queue.create_candidate_job({ run_id: run.run_id, kind: "candidate", lesson_id, idempotency_key: job_key(run.run_id, lesson_id, parent.prompt_version_id), priority: 0, reviewer_note: note }, t)`.
   c. `await audit.append({ actor_id: user.user_id, action: "candidate.regenerate", target_kind: "lesson", target_id: lesson_id, version_hash: <current hash or null>, reason: null, details: { run_id: run.run_id, parent_run_id: parent.run_id, cap_usd: cap.toFixed(6), has_note: note !== null }, request_id: user.request_id, store_id: null }, t)`. The note text never goes in `details` or any log line.
   d. Return `run`.
   No separate NOTIFY: `PgRunRepo.insert_run` issues `pg_notify('lesson_job', run_id)` inside the transaction and Postgres delivers it at commit.
10. Race: wrap step 9 in `try/catch`; on `DomainRefusal` with `code === "INVALID_TRANSITION"` and `details?.reason === "candidate_in_flight"` the tx has rolled back (no run, job or audit row is left): `winner = await lookup.in_flight_run(lesson_id)`; if not null return `view(lesson_id, row, winner)`, else rethrow. Any other error rethrows.
11. Return `{ candidate_id: run.run_id, version_number: await lookup.next_version_number(lesson_id), status: "queued", adopted: false, failure_reasons: [], cost_usd: 0, current_content_hash: await current_hash(row), sections: [] }`.
Invariant: nothing touches `lesson` or `lesson_version`; the lesson state and `current_version_id` are unchanged (WF-13).

### 5.4 `get(user, lesson_id, candidate_id)` and the shared `view(lesson_id, row, run_id)`
`get`: no role check (every role may read). `row = states.get(lesson_id)` null -> NOT_FOUND. Then `view(lesson_id, row, candidate_id)`.
`view`:
1. `run = await runs.get(run_id)`; null -> NOT_FOUND `{ lesson_id }`.
2. `job = (await queue.jobs_for_run(run_id)).find(j => j.kind === "candidate" && j.lesson_id === lesson_id)`; undefined -> NOT_FOUND (this is the "candidate of another lesson" case; the message and details must not reveal the other lesson).
3. `vid = await lookup.version_of_run(lesson_id, run_id)`; `version = vid === null ? null : await versions.candidate(lesson_id, vid)`.
4. Status: `version !== null` -> `"ready"`. Else by `job.status`: `queued` -> `"queued"`; `running` -> `"drafting"`; `generation_failed` or `cancelled` -> `"failed"`; `ready` (job finished, version not visible yet) -> `"drafting"`.
5. Build `Candidate`: `candidate_id: run_id`; `version_number: version?.number ?? await lookup.next_version_number(lesson_id)`; `adopted: version?.adopted ?? false`; `failure_reasons: status === "failed" ? job.failure_reasons : []`; `cost_usd: (version ? version.provenance.cost_usd : job.cost_usd).toNumber()`; `current_content_hash: await current_hash(row)`; `sections: status === "ready" ? sections_of(version) : []`.
A failed candidate is a status; never throw for it.

### 5.5 `adopt(user, lesson_id, candidate_id, req)`
1. Role must be `reviewer` else ROLE_FORBIDDEN. 2. Lesson NOT_FOUND. 3. Build the view as in 5.4 (same NOT_FOUND for a foreign or unknown candidate) and keep the resolved `version` (null unless ready).
4. `req.scope === "section"`: `section_address` missing/blank -> `DomainRefusal("INVALID_REQUEST", "The request is not valid.", { fields: ["body.section_address"] })`; if a ready version has no section with that address, same INVALID_REQUEST. Do this before the transition check (parse-class errors first).
5. `version === null` (status not ready) or (`scope === "whole"` and `version.adopted`) -> `DomainRefusal("INVALID_TRANSITION", "This candidate cannot be adopted.", { lesson_id, reason: version === null ? "not_ready" : "already_adopted" })`. Zero collab calls so far.
6. `actor: Actor = { user_id: user.user_id, name: user.name, role: user.role, synthetic: user.synthetic }`; `edit: AdoptEdit = { kind: "adopt", candidate_version_id: version.version_id, scope: req.scope, section_address: req.scope === "section" ? req.section_address : null }`.
7. `try { ack = await collab.apply_edit({ lesson_id, actor, edit, tag: "candidate-adopt", request_id: user.request_id }) } catch (e) { if (e instanceof CollabUnavailable) throw new DomainRefusal("COLLAB_UNAVAILABLE", "The collaboration server could not apply the change. Try again.", { lesson_id }); throw e; }`. No retry (commands are not idempotent). A collab refusal (`LESSON_LOCKED`, `NOT_FOUND`) keeps its code. Nothing has been written yet, so a failure leaves the candidate unadopted with no audit row.
8. `audit_id = await tx.with_tx(async (t) => { if (req.scope === "whole") await versions.mark_adopted(version.version_id, t); return audit.append({ actor_id: user.user_id, action: "candidate.adopt", target_kind: "lesson", target_id: lesson_id, version_hash: ack.content_hash, reason: null, details: { candidate_id, version_id: version.version_id, scope: req.scope, section_address: edit.section_address }, request_id: user.request_id, store_id: ack.store_id }, t); })`. A section adopt does not call `mark_adopted`, so `adopted` stays false and a later whole adopt stays possible (DO-4 R-5). If `mark_adopted` throws (concurrent whole adopt won), the tx rolls back and `INVALID_TRANSITION` propagates; the collab edit was already applied (accepted: both edits carry the same content; stated in Risks).
9. Return `{ candidate_id, audit_id, last_editor: user.name, content_hash: ack.content_hash }`. The adopter becomes last editor through the collaboration store (`StoreAck.stored_by`); the service does not call `record_last_editor`.
