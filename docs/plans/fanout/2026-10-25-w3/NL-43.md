## 5. Steps
Shared helper inside the file: `function real_tx(tx: Tx): DbTx { if (!(tx instanceof DbTx)) throw new InvariantViolation("repository write needs a real transaction"); return tx; }` (same pattern as `PgAuditLog.append`). Reads use `this.db.with_tx(async (tx) => (await tx.query(...)).rows)`. Pg returns `timestamptz` as `Date` and nothing here is numeric. Never use `Number(`-style money code (none needed). **No logging anywhere in this file** (selected_text must never reach a log; do not import a logger).

**Step 1: SafetyFlagRepo.**
1. `create_for_lesson(lesson_id, source_rows, tx)`: for each distinct `source_row` (dedupe the input, keep order) insert id `` `sf:${lesson_id}:${source_row}` `` with status `open`, other columns null, using `INSERT ... ON CONFLICT (id) DO NOTHING RETURNING *`. Return only the rows actually created (empty array on a repeat). Invariant: one flag per (lesson, source row) ever, and a repeat can never reopen a cleared flag (the deterministic id is the idempotency key; no schema change needed).
2. `open_for(lesson_id)`: `WHERE lesson_id=$1 AND status='open' ORDER BY source_row, id`. Map `id` -> `flag_id`.
3. `clear(flag_id, by, note, tx)`: (a) if `note.trim() === ""` throw `InvariantViolation("safety flag note required", { flag_id })` before any SQL (the service's `NOTE_REQUIRED` is NL-45). (b) `UPDATE safety_flag SET status='cleared', cleared_by=$2, note=$3, cleared_at=$4::timestamptz WHERE id=$1 AND status='open' RETURNING *`. Store `note` as given (not trimmed). (c) If zero rows: `SELECT status FROM safety_flag WHERE id=$1`; none -> `InvariantViolation("safety flag not found", { flag_id })`; cleared -> `InvariantViolation("safety flag already cleared", { flag_id })`. Invariant: the guarded UPDATE is atomic, so two racing clears cannot overwrite the first.

**Step 2: AlignmentRepo.** Define one SQL fragment constant `LATEST_HASH = "(SELECT content_hash FROM lesson_doc WHERE lesson_id = $1 ORDER BY seq DESC LIMIT 1)"` (the lesson's "current hash" = its latest `lesson_doc` row; DO-4 §3.5). A private `current_hash(tx, lesson_id)` runs it and throws `InvariantViolation("lesson has no stored document", { lesson_id })` when empty.
1. `replace_for_hash(lesson_id, content_hash, links, tx)`: throw `InvariantViolation` if any link has a different `lesson_id` or `content_hash` than the arguments. In the one tx: (a) read the carry source: `SELECT code, address, origin, confirmed_by FROM alignment_link a WHERE lesson_id=$1 AND content_hash<>$2 AND confirmed_by IS NOT NULL ORDER BY (SELECT max(seq) FROM lesson_doc d WHERE d.lesson_id=a.lesson_id AND d.content_hash=a.content_hash) DESC NULLS LAST`; build a Map keyed `code|address|origin` keeping the **first** (most recent hash) hit. (b) `DELETE FROM alignment_link WHERE lesson_id=$1 AND content_hash=$2`. (c) insert each link with `confirmed_by = link.confirmed_by ?? carried.get(key) ?? null`. (d) return the number inserted. Rows at other hashes are left untouched (approved snapshots need them). Invariant: confirmation follows an identical (code, address, origin) only; a changed address or origin drops it.
2. `for_lesson(lesson_id)`: rows at `content_hash = LATEST_HASH`, `ORDER BY code, address`. If the lesson has no `lesson_doc` the subquery is NULL and the result is empty.
3. `confirm(lesson_id, code, by, decision, tx)`; hash = `current_hash`:
   - `confirm`: `UPDATE alignment_link SET confirmed_by=$by WHERE lesson_id=$1 AND content_hash=$h AND code=$c AND confirmed_by IS NULL RETURNING *`; `asserted_by` stays as it was. If the code has no rows at that hash at all, throw `InvariantViolation("no alignment rows for code", { lesson_id, code })`. If rows exist but all were already confirmed, no write; return the first row (by address). Return the first row ordered by address.
   - `remove`: `DELETE ... WHERE lesson_id, content_hash=$h, code RETURNING *`; zero rows -> same InvariantViolation as above; return the first deleted row ordered by address (sort in JS).
   - `add`: the port gives no address or role, so (decision made here, see Open items) insert one row `address = lesson_id`, `role = "P"`, `origin = "added"`, `asserted_by = "reviewer"`, `confirmed_by = null`, with `ON CONFLICT (lesson_id, content_hash, code, address) DO UPDATE SET origin='added', asserted_by='reviewer', confirmed_by=NULL`; return it. It opens its own confirmation (CON-13).
   Does **not** re-run checks (the collab edit and the check re-run rewrite the set later).
4. `restore(lesson_id, code, rows, tx)`: hash = `current_hash`; reject (InvariantViolation) any row whose `lesson_id` or `code` differs from the arguments; `DELETE ... WHERE lesson_id, content_hash=$h, code`; insert each of `rows` with `content_hash` forced to `$h` and `confirmed_by`/`asserted_by`/`origin` exactly as given; return the count. Zero rows is valid (undo of an `add`).
5. `coverage_rows(unit_id)`: **exactly one `tx.query` call** inside one `with_tx`. SQL (use as written; adjust only for syntax errors):
```sql
WITH ls AS (SELECT id FROM lesson WHERE unit_id = $1),
approved AS (
  SELECT DISTINCT ON (v.lesson_id) v.lesson_id, v.content_hash
    FROM lesson_version v JOIN ls ON ls.id = v.lesson_id
   WHERE v.kind = 'approve' ORDER BY v.lesson_id, v.number DESC),
working AS (
  SELECT DISTINCT ON (d.lesson_id) d.lesson_id, d.content_hash
    FROM lesson_doc d JOIN ls ON ls.id = d.lesson_id
   ORDER BY d.lesson_id, d.seq DESC),
chosen AS (
  SELECT ls.id AS lesson_id,
         COALESCE(a.content_hash, w.content_hash) AS content_hash,
         CASE WHEN a.content_hash IS NOT NULL THEN 'approved' ELSE 'working' END AS source
    FROM ls LEFT JOIN approved a ON a.lesson_id = ls.id LEFT JOIN working w ON w.lesson_id = ls.id)
SELECT al.code, al.lesson_id, al.role, c.source,
       bool_or(al.confirmed_by IS NOT NULL OR al.asserted_by = 'reviewer') AS person,
       bool_or(al.asserted_by = 'judge') AS judged
  FROM alignment_link al
  JOIN chosen c ON c.lesson_id = al.lesson_id AND c.content_hash = al.content_hash
 GROUP BY al.code, al.lesson_id, al.role, c.source
 ORDER BY al.code, al.lesson_id, al.role
```
   Map: `person` true -> `"person"`; else `judged` -> `"judge_only"`; else `"generator_only"` (this includes `asserted_by` `generator` and `outline`). Invariant: a lesson with an approve snapshot reads that snapshot's hash, never the newer working row's.

**Step 3: SuggestionRepo.**
1. Row mapper: `id` -> `suggestion_id`; omit `note` (not in `SuggestionRow`).
2. `insert(s)`: `id = this.ids.new_id("sug")`, status `pending`, `expires_at` as given, all other nullable columns null; insert in its own `db.with_tx` (the port has no tx); return the mapped row. No settings read.
3. `get(id)`: select; null if absent; if `status='pending'` and `expires_at <= clock.now()`, return the row with `status: "closed"` (not written back).
4. `decide(id, status, by, tx)`: `now = clock.now()`. Run `UPDATE suggestion SET status=$2, decided_by=$3, decided_at=$4::timestamptz WHERE id=$1 AND status='pending' AND (expires_at > $4::timestamptz OR $2 = 'closed') RETURNING *`. Zero rows -> `SELECT` the row: absent -> `InvariantViolation("suggestion not found")`; otherwise `InvariantViolation("suggestion already decided or expired", { suggestion_id: id, status })` (details hold ids and the status only, never text). Invariant: a second decision, or accept/reject after expiry, changes nothing.
5. `pending_for(lesson_id, now)`: `WHERE lesson_id=$1 AND status='pending' AND expires_at > $2::timestamptz ORDER BY expires_at, id`.
