## 5. Steps
**Step 1. Repository `packages/db/src/repos/prompts.ts`.** Imports as in `audit.ts`. `export class PgPromptRepo implements PromptRepo` with `constructor(deps: PgRepoDeps)` (import `PgRepoDeps` from `./audit.ts`). Private `map(r)` converts `{id, locked_hash, guidance_text, number, author_id, reason, diff, created_at}` to `PromptVersionRow` (`id` becomes `prompt_version_id`). Methods:
- `current()`: `with_tx` select the row with max `number`; none found throws `InvariantViolation("no prompt version")`.
- `get(id)`: row or `null`. `all()`: `ORDER BY number ASC`.
- `pinned_by_runs(id)`: `SELECT id FROM run WHERE prompt_version_id = $1 ORDER BY created_at ASC, id ASC` returns `RunId[]`.
- `author_names(ids: string[]): Promise<Map<string, string>>` (repo-level, NOT on the port): `SELECT id, name FROM app_user WHERE id = ANY($1::text[])`; empty input returns an empty map without querying.
- No update or delete method exists. Do not add one.

**Step 2. `sync_locked_layer(locked_hash: string, tx: Tx): Promise<PromptVersionRow | null>`** (repo-level, DO-4 §3.5/§13 R-6). Inside the caller's tx (assert `tx instanceof DbTx`, else `InvariantViolation`):
1. `SELECT pg_advisory_xact_lock(hashtext('prompt:sync'))` (invariant: two processes booting together insert v1 once; the lock is held to commit).
2. Read the latest row (`ORDER BY number DESC LIMIT 1`) with a new statement after the lock (READ COMMITTED then sees the other process's committed row).
3. None: insert `number 1`, the hash, `guidance_text ''`, `author_id null`, `reason 'initial'`, `diff null`; return the row.
4. Latest `locked_hash === locked_hash`: return `null`, write nothing.
5. Differs: insert `number+1` with the new hash, the latest row's `guidance_text` carried over, `author_id null`, `reason 'locked layer changed'`, `diff null`; return it. The old row is never touched.
Ids: `this.ids.new_id("pr")`; `created_at`: `this.clock.now().toISOString()` cast `::timestamptz`.

**Step 3. `insert_guidance(v, diff, tx)`.** Same tx check, then take the same advisory lock `'prompt:sync'` first. Why not the ticket's `FOR UPDATE`: `SELECT ... ORDER BY number DESC LIMIT 1 FOR UPDATE` can hand the waiting transaction the old locked row after the winner commits, so both callers would pass the base check. A transaction-scoped advisory lock taken as the first statement, then a plain read of the latest row, is correct under READ COMMITTED and still serialises the writers (AC-7). Then: latest missing throws `InvariantViolation`; `latest.prompt_version_id !== v.base_version_id` throws `new DomainRefusal("STALE_BASE", "The guidance changed since you opened it.", { latest_version_id: latest.prompt_version_id })` and inserts nothing; else insert `number+1`, the SAME `locked_hash`, `v.guidance_text`, `v.author_id`, `v.reason`, `diff`; return the row.
