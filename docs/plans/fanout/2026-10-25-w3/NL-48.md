## 5. Steps (dependency order: core, db, services, route, docs)

Decisions made here (do not revisit): beats are counted by the **server clock** (`at = clock.now()`), not `sent_at`; `sent_at − last_input_at` is used only for the active test. A beat skipped by the 10 s rule is stored in `heartbeat` but never touches `review_session` and never moves `last_at`, so its 5 s are counted by the next kept beat (AC-4: "add 5 s once").

**Step 1: `packages/core/src/metrics/sessions.ts`.**
```ts
export interface ActiveInterval { user_id: UserId; start: Date; end: Date; synthetic: boolean }
export function merge_heartbeats(beats: readonly HeartbeatRecord[], gap_s: number, min_spacing_s = 10): ActiveInterval[]
```
Algorithm (invariant: one person in two tabs counts once, idle counts nothing):
1. Drop beats with `active === false`.
2. Group by `user_id`; within a user sort by `at` ascending (stable).
3. Per tab (key `tab_id`) drop a beat whose `at` is `< min_spacing_s` after the previous *kept* beat of the same tab (spacing rule).
4. Walk the user's remaining beats in time order: start a new interval at the first; a beat joins the open interval if `at − interval.end ≤ gap_s` (extend `end = max(end, at)`); otherwise close it and open a new one. A single beat gives a zero-length interval.
5. Return intervals ordered by user then start; copy `synthetic` from the beats (a user's flag is constant).
Test file `sessions.test.ts` (names): `two_tabs_merge_to_ten_minutes` (tab A beats every 15 s for 0..600 s, tab B every 15 s offset 7 s for 360..600 s: one interval of 600 s = 10.0 min, not 14), `idle_tab_adds_zero` (focused false beat, and a beat flagged inactive, add nothing), `gap_splits_intervals` (a 90 s hole with gap_s 60 gives two intervals), `spacing_skips_close_beats` (two beats 5 s apart from one tab: one kept), `synthetic_carried`. Evidence line AC-1: `10.0 minutes; idle adds 0`.

**Step 3: `packages/db/src/repos/metrics.ts`.** Header comment `// NL-48`. No logging. Both classes take `PgRepoDeps`.
`PgMetricsRepo implements MetricsRepo`:
- `insert_heartbeat(hb)`: one `with_tx` INSERT `(user_id, tab_id, lesson_id, version_id, at, synthetic)` with `at` as `$5::timestamptz` of `hb.at.toISOString()`. Store every beat it is given.
- `extend_session(hb, gap_s)`: `this.db.with_tx(fn, \`review_session:${user_id}:${lesson_id}:${version_id}\`)` (transaction-scoped advisory lock: the table has no unique index, so this lock is what makes "one row per user, lesson, version" true under two tabs posting at once). Inside: `SELECT ... FROM review_session WHERE user_id=$1 AND lesson_id=$2 AND version_id=$3 ORDER BY id LIMIT 1 FOR UPDATE`.
  1. No row and `!hb.active`: return a transient `ReviewSessionRow` (`started_at = last_at = hb.at`, `active_seconds 0`), persist nothing (idle opens no session, so idle users never count as a human session).
  2. No row and active: INSERT with `started_at = last_at = hb.at`, `active_seconds 0`, `synthetic = hb.synthetic`; return it.
  3. Row exists and (`!hb.active` or `hb.at <= last_at`): return it unchanged (inactive adds 0; a second tab inside the covered span adds nothing; never move `last_at` backwards).
  4. Row exists, active, `hb.at > last_at`: `delta = Math.round((hb.at - last_at) / 1000)`; `add = delta <= gap_s ? delta : 0` (this is `min(at − last_at, gap_s)` for a beat within `gap_s`; beyond it the gap is idle time); `UPDATE ... SET last_at=$at, active_seconds = active_seconds + $add WHERE id=$id RETURNING *`. A gap beat still moves `last_at` (a new span starts there).
- `sessions_for(lesson_id)`: `SELECT ... WHERE lesson_id=$1 ORDER BY id`. (Contains `user_id`; consumed only by `MetricsWriter`; no route may expose it.)
- `first_approval_exists(lesson_id, tx)`: `real_tx(tx).query("SELECT 1 FROM lesson_metrics WHERE lesson_id=$1")`; true when a row exists.
- `write_lesson_metrics(row, tx)`: `INSERT INTO lesson_metrics (...) VALUES (...) ON CONFLICT (lesson_id) DO NOTHING RETURNING lesson_id`; return `rowCount > 0`. Pass `active_minutes.toFixed(2)`, `g2_threshold_minutes.toFixed(2)`. `draft_rating` integer map (module const, both directions): `usable_as_drafted` 1, `usable_with_edits` 2, `rewritten` 3. Never UPDATE.
- `unit_metrics_rows(unit_id)`: `SELECT m.* FROM lesson_metrics m JOIN lesson l ON l.id = m.lesson_id WHERE l.unit_id=$1 ORDER BY l.number NULLS LAST, l.id`; map to `LessonMetricsRecord` (numeric -> `new Decimal(String(v))`, integer rating -> string via the map, null rating -> throw `InvariantViolation`).
`PgBoardReadRepo implements BoardReadRepo` (read-only; selects no minutes column, no `user_id`, no heartbeat or session table):
```sql
SELECT l.id AS lesson_id, l.number, l.type, l.title, l.state, u.name AS reviewer_name,
  GREATEST(
    COALESCE((SELECT max(e.at) FROM review_event e WHERE e.lesson_id = l.id), 'epoch'::timestamptz),
    COALESCE((SELECT max(v.stored_at) FROM lesson_version v WHERE v.lesson_id = l.id), 'epoch'::timestamptz)) AS last_change_at,
  EXISTS (SELECT 1 FROM lesson_link k JOIN lesson s ON s.id = k.to_lesson_id
          WHERE k.from_lesson_id = l.id
            AND k.outline_version_id = (SELECT ov.id FROM outline_version ov WHERE ov.unit_id = l.unit_id ORDER BY ov.number DESC LIMIT 1)
            AND s.state NOT IN ('approved','exported')) AS dependency_flag
FROM lesson l LEFT JOIN app_user u ON u.id = l.reviewer_id
WHERE l.unit_id = $1 AND ($2::text IS NULL OR l.state = $2)
ORDER BY l.number NULLS LAST, l.id
```
Map each row to exactly the `BoardRowRecord` keys (no extra keys). Decision: `dependency_flag` = "some lesson this one waits on (newest outline version's `from_lesson_id` -> `to_lesson_id`) is not approved or exported"; per-slot detail (`slot_empty`, `source_reopened`) is NL-54's to build from `LessonGraphRepo`. The `lesson_version.stored_at` fallback for `last_change_at` is a deliberate small widening of the ticket's table list (needed because `BoardRowRecord.last_change_at` is non-null and a freshly generated lesson has no `review_event`); it reads a timestamp only.

**Step 4: `apps/web/src/server/services/heartbeat-service.ts`.**
```ts

export type HeartbeatSettings = Pick<WebSettings, "heartbeat_merge_gap_s" | "heartbeat_min_spacing_s">;
export class HeartbeatService {
  constructor(metrics: MetricsRepo, clock: Clock, settings: HeartbeatSettings, lessons: LessonLookup)

```
(DO-4 shows `(metrics, clock, settings)`; the fourth parameter is how `NOT_FOUND` is decided without a new port method. See Risks.) `record`:
1. `user.role === "author"` -> `throw new DomainRefusal("ROLE_FORBIDDEN", "Your role cannot do this.")` before any read or write.
2. `await lessons.get(lesson_id)` is null -> `DomainRefusal("NOT_FOUND", "Not found.")`.
3. `now = clock.now()`; `active = hb.focused && hb.visible && (Date.parse(hb.sent_at) − Date.parse(hb.last_input_at)) <= gap_s * 1000` (a future `last_input_at` is active; unparseable dates cannot reach here, the route schema validated them).
4. Build `rec: HeartbeatRecord = {user_id: user.user_id, tab_id: hb.tab_id, lesson_id, version_id: hb.version_id, at: now, active, synthetic: user.synthetic}`.
5. `await metrics.insert_heartbeat(rec)` (every beat is stored).
6. Spacing: private `Map<string, number>` keyed `${user_id}|${tab_id}|${lesson_id}` holding the `at` ms of the last *kept* beat. If an entry exists and `now − entry < min_spacing_s*1000`, return (stored, adds no time, map unchanged). Otherwise set the entry **before** awaiting `extend_session` (so two quick calls cannot both pass). When the map exceeds 5000 entries, delete entries older than `gap_s*1000` (bounds memory; an evicted tab only loses the spacing guard, never counted time).
7. `await metrics.extend_session(rec, gap_s)`; return void (the route returns 204; nothing is returned).
No logging, no names in errors.
