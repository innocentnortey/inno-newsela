## 1. Goal and sources

Deliver `apps/worker/src/generation/unit-plan-job.ts`: `UnitPlanJob.run(job: ClaimedJob) -> UnitPlanOutcome`. It renders the unit-plan prompt for the
run's in-scope rows, makes one schema-enforced paid call (checkpointed), validates the plan (Zod `UnitPlanDraft` + code checks), allows at most one repair
call, then either stores the plan (`RunRepo.store_unit_plan`, which makes lesson jobs claimable) or pauses the run (`mark_plan_failed`) or caps it
(`mark_capped`).

## 5. Steps

Constructor (decision): `constructor(paid: UnitPlanPaidCaller, renderer: UnitPlanRenderer, runs: UnitPlanRuns, outlines: UnitPlanOutlines, prompts: UnitPlanPrompts, settings: UnitPlanSettings, queue: UnitPlanQueue, calls: UnitPlanCalls, tx: TxRunner)`. DO-4 lists only the first six; the three trailing ones are needed because `RunRepo` has no scope, the checkpoint lives on `ModelCallLog`, and `mark_*` need a `Tx` (Open item 2). Receive all by injection; never construct a repo or client inside.

Module-level: `const SCHEMAS = new SchemaRegistry();` and `const PLAN_SCHEMA = SCHEMAS.json_schema("UnitPlanDraft");` computed lazily inside the method on first use (pure; deterministic).

1. **Guard.** `job.kind !== "unit_plan"` -> `throw new InvariantViolation("unit_plan_job.wrong_kind", {job_id: job.job_id})`. Invariant: the claim loop only routes unit_plan jobs here.
2. **Load prompt and choices.** `prompt = await prompts.get(job.prompt_version_id)`; null -> `InvariantViolation("unit_plan_job.prompt_missing")`. `choices = await runs.pinned_choices(job.run_id)`.
3. **Scope and input.**
   a. `jobs = await queue.jobs_for_run(job.run_id)`; `scope_ids = new Set(jobs.filter(j => j.kind === "lesson" && j.lesson_id !== null).map(j => j.lesson_id))`. Reason: `RunRow` has no scope, and `RunService.start` creates one lesson job per in-scope lesson **before** the plan runs (DO-4 RunService.start), so the lesson jobs ARE the scope. Empty set -> `InvariantViolation("unit_plan_job.empty_scope")`.
   b. `records = await outlines.rows(job.outline_version_id)`; `rows = records.map(r => r.row).filter(r => (r.kind === "lesson" || r.kind === "flex_day") && r.lesson_id !== null && scope_ids.has(r.lesson_id)).sort((a, b) => a.row_number - b.row_number)`. Rows outside scope never reach the prompt (AC-3).
   c. `first = rows[0]`; empty `rows` -> `InvariantViolation("unit_plan_job.no_rows_in_scope")`. `unit_rules = (await outlines.row_context(job.outline_version_id, first.lesson_id as LessonId, choices)).unit_rules`.
   d. `links = await outlines.links(job.outline_version_id)` (computed by code, HP-1; passed to the prompt as read; never written, never derived from model text).
   e. `expected = rows.map(r => r.lesson_id)`.
4. **First plan (checkpointed).**
   `const stored_first = await calls.completed_for(job.job_id, "unit_plan", 1)`. If non-null use it (NO `paid.call`, no render needed for it). Else `rendered = renderer.render_unit_plan({run_id: job.run_id, prompt, rows, unit_rules, links, repair_of: null})` and `paid.call(make_request("unit_plan", 1, rendered))`. Invariant: a completed paid call is never paid twice (AC-7, WF-21).
   `make_request(purpose, attempt, rendered, alias)` builds a `UnitPlanPaidCallRequest`:
   `ctx = {run_id: job.run_id, lesson_id: null, job_id: job.job_id, attempt, purpose, request_id: null, experiment_id: null, reservation_id: null}`;
   `req: StructuredCallRequest = {alias, system_blocks: rendered.system_blocks, user_blocks: rendered.user_blocks, output_schema_name: "UnitPlanDraft", output_json_schema: PLAN_SCHEMA, output_mode: "schema_enforced", max_output_tokens: settings.draft_output_token_cap, timeout_ms: settings.model.model_call_timeout_ms, effort: settings.model.model_effort, temperature: null}`;
   `run_id: job.run_id, job_id: job.job_id, user_id: job.started_by`. Alias `"GENERATION"` for the first call, `"REPAIR"` for the repair (decision: the repair uses the repair alias like lesson repairs; both default to the same model id).
   `PromptBlock` types: `rendered.system_blocks` come from `@ls/prompts/inputs` (local `PromptBlock`, structurally identical to the core one); if tsc rejects the assignment, cast through no `any`: write `system_blocks: [...rendered.system_blocks]` and fix the type with a typed helper, not `as any` (the two types are structurally identical, so tsc accepts it).
5. **Validate (pure helper `validate_plan(raw: string, expected: readonly LessonId[]): {plan: UnitPlanDraft | null; issues: string[]}`, exported for tests).**
   1. `JSON.parse(raw)` in try/catch -> issues `["output: not valid JSON"]`, plan null.
   2. `UnitPlanDraft.safeParse(parsed)`; failures -> one issue per Zod issue: `` `${issue.path.join(".")}: ${issue.message}` `` (an empty path prints `$`). Zod already catches duplicate `lesson_id` (message `duplicate lesson_id`), a missing `entries`, an empty list.
   3. Only if Zod passed, code checks (collect all, do not stop at the first): for each entry `i`, `lesson_id` not in `expected` -> `` `entries.${i}.lesson_id: ${id} is not in this run's scope` ``; for each expected id absent -> `` `missing entry for ${id}` ``; for `i > 0` `entries[i].day <= entries[i-1].day` -> `` `entries.${i}.day: days must be strictly ascending` ``.
   4. `plan` is non-null only when `issues.length === 0`.
   Invariant protected: nothing is stored before every in-scope day has exactly one entry (CON-8: 47 entries on the issued unit).
6. **Valid first plan -> step 8. Invalid -> one repair.**
   `stored_repair = await calls.completed_for(job.job_id, "repair", 1)`; if non-null reuse it, else
   `rendered2 = renderer.render_unit_plan({... same inputs ..., repair_of: {draft_raw: first.raw_output, issues}})` and `paid.call(make_request("repair", 1, rendered2, "REPAIR"))`.
   `issues` here are the strings from step 5. Validate the repair raw output the same way. Valid -> step 8 with the repair call; invalid -> step 7 failure `schema_invalid`. Never a second repair.
7. **Failure paths (each ends by returning an outcome; none stores anything).**
   - Wrap steps 4 and 6 calls in try/catch (only around `paid.call`).
   - `SpendRefused e`: `await tx.with_tx(t => runs.mark_capped(job.run_id, e.refused_by, t))`; `failure = failure_reasons_for({brakes_fired: [brake_for(e.refused_by)], provider_error: null, schema_valid: true, compile_error: null, first_failing_kind: null})[0]` where `brake_for`: `run_cap -> "spend_run_cap"`, `day_cap -> "spend_day_cap"`, `project_cap -> "spend_project_cap"`. Outcome `{stored:false, entries:0, model_call_id:null, failure}` (check `capped`). No model_call row is written by the job (the refusal comes before the send).
   - `ProviderError e`: `await tx.with_tx(t => runs.mark_plan_failed(job.run_id, t))`; `failure = failure_reasons_for({brakes_fired: [], provider_error: e.kind, schema_valid: true, compile_error: null, first_failing_kind: null})[0]` (gives `rate_limited` for rate_limited/overloaded, `timeout` for timeout, else `provider_error`).
   - Schema failure after the repair: `await tx.with_tx(t => runs.mark_plan_failed(job.run_id, t))`; `failure = failure_reasons_for({brakes_fired: [], provider_error: null, schema_valid: false, compile_error: null, first_failing_kind: null})[0]` (check `schema_invalid`).
   - Any other error (InvariantViolation, LeaseLost, a bug) is NOT caught: it propagates to the claim loop.
8. **Store.** `await runs.store_unit_plan(job.run_id, plan, call.model_call_id)` (one call; it owns its transaction). Outcome `{run_id, stored: true, entries: plan.entries.length, model_call_id: call.model_call_id, failure: null}` where `call` is the call whose output validated (first or repair). The model's `hands_forward` text is stored as given and used only as advisory text; the job calls no link-writing method (none exists on the narrowed `UnitPlanRuns`).
9. **Logging.** None (no Logger dependency; keeps outline text out of logs). Do not log raw output, rows or prompts.
10. **Docs.** Devlog (Changed, Why, Checked, Remaining) must record: the three extra constructor params, scope-from-`jobs_for_run`, the local `UnitPlanPaidCaller` types, the REPAIR alias choice, and Open items 1-4. Area-map edit as in section 2. Run `check_context.py`.

Non-goals: no lesson rows, no job creation, no edits to `claim-loop.ts` or `run-finalizer.ts` (NL-30), no link computation, no console output, no `any`.
