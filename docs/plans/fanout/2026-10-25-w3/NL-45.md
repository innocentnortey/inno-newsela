Never import a concrete adapter, `PgDatabase`, a logger or `process.env` in the service. No code path may call a content-writing method other than `collab.apply_edit`.

1. **Module constants** in `issue-service.ts`: `const MANAGED_KINDS`-free; `const FLAG_CLEAR_STATES: ReadonlySet<LessonStateName> = new Set(["in_review","submitted","changes_requested","reopened"])` (refused: `draft`, `generation_failed`, `approved`, `exported`; CON-14); `const USE_FOR: Partial<Record<CheckKind, string>> = { standard_confirmation: "decideStandard", safety_flag_open: "clearSafetyFlag", suggestion_pending: "decideSuggestion", rights_to_clear: "fillSlot", safety_note_without_tip: "editContent", safety_text_in_student_block: "editContent", cross_lesson_link: "approveSourceLesson" }` (decided here; the first four are named by the ticket).
2. **Helpers (private, pure):**
   - `refuse(code, message, details = {}): never` throws `new DomainRefusal(...)`. Messages are fixed phrases plus ids and codes, never lesson text or the reason/note.
   - `is_open(r: IssueRow): boolean` = `r.resolved_at === null && r.cleared_by === null`; `counts_of(rows: IssueRow[]): IssueCounts` = number of `is_open` rows per level (`blocking`, `confirmation`, `advisory`). Rows with `cleared_by === "fix"` are dropped from the list before counting.
   - `actor_of(user): Actor` = `{ user_id: user.user_id, name: user.name, role: user.role, synthetic: user.synthetic }`.
   - `load_lesson(lesson_id): Promise<LessonRow>`: `states.get`; `null` -> `refuse("NOT_FOUND", "Lesson not found.", { lesson_id })`.
   - `require_editable(row)`: `if (!is_editable(row.state, "reviewer")) refuse("LESSON_LOCKED", "The lesson is not editable.", { state: row.state })`.
3. **Read the stored state of a lesson once** (`get_issues` only): `Promise.all([issues.current, checks.pending_for, graph.dependencies])` after `load_lesson`.
4. **`blocks_for(row, deps)` and `resolvable_for(row)`** (pure, exported for the table test):
   - default `blocks`: `level === "advisory" ? [] : ["submit","approve"]`.
   - overlay (UXP-2, ticket "planner confirms"): for `kind === "cross_lesson_link"` find `d` in `deps` with `d.direction === "waits_on" && d.lesson_id === row.related_lesson_id`; if `d` exists AND `d.slot_filled === true` AND `d.source_state` is neither `"approved"` nor `"exported"` -> `["approve"]`; otherwise keep the default (`["submit","approve"]` for a blocking row; an empty slot stays blocking for both). This is an overlay on the stored `cross_lesson_link` finding the check job writes (NL-39/NL-81); the service never invents an issue row (it has no id to give).
   - `resolvable = !NON_RESOLVABLE.has(row.kind)`.
5. **`get_issues(user, lesson_id)`** (any role). Invariants: read-only (no `tx`, no write); `counts` equal the unresolved rows of the returned list.
   a. `load_lesson`. b. step 3 reads. c. `stored = pending.latest_stored_hash`; `null` -> `refuse("NOT_FOUND", "Lesson has no stored content.", { lesson_id })` (same choice as NL-44). d. `rows = set.issues.filter(r => r.cleared_by !== "fix")`. e. `checked_hash = set.checked_hash ?? stored`; `checked_at = set.checked_at ?? pending.latest_stored_at ?? this.clock.now()`; `pending_flag = pending.pending || set.checked_hash === null` (never-checked means checking). f. Map each row to `Issue`: `issue_id, level, blocks: blocks_for, resolvable: resolvable_for, kind, message, address, span_anchor, related_lesson_id`, `resolution = r.resolved_at === null ? null : { by: r.resolved_by ?? "", reason: r.resolution_reason ?? "", at: r.resolved_at.toISOString() }` (`by` is the user id, see R3). Text fields are returned verbatim as strings. g. Return `{ lesson_id, stored_hash: stored, checked_hash, checked_at: checked_at.toISOString(), pending: pending_flag, counts: counts_of(rows), issues }`.
6. **`record_resolution(user, lesson_id, issue_id, req)`** — CON-13/14 precedence, each refusal BEFORE any write:
   1. `user.role !== "reviewer"` -> `ROLE_FORBIDDEN` ("Your role cannot do this.").
   2. `row = await load_lesson(lesson_id)` (`NOT_FOUND`); `cur = await this.issues.current(lesson_id)`; `issue = cur.issues.find(r => r.issue_id === issue_id)`; absent (also: an id of another lesson or an old hash) -> `NOT_FOUND` ("Issue not found.", `{ lesson_id, issue_id }`).
   3. `require_editable(row)` -> `LESSON_LOCKED`.
   4. `req.reason.trim() === ""` -> `REASON_REQUIRED` (422).
   5. `NON_RESOLVABLE.has(issue.kind)` -> `NOT_RESOLVABLE` with `details { kind: issue.kind, use: USE_FOR[issue.kind] ?? "editContent" }`.
   6. `ack = await this.tx.with_tx(async (tx) => { const r = await this.issues.resolve({ issue_id, by: user.user_id, reason: req.reason, request_id: user.request_id }, tx); const audit_id = await this.audit.append({ actor_id: user.user_id, action: "issue.resolve", target_kind: "issue", target_id: issue_id, version_hash: issue.content_hash, reason: req.reason, details: { lesson_id, kind: issue.kind, code: issue.code, address: issue.address }, request_id: user.request_id, store_id: null }, tx); return { r, audit_id }; })`. The reason is stored verbatim (not trimmed, not escaped; AC-10). Never call `states.set_state`, `alignment.*`, `collab.*`, or any `lesson_doc` writer.
   7. After commit: `counts = counts_of((await this.issues.current(lesson_id)).issues.filter(r => r.cleared_by !== "fix"))`. Return `{ item_id: issue_id, status: "resolved", by: user.name, at: (ack.r.resolved_at ?? this.clock.now()).toISOString(), audit_id: ack.audit_id, counts }`.
   Re-resolving an already resolved issue is allowed (a newer named resolution is a recorded decision, with its own audit row); not an error (Open item O2).
7. **`clear_safety_flag(user, lesson_id, flag_id, req)`**:
   1. `user.role` not `"reviewer"` or `"approver"` -> `ROLE_FORBIDDEN`.
   2. `row = load_lesson`; `flag = (await this.flags.open_for(lesson_id)).find(f => f.flag_id === flag_id)`; absent (unknown or already cleared) -> `NOT_FOUND` ("Safety flag not found.", `{ lesson_id, flag_id }`).
   3. `FLAG_CLEAR_STATES.has(row.state)` false -> `LESSON_LOCKED` with `{ state: row.state }`.
   4. `req.note.trim() === ""` -> `NOTE_REQUIRED`; the flag stays open (nothing written).
   5. One tx: `cleared = await this.flags.clear(flag_id, user.user_id, req.note, tx)`; `doc = await this.reader.latest(lesson_id)`; `audit.append({ actor_id: user.user_id, action: "safety_flag.clear", target_kind: "safety_flag", target_id: flag_id, version_hash: doc?.content_hash ?? null, reason: req.note, details: { lesson_id, source_row: flag.source_row }, request_id: user.request_id, store_id: null }, tx)`; and, so the now-stale `safety_flag_open` issue is dropped, `if (doc !== null) await this.checks.enqueue(lesson_id, doc.content_hash, doc.store_id, tx)` (a re-check of the SAME stored hash; it does not touch the document, its hash or the last editor). Return `{ item_id: flag_id, status: "cleared", by: user.name, at: (cleared.cleared_at ?? this.clock.now()).toISOString(), audit_id, counts }` with counts as in step 6.7 (they may still include the old `safety_flag_open` row until the check finishes; the list's `pending` says so, O3).
8. **`decide_standard` confirm / remove / add** (`req.decision !== "undo"`):
   1. role `reviewer` only -> `ROLE_FORBIDDEN`. `row = load_lesson`. `require_editable(row)`. (CON-14 order: role, NOT_FOUND, LOCKED.)
   2. `derived = await this.reader.latest_derived(lesson_id)`; `null` -> `NOT_FOUND` ("Lesson has no stored content."). `entry = derived.lesson.front_matter.standards.find(s => s.code === req.code) ?? null`. `before_links = (await this.alignment.for_lesson(lesson_id)).filter(l => l.code === req.code)`.
   3. Validity: `confirm`/`remove` need `entry !== null` and `entry.origin` in `{"narrowed","added"}` (CON-14), else `INVALID_REQUEST` with `details { fields: ["code"] }`; and `before_links.length > 0`, else `NOT_FOUND` ("No alignment rows for this code yet.", `{ lesson_id, code }`) so NL-43's `confirm` never throws on a lesson whose latest hash has not been checked (O4). `add` needs `entry === null || entry.confirmation === "removed"`, else `INVALID_REQUEST` `{ fields: ["code"] }`.
   4. ONE `tx.with_tx` (deliberate order, see R2): `link = await this.alignment.confirm(lesson_id, req.code, user.user_id, req.decision, tx)`; THEN `ack = await this.collab.apply_edit({ lesson_id, actor: actor_of(user), edit: { kind: "standard", code: req.code, decision: req.decision, restore: null }, tag: "standard-decision", request_id: user.request_id })`; THEN `audit_id = await this.audit.append({ actor_id: user.user_id, action: "standard." + req.decision, target_kind: "lesson", target_id: lesson_id, version_hash: ack.content_hash, reason: null, details: { code: req.code, decision: req.decision, undo_of: null, before_entry: entry, before_links }, request_id: user.request_id, store_id: ack.store_id }, tx)`. `before_entry` is the full `Standard` object (or `null`); `before_links` the full `AlignmentLinkRow[]` (they must be plain JSON: no Dates).
   5. `catch (e)` around the `with_tx` call: `if (e instanceof CollabUnavailable) refuse("COLLAB_UNAVAILABLE", "The collaboration server is unavailable. Try again.", { lesson_id })`; rethrow everything else (`DomainRefusal` from collab such as `LESSON_LOCKED` passes through unchanged). The transaction rolls back, so nothing is recorded. Invariant: exactly one `apply_edit` call per decision, never retried.
   6. Return `{ item_id: req.code, status: { confirm: "confirmed", remove: "removed", add: "added" }[req.decision], by: user.name, at: this.clock.now().toISOString(), audit_id, counts }` (counts: step 6.7; they are the stored-issue counts and may lag the new store until the re-check runs; the store already enqueued that check).
   `add` opens its own confirmation: `AlignmentRepo.confirm(.., "add")` inserts the unconfirmed `added` row and the front-matter edit makes the check job emit a `standard_confirmation` item; the service adds no issue row itself.
9. **`decide_standard` undo** (`req.decision === "undo"`), exact order of refusals (DO-4 §5):

## 8. Risks and requests
- **R1 (constructor additions):** DO-4's `IssueService` constructor has no `LessonGraphRepo` or `LessonDocReader`. The ticket requires the cross-lesson overlay (graph) and the audit `before_entry` (front matter, only readable from the stored derived row). Both are existing ports; `LessonReadService` and `SuggestionService` already take the same ones (§13 R-6). Request to the integrator: add `graph` and `reader` to the DO-4 `IssueService` signature when NL-53 wires it (last two constructor arguments).
- **R2 (ordering deviation, important):** the ticket says "`apply_edit` first, then one tx records `AlignmentRepo.confirm`". NL-43's `confirm`/`restore` act on the rows of the LATEST stored hash and throw `InvariantViolation` if none exist; `apply_edit` stores a new hash whose alignment rows only appear when the check job runs. Done in ticket order, `confirm` would throw after the front matter had already changed. This plan therefore runs `alignment.confirm|restore` first, then `apply_edit`, then the audit append, all inside the one `with_tx`; a `CollabUnavailable` rolls everything back, so "nothing recorded" still holds. Consequences: the transaction stays open for one collab hop (about 1 s, p95 target); the plan takes NO row lock (`lock_for_update`) in that tx because collab's own store updates the `lesson` row (`record_last_editor`) and would deadlock against it. Confirmation carries to the new hash through `AlignmentRepo.replace_for_hash`'s carry-forward. If the integrator prefers the ticket's literal order, `AlignmentRepo` needs to accept an explicit hash; that is a port change, not made here.
- **R3 (names):** the issue list's `resolution.by` is the resolver's user id (no user-lookup port in the constructor); the mutation responses' `by` is the caller's display name. Needs a name source before SCR-9 shows "resolved by <name>" (same gap as NL-44 R3). NL-62/63 must not assume names in the list.
- **R4 (audit detail size):** `PgAuditLog.append` rejects any string over 120 characters in `details` (`check_details`, `MAX_STRING = 120`) and the standard decision rows carry `before_entry.official_text` (CDE text, often longer). A real standard longer than 120 characters would throw `InvariantViolation` inside the decision's transaction (rolled back, 500). Request to the owner of `packages/db/src/repos/audit.ts` (NL-12 area): exempt `details.before_entry.official_text` from the length rule (it is CDE text, allowed by DO-4 §3.5) or raise the limit. Not worked around here (truncating would break the exact undo).
- **R5 (bridge helper):** the Next `Request` <-> `HttpRequest` bridge does not exist on main; NL-44 ships its own in `lesson-read-routes.ts`. This slice ships `to_http_request`/`to_response` in `issue-routes.ts` and imports nothing from NL-44. Request: the integrator extracts one shared helper later.
- **R6 (check job):** `cross_lesson_link` overlay assumes NL-39/NL-81 store a `cross_lesson_link` finding with `related_lesson_id` = the source lesson while the dependency is unmet (the current `cross_lesson_link_rule.run` on main is a stub returning `[]`). If the stored finding is absent, no entry appears; the service does not synthesize one. The same-hash re-check enqueue in `clear_safety_flag` assumes `PgCheckQueue.enqueue` accepts the already-checked hash (coalesced per lesson); verify when NL-81 lands (NL-113 integration covers it).
- **R7 (lesson id forms):** routes accept only the canonical id (`G6.U4.L4`, `LESSON_ID_RE`). The `g6-u4:L4` form (`parse_lesson_ref`, NL-44) is not yet on main; swapping the `LessonParams` regex for it later is a one-line change.
