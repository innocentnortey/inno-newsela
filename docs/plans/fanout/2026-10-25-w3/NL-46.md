## 0. Decision on the `quote` node (carry-in)
**Finding.** `packages/editor-schema/src/schema.ts` (NL-10, merged) has `quote_placeholder` (attrs `slot_id`, `reason`; atom) and `excerpt_slot` (attrs `slot_id`, `rights`, `source_ref`; atom) but **no `quote` node**. The check core already reads one: `packages/core/src/checks/rules/grounding/fields.ts` collects `node.type === "quote"` with `attrs.source_ref` (a non-blank STRING; `quote_without_source`) and `attrs.rights` (`rights_to_clear`), and treats the quote's children as quote text. CON-15 says the fill "inserts a `quote` node". Ticket > DO-4 > DO-3: the ticket and CON-15 say `quote` node; DO-4 §8 lists only three Lesson Studio nodes (R-20) and is silent on the filled form.

**Why no existing node works.** `paragraph` has no `source_ref`/`rights` attrs, so M-7 (quotes sourced) and the checks `quote_without_source`/`rights_to_clear` could not compute. An `excerpt_slot` atom has no text. So the fill cannot be represented with existing nodes. Without the node, `assert_known_nodes` would throw `SCHEMA_UNKNOWN` on every lesson that holds a filled quote, which breaks `getLesson` (NL-44).

**Required additive change (NOT in NL-46's files; a request, see §8 R1).** In `packages/editor-schema/src/schema.ts` add to `nodes`, after `excerpt_slot`:
```ts
  quote: {
    group: "block",
    content: "text*",
    marks: "",
    attrs: {
      slot_id: { validate: "string" },
      source_ref: { default: "", validate: "string" },   // the check core reads a non-blank string
      rights: { default: "unset", validate: one_of("quote rights", RIGHTS) },
    },
    toDOM: block_dom("quote"),
  },
```
Plain text only (`marks: ""`, `text*`; R-58). `SCHEMA_VERSION` stays 1 (additive; old docs still validate). Also: update the node-name lists in `schema.test.ts` and `roundtrip.test.ts` and DO-4 §8's "three Lesson Studio nodes" wording (R-20 as amended). The collab fill (NL-105, AC-5 `slot_fill_and_adopt_scopes`) then replaces the whole node whose `slot_id` equals the edit's, whether it is a `quote_placeholder`, an `excerpt_slot` or an earlier `quote`, with `{type:"quote", attrs:{slot_id, source_ref:<string citation>, rights}, content:[{type:"text", text}]}`. Re-fill finds the earlier `quote` by its `slot_id`, which is why `slot_id` is an attr. The string format of `source_ref` is NL-105's choice (suggest `JSON.stringify(SourceRef)`; it must be non-blank iff the SourceRef has a non-blank field).

**What NL-46 does without it.** Nothing in NL-46's code or tests depends on the node existing: the service sends `SlotFillEdit` (CON-15's `source_ref`, `rights_status`, `text`) and the node is the collab server's concern. The AC-7 test double models the collab behaviour on the **planned** node shape (§5 step 7) in plain JSON and never loads `EDITOR_SCHEMA`. Do NOT edit `packages/editor-schema` here.

2. **`count_words(text: string): number`** (CON-15 word rule). `text.split(/\s+/).filter((t) => /[\p{L}\p{N}]/u.test(t)).length`. Invariant: a token counts only if it has a letter or digit, so `"-"`, `"..."`, `"—"` add 0.
3. **`has_source(ref: SourceRef): boolean`.** Read `book`, `title`, `chapter`, `pages`, `url` through `const r = ref as unknown as Record<string, unknown>` and return true when any value is a string whose `trim()` is non-empty. Invariant: matches the ticket's "none of `book`/`title`, `chapter`, `pages`, `url`" (`book` can only arrive from a non-HTTP caller, because the Zod mirror strips it; see R2).
4. **`fill(...)` order (CON-15 precedence; nothing is sent before check 6).**
   1. Role: `if (user.role !== "reviewer") throw new DomainRefusal("ROLE_FORBIDDEN", "Your role cannot do this.")`.
   2. Lesson: `const row = await this.states.get(lesson_id); if (row === null) throw new DomainRefusal("NOT_FOUND", "Lesson not found.", { lesson_id })`.
   3. State: `if (!is_editable(row.state, user.role)) throw new DomainRefusal("LESSON_LOCKED", "This lesson cannot be edited in its current state.", { lesson_id, state: row.state })`. This is before the source and word checks (AC-4).
   4. Text (defence in depth; the route's Zod already refuses these): `if (req.text.trim() === "" || req.text.length > 10000) throw new DomainRefusal("INVALID_REQUEST", "The request is not valid.", { fields: ["body.text"] })`. Never alter, trim or escape `req.text` when sending it on (plain text stored verbatim; R-58).
   5. `if (!has_source(req.source_ref)) throw new DomainRefusal("SOURCE_REQUIRED", "A quote needs a source: a title, chapter, pages or link.", { lesson_id, slot_id })`.
   6. `if (req.rights_status === "short-quote-commentary" && count_words(req.text) > this.policy.reviewer_quote_max_words) throw new DomainRefusal("QUOTE_TOO_LONG", "A short quote with commentary can be at most " + this.policy.reviewer_quote_max_words + " words.", { lesson_id, slot_id, max_words: this.policy.reviewer_quote_max_words })`. Other rights statuses have no word limit.
5. **Send exactly one edit (continuing `fill`).**
   ```ts
   const actor: Actor = { user_id: user.user_id, name: user.name, role: user.role, synthetic: user.synthetic };
   const edit: SlotFillEdit = { kind: "slot_fill", slot_id, text: req.text, source_ref: req.source_ref, rights_status: req.rights_status };
   let ack: StoreAck;
   try {
     ack = await this.collab.apply_edit({ lesson_id, actor, edit, tag: "slot-fill", request_id: user.request_id });
   } catch (e) {
     if (e instanceof CollabUnavailable) throw new DomainRefusal("COLLAB_UNAVAILABLE", "The collaboration server could not apply the insert. Try again.", { lesson_id });
     throw e;   // a DomainRefusal from collab (LESSON_LOCKED, NOT_FOUND for a slot a co-editor deleted) passes through with its own code
   }
   ```
   No retry (commands are not idempotent). No audit write, no `with_tx`: the collab server mints `store_id` and the audit event (WF-12).
