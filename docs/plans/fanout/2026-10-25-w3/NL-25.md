`with_route` (do not edit): `make_with_route(deps: WithRouteDeps)` and the default `with_route` (public via `spec.public: true`, handler `(user: null, request: HttpRequest)`), `HttpRequest`/`HttpResponse` (headers lower-case in request, response headers a `Record<string,string>` that always has `X-Request-Id`), `mint_request_id()`. ## 5. Steps (build order; each checkable)

Frozen-test first: the orchestrator runs `test-writer-agent` on AC-1..AC-9 and AC-12 BEFORE the implementer (see section 7). Before writing the tests it uses the fixed module surface in steps 1-9 below; the implementer then must not edit frozen files.

1. **`passwords.ts`** (pure, `node:crypto` only, no web imports). `hash_password(password: string): string` -> `scrypt$N$r$p$salt_b64$hash_b64` with `N=16384, r=8, p=1`, 16-byte `randomBytes` salt, 32-byte key via `scryptSync`. `verify_password(stored_hash: string, password: string): boolean`: split on `$`; require exactly 6 parts, part0 `scrypt`, N/r/p positive integers (cap `N <= 2**20`, `r <= 16`, `p <= 4` so a tampered hash cannot make us burn CPU), salt and hash valid base64 with non-empty decoded length; derive with the SAME N/r/p and `keylen = decoded hash length`; compare with `timingSafeEqual` (lengths equal by construction). Whole body in `try/catch` -> `false`; never throws; empty password -> `false` without deriving. Invariant: attacker-controlled stored data cannot throw or hang.
2. **`session-cookie.ts`** (pure). `build_set_cookie(name: string, token: string, max_age_s: number, app_origin: string): string` -> `${name}=${token}; HttpOnly; SameSite=Strict; Path=/; Max-Age=${max_age_s}` plus `; Secure` unless `new URL(app_origin).hostname` is `localhost` or `127.0.0.1`. `build_clear_cookie(name, app_origin)` -> same attributes with empty value and `Max-Age=0`. Token is base64url (no cookie-unsafe chars).
3. **`PgSessionRepo`** in `packages/db/src/repos/sessions.ts`: `export class PgSessionRepo implements SessionRepo`, `constructor(deps: PgRepoDeps)` (import the type from `./audit.ts`). Methods:
   - `find_user_by_email(email)`: `SELECT id, email, name, role, synthetic, password_hash FROM app_user WHERE lower(email) = lower($1)` via `this.db.with_tx`; map `id` -> `user_id`; null when no row.
   - `create_session(user_id, token_hash, expires_at, tx)`: require `tx instanceof DbTx` (from `../tx.ts`) else `InvariantViolation`; `INSERT INTO app_session (token_hash, user_id, created_at, expires_at) VALUES ($1,$2,$3,$4) RETURNING created_at` using `this.clock.now()` for `created_at` (so FakeClock drives it); return `AppSessionRow`.
   - `resolve(token_hash, now)`: `SELECT ... FROM app_session s JOIN app_user u ON u.id = s.user_id WHERE s.token_hash=$1 AND s.revoked_at IS NULL AND s.expires_at > $2`; null otherwise. This is the one method the collab authenticator also calls (AC-9): do not add a second read path.
   - `revoke(token_hash, now)`: `UPDATE app_session SET revoked_at = $2 WHERE token_hash=$1 AND revoked_at IS NULL` (idempotent, keeps the first revoke time). Runs in its own `with_tx`. (`sign_out` calls it inside `tx.with_tx`'s callback? No: `revoke` opens its own tx; see step 4 for how the audit and revoke stay atomic.)
   Hmm, atomicity: `SessionRepo.revoke` has no `tx` parameter (port is fixed, DO-4). Decision: `sign_out` does `revoke` then the audit append in ONE `tx.with_tx` for the audit only; if the audit append throws after revoke succeeded the session is still revoked (fail-closed, safe direction). Do not change the port.
4. **`SessionService`** in `apps/web/src/server/services/session-service.ts`:
   ```ts
   export interface RequestMeta { request_id: RequestId; ip_hash: Sha256 | null }
   export interface SignInOutcome { session: Session; cookie_token: string; expires_at: Date }
   export class SessionService implements SessionResolver /* structural; do not import from with-route */ {
     constructor(sessions: SessionRepo, audit: AuditLog, tx: TxRunner, clock: Clock, ids: IdGenerator, settings: WebSettings, logger: Logger)
     sign_in(req: SignInRequest, meta: RequestMeta): Promise<SignInOutcome>
     require(cookie_token: string | null, request_id: string): Promise<RequestUser>
     get_session(user: RequestUser): Promise<Session>
     sign_out(user: RequestUser, cookie_token: string): Promise<void>
   }
   ```
   (The 7th `logger` parameter is an additive deviation from DO-4, needed for the refusal log line; DO-4 gives the service no logger. See Risks.)
   - `sha256_hex(s)` = `createHash("sha256").update(s).digest("hex")`.
   - **sign_in order** (each step protects an invariant):
     1. `found = await sessions.find_user_by_email(req.email)`. Always run `verify_password` on a fixed dummy scrypt hash (constant created once at module load with `hash_password("x")`) when `found` is null, so timing does not reveal list membership. Invariant: no allow-list oracle from CPU time.
     2. null -> refuse `NOT_ON_ALLOW_LIST` (message `That email isn't on the staff list.`); `verify_password(found.password_hash, req.password)` false -> refuse `INVALID_CREDENTIALS` with message exactly `That email and password don't match` (AC-3 string, no trailing period).
     3. Refusal = `logger.warn("session.sign_in_refused", {request_id: meta.request_id, extra: {code, email_hash}})` where `email_hash = sha256_hex(settings.audit_hash_salt.reveal() + req.email.toLowerCase())`; then `await clock.sleep(1000)`; then `throw new DomainRefusal(code, message)`. Write NO row. Never log/echo email, password or token. (Order log-then-sleep or sleep-then-log both fine; test only counts sleeps and log lines.)
     4. Success: `token = randomBytes(32).toString("base64url")`; `token_hash = sha256_hex(token)`; `now = clock.now()`; `expires_at = new Date(now.getTime() + settings.session_ttl_hours*3600_000)` (fixed at issue; no sliding renewal).
     5. One `tx.with_tx(async (t) => { await sessions.create_session(user_id, token_hash, expires_at, t); await audit.append({actor_id: user_id, action: "session.sign_in", target_kind: "session", target_id: token_hash.slice(0,16), version_hash: null, reason: null, details: {user_id}, request_id: meta.request_id, store_id: null}, t) })`. Session row and audit row commit together or not at all.
     6. Return `{session: {user: {user_id, name, email, role, synthetic}, expires_at: expires_at.toISOString()}, cookie_token: token, expires_at}`. Remember `expires_at` for `get_session` only through `require` (below).
   - **require**: null/empty token -> `DomainRefusal("UNAUTHENTICATED","Sign in again.")`; `ctx = await sessions.resolve(sha256_hex(token), clock.now())`; null -> same refusal. Return `RequestUser{...ctx.user, request_id}` and store `ctx.session.expires_at` in a private `WeakMap<RequestUser, Date>` (`with_route` hands the same object to the handler, so `get_session(user)` can read it). Writes nothing.
   - **get_session(user)**: look up the WeakMap; missing -> `UNAUTHENTICATED`; return `Session` shape (email/role/synthetic from `user`).
   - **sign_out(user, cookie_token)**: `h = sha256_hex(cookie_token)`; `await sessions.revoke(h, clock.now())`; then `tx.with_tx(t => audit.append({actor_id: user.user_id, action: "session.sign_out", target_kind: "session", target_id: h.slice(0,16), details: {user_id: user.user_id}, request_id: user.request_id, ...nulls}, t))`.
   - Audit `details` must hold ids only: `PgAuditLog.check_details` rejects email-shaped strings, so never put the email in it.
