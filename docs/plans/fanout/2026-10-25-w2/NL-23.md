3. **`scripts/docker-entrypoint.sh`** (`#!/bin/sh`, `set -eu`):
   1. if `RUN_MIGRATIONS=1`: `npm run db:migrate --silent` (env `DATABASE_URL` already = owner URL for that container). Invariant: only the one-shot `migrate` service holds the owner credential.
   2. if `RUNTIME_DATABASE_URL` is non-empty: `node scripts/apply-runtime-grants.mjs`.
   3. `exec "$@"`. Never echo env. Must exit non-zero if migration fails (`set -e`).
4. **`scripts/apply-runtime-grants.mjs`** (ESM, `import pg from "pg"`, env only, no output of URLs/passwords; prints `{"event":"runtime_grants","role":"<name>"}`). Algorithm:
   1. Parse `DATABASE_URL` (owner) and `RUNTIME_DATABASE_URL`; take role `decodeURIComponent(url.username)`, password `decodeURIComponent(url.password)`. Exit 1 (message names the variable only) if either is missing, or the two usernames are equal (invariant: runtime role must not be the owner), or the role name is not `/^[a-z_][a-z0-9_]*$/`.
   2. Connect as owner; `BEGIN`; `SELECT pg_advisory_xact_lock(hashtext('ls_runtime_grants'))` (concurrent starts serialize).
   3. Create-or-alter: `SELECT format('CREATE ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION PASSWORD %L', $1, $2)` if `pg_roles` lacks it, else `format('ALTER ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION PASSWORD %L', ...)`; execute the returned string (never string-concatenate the password).
   4. `format()`-built statements, in this order: `GRANT CONNECT ON DATABASE <current_database()>`; `GRANT USAGE ON SCHEMA public`; `REVOKE ALL ON ALL TABLES IN SCHEMA public FROM role`; `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO role`; `GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO role`; then `REVOKE UPDATE, DELETE ON` `review_event, audit_event, lesson_metrics, ops_event`; `REVOKE DELETE ON lesson_version`; `REVOKE INSERT, UPDATE, DELETE ON schema_migrations`. TRUNCATE is never granted (step `GRANT` omits it). Constants `APPEND_ONLY = [...]` at top of file.
   5. `COMMIT`. Idempotent (a second run changes nothing visible). Because it runs after every migrate, tables added by later migrations are granted on next start; the drift test (step 12) fails if a later migration adds a guarded table that is not in the list.
5. **Start-event helpers** (three near-identical files; duplication is deliberate, no new shared package: code-design rule "wait for the third case"). Signature in each:
   ```ts
   export interface StartEventOptions { attempts?: number; delay_ms?: number; sleep?: (ms: number) => Promise<void>; }
   export async function write_start_event(settings: WorkerSettings /* CollabSettings | WebSettings */, logger: Logger, opts?: StartEventOptions): Promise<boolean>
   ```
   Algorithm: (1) `const db = new PgDatabase(settings.shared, 1, 2000, "worker")` (`"collab"`, `"web"` respectively; web uses `settings.pg_acquire_timeout_ms`). (2) Up to `attempts` (default 10) tries, `delay_ms` default 500 between: `await record_ops_event(db, { kind: "process_start", service: "worker", build_id: settings.shared.build_id, details: {} })`; success returns `true`. (3) On every failed try wait, never throw. After the last failure `logger.warn("process_start.not_recorded", { extra: { error: e.name } })` and return `false` (a failed write is logged, not fatal). (4) `finally { await db.close() }`. Invariant: nothing but the ids/build id is stored (OBS-7): `details` is `{}`.
