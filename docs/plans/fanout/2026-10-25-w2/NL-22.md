## 5. Steps
1. `state.ts`: types above plus
   - `initial_state<Job extends {unit_id:string}>(job: Job, now: number): LessonJobState<unknown, unknown, unknown, Job>`: all nulls, empty arrays, counters 0, `started_at = now`, `cost_usd = "0"`.
   - `with_brake<S extends {brakes_fired: readonly BrakeName[]}>(s: S, brake: BrakeName): S`: if already included return `s` itself (idempotent); else `{...s, brakes_fired: [...s.brakes_fired, brake]}` (never mutate input).
   - `wall_clock_exceeded(s: {started_at:number}, now: number, limit_ms: number): boolean` = `now - s.started_at > limit_ms` (strictly).
   Tests (5 cases): initial_state fields; with_brake adds; with_brake idempotent; with_brake does not mutate input (`Object.isFrozen` or compare snapshot); wall clock false at exactly limit, true at limit+1.
2. `route-after-checks.ts`: `route_after_checks(i: RouteInput): NextStep`: `if (i.schema_valid && i.compiled && i.check_passed) return "store"; if (i.repair_rounds < i.max_repair_rounds) return "repair"; return "fail";`. Invariant: with max 1 a second repair is impossible. Tests: 8 combos x rounds {0,1} with `max_repair_rounds: 1` generated by nested loops into an `it.each` table inside `describe("table")`; `describe("wp1_one_repair")` with the 3 steps.
3. `failure-reasons.ts`: export `FAILURE_MESSAGES: Record<FailureCheck, string>` (fixed plain English, no braces, e.g. cancelled: "This lesson was cancelled before it finished.", capped: "Generation stopped because a spending limit was reached.", timeout: "This lesson took too long to generate.", truncated: "The draft was cut off twice before it finished.", rate_limited: "The model service was too busy; retries ran out.", provider_error: "The model service returned an error.", compile_error: "The draft could not be turned into a lesson.", schema_invalid: "The draft did not match the lesson format.", check_failed: "The draft failed a required lesson check."). `failure_reasons_for(i)` builds an array in this order, one push per matching row: (a) brake `cancelled` -> cancelled; (b) any of `spend_run_cap|spend_day_cap|spend_project_cap` -> one `capped` (even if several brakes); (c) brake `job_wall_clock` -> timeout; (d) brake `truncation_retry` -> truncated; (e) provider_error `rate_limited|overloaded` -> rate_limited (also ok if brake `rate_limit_retries` present; do not require it); (f) provider_error `timeout` -> timeout; (g) any other non-null provider_error -> provider_error. NOTE (c) and (f) both yield `timeout`: de-duplicate so a `timeout` appears once (order stays first occurrence). (h) `compile_error !== null` -> compile_error (test the null check, an empty string still counts as set); (i) `!schema_valid` -> schema_invalid; (j) `first_failing_kind !== null` -> check_failed with `check_kind`. `circuit_breaker` and `repair_round` brakes add nothing. All other records have `check_kind: null`. `message` always `FAILURE_MESSAGES[check]`; never reads `compile_error` text.
   Tests: 14 single rows = cancelled, spend_run_cap, spend_day_cap, spend_project_cap, job_wall_clock, truncation_retry, rate_limited, overloaded, provider timeout, auth, compile error, invalid schema, failing kind, circuit_breaker-only (-> `[]`); 3 combos: `spend_run_cap`+invalid schema -> `[capped, schema_invalid]`; `cancelled`+compile_error -> `[cancelled, compile_error]`; `job_wall_clock`+provider timeout -> `[timeout]` once. Use a `base` FailureInput `{brakes_fired: [], provider_error: null, schema_valid: true, compile_error: null, first_failing_kind: null}`. `messages_fixed` test per table above.
4. `circuit-breaker.ts`: `TerminalJobView {lesson_id: string; status: "queued"|"running"|"ready"|"generation_failed"|"cancelled"; first_failing_kind: CheckKind|null; finished_at: number /* epoch ms */}`, `PauseDecision {pause: boolean; check: CheckKind|null; lesson_ids: string[]}`, `should_pause_run(recent: readonly TerminalJobView[], threshold: number): PauseDecision`. Steps: (1) keep only status `ready` or `generation_failed`; (2) sort a copy by `finished_at` descending, ties by `lesson_id` ascending (invariant: deterministic; do not mutate input); (3) take first `threshold`; (4) if fewer than `threshold` (or threshold < 1) -> `{pause:false, check:null, lesson_ids:[]}`; (5) pause iff all are `generation_failed` with identical non-null `first_failing_kind`; return `{pause:true, check, lesson_ids: ids in that sorted order}`. Eight tests as in AC-5 (3 same; 2 same+1 different; ready among the three; cancelled ignored (cancelled newest + 3 failing older -> still pause based on the 3, and cancelled + 2 failing -> no pause); fewer than 3; tie-break on finished_at; threshold 2; null kind -> no pause).
