Exact exports:
```ts
export type TransitionAction = "start_review" | "submit" | "withdraw" | "approve" | "request_changes" | "reopen";
export interface TransitionInput {
  action: TransitionAction; role: Role; from_state: LessonState;
  note?: string | null; reason?: string | null; tag?: string | null;
  rating?: Approve["rating"] | null;
}
export interface TransitionDecision {
  allowed: boolean; to_state: LessonState | null;
  refusal: Extract<ErrorCode, "ROLE_FORBIDDEN"|"INVALID_TRANSITION"|"NOTE_REQUIRED"|"REASON_REQUIRED"|"RATING_REQUIRED"> | null;
  writes_snapshot: "submit" | "approve" | "reopen" | null;
  collab_mode_after: CollabMode | null;
}
export function decide_transition(i: TransitionInput): TransitionDecision;
export function transition_roles(action: TransitionAction): Role[];
export function is_editable(state: LessonState, role: Role): boolean;
```

## 5. Steps
1. (Test-writer, before implementation) Write `lesson-machine.test.ts` with describe blocks named exactly `exhaustive`, `role_first`, `precedence`, `decision_fields`, `transition_roles`, `is_editable`; AC-1..3 frozen (manifest + tamper check). The oracle is a literal table of the 9 allowed (role, action, from) rows with to/snapshot/mode, built from the ticket table; loop 6 actions x 8 states x 3 roles x {missing input, input supplied}. Import states/roles as literal arrays in the test (no import of implementation internals). Red for the right reason: module not found/exports missing.
2. Implement `MOVES: Record<TransitionAction, {role: Role; from: readonly LessonState[]; to: LessonState; snapshot; mode; need?: "rating"|"note"|"reason"}>`:
   - start_review: reviewer, [draft], in_review, null, null
   - submit: reviewer, [in_review, changes_requested, reopened], submitted, "submit", "read_only"
   - withdraw: reviewer, [submitted], in_review, null, "editable"
   - approve: approver, [submitted], approved, "approve", null, need rating
   - request_changes: approver, [submitted], changes_requested, null, "editable", need note
   - reopen: approver, [approved, exported], reopened, "reopen", "editable", need reason
3. `decide_transition`: (a) if `i.role !== move.role` return refusal ROLE_FORBIDDEN (protects: wrong role never learns state); (b) if `!move.from.includes(i.from_state)` INVALID_TRANSITION (protects: approve in `in_review` without rating is INVALID, not RATING_REQUIRED); (c) missing input: rating null/undefined -> RATING_REQUIRED; note/reason not a string or `trim()===""` -> NOTE_REQUIRED / REASON_REQUIRED; (d) allowed with the row's fields. `tag` is ignored. Refusal = `{allowed:false,to_state:null,refusal,writes_snapshot:null,collab_mode_after:null}` through one `refuse(code)` helper.
4. `transition_roles(action)` returns `[MOVES[action].role]` (new array each call).
5. `is_editable(state, role)`: `role === "reviewer" && EDITABLE_STATES.includes(state)` with `EDITABLE_STATES = ["in_review","changes_requested","reopened"]` (the only such list in the repo).
6. Header comment: pure, no clock/IO; callers WriteGuard/apply_edit use `is_editable`; pin/four-eyes/blocking/dependency codes belong to services. Never return those codes.
7. Area-map row + devlog entry (Changed / Why / Checked / Remaining).
