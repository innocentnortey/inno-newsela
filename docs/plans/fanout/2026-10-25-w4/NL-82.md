## 5. Steps
Exports of `ops/seed.ts`:
```ts
export interface SeedReport { standards: number; users: number; ops_event_id: string }  // counts of rows INSERTED this run
export interface SeedOptions { env?: Env; standards_dir?: string; credentials_path?: string; build_id?: string }
export class SeedInputError extends Error { constructor(readonly file: string, message: string) }
export async function seed_reference_data(db: PgDatabase, opts: SeedOptions = {}): Promise<SeedReport>
export async function main(env?: Env): Promise<SeedReport>
```
1. **Constants.** `DEMO_ACCOUNTS = [{role:"author",email:"author.demo@example.test",name:"Demo author"}, {role:"reviewer",email:"reviewer.demo@example.test",name:"Demo reviewer"}, {role:"approver",email:"approver.demo@example.test",name:"Demo approver"}]` (same emails the NL-25 harness uses). `SET_FILE = {CA_CCSS_ELA_6:"ccss-ela-6.json", CA_ELD_6:"eld-6.json", MSLS_6:"msls-6.json"}`. Default credentials path: `fileURLToPath(new URL("../.demo/seed-credentials.txt", import.meta.url))` (never cwd-relative).
2. **Validate first (AC-7; invariant: no row written on bad input).** Before any DB call: `try { rows = load_standard_rows(dir) } catch (e) { throw new SeedInputError(<file from message prefix before ":" or "standards">, e.message) }`; then for each row, if `typeof text !== "string" || text.trim() === ""` throw `SeedInputError(SET_FILE[row.set], "<code> has no text")`. Messages name file and code only, never text values. Missing dir/file surfaces from `load_standard_rows`; wrap it the same way.
3. **Resolve the password (OBS-7).** `read_optional_string(env,"SEED_DEMO_PASSWORD")`; if blank/undefined, generate 20 chars with `crypto.randomInt` over `A-Za-z0-9` plus `-_!` and flag `generated = true`. Do this only after step 2 succeeds, and only use it if step 4 will insert at least one user (hash lazily: compute `hash_password(pw)` once per inserted account, never store `pw` in any variable that reaches `details`, a log or `console`).
4. **One transaction** (`db.with_tx`): (a) insert standards, counting `rowCount` per set; (b) `repo.sync_locked_layer(locked_hash(LOCKED_DIR), tx)`, `prompt_inserted = result !== null`; (c) for each demo account, `INSERT INTO app_user (id,email,name,role,synthetic,password_hash) VALUES ($1,$2,$3,$4,true,$5) ON CONFLICT (lower(email)) DO NOTHING`, id from `new PrefixedIdGenerator().new_id("usr")`; count inserted. `synthetic` is the literal `true` here and nowhere else in the codebase writes it (the AC-3 test asserts a signed-up path cannot; `SignInRequest` is strict). Never UPDATE an existing user (a rerun must not change a hash or a flag). If a role already has a row whose email is not in the allow list, do nothing and do not count it.
5. **Credentials file (AC-5).** Only if `generated` and users inserted > 0, after the tx commits: `mkdirSync(dirname, {recursive:true, mode:0o700})`, `writeFileSync(path, lines, {mode:0o600})`, then `chmodSync(path, 0o600)`. Lines: `author.demo@example.test <password>` etc. If env password was supplied, write no file. If the file write fails, throw (the accounts exist but the operator would not know the password; message must not contain it) and tell the operator to drop the three rows and rerun is NOT needed: rerun cannot recover, so write the file BEFORE committing: generate, write file, then run the tx; if the tx throws, delete the file in a `finally`-style cleanup. Use that order.
6. **ops_event (OBS-9).** `new PgEvidenceRepo({db,ids,clock}).ops_event({kind:"seed", service:"seed", build_id, details:{standards_inserted:{CA_CCSS_ELA_6:n,CA_ELD_6:n,MSLS_6:n}, standards_total:{...per set from SELECT count(*) GROUP BY "set"}, prompt_version_inserted: boolean, users_inserted: n, users_total: n}})`. Only numbers and booleans; no emails, passwords, hashes.
7. **`main` + CLI guard** as in `ops/migrate.ts` (`import.meta.url === pathToFileURL(process.argv[1]).href`). Pool as migrate.ts. Success: `console.log(JSON.stringify({event:"seed", standards, users, ops_event_id}))`, exit 0. Failure: `console.error(JSON.stringify({event:"seed_failed", problem, file?}))` (`file` only for `SeedInputError`), exit 1. When a password was generated, additionally print the single line `credentials written to .demo/seed-credentials.txt` (path only). Always `db.close()` in `finally`.
8. **Tests** (write with the code; test-writer freezes first, see section 7). Use `create_test_db`/`TestDb` from `@ls/db/testing/test-db` (one DB per file; call `t.drop()` in `afterAll`). Pass `credentials_path` into a `mkdtemp` dir and `standards_dir` overrides for AC-7 (copy the real three JSON + verdicts file into a temp dir, blank one `text`, or delete one file). AC-5 `git check-ignore -q .demo/seed-credentials.txt` via `execFileSync`, exit 0. AC-4 table scan: for every table in `information_schema.tables` (public) run `SELECT t::text FROM <table> t` and assert no match. AC-8: `vi.spyOn(fs, "readFileSync")` (default `import fs from "node:fs"`), also `readdirSync`, `existsSync`, `statSync`, `openSync`; create a marker file under `docs/source/restricted/` only if the dir exists (it is git-ignored; if absent skip creating) and assert no recorded path matches `/restricted/`. AC-11 `wf-37-obligations.test.ts` one `it` each: `GR-5` (every seeded row text equals the text in the JSON file and none equals a sheet label from `docs/data/samples/*.json` ELD label field if present; at minimum equality with the files), `GR-9` (no `restricted` in `ops/seed.ts`, no fs path under it), `GR-13` (no table other than `standard, prompt_version, app_user, ops_event` gained rows; app_user count 3 all `synthetic`), `OBS-11` (`docs/design/observability.md` contains a `| WF-37 |` row and `scripts/script-targets.json` maps `db:seed` to `ops/seed.ts`).
9. **Web-side AC-3 test** `apps/web/src/server/http/seeded-accounts.int.test.ts`: `create_test_db()`, `execFileSync("npx", ["tsx","ops/seed.ts"], {cwd: repo_root, env:{...process.env, DATABASE_URL: t.url, SEED_DEMO_PASSWORD:"<test-seed-password>"}})` (the real entry; the web app may not import `ops`), then build `SessionService` the way `make_harness()` does (read `session-harness.ts` L55-80; copy the wiring, do not import the harness because it inserts its own users) and for each role call the sign-in method with the seeded email and password; assert returned `session.user.role` equals the role and `synthetic === true`. Use the actual sign-in method name found in `apps/web/src/server/services/session-service.ts` (read it; do not guess).
