### 4.2 Real CON-12 wire shapes (copied from `apps/collab/src/acks.ts`, `permissions.ts`, `auth.ts`)

Stateless messages, JSON strings, received in `HocuspocusProvider` `onStateless({ payload })`:

```ts
// stored  (AckBroadcaster.stored)
{ type: "stored", content_hash: string /*64 hex*/, state_vector: string /*base64*/, stored_at: string /*ISO date-time*/ }
// mode    (AckBroadcaster.mode / mode_to; ModeMessage = { mode: CollabMode; state: LessonStateName })
{ type: "mode", mode: "editable" | "read_only", state: "draft"|"in_review"|"changes_requested"|"submitted"|"approved"|"reopened"|"exported"|"generation_failed" }
// refused (AckBroadcaster.refused)
{ type: "refused", code: "LESSON_LOCKED", message: string, refused_from: string /*base64 state vector before the refused updates*/ }
```
The server sends `mode` to a socket right after it connects (`connected` hook), so the first `mode` tells the client whether it can write. `mode: "read_only"` also flips `connection.readOnly` on the server; the provider's `onAuthenticated({ scope })` is `"readonly"` or `"read-write"` too (use both: whichever says read-only wins).

Auth (`CollabAuthenticator.authenticate`): the server reads ONLY the `ls_session` cookie from the WebSocket upgrade request headers (`cookie_value(req.cookie_header, settings.session_cookie_name)`). `token` is never an identity (`token_param` "never an identity") but Hocuspocus will not run `onAuthenticate` for a client that sends no token, so **the browser client must send a non-empty token**. Use the constant `"session-cookie"` (a literal placeholder; never read `document.cookie`, the cookie is HttpOnly). Document name must match `/^lesson:(.+)$/`. A failed authentication throws `DomainRefusal` (no `.reason`), so the provider receives `onAuthenticationFailed({ reason: "permission-denied" })` for UNAUTHENTICATED and NOT_FOUND alike: the editor cannot tell them apart and treats every authentication failure as "signed out or no access" (Open item 2).

The NL-24 mock (`mocks/collab-mock.ts`) differs in two ways the editor must tolerate:
- cookie refusal happens in `onConnect` and closes the socket with code 4401 (`Unauthorized`) instead of sending an auth failure → handle `onClose` with `event.code` 4401 or 4403 as the same "signed out" signal;
- after lock, every sync step 2 / update gets a `refused` message, including the empty step 2 of a fresh client, and new connections to a locked doc get no `mode` message → the first `refused` is latched; later `refused` messages are ignored once the editor is in the refused state.

**5.1 `src/editor/messages.ts`**
```ts
export type CollabMode = "editable" | "read_only";
export interface StoredMessage { type: "stored"; content_hash: string; state_vector: string; stored_at: string }
export interface ModeMessage { type: "mode"; mode: CollabMode; state: string }
export interface RefusedMessage { type: "refused"; code: "LESSON_LOCKED"; message: string; refused_from: string }
export type CollabMessage = StoredMessage | ModeMessage | RefusedMessage;
export function parse_collab_message(payload: string): CollabMessage | null;
```
`parse_collab_message`: `JSON.parse` in try/catch → `null` on any failure; accept only objects with the exact `type` values and string fields as above (`mode` must be `"editable"` or `"read_only"`; `code` must equal `"LESSON_LOCKED"`; an unknown `type` or a missing/non-string field → `null`). Never throws, never evaluates anything. Also export `b64_to_bytes(s: string): Uint8Array` and `bytes_to_b64(u: Uint8Array): string` (use `atob`/`btoa` with a loop; no Buffer, this runs in the browser; Node 24 has both globals so tests work).

**5.2 `src/editor/client-state.ts`** (pure, no I/O)
```ts
export type EditorClientState = "connecting" | "synced" | "saving" | "stored" | "DISCONNECTED" | "read_only";
export interface StoredAck { content_hash: string; state_vector: string; stored_at: string }
export interface ClientInputs {
  ever_connected: boolean;     // provider reached "connected" at least once
  connected: boolean;          // provider status is "connected" now
  synced: boolean;             // provider reported synced since the last connect
  read_only: boolean;          // prop, mode message, provider scope or refusal
  dirty: boolean;              // a local edit exists that no stored ack covers yet
}
export function derive_client_state(i: ClientInputs): EditorClientState;
export function covers(stored_sv: Uint8Array, local_sv: Uint8Array): boolean;
```
`derive_client_state` order (first match wins): `read_only` → "read_only"; `!ever_connected` → "connecting"; `!connected` → "DISCONNECTED"; `!synced` → "connecting"; `dirty` → "saving"; else "stored" is NOT derived here (stored needs an ack): return "synced". The caller (5.4) upgrades "synced" to "stored" when `last_stored !== null && !dirty && last_stored covers everything the user typed`; keep that rule inside `CollabSession.report()` (5.4 step 7) so this function stays pure. Invariant protected: Submit must stay off for `saving` and `DISCONNECTED`.
`covers(stored_sv, local_sv)`: decode both with `Y.decodeStateVector` (Map<clientId, clock>); true iff for every `[client, clock]` of local, `(stored.get(client) ?? 0) >= clock`. Invariant: an ack counts only when it includes every local operation.

**5.3 `src/editor/refusals.ts`** (the DO-4 `apply_refusal`, adapted: the ticket says drop by discarding local state, not by UndoManager, because an undo would itself be a new update to send)
```ts
export interface RefusalOutcome { dropped_updates: number; refused_text: string[]; read_only: true }
export interface EditorHandle {
  doc: Y.Doc;                       // the local doc holding the refused edits
  discard_local_state(): void;      // destroy provider + doc, build a fresh doc/provider that only RECEIVES the server state
  set_read_only(): void;
}
export function apply_refusal(editor: EditorHandle, msg: RefusedMessage): RefusalOutcome;
```
Steps inside `apply_refusal`, in this order:
1. `const from = b64_to_bytes(msg.refused_from)`.
2. `const refused = Y.encodeStateAsUpdate(editor.doc, from)`: everything the local doc has beyond the server's state at the refusal = the refused local edits.
3. `const { structs } = Y.decodeUpdate(refused)`. `dropped_updates = structs.length`. `refused_text` = for each struct in order, if `(struct as { content?: { str?: unknown } }).content?.str` is a non-empty string, push it (these are the typed characters; `ContentString.str`). Truncate nothing here.
4. `editor.discard_local_state()` (so the refused operations can never be sent: they live only in the destroyed doc), then `editor.set_read_only()`.
5. return `{ dropped_updates, refused_text, read_only: true }`.
If `b64_to_bytes` or decoding throws (malformed message), still do step 4 and return `{ dropped_updates: 0, refused_text: [], read_only: true }`: fail closed, never keep the refused edits. Never mutate `msg`.

1. 2. Set awareness local state once connected: `provider.awareness.setLocalStateField("user", { name, initials, slot })`. Use ONLY `user` and `section` fields (set `section` in 5.8). Never put colours (hex) in awareness: send the slot number, the CSS maps it to `var(--color-presence-N)`.
3. Track `ever_connected`, `connected` from `onStatus`; `synced` set true in `onSynced`, set false when status leaves "connected". Invariant: `DISCONNECTED` only after having connected once (a first failed connect stays `connecting`).
4. Dirty tracking: `doc.on("update", (_u, origin) => { if (origin !== provider) { dirty = true; pending_sv = Y.encodeStateVector(doc); } })`. Local edits (origin is the y-sync plugin key) set dirty; remote updates (origin is the provider) do not. Invariant: "Saving…" only for the person's own edits.
5. `onStateless({ payload })` → `parse_collab_message`:
   - `stored`: remember it as `last_stored`; if `pending_sv !== null && covers(b64_to_bytes(msg.state_vector), pending_sv)` then `dirty = false`. Invariant: only an ack that covers the last local edit clears "saving".
   - `mode`: `mode_state = msg.state`; `mode_read_only = msg.mode === "read_only"`; recompute `read_only` = prop ∥ mode ∥ scope ∥ refused. A `mode: "editable"` message clears only the mode part (unfreeze: Withdraw, Request changes, Reopen), never a prop/role/refusal part; after a refusal the session stays read-only (the page reloads the editor on unfreeze; Open item 3).
   - `refused`: if already `refused` latched → ignore. Else `apply_refusal(handle, msg)` with the handle from step 9; store `refusal = { message: <editor's own notice text from 5.10, not the server text>, text: outcome.refused_text, dropped: outcome.dropped_updates }`.
   - `null` (unknown): ignore silently.
6. `onAuthenticated({ scope })`: `scope === "readonly"` → `scope_read_only = true` (else false).
7. `snapshot()` computes `state`: `inputs = {ever_connected, connected, synced, read_only, dirty}`; `s = derive_client_state(inputs)`; if `s === "synced" && last_stored !== null && !dirty && covers(b64_to_bytes(last_stored.state_vector), Y.encodeStateVector(this.doc))` → `"stored"`; wait: remote edits can make local SV larger than the ack; for that case use `pending_sv` instead of the whole doc: `stored` iff `last_stored` was received after the last local edit, i.e. keep a boolean `stored_since_edit` set true in step 5 when dirty clears and set false in step 4. So: `s === "synced" && stored_since_edit` → `"stored"`. `state_vector` = base64 of `Y.encodeStateVector(this.doc)`, `null` until `synced` once.
8. Signed-out detection: `onAuthenticationFailed` (any reason) OR `onClose` with `event.code` in `{4401, 4403}` while `!ever_synced` → `signed_out = true`; then call `provider.configuration.websocketProvider.disconnect()` / `provider.destroy()` so it stops retrying. Invariant: no empty document is shown for a refused socket. (Real server: `UNAUTHENTICATED` and `NOT_FOUND` both arrive as authentication failures. Mock: close code 4401.)
9. Refusal handle: `discard_local_state()` = unsubscribe listeners from the old doc, `provider.destroy()`, `doc.destroy()`, then create a NEW `Y.Doc` and a NEW provider (same step 1 options, `read_only` forced true, and an `onStateless` handler that ignores further `refused` messages), then notify subscribers (the React layer re-binds the views to the new doc, which only receives the server state). `set_read_only()` sets `refused = true`. Invariant: the refused operations exist only in the destroyed doc; a fresh doc has nothing to send, so nothing is ever re-sent (the mock re-sends `refused` for the fresh doc's empty step 2: ignored by the latch).
10. `destroy()`: remove listeners, `provider.destroy()`, `doc.destroy()`. Idempotent.
