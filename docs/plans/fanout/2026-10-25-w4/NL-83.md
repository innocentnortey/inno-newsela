## 5. Steps

The three `health.ts` cores are deliberately duplicated (apps may not import each other; NL-23 precedent). Keep them identical in behaviour.

**Core shape (same in each app).** In each app's health file define:

```ts
export interface HealthDb { ping(): Promise<boolean>; with_tx: PgDatabase["with_tx"] }   // PgDatabase satisfies it
export interface HealthOptions { build_id: string; logger: Logger; now?: () => number; ping_timeout_ms?: number /* default 3000 */; throttle_ms?: number /* default 60_000 */ }
export interface HealthResult { status: 200 | 503; body: { status: "ok"; service: string; build_id: string } | { status: "unavailable"; service: string }; request_id: string }
export function create_health_check(db: HealthDb, service: string, opts: HealthOptions): (request_id_in?: string) => Promise<HealthResult>;
```

`create_health_check` algorithm (each numbered step protects an invariant):
1. `request_id` = incoming `x-request-id` if it matches `/^[A-Za-z0-9_-]{8,64}$/`, else `randomUUID()` (node:crypto). Invariant: OBS-3, and no attacker-chosen text reaches logs.
2. `ok = await Promise.race([db.ping(), timeout(ping_timeout_ms) resolving false])` inside try/catch (any throw means false). The handler never throws.
3. If ok: return 200 with exactly `{status:"ok",service,build_id}`. No event, no log. Invariant: AC-1.
4. If not ok: let `t = now()`. If `last_event_at === null || t - last_event_at >= throttle_ms`, set `last_event_at = t` **synchronously, before any await** (two concurrent failures must produce one event), then `await record_ops_event(db, {kind:"health.failure", service, build_id, details:{}})` in try/catch. On catch: `logger.error("health.event_write_failed", {request_id, extra:{error: e instanceof Error ? e.name : "Error"}})` (exactly one line, error name only, never the message). Invariant: AC-2, and OBS-7 (messages can carry connection strings).
5. Return 503 with exactly `{status:"unavailable",service}`. Invariant: no connection string, env value or version in the body.

State (`last_event_at`) lives in the closure, so it is per process. A stamp set when the write fails still throttles: a down database must not turn every probe into a write attempt.

**Step 11. `ops/backup.sh`** (bash, `#!/usr/bin/env bash`, `set -euo pipefail`, executable bit set). Steps in order, each with its invariant:
1. `cd "$(dirname "$0")/.."`; `[ -n "${DATABASE_URL:-}" ] || { echo "backup: DATABASE_URL is not set" >&2; exit 2; }`. Nothing else runs first. (AC-7: no file, no event.)
2. Parse `DATABASE_URL` into env vars without argv: run `node -e '...'` that reads `process.env.DATABASE_URL`, parses with `new URL`, and prints NUL-separated `user`, `password`, `host`, `port`, `dbname` (URL-decoded); read them with `IFS= read -r -d ''`. The URL is never in argv. Export `PGUSER PGPASSWORD PGHOST PGPORT PGDATABASE` (never put them on a command line; `export` is a shell builtin, so it is not visible in `ps`). Require protocol `postgres:` or `postgresql:`, else exit 2.
3. `umask 077; mkdir -p backups; chmod 700 backups`. The dump directory is **fixed** at `<repo>/backups` (no `BACKUP_DIR` override, so it can never point into `apps/web/public` or any served path). File name `backups/ls-<UTC yyyymmddThhmmssZ>-<8 random hex>.dump` (uses `date -u` and `od`/`openssl`-free: `$(head -c4 /dev/urandom | od -An -tx1 | tr -d ' \n')`).
4. Dump. Two modes, chosen by env, defaulting to the host tools:
   - Host mode (default, needs `pg_dump` and `pg_restore` on PATH): `pg_dump --format=custom --file "$out"` (connection comes from the exported `PG*` vars). If `pg_dump` is missing and `BACKUP_DOCKER_CONTAINER` is unset, print `backup: pg_dump not found (install postgresql-client or set BACKUP_DOCKER_CONTAINER)` and exit 3. This VPS has **no** host `pg_dump`; the tests use container mode.
   - Container mode (`BACKUP_DOCKER_CONTAINER` set, for example `newsela-test-postgres-1` or the Compose postgres container): `docker exec -i -e PGPASSWORD -e PGUSER -e PGDATABASE "$BACKUP_DOCKER_CONTAINER" pg_dump --format=custom > "$out"`. `-e NAME` with no value forwards the value from the environment, so the password is not in argv. Do **not** pass `PGHOST`/`PGPORT` (inside the container the unix socket is used). The `docker` binary is `${BACKUP_DOCKER:-docker}` (word-split not allowed; a single command name only).
   - On any non-zero status: `rm -f "$out"`, print `backup: dump failed` (no details), exit 1. Never write an event.
5. `chmod 600 "$out"`.
6. Verify: host mode `pg_restore --list "$out" >/dev/null`; container mode `docker exec -i "$BACKUP_DOCKER_CONTAINER" pg_restore --list < "$out" >/dev/null`. On failure: `rm -f "$out"`, print `backup: verification failed`, exit 1, no event. Also require the listing be non-empty.
7. `size=$(stat -c %s "$out")`, `sha=$(sha256sum "$out" | cut -d' ' -f1)`.
8. Record: `npx tsx ops/record-event.ts backup ops "{\"path\":\"backups/$(basename "$out")\",\"size\":$size,\"sha256\":\"$sha\"}"`. The path in the event is **relative** (`backups/<name>`). If recording fails, keep the file, print `backup: event not recorded` and exit 1 (the dump is real but unaudited; the operator must know).
9. Print one line `backup ok backups/<name> <size> <sha>` and exit 0.
Never `set -x`, never `echo` any `PG*` variable, never write `DATABASE_URL` anywhere.
