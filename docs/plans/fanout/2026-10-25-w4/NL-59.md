## 5. Steps
Dependency direction: `app page → progress-screen → {hooks, banners, controls, tiles} → src/lib + components/ui`; nothing in
`src/lib` or `components` imports from `features/progress`. Pure logic (`backoff`, `announcements`, `run-copy`) has no React and no
network, so it is tested without a DOM. The network is only in `use-run-progress`, `use-calls-lost`, `control-bar`.

1. **`backoff.ts`**: `export class BackoffSkip extends Error {}`; `export function backoffMs(failures: number): number { return Math.min(2000 * 2 ** failures, 10000); }` (1→4000, 2→8000, 3+→10000).
2. **`use-run-progress.ts`** (`"use client"`). `export function useRunProgress(runId: string): UsePollResult<RunProgress> & { notFound: boolean }`.
   - Refs: `failures`(0), `nextAttemptAt`(0). Invariant: a poll tick during backoff makes no request and throws `BackoffSkip`, so
     `usePoll`'s own clock still marks the data stale >10 s after the last success (a sleep inside the fetcher would delay that).
   - Fetcher: `if (Date.now() < nextAttemptAt.current) throw new BackoffSkip();` then `try { const { data } = await api.GET(...); if (!data) throw new Error("empty"); failures.current = 0; nextAttemptAt.current = 0; return data; } catch (e) { failures.current += 1; nextAttemptAt.current = Date.now() + backoffMs(failures.current); if (isApiError(e) && e.code === "NOT_FOUND") setNotFound(true); throw e; }`
     (`notFound` also from `useState`). `NOT_FOUND` passes `enabled=false`.
   - `const terminal = data && (["complete","cancelled","capped"] as const).includes(data.state)`. Call `usePoll(fetcher, { enabled: !terminal && !notFound })`. Terminal states stop the poll (data stays); `partial` and `paused` keep polling (a control can restart them).
   - Reset the refs when `runId` changes (effect on `runId`).
   - Return `{ ...poll, notFound }`. Unmount safety comes from `usePoll`; do not add timers of your own.
3. **`use-calls-lost.ts`**: `useCallsLost(runId, state: RunState | undefined): number` : effect keyed on `[runId, state]`; if `state` is undefined return; `api.GET(summary)` → `setN(data.calls_lost_in_flight)`; errors ignored (the line just stays hidden); `alive` flag on cleanup. One request per state change, never polled.
4. **`announcements.ts`** (pure + one hook).
   - `describeChanges(prev: RunProgress | undefined, next: RunProgress): string[]`: `prev` undefined → `[]` (nothing is announced for the first load). For each tile with `tile_state === "ready"` whose previous tile (same `lesson_id`) was not ready, push `Lesson ${tile.number ?? tile.lesson_key} is ready` (one → that sentence; several → one sentence `Lessons 4, 5 and 7 are ready`, with "and" before the last). If `prev.state !== next.state`, push the state sentence: complete → `Run complete: ${ready} of ${total} ready.`; partial → `Run partial: ${failed} of ${total} failed.`; paused → `Run paused.`; capped → `Run capped.`; cancelled → `Run cancelled.`; other states: nothing.
   - `useRateLimitedAnnounce(minGapMs = 5000)`: wraps `useAnnounce()`. `say(messages: string[])`: join with " "; if `now - lastAt >= minGapMs` announce now, else keep the latest text as pending and flush it with one `setTimeout` at `lastAt + minGapMs`; clear the timer on unmount. Invariant: at most one message per 5 s and no growing queue.
   - In `progress-screen.tsx` keep `prevRef`; on each new `data` (effect on `data`), `say(describeChanges(prevRef.current, data))` then `prevRef.current = data`.
5. **`run-copy.ts`** (pure). Exact exports:
   - `formatUsd(n: number): string` → `$${n.toFixed(2)}`.
   - `CONTROLS_BY_STATE`: `availableControls(state: RunState): ("cancel"|"retry_failed"|"resume")[]` : planning/running → `["cancel"]`; paused → `["resume","cancel"]`; partial → `["retry_failed"]`; complete/capped/cancelled → `[]` (matches the OpenAPI text on `controlRun`).
   - `failureLine(tile: Tile): string`: no reasons → `Failed`; first reason `check === "truncated"` → `tile.truncation_retry_used ? "Failed: truncated (retried once with a bigger limit)" : "Failed: truncated"`; else `(tile.repair_used ? "Failed after 1 repair: " : "Failed: ") + reasons.map(r => r.message).join("; ")`.
   - `pausedSentence(p: RunProgress): string`: `Run paused: ${n} lessons in a row failed the same check (${reason}). Read the failures, then resume.` where `n = paused_reason.lesson_ids.length`, `reason` = message of the first failure reason of the first tile whose `lesson_id` is in `paused_reason.lesson_ids`, fallback `paused_reason.check`.
   - `controlErrorText(action)`: cancel → `Couldn't cancel. Nothing changed. Try again.`; retry_failed → `Couldn't retry. Nothing changed. Try again.`; resume → `Couldn't resume. Nothing changed. Try again.`.
   - `unitLabel(unitKey)`: `unitIdFromKey` → "G6.U4" → `Grade 6 · Unit 4`; fallback `unitKey`.
6. **`cost-meter.tsx`**: props `{ spent: number; reserved: number; cap: number }`. Visible text `${formatUsd(spent)} of ${formatUsd(cap)} cap`; below it, when `reserved > 0`, `text-small text-ink2` "$X reserved for calls in flight". Bar: `<div role="meter" aria-label="Spend against the run cap" aria-valuemin={0} aria-valuemax={cap} aria-valuenow={spent} aria-valuetext={same sentence}>` track `bg-well rounded-full h-2`, fill `bg-primary h-2 rounded-full` with inline `style={{ width: pct + "%" }}` (pct clamped 0–100; cap 0 → 0). Tokens only.
7. **`control-bar.tsx`** (`"use client"`): props `{ runId, state, role, onChanged: () => void }`.
   - `role !== "author"` → `<RoleNote>Only authors can control a run</RoleNote>` and return (no buttons rendered at all).
   - Buttons for `availableControls(state)`: "Cancel run" (`variant="danger"`), "Retry failed" (`primary`), "Resume" (`primary`). Empty list → render nothing.
   - Cancel flow: clicking "Cancel run" sets `confirming=true` and swaps in `<div role="group" aria-label="Confirm cancel">` with text `Cancel the run? Calls in flight will finish; no new calls start.` and buttons **Cancel run** (danger, performs the request) and **Keep running** (secondary, `confirming=false`). Move focus to "Keep running" on open (safe default).
   - Request: `setBusy(action)` (button `loading`); `await api.POST("/runs/{runId}/actions", …)`; on success `setError(null)`, `confirming=false`, `onChanged()` (the screen calls `poll.retry()` so "the next poll shows the real state"; the UI never assumes the new state). On error: `isApiError(e) && e.code === "ROLE_FORBIDDEN"` → `{kind:"forbidden", message: e.message}` (`ForbiddenBanner`, server's sentence); otherwise `{kind:"failed", text: controlErrorText(action)}`; for `INVALID_TRANSITION` also call `onChanged()` to re-read progress.
