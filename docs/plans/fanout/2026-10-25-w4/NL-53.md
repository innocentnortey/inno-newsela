## 5. Steps
**Step 1: `approve-service.ts`.** Export `ApproveApi { approve(user, lesson_id, req: Approve-shaped): Promise<TransitionResult> }` and
```ts
export class ApproveService implements ApproveApi {
  constructor(
    states: LessonStateRepo, versions: LessonVersionRepo, graph: LessonGraphRepo, issues: IssueRepo,
    suggestions: SuggestionRepo, loader: CheckContextLoader, metrics: MetricsWriter, tx: TxRunner, clock: Clock,
    settings: Pick<WebSettings, "four_eyes_enabled">, rules: CheckRuleList = CHECK_RULES, policy: CheckPolicy = CHECK_POLICY)
```
`approve` runs ONE `tx.with_tx(async (tx) => ...)`:
1. `row = states.lock_for_update(lesson_id, tx)` (invariant: concurrent approves serialize; AC-12).
2. `d = decide_transition({action:"approve", role:user.role, from_state:row.state, rating:req.rating})`; if not allowed throw `DomainRefusal(d.refusal, ...)` (second approver sees `approved` -> INVALID_TRANSITION).
3. `snap = versions.latest_snapshot(lesson_id)`; pin ok only if `snap !== null && snap.kind === "submit" && snap.content_hash === req.snapshot_hash && snap.state_vector === req.snapshot_state_vector`; else `DomainRefusal("STALE_PIN", "...", {request_id: user.request_id})`. (Never read the live row or the client's view of blocking issues.)
4. `ctx = loader.load(lesson_id, snap.lesson, snap.content_hash)`; `result = run_checks(ctx, rules, policy)`; `issues_merged = merge_resolutions(result.findings, await issues.resolutions_for(lesson_id))`.
5. `GateState {action:"approve", issues: issues_merged, pending_check:false, pending_suggestions:(await suggestions.pending_for(lesson_id, clock.now())).length, open_confirmations: issues_merged.filter(i=>i.level==="confirmation" && !i.resolved).length, last_editor_id: row.last_editor_id, approver_id: user.user_id, four_eyes_enabled: settings.four_eyes_enabled, dependencies: await graph.dependencies(lesson_id)}`; `g = approve_gate(state)`; if `!g.allowed` throw `DomainRefusal(g.refusals[0], msg, g.details)` (the gate already ranks FOUR_EYES, SUGGESTION_PENDING, BLOCKED, CONFIRMATION_OPEN, DEPENDENCY_UNAPPROVED).
6. `dependency_record = state.dependencies.filter(waits_on && source_approved_hash !== null).map(d => ({lesson_id: d.lesson_id, approved_hash: d.source_approved_hash}))`.
7. `v = versions.write_snapshot({lesson_id, kind:"approve", lesson:snap.lesson, content_hash:snap.content_hash, state_vector:snap.state_vector!, dependency_record, created_by:user.user_id}, tx)`; `states.set_state(lesson_id, "approved", row.reviewer_id, tx)`; `ev = states.append_review_event({lesson_id, version_id:v.version_id, from_state:"submitted", to_state:"approved", actor_id:user.user_id, reason:null, reason_tag:null, note:null, content_hash:v.content_hash, request_id:user.request_id}, tx)`; `m = metrics.write_first_approval(lesson_id, v, req.rating, tx)`.
8. Return `TransitionResult {lesson_id, from_state:"submitted", to_state:"approved", version:{version_id, version_number:v.number, content_hash:v.content_hash, state_vector:v.state_vector}, audit_id: ev.review_event_id, dependency_record, metrics_row_written: m.written}`.
No collaboration call. Throwing before step 7 rolls back; write nothing earlier than step 7. No logging in the service (with_route writes the one `route.refused` line with request_id and code). Never log notes or lesson text.

**Step 2: `transition-service.ts`.** `TransitionApi { transition(user: RequestUser, lesson_id: LessonId, req: TransitionRequestInput): Promise<TransitionResult> }`;
```ts
export class TransitionService implements TransitionApi {
  constructor(states: LessonStateRepo, versions: LessonVersionRepo, approvals: ApproveApi, collab: CollabCommands, tx: TxRunner, logger: Logger)
```
`transition` (CON-18 precedence, in this order):
1. `if (!transition_roles(action).includes(user.role)) throw ROLE_FORBIDDEN`.
2. `row = states.get(lesson_id)`; null -> `NOT_FOUND` with `{lesson_id}`.
3. `decide_transition({action, role:user.role, from_state:row.state, note, reason, tag, rating})`; refused -> `DomainRefusal(refusal)`. (Note `withdraw` note and `submit` need nothing extra; `request_changes` passes `note: req.note`.)
4. Per action:
 - `start_review`: one `tx.with_tx`: re-lock (`lock_for_update`), re-decide, `set_state(lesson_id,"in_review",user.user_id)`, `append_review_event`. No collab call.
 - `submit`: no tx. `await collab.lock_and_snapshot({lesson_id, actor:{user_id:user.user_id,name:user.name,role:user.role,synthetic:user.synthetic}, client_state_vector:req.client_state_vector, request_id:user.request_id})`. Let `DomainRefusal` (NOT_STORED, BLOCKED, CONFIRMATION_OPEN, SUGGESTION_PENDING, LESSON_LOCKED, INVALID_TRANSITION) propagate unchanged (same code and details). `CollabUnavailable` -> `DomainRefusal("COLLAB_UNAVAILABLE", ..., {lesson_id})`. Build result from `SnapshotResult` (`audit_id = review_event_id`, `version` from its fields). Web writes nothing.
 - `approve`: `return approvals.approve(user, lesson_id, req)`.
 - `withdraw` / `request_changes` / `reopen`: ONE `tx.with_tx`: `locked = lock_for_update`; re-decide on `locked.state` (refusal -> throw); for `reopen` only: `src = versions.latest_snapshot(lesson_id)` (must be kind `approve`, else `InvariantViolation`), `v = write_snapshot({kind:"reopen", lesson:src.lesson, content_hash:src.content_hash, state_vector:src.state_vector!, dependency_record:[], created_by:user.user_id}, tx)` (the repo sets `derived_from_version_id`); `set_state(to_state, locked.reviewer_id)`; `append_review_event({... from_state, to_state, reason: reopen reason or null, reason_tag: request_changes tag or null, note: withdraw/request_changes note or null, version_id, content_hash, request_id})`; THEN `collab.set_mode({lesson_id, mode:"editable", state:to_state, request_id:user.request_id})` as the LAST statement inside the callback; set a local flag `mode_set = true` after it returns.
   - catch around the whole `with_tx`: a `CollabUnavailable` thrown by `set_mode` -> convert to `DomainRefusal("COLLAB_UNAVAILABLE", ..., {lesson_id})` (the throw inside the callback rolls the tx back). If an error surfaces while `mode_set === true` (commit failed after set_mode): best-effort `await collab.set_mode({lesson_id, mode:"read_only", state: locked_from_state, request_id}).catch(() => undefined)`, then `logger.error("transition.commit_failed_after_set_mode", {request_id, lesson_id, extra: new InvariantViolation("commit_failed_after_set_mode", {action})})`, then rethrow the original error.
 - Version in results for moves with no new snapshot (`start_review`, `withdraw`, `request_changes`): `versions.latest_snapshot(lesson_id) ?? versions.version(row.current_version_id)`; `state_vector` null -> `""` (see Open items).
5. `audit_id` is always the move's `review_event` id.
Invariants: refused call writes nothing; one lesson per call; service never writes lesson content.
