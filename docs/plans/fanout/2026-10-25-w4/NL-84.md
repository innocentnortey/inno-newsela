## 5. Steps

1. **Case-file format and loader** (`case-files.ts`). A case file is JSON:
   `{ "case_id", "provenance", "source", "guards", "input": {...}, "expected": {...}, "note"?: string }`.
   `load_cases(dir_abs, suite_prefix): EvalCase[]` reads `*.json` in sorted file-name order and builds `EvalCase` with `input_path` = the repo-relative path. It throws `InvariantViolation` (from `@ls/core/errors`) if `provenance` is not one of the 4 allowed values or `source`/`guards` is a blank string, or if `case_id` differs from the file name. Resolve the cases dir from `import.meta.dirname` (`../../cases/s1`). Invariant protected: a case without provenance can never be scored.
2. **S1 grid selection** (`s1-support.ts`). The case `input` is one of:
   - `{ "grid": "issued" }`, `{ "grid": "syn2" }`, `{ "grid": "syn3" }` (the three loaders)
   - `{ "grid": "rows", "sheet_rows": [n,...] }` (`grid_from_rows`; `[4,4]` for the duplicate case)
   - `{ "grid": "rows", "sheet_rows": [4], "blank_header_prefix": "designated eld" }`: after `grid_from_rows`, replace in the header row (index 1) every cell whose lowercase starts with that prefix by `"x"`, as measured in the planner's check.
3. **S1 projection and scoring.**
   - Run `normalize_outline(grid, load_standards_index(), 200)`. If it throws `IntakeError`, the outcome is `passed false`, `failure_category "intake_refused"`, `actual { refused: err.code }`.
   - If `options.mutate` is set (test hook), apply it to the outline before the report is built.
   - Build the report once with `build_validation_report`.
   - Build `actual` from fixed-order projections. The projection is chosen by which keys the case's `expected` holds; each key below is a pure function over (outline, report):
     - `counts` (the report's `counts` object, all 13 fields)
     - `generate_allowed`
     - `defect_kinds` (an object with the 7 kinds in the fixed order above, each the number of findings of that kind)
     - `unit_as_written`, `unit_from_filenames`
     - `nonexistent_findings`
     - `eld_mismatch_whole_code_set` (sorted distinct codes from `eld_mismatch` findings, parsed with `/ELD\.P(?:I|II)\.\d+\.?\d*[a-z]?/` on `original_text`, minus ELD.PI.6.6 and ELD.PI.6.7)
     - `eld_partial_code_label_mismatches` (a code to count object for those two codes)
     - `row_index` (array of `{row_number, kind, lesson_id}` in row order)
     - `row` (a detail object for one `row_number`: `lesson_id, lesson_type, focus_codes, eld_codes, vocabulary_count`)
     - `same_rows_as_issued` (SYN-2 only; see step 5)
     - `row_report` (WP-5 only: `{row_number, level, finding_count}` from the report row, plus `lesson_id, lesson_type, focus_codes, vocabulary_count, has_editor_note`)
   - Compare each expected key with `JSON.stringify` after a key-sorted canonical stringify. `passed` = all equal. `failure_category` = `"expected_field_mismatch"` on the first mismatch, else `null`. Put the list of mismatched keys in `actual.mismatched_fields` **only when it is non-empty** (so passing runs stay identical). `cost_usd: new Decimal(0)`.
   - Two runs are byte-identical because nothing here reads time, random numbers or the network. Use a canonical stringify (sorted keys) for both the comparison and the identity test.
