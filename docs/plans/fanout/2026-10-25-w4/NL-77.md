3. **`outline-choices.ts`** (pure, no I/O; < 200 lines). Exports:
   ```ts
   export interface ChoiceTarget { kind: "finding"; finding: IntakeFinding } | { kind: "segment"; row_number: number; index: number; segment_kind: string } | { kind: "unit_rule"; index: number }
   export function find_target(outline: NormalizedOutline, target_id: string): ChoiceTarget | null
   export function stored_default(outline: NormalizedOutline, t: ChoiceTarget): string
   export function validate_choice(req: IntakeChoiceRequest, t: ChoiceTarget, ctx: { outline: NormalizedOutline; standards: StandardsIndex; unit_id: string }): string   // returns the string to store in intake_choice.choice, or throws DomainRefusal("INVALID_CHOICE", msg, { reason })
   ```
   `find_target`: finding id match first; else `/^S(\d+)\.(\d+)$/` -> row with that `row_number` having `segments[index]`; else `/^unit_rule:(\d+)$/` with index < `outline.unit_rules.length`; else `null` (caller throws `NOT_FOUND` "That item is not in this outline.", details `{ target_id }`). Segment kinds come from `row.segments[i].kind` (`content|writer_task|editor_note|unit_rule|safety_note`).
   Kind rules (value -> stored string; reasons are the exact `details.reason` strings):
   | kind | target must be | value | stored | reasons |
   |---|---|---|---|---|
   | `confirm_unit` | finding kind `unit_conflict` | omitted/null (-> `ctx.unit_id`) or a string equal to `UNIT_ID_RE`-valid id | the unit id | `kind_target_mismatch`, `bad_unit_id` |
   | `confirm_fix` | any finding | ignored | `finding.proposed_fix ?? finding.default_choice ?? "confirmed"` | `kind_target_mismatch` if target is not a finding |
   | `edit_fix` | finding kind in `malformed_code`,`nonexistent_code`,`parent_code` | string; `standards.text_of(value) !== null` | the trimmed code | `kind_target_mismatch`, `value_required`, `unknown_standard_code` |
   | `set_note_action` | segment whose kind is not `content` | `apply`\|`show_only`\|`ignore` | that string | `kind_target_mismatch`, `segment_not_a_note`, `bad_action` |
   | `change_split` | finding kind `vocabulary_over_cap` | `confirm_split`\|`keep_whole` | that string | `kind_target_mismatch`, `bad_split` |
   | `set_unit_rule_scope` | `unit_rule:{i}` | array of integers, each a `row_number` of an outline row with `kind==="lesson"` | `JSON.stringify(sorted unique ints)` | `kind_target_mismatch`, `bad_scope`, `row_outside_sheet` |
   | `eld_keep` | finding kind `eld_mismatch` | ignored | `"keep"` | `kind_target_mismatch` |
   | `eld_remap` | finding kind `eld_mismatch` | ignored | `"remap"` | `kind_target_mismatch` |
   | `confirm_safety_note` | finding kind `safety_note_proposed` | ignored | `"confirm_safety_note"` | `kind_target_mismatch` |
   | `reject_safety_note` | same | ignored | `"reject_safety_note"` | `kind_target_mismatch` |
   | `revert` | anything found | ignored | `stored_default(...)` | none |
   `stored_default`: finding -> `finding.default_choice ?? ""`; segment -> the segment's `applies` string when kind is not `content`, else `""`; unit_rule -> `""`. (Decision: ELD default is the finding's `default_choice` "eld_keep"; the report treats any non-"remap" value as keep.) `choice` column is `not null`, hence `""`.
