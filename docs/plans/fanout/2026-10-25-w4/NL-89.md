   Then amend `migrate.int.test.ts` counts as listed in section 2.
2. **`packages/llm/src/openrouter-judge.ts`**
   `export interface OpenRouterJudgeAdapterInit { api_key: SecretStr; model_id: string; timeout_ms: number; base_url?: string; fetch_impl?: typeof fetch }` (the last two are tests only, never from the environment). `export class OpenRouterJudgeAdapter implements JudgeClient`. `export const JUDGE_RUBRIC_V1: string` fixed text (one paragraph: "answer yes only if the activity, as written, has students do what the standard asks; otherwise no; reply with JSON only"); `export const JUDGE_MAX_OUTPUT_TOKENS = 300`.
   `verdict(req)`:
   a. Build the body, exactly these top-level keys: `{ model, messages, temperature: 0, max_tokens: JUDGE_MAX_OUTPUT_TOKENS, response_format: { type: "json_object" } }`. `messages` = `[{role:"system", content: JUDGE_RUBRIC_V1}, {role:"user", content: JSON.stringify({ rubric: JUDGE_RUBRIC_V1, question: <fixed sentence per req.question>, standard_text: req.standard_text, activity_text: req.activity_text })}]`. Nothing else from `req` (not lesson_id, content_hash, address, code, rubric_version) enters the body. Invariant: only four inputs leave the box (GR-4, WF-23).
   b. `POST ${base_url ?? "https://openrouter.ai/api/v1"}/chat/completions`, headers exactly `content-type: application/json` and `authorization: Bearer ${api_key.reveal()}` (call `reveal()` only here), `signal: AbortSignal.timeout(timeout_ms)`. No retry loop. No logger and no `console` in this file.
   c. Error mapping (every message is a fixed string, never the response body, URL, header or key; `provider_request_id` from the `x-request-id` header or body `id`): abort/timeout (`DOMException` name `TimeoutError`/`AbortError`) -> `timeout`; other thrown fetch error -> `connection`; 429 -> `rate_limited` (+ `retry_after_s` from `retry-after` if numeric); 401/403 -> `auth`; other 4xx -> `bad_request`; >=500 -> `server_error`; 200 with a body that fails the Zod schema below, or content that is not strict JSON `{verdict: "yes"|"no", rationale: string}` -> `server_error` with message `unparsable judge output` and `http_status: 200`.
   d. Zod (4.6.7, already a dependency): response `{ id?: string, model: string, choices: [{ message: { content: string } }].min(1), usage: { prompt_tokens: number, completion_tokens: number } }`; content schema `z.object({verdict: z.enum(["yes","no"]), rationale: z.string().max(2000)}).strict()`.
   e. Return `{ verdict, rationale, served_model: body.model, usage: {input_tokens: prompt_tokens, output_tokens: completion_tokens, cache_read_tokens: 0, cache_write_tokens: 0}, raw_text: content, provider_request_id }`.
   Fixtures: two recorded-shape bodies (`id: "gen-synthetic-1"`, `model: "judge-model-served"`) with a yes and a no.

4. **Pair source seam, `apps/worker/src/judge/pair-source.ts`** (consumed interface; NL-110 supplies the production implementation; nothing speculative):

5. **`apps/worker/src/judge/judge-job.ts`**
   `export interface JudgeRunReport { lesson_id: LessonId; pairs: number; verdicts_no: number; skipped: number; failed: number; cost_usd: Usd }` (`skipped`, `failed` are additive to DO-4; Risks 4).
   `export interface JudgeJobConfig { expected_locked_hash: string; rubric_version: string; judge_model_id: string; max_output_tokens: number }`.
   `export class JudgeJob { constructor(judge: JudgeClient, calls: ModelCallLog, verdicts: JudgeRepo, renderer: Pick<PromptRenderer,"render_judge">, spend: SpendLedger, prices: PriceLookup, cost: CostMath, source: JudgePairSource, config: JudgeJobConfig, clock: Clock)`. There is deliberately **no IssueRepo and no TxRunner** (NL-110 adds the advisory issue). `async run(lesson_id: LessonId, content_hash: Sha256): Promise<JudgeRunReport>`.
   Per pair, in order (loop is sequential, so a refusal or failure never stops the others):
   1. `rendered = renderer.render_judge({standard_text, activity_text, question, rubric_version, expected_locked_hash})`.
   2. `amount = cost.max_call_cost(prices.price_for(config.judge_model_id), rendered.input_tokens_estimate, config.max_output_tokens)`; `decision = spend.reserve({run_id: ctx.run_id, job_id: null, user_id: ctx.user_id, purpose: "judge", amount_usd: amount})`. If `!decision.allowed` -> `skipped++`, continue (no model_call row). If allowed with `reservation_id === null` throw `InvariantViolation`. Invariant: no call without a reservation.
   3. `id = await calls.insert_sent({run_id, lesson_id, job_id: null, attempt: index + 1, purpose: "judge", alias: "JUDGE", requested_model: config.judge_model_id, rendered_prompt: rendered.text, request_id: null, experiment_id: null, reservation_id})` **before** the call. Invariant: no send without a committed row (R-22/OBS-5).
   4. `try { res = await judge.verdict({lesson_id, content_hash, address, code, standard_text, activity_text, question, rubric_version}) }`; on `ProviderError e`: `await calls.fail(id, {kind: e.kind, http_status: e.http_status, message: e.kind, retry_after_s: e.retry_after_s})`, `await spend.release(reservation_id)`, `failed++`, continue. On any other error: fail (`kind "server_error"`, message `unexpected judge client error`), release, rethrow.
   5. `cost_usd = cost.settle_cost(prices.price_for(res.served_model), res.usage)`; if the served model has no price, use `amount` (settle at the reserved worst case, as `PaidCaller` does). `await calls.complete(id, {raw_output: res.raw_text, stop_reason: "end_turn", usage: res.usage, cost_usd, served_model: res.served_model, provider_request_id: res.provider_request_id, latency_ms})` (latency from `performance.now()` deltas), then `await spend.settle(reservation_id, cost_usd, id)`, `await spend.release(reservation_id)`.
   6. `await verdicts.insert_verdict({lesson_id, content_hash, address, code, question, verdict: res.verdict, model_call_id: id, served_model: res.served_model})`; `if (res.verdict === "no") verdicts_no++`; accumulate `cost_usd`.
   Return `{lesson_id, pairs: ctx.pairs.length, verdicts_no, skipped, failed, cost_usd}`. A verdict is data only: nothing in this file reads or writes `issue`.
   Export `JUDGE_MAX_OUTPUT_TOKENS` re-use from `@ls/llm/openrouter-judge` for the default config value (worker -> llm direction is already allowed; core stays free of adapters).

## 8. Risks and requests

1. **Migration `0014` and `migrate.int.test.ts` (shared, NL-08 frozen).** The ticket says the append-only DDL trigger is NL-08's, but `0011_judge.sql` has none and no `created_at` (the port's `JudgeVerdictRow.created_at` needs it). AC-7 cannot pass without it. Request to the integrator: confirm `0014` is free in wave 4 (NL-79 only mentions it as unbuilt) and amend NL-08's manifest hash for the edited `migrate.int.test.ts`, as NL-34 did for `0013`.
2. **No judge id prefix.** Interim `ids.new_id("ev")`; request: add a `jv` prefix to `IdPrefix` (`packages/schema/src/ids.ts`, not ours) and switch the one call.
3. **No price for the judge model.** `PRICE_TABLE` (`packages/llm/src/prices.ts`) has no OpenRouter row and `MODEL_JUDGE_ID` is unset. `price_for` throws, so `JudgeJob.run` fails before any call. Tests inject their own `PriceLookup`. Request: whoever picks the judge model (NL-110/NL-111 or Innocent) adds the row. Not a blocker for this ticket.
4. **Contract drift (additive).** `JudgeRunReport` gains `skipped` and `failed` (AC-6 needs "skipped"); `JudgeJob` ctor omits `IssueRepo`/`TxRunner` and adds `JudgePairSource`, `CostMath`, config and clock. Request: a CHG note or DO-4 update by the integrator (DO-4 is a design doc, not an agreed CON card, so no CON `CHG-N`).
5. **Rubric duplication.** `JudgeClient.verdict` receives no rendered prompt, and `@ls/llm` may not import `@ls/prompts`, so the wire rubric (`JUDGE_RUBRIC_V1`) lives in the adapter while `model_call.rendered_prompt` stores the locked-prompt text from `render_judge`. The audit row therefore describes, not byte-copies, what was sent. Accepted for cut #2; fix would be a port change (optional `rendered_prompt` on `JudgeRequest`), not made here.
6. **Unparsable output has no dedicated `ProviderErrorKind`;** it maps to `server_error` (not retried by the adapter; the job never retries).
7. `StubJudgeClient` needs nothing new (calls recorded, scripted `yes, no, yes` supported, errors scripted by `ProviderError`). No request on `stub.ts`.
