### What to build
Fill the bodies of the rule files NL-20 left as stubs returning `[]` (Metz C1: bodies only, never the registry, policy, gates or types). Each rule is a pure `CheckRule.run(ctx: CheckContext, policy: CheckPolicy) -> CheckFinding[]`, never throws for content, never reads the database. Findings carry `kind`, `level`, `message`, `address`, `span_anchor`, `related_lesson_id` and `code`; the message names the address and the kind, never repeats a safety note's text.
**`packages/core/src/checks/rules/alignment/`** — `standard_not_taught` and `standard_not_checked` (blocking: each *focus* standard needs a teaching part and a `cfu_item` tagged with it; derives `CheckResult.alignment` rows `AlignmentLinkRow{code, address, role I/P/A, origin, asserted_by}` — never an empty `asserted_by`, GR-4); `code_not_allowed` (blocking: a code outside the row's lists that is not a leaf of a listed parent, or any non-leaf code); `standard_confirmation` (level `confirmation`: origin `narrowed` or `added` with no `confirmed_by` in `ctx.confirmations`; HP-3 — counted in `CheckResult.confirmation`, not `blocking`); `standard_add_suggestion` (advisory: an unlisted leaf of a listed parent, "add?", never added silently); `eld_label_mismatch` (advisory: an ELD code whose strand does not match the row's ELD label, using `ctx.standards[].eld_strand` and the seeded verdict table).
**`rules/safety/`** — `safety_flag_open` (blocking per open flag in `ctx.safety_flags`, `related` to its `teacher_tip_address`); `safety_note_without_tip` (blocking: a flag/confirmed note with no `teacher_tip` block carrying its id); `safety_text_in_student_block` (blocking: a run of ≥ `policy.safety_run_min_words` = 6 words of the note's original text in a student-facing block — assignment items, `directions`, student-facing prompts); `disclosure_prompt` (patterns "a time you…", "your own experience", "have you ever…", "in your family" in student-facing prompts: blocking in the flagged lesson **and the next** — the lesson with an open flag in `ctx.safety_flags`, or whose `ctx.previous_lesson_flags` is non-empty (DO-4 §6, §13 R-1) — advisory elsewhere; per-finding `level`).
**`rules/links/`** — `cross_lesson_link` (blocking while a linked lesson's stored row has the slot the dependant points to empty; `related_lesson_id` = the source lesson; reads `ctx.linked_lessons`, never another lesson's live document); `linked_text_changed` (the linked lesson's current hash differs from the one this lesson recorded); `suggestion_pending` (blocking per pending, unexpired suggestion in `ctx.pending_suggestions`, CON-17).
Must not: edit `registry.ts`, `policy.ts`, `gates.ts`, `types.ts`, `rules/structural/**`, `rules/grounding/**`, `rules/arc/**` (other owners), or add a `CheckKind`. Settled (DO-4 §13): the "and the next" scope reads `ctx.previous_lesson_flags`, filled by NL-38 (R-1); `vocabulary_word_missing` is blocking and belongs to NL-20's structural group, not this ticket (R-8).
