### Story
US-19 / US-20 — As a reviewer I clear a safety flag with a note, confirm or remove an AI-proposed standard, and see AI suggestions held outside the lesson; each is a row that names the person and the time. Platform work: the issue list, resolve, assist and coverage tickets read and write these rows.

### What to build
Implement three classes in `packages/db/src/repos/review-extras.ts` (DO-4 §3.5), over the tables NL-08 created (`safety_flag`, `alignment_link`, `suggestion`; no DDL here), each write taking the caller's `Tx`:
**`PgSafetyFlagRepo`** — `create_for_lesson(lesson_id, source_rows, tx)` (one `open` flag per source row; a repeat creates none), `open_for(lesson_id)`, `clear(flag_id, by, note, tx)` (sets `status cleared`, `cleared_by`, `note`, `cleared_at`; an empty or whitespace note throws and changes nothing — the service's `NOTE_REQUIRED` is NL-45; clearing a cleared flag throws `InvariantViolation`, never overwrites the first clear).
**`PgAlignmentRepo`** — `replace_for_hash(lesson_id, content_hash, links, tx)` (replaces the rows of that lesson and hash, keeps `confirmed_by` for an identical `(code, address, origin)` carried onto the new hash, returns the row count), `confirm(lesson_id, code, by, decision, tx)` (reading of CON-14, planner confirms: `confirm` sets `confirmed_by` on the code's rows at the current hash; `remove` deletes the code's rows at the current hash, the re-run after the collaboration edit rewrites the set; `add` writes rows with `origin "added"`, `asserted_by "reviewer"` and `confirmed_by` null so it opens its own confirmation), `for_lesson`, `coverage_rows(unit_id)` (one SQL statement: a `CoverageCell` per code × lesson × role with `confirmation` = `person` when `confirmed_by` or `asserted_by = reviewer`, `judge_only`, or `generator_only`; cut #4's CON-22 reads it).
**`PgSuggestionRepo`** — `insert`, `get` (a pending row past `expires_at` is read back as `closed`), `decide(suggestion_id, status, by, tx)` (only from `pending`; a second decision throws `InvariantViolation`), `pending_for(lesson_id, now)` (excludes expired). Open item for the planner: DO-4 §5 says the service sets `expires_at = now + SUGGESTION_TTL_MIN` but `NewSuggestion` has no `expires_at`; add it additively (record in the dev log) rather than reading settings in the repo.
Must not: write DDL, edit `ports.ts` (NL-12), store a person's review minutes, or return `selected_text` in any log. Tests use the Postgres container.
