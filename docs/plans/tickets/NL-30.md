### Story
US-8 — As an outline author (P-2), I need the worker to keep at most six lessons in flight, to pick up exactly where a killed worker stopped, and to move a run to complete, partial, paused or capped by itself, so that a 47-lesson unit finishes without me watching it and a restart costs at most the calls in flight.

### What to build
**Modules (DO-3 §2.4, DO-4 §6):** `apps/worker/src/queue/claim-loop.ts` (`ClaimLoop`) and `apps/worker/src/generation/run-finalizer.ts` (`RunFinalizer`). Collaborators typed from DO-4 and tested with doubles where they are same-wave (`LessonJobRunner` NL-29, `UnitPlanJob` NL-31, `PgJobQueue` NL-28, `PgRunRepo` NL-27, `PgModelCallLog` NL-33, `PgSpendLedger` NL-35); `derive_run_state` is NL-27's pure code typed from DO-4 §8, `should_pause_run` is NL-22's.
- **ClaimLoop.start() → TickReport.** `queue.requeue_expired(clock.now())` once; for the returned `job_ids`, `calls.mark_lost(job_id)` for each (counted in `lost_calls_marked`) and `spend.release_for_jobs(job_ids)` (`reservations_released`) — in that order, before any claim (G-9). The report also carries `requeued_at_start`.
- **ClaimLoop.run_until(stop) → LoopExit.** Keeps up to `GENERATION_CONCURRENCY` (6, SP-1) jobs in flight with a counting semaphore. Each cycle: `queue.claim(settings.worker_id, MAX_ACTIVE_RUNS, JOB_LEASE_MS)`; a `unit_plan` job goes to `UnitPlanJob.run` and then `queue.finish` (status from `UnitPlanOutcome.stored`; a stored plan finishes `ready`; a failure finishes `generation_failed` with its `FailureReason`); a `lesson` or `candidate` job goes to `LessonJobRunner.run` (which finishes its own job). When nothing is claimable it `clock.sleep(JOB_POLL_MS)`. Lease renewal: every 30 s per in-flight job `queue.renew_lease`; false → that job is told to stop (`LeaseLost`) and the loop does not finish it. On `stop.is_set()` (SIGTERM) it stops claiming, waits for in-flight calls to finish, and returns `LoopExit{reason "sigterm", drained_jobs, abandoned_jobs}`; an `InvariantViolation` from a runner is logged at error level and returns `reason "fatal"`. Additive to DO-4 (reported): `ClaimLoop` receives a `TxRunner`, used only so that a run whose plan call was capped gets `queue.cancel_run(run_id, "capped", tx)` (DO-4's `UnitPlanJob` marks the run capped but nothing could cancel its queued lesson jobs).
- **RunFinalizer.after_job(run_id, outcome) → RunStateChange | None.** One `tx.with_tx`: if `outcome.brakes_fired` holds a `spend_*` brake → `runs.mark_capped(run_id, cap)` (`spend_run_cap→run_cap`, `spend_day_cap→day_cap`, `spend_project_cap→project_cap`) and `queue.cancel_run(run_id, "capped", tx)` (queued tiles `failed`, reason `capped`; in-flight jobs finish); else `should_pause_run(recent terminal jobs, CIRCUIT_BREAKER_SAME_CHECK = 3)` → `runs.set_state(run_id, "paused", check)`; else `derive_run_state(jobs_for_run, RunStateInput)` and `runs.set_state` only when it changed. A change to `complete`/`partial`/`capped`/`paused` is returned as `RunStateChange{from_state,to_state,paused_check}`; no change returns null. When the run reaches a terminal state it calls `completeness(run_id)` and logs a warning line `run.incomplete` for any gap.
- **RunFinalizer.completeness(run_id) → CompletenessReport.** `terminal_jobs_without_calls`: jobs `ready` or `generation_failed` with no `model_call` row, excluding jobs refused before their first call (reasons `capped` or `cancelled` and no lesson row); `summary_matches_calls`: `calls.totals_for_run(run_id).cost_usd` equals the run's settled spend (DO-6 missing-instrumentation checks 1 and 2).
Must not: run a node itself; write `lesson_version`, `lesson_doc` or `spend_reservation` rows; edit `lesson-job-runner.ts` (NL-29), `unit-plan-job.ts` (NL-31), `main.ts` or `wiring/generation.ts` (NL-07/NL-79).
