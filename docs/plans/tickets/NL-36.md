### Story
US-15 — As a reviewer (P-1), I need my edits stored durably together with the checks that follow them, and edits made from other screens (standards, slots, adopt, accept) to go through the same single writer, so that what I see, what is checked and what I later submit are one document. This ticket is the store transaction and the web side of the private call into the collaboration server.

### What to build
**1. Store (`packages/db/src/repos/lesson-docs.ts`, DO-4 §3.4).** `PgLessonDocStore implements LessonDocStore` from `PgLessonDocStore_ctor{db, ids, clock, checks: CheckQueue, states: LessonStateRepo, audit: AuditLog}`. It is the **only writer of `lesson_doc`** and writes no other table in its own SQL (Metz S2): the other tables are written through their ports.
- `store(req: StoreRequest) → StoreAck`: ONE transaction (HP-4): take `pg_advisory_xact_lock('lesson_doc:'||lesson_id)` → `INSERT lesson_doc` (`seq = max+1`, `store_id st_…`, `ydoc_bytes`, `derived_json`, `content_hash`, `state_vector`, `schema_version`, `stored_by`, `stored_at = clock.now()`, `request_id`) → `checks.enqueue(lesson_id, content_hash, store_id, tx)` → `states.record_last_editor(lesson_id, stored_by, tx)` when `stored_by` is set → `audit.append({action "lesson.store", target_kind "lesson", target_id lesson_id, version_hash content_hash, request_id, store_id, details {seq, tag}}, tx)`. Returns `StoreAck{…, check_job_enqueued true}`. Any failure rolls all four back; every durable store is one row (WF-9 asserts one `lesson_doc` row per store).
- `seed_initial(lesson_id, lesson, actor, tx) → SeedResult`: joins the **caller's** transaction (G-25): `lesson_to_ydoc(lesson)` (NL-19), `content_hash(lesson)`, `state_vector_of(bytes)`, then `INSERT … seq 1 ON CONFLICT (lesson_id, seq) DO NOTHING` (`seeded false`, `store_id null` on the conflict path) and, only when seeded, `checks.enqueue` in the same transaction. Writes no audit row (a system action; the version row carries provenance).
**2. Reader (`packages/db/src/repos/lesson-doc-reads.ts`).** `PgLessonDocReader implements LessonDocReader`: `latest(lesson_id) → StoredDoc | null` and `latest_derived(lesson_id) → DerivedRow | null` (highest `seq`; parses `derived_json` with the stored-lesson Zod schema and leaves `schema_version` for callers to check). Added here because no other ticket owns this file (reported as a slice-plan gap).
**3. Client (`apps/web/src/server/adapters/collab-commands.ts`, DO-4 §3.3).** `HttpCollabCommandClient implements CollabCommands` from `HttpCollabCommandClient_ctor{base_url = COLLAB_INTERNAL_URL, token: SecretStr, timeout_ms 5000}`: `lock_and_snapshot(SubmitCommand) → SnapshotResult`, `apply_edit(EditCommand) → StoreAck`, `set_mode(ModeCommand) → ModeResult`, each `POST {base_url}/lessons/{encodeURIComponent(lesson_id)}/{lock-and-snapshot|apply-edit|set-mode}` with `Authorization: Bearer <token>`, `X-Request-Id`, a JSON body, **no retry**. Results are parsed with Zod mirrors of the DO-4 records (dates revived). `collab_refusal_from(status, body, command, lesson_id, request_id)`: a non-2xx whose body parses as the OpenAPI `Error` envelope becomes `DomainRefusal` with the **same** `code`, `message` and `details` (so `NOT_STORED`, `BLOCKED` with `details.issues`, `LESSON_LOCKED` with `details.state`, `ANCHOR_CHANGED`, `SUGGESTION_PENDING`, `CONFIRMATION_OPEN` reach the browser unchanged), with `details.request_id` replaced by the web request's id and the collab request id logged as `collab_request_id`; a timeout (5 s), connection failure, a body that is not an envelope, or a 401 from the command route (a token mismatch: logged as `InvariantViolation`) becomes `CollabUnavailable{lesson_id, command}` → `COLLAB_UNAVAILABLE`, with nothing changed. The token is never logged or put in an error.
Must not: write `lesson_doc` anywhere else; call a model; implement the collaboration server's command handlers (NL-105/NL-106) or socket auth (NL-80); retry a command; edit `repos/lessons.ts` (NL-42), `repos/check-queue.ts` (NL-37), `packages/ydoc/**` (NL-19), DDL.
