### What to build
After NL-124's "seeded review done", unseal the key and score it.

1. `npm run eval:seed -- --score <eval_run_id>` (NL-92) matches each planted error in `evals/local/seed-key.json` to what happened: **caught by a check** (an `issue` before any human), **caught by the reviewer**, **caught at approval**, or **missed (approved with the error)**. Caught-before-approval = the first three.
2. Write `evals/reports/seeded-<run_id>.md`: planted count, caught count by route, missed list by error kind (not the lesson text), catch rate = caught before approval ÷ planted, with *n* and the label **"our reviewers: one reviewer (Innocent), n = k planted"**. Compare with the S10 bar: ≥ 90% caught (aspiration), < 70% fails the guard; with about 5 errors, 5 of 5 meets the aspiration, 4 of 5 is reported as is, 3 or fewer fails; the **wrong-code plant must be caught (floor)**.
3. Say what the number does and does not show: one reviewer, a tiny *n*, planted errors are not the full range of real ones. Never write that Newsela's reviewers catch anything. A miss is reported, with what it means for the north star (M-1 is then not to be read as a saving, G-3).
4. Seal again: the key stays git-ignored; the report names kinds, not locations. Lane guard (`ticket-lanes`): before committing, `git diff --name-only` must list no file that code or tests read (source, tests, schemas, migrations, prompts, settings, lockfiles, fixtures, CI); if it does, stop, relabel the ticket `lane::build-loop` and report.
