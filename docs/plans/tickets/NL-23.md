### Story
Platform work, no US of its own: the demo runs locally under Docker Compose with the deploy config committed (PD-15 option D: no new hosting spend). This ticket makes the three Node processes and Postgres start together, migrate once, record that they started, and keep the database and secrets off the host and out of the images.

### What to build
Root files (A0): `Dockerfile.web`, `Dockerfile.node`, `docker-compose.yml` (replaces NL-01's Postgres-only file), `.dockerignore`, `.env.example`, `render.yaml`, `scripts/docker-entrypoint.sh`; and, in each app, one start-event helper.
**Images (DO-3 §1; AD-15).** `Dockerfile.web`: Node 24, multi-stage, Next standalone output of `apps/web`, non-root user. `Dockerfile.node`: one image for `apps/worker` and `apps/collab`, two entry points selected by `command`. No `ENV` or `ARG` carries a secret; `.dockerignore` excludes `.git`, `.env*`, `node_modules`, `evals/local/`, `docs/source/restricted/` (GR-9) and test output.
**Compose.** Services `web` (3000), `worker`, `collab` (1234, published: the browser's socket channel), `postgres` (16, named volume, healthcheck, **no `ports`**), one internal network, `depends_on` on Postgres health. `COLLAB_INTERNAL_TOKEN`, `AUDIT_HASH_SALT`, `DATABASE_URL` are required from the environment (`${VAR:?set it}`); provider keys appear by name only (`ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`), supplied at launch by `/home/linuxuser/workspaces/bin/with-provider-env --project-env .env -- docker compose up`; `MODEL_PROVIDER_MODE` defaults to `stub`. `docker-compose.test.yml` (NL-01) keeps working and is the only place Postgres is published (127.0.0.1:55440). `.env.example` lists names and safe local values only.
**Start-up.** `scripts/docker-entrypoint.sh` runs `npm run db:migrate` (NL-08) once, then `exec`s the process. Each entry point calls its helper (`apps/web/instrumentation.ts` `register()`, `apps/worker/src/start-event.ts`, `apps/collab/src/start-event.ts`), which writes one `ops_event` (`kind process_start`, `service`, `build_id` from `resolve_build_id`) through `record_ops_event` (NL-08) once the database answers; a failure to write is logged, not fatal. This is the one edit this ticket makes to NL-06/NL-07 files (`main.ts`: one call), both A0.
**`render.yaml` (committed, not provisioned).** Per the workspace hosting default: web (Docker web service), worker (Docker background worker), collab (Docker web service), Postgres (Basic), region Ohio, `autoDeploy false`, secrets via an environment group `ls-secrets` (`fromGroup`), Postgres `ipAllowList: []`. The hosting-default rule's monthly lines are cited in a header comment; nothing is created on Render.
Must not: publish Postgres, put a key or token in a Dockerfile, image layer, compose file or `render.yaml`, copy `docs/source/restricted/` into any image, or call the Render API.
