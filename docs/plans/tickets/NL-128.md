### Story
Platform work for the §9 experiment stage (GP-21, GP-44, GP-51): after the error-analysis round names the failure types (`FT-N`), experiment XP-1 changes exactly one thing aimed at one failure type and scores it on the frozen development set, with score and cost before and after. This is the first of up to three; XP-2 and XP-3 are slots.

### What to build
Run one experiment (`docs/testing/experiments/XP-1-<slug>.md`, zero-to-hero `ARTIFACT-MAP.md` §9). The target and the change are **chosen from the round-1 error analysis** (`docs/testing/error-analysis/<date>-round-1.md`, NL-120, reviewed by Innocent); this ticket's planner reads that file and fills the plan with them. Nothing here names a prompt change in advance: no tuning before the failure type is named.

- **Target:** one `FT-N` from the round-1 taxonomy. Prefer the failure type with the most traces whose fix lives in a prompt, schema, check or parameter (DO-5 *Failure categories*, "Fix lives in").
- **The one change:** a single variable in a single place: one prompt-layer edit (guidance or locked layer, via the prompt version path, never a UI edit of the locked layer: GR-18), or one model setting, or one check/schema tweak. Not two.
- **Frozen set:** the development cases `evals/cases/**` (S1–S3, S7, WP-1…WP-5, SYN), `docs/data/samples/**` and `docs/data/worked-pairs.md`. It is never edited to make a result pass; any expected-output change is a separate commit by rule (DO-5) and is out of scope here.
- **Scoring:** run `npm run eval:golden -- --suite drafts --repeat 3` (S3, real model, about $1.64 per run) and the golden tier (`--suite intake,checks`) **before** and **after** the change at otherwise identical settings; attach both reports and the cost (EV-R2). Spend is real model spend inside the PD-29 $75 ceiling (about $3.30 for the two S3 runs).
- **Decision:** keep if the target `FT-N` count falls on the frozen set with no new failure type appearing and no passing case flipping to failing; otherwise revert the change in a separate commit and record "reverted". Either outcome is a finished experiment.
- **Record fields** (one line each, greppable): `Target: FT-N`, `Change: <file> — <one-line diff summary>`, `Before:`, `After:`, `Cost:`, `Decision: keep|reverted`.
- Order: XP-1 starts after NL-120 merges.
- Must not: change two variables, edit the frozen set, use any text from `docs/source/restricted/` as an in-context example (GR-9, GR-11), or touch a file outside the one declared in `Change:` (plus the record and the two reports).
