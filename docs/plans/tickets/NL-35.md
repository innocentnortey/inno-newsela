### Story
US-8 — As an outline author (P-2), I need a run to stop at its cap and never spend past it, even with six calls in flight, and the project to stop at the $75 build ceiling, so that no run, retry or AI suggestion can overspend. Money is decided in one pure function and written under one lock.

### What to build
**1. Pure math (`packages/core/src/spend/reservation.ts`, DO-4 §8 *spend*).** All money is `Decimal`; every result is rounded to 6 decimal places (`numeric(12,6)`).
- `max_call_cost(price, input_tokens_estimate, output_cap)` = `(input_tokens_estimate × max(input_per_mtok, cache_write_per_mtok) + output_cap × output_per_mtok) / 1,000,000`, rounded **up**. Example: 5,700 input, cap 32,000 at $2/$10 (cache write $2.50) → `0.014250 + 0.320000 = 0.334250`.
- `settle_cost(price, usage)` = `(input×input + output×output + cache_read×cache_read + cache_write×cache_write) / 1,000,000`, rounded half-up. Example: input 1,000, output 2,000, cache read 10,000 at $2/$10/$0.20 → `0.024000`; add 4,000 cache-write tokens at $2.50 → `0.034000`.
- `run_cap_for(cost_per_lesson, lessons, multiplier, unit_plan_cost)` = `cost_per_lesson × lessons × multiplier + unit_plan_cost` rounded **up** to the next whole dollar. Example: `0.182 × 47 × 1.5 + 0.16 = 12.991 → 13.00`. `user_day_cap_for(run_cap_default, multiplier)` = `13.00 × 2 = 26.00`.
- `decide_reservation(snapshot, amount_usd)`: caps are inclusive (`spent + reserved + amount ≤ cap`, CON-6); checked in the order `run_cap` (skipped when `run_cap_usd` is null, i.e. AI assist) → `day_cap` → `project_cap`; `refused_by` is the first that fails; `scope` is `user` for `day_cap`, `project` for `project_cap`, null for `run_cap`; `remaining_usd` is the headroom left on the refusing cap (never negative); `reservation_id` is always null (the ledger assigns it); the snapshot is returned unchanged. An `amount_usd ≤ 0` raises `InvariantViolation`.
**2. Ledger (`packages/db/src/repos/spend.ts`, DO-4 §3.4).** `PgSpendLedger implements SpendLedger` from `PgSpendLedger_ctor{db, ids, clock, settings: SpendSettings}` (project ceiling `BUILD_SPEND_CEILING_USD` 75, `USER_DAY_CAP_MULTIPLIER` 2, `RUN_CAP_DEFAULT_USD` 13.00; G-1, G-2). Table `spend_reservation` (NL-08 `0004_runs.sql`).
- `reserve(req)`: one transaction under `pg_advisory_xact_lock('spend')`: read the three sums — run (`settled + reserved` of this run's rows, cap from `run.cap_usd`), user-day (this user's rows whose `day` equals today's **UTC** date), project (every row's `settled_usd` + `reserved_usd` of rows still `reserved`, **plus** `model_call.cost_usd` of rows with `reservation_id` null, i.e. imported spike calls, G-5) — build the `SpendSnapshot`, call `decide_reservation`, and only if allowed `INSERT` one row (`id sr_…`, `status reserved`, `day`, `job_id`, `purpose`). A refusal writes nothing (shared guarantee 2).
- `settle(reservation_id, actual_usd, model_call_id)`: `reserved → settled` (or `released → settled`: a lost call that completed after `release_for_jobs` still records real spend); `settled_usd = actual`, `overshoot_usd = max(0, actual - reserved)` recorded, never refused, with a warning log line `spend.overshoot`; idempotent for the same `model_call_id`; `settled` is terminal. Returns `SettledReservation{released_usd = max(0, reserved - settled), overshoot_usd}`.
- `release(reservation_id)`: `reserved → released` (settled 0); a no-op returning the stored result on a settled or released row. `release_for_jobs(job_ids)`: every `reserved` row of those jobs → `released`; returns the count. `run_totals(run_id)` → `RunSpend{cap_usd, settled_usd, reserved_usd}`. `check_day_cap(user_id, amount_usd)`: dry run, writes nothing, `reservation_id` null, checks `day_cap` then `project_cap` (no run cap).
Must not: float arithmetic anywhere (a lint test greps `Number(`/`parseFloat` in the two files); write a row on refusal or on a dry run; call a model; edit `recorder.ts`/`paid-call.ts` (NL-33), `run-service.ts`, DDL.
