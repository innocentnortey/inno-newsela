### Story
Platform ticket (no user story): the deploy and the recording need liveness probes, an auditable start of every process, a verified database backup after the full run (PD-30) and a logged sample build. It serves US-36 (trust the build's numbers) indirectly: the backup is what protects the full-run evidence.

### What to build
Fill the operations surface NL-07 stubbed.

- **Health (WF-39):** `GET /healthz` on each process. `apps/worker/src/health.ts`: `serve_health(db, port, service) -> HealthServer`; `apps/collab/src/health.ts`: same through Hocuspocus `onRequest`; `apps/web/app/api/healthz/route.ts` (no `with_route` session; open, liveness only). Response `200 {"status":"ok","service","build_id"}` when `PgDatabase.ping` succeeds, else `503 {"status":"unavailable","service"}` plus one `ops_event` of kind `health.failure` (at most one per 60 s per process; if the event write also fails the 503 still returns and the failure goes to the JSON log; the handler never throws). The body carries no connection string, no env value and no version of anything else.
- **Start events (WF-38):** every process writes one `ops_event` `process.start` with `service` and a non-empty `build_id` (`BUILD_ID` = `RENDER_GIT_COMMIT` or the local git SHA). Web: `apps/web/instrumentation.ts` (Next `register`); worker and collab: the call NL-07 left in `main.ts`; if it is missing NL-83 may add that single call (the one allowed edit to NL-07 files, noted in the review).
- **Backup (WF-40):** `ops/backup.sh` (`npm run ops:backup`): one `pg_dump` in custom format to a git-ignored `backups/` path with mode 600; records one `ops_event` `backup` with path, size and SHA-256; verifies it with `pg_restore --list`. The database password is passed through the environment, never argv; the script refuses to run without `DATABASE_URL`.
- **Sample builder (WF-35):** `ops/run-sample-builder.ts` runs `docs/data/scripts/build_samples.py` and records one `ops_event` `samples.built` with the hashes of its inputs and outputs.

**Must not:** publish Postgres or expose the backup path over HTTP; put a secret in a health body, event, argv or log; call a model; change the build script.
