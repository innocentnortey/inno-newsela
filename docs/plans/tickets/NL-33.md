### Story
US-32 — As a content lead (P-3), I need one trace per run whose totals equal the sums over the stored calls, with cost taken from the provider's usage fields, so that I can trust what the batch cost. This ticket makes sure no call is ever invisible: the row exists before the send, the raw answer is saved the moment it arrives, and lost calls are counted.

### What to build
**Modules:** `packages/llm/src/recorder.ts` (`ModelCallRecorder`), `packages/llm/src/paid-call.ts` (`PaidCaller`, Metz S6) and `packages/db/src/repos/model-calls.ts` (`PgModelCallLog implements ModelCallLog`, table `model_call`, NL-08 `0005_traces.sql`). Interfaces exactly as DO-4 §3.4 and §4. Two same-wave collaborators are injected as typed-from-DO-4 objects and tested with doubles: the cost functions `settle_cost` and `max_call_cost` (NL-35 owns `packages/core/src/spend/reservation.ts`) arrive as one additive constructor parameter `cost: CostMath{settle_cost, max_call_cost}` (reported to the orchestrator; the wiring in NL-79/NL-116 passes NL-35's functions), and the `SpendLedger` is the port from NL-12.
- **`ModelCallRecorder.call(ctx, req, rendered)` → `RecordedCall`.** (1) `log.insert_sent(ModelCallStart{…, rendered_prompt = rendered.text, requested_model, reservation_id})` **before** the send; (2) `client.complete(req)` with retries on `ProviderError` kinds `rate_limited`, `overloaded`, `server_error` and `connection` — at most `PROVIDER_MAX_RETRIES` (3), the delay is `retry_after_s` when the provider gave one, else `1 s × 2^n` with ±20 % jitter, always `clock.sleep` (a `timeout` is **not** retried: a retry could pay for a call the provider already ran; reported as a refinement of DO-4's `retryable` flag), the same `model_call` row for every attempt, `retries` counted; the hard per-call timeout is `req.timeout_ms` (`MODEL_CALL_TIMEOUT_MS` 240000, SP-1); (3) on success `log.complete(id, ModelCallCompletion{raw_output, stop_reason, usage, cost_usd = cost.settle_cost(prices.price_for(served_model), usage), served_model, provider_request_id, latency_ms})` **the moment the response arrives, before any parsing**; on final failure `log.fail(id, ProviderErrorRecord)` and re-raise the `ProviderError`. It never retries a truncation or a schema failure (the callers decide). `checkpoint(job_id, purpose, attempt)` = `log.completed_for`; `attempt` is the call's own ordinal for `(job, purpose)`, never `ClaimedJob.attempt` (G-19). One `model_call` JSON log line per call end (`service, build_id, request_id, run_id, lesson_id, job_id, model_call_id, purpose, alias, served_model, token counts, cost_usd, latency_ms, retries, status`) — never the prompt, the output or a key.
- **`PaidCaller.call(p)` → `RecordedCall`** (the only reserve → call → settle | release protocol): `amount = cost.max_call_cost(prices.price_for(recorder model for req.alias), rendered.input_tokens_estimate, req.max_output_tokens)`; `spend.reserve({run_id, job_id, user_id, purpose, amount_usd})`; a refusal raises `SpendRefused(refused_by, scope, amount)` with **no `model_call` row and nothing sent**; allowed → `recorder.call` with `ctx.reservation_id`; then `spend.settle(reservation_id, recorded.cost_usd, model_call_id)`; in `finally`, `spend.release(reservation_id)` (a no-op once settled, so a thrown error or abort always frees the reservation). Every call reserves its own worst case right before it is sent (draft 32,000, truncation retry 48,000, repair 32,000 output tokens).
- **`PgModelCallLog`** from `PgRepo_ctor`: `insert_sent` (id `mc_…`, `status sent`, `sent_at`, `attempt`, `reservation_id`, `rendered_prompt`, `request_id`, `experiment_id`), `complete` (`status completed` plus the fields), `fail` (`status failed`; the error is stored as `stop_reason = "error:<kind>[:<http_status>]"`, no message text), `mark_lost(job_id)` (every `sent` row of the job → `lost`; returns the count; called by `ClaimLoop.start`), `completed_for(job_id, purpose, attempt)` (a `completed` row with `raw_output`, never re-sent), `totals_for_run(run_id)` → `RunCallTotals{calls, completed, failed, lost, retries, truncation_retries (rows with purpose truncation_retry), repairs (purpose repair), cost_usd (sum over completed), input_tokens, output_tokens}`. The `retries` per call needs a `model_call.retries` column; DO-3 §6's column list does not show one, so if NL-08's DDL lacks it this ticket stops and raises a `CHG` to NL-08 (reported).
Must not: send before the row exists; parse or validate model output; log prompt text, raw output or a key; import the Anthropic SDK; retry timeouts or truncations; edit `anthropic.ts`/`stub.ts`/`prices.ts` (NL-32), `repos/spend.ts` or `reservation.ts` (NL-35), DDL.
