### Story
US-10 — As an outline author (P-2), I need to see the locked prompt layer (read-only) and every guidance version, and to start each run on exactly one of them, so that I know which instructions produced a lesson and nobody can edit the rules that keep the output safe. Saving guidance is a later ticket (NL-88, cut #7); this one makes the versions exist, list and pin.

### What to build
**1. Repository (`packages/db/src/repos/prompts.ts`, DO-4 §3.5).** `PgPromptRepo implements PromptRepo` from `PgRepo_ctor`; table `prompt_version` (NL-08 `0003_prompts.sql`). `current()` → the highest-numbered `PromptVersionRow`; `get(id)`; `all()` ordered by `number`; `pinned_by_runs(id)` → run ids from `run.prompt_version_id`; `insert_guidance(v, diff, tx)` (implemented now so NL-88 only adds the service path): locks the current row `FOR UPDATE`, refuses with `DomainRefusal(STALE_BASE, details.latest_version_id)` unless `v.base_version_id` is the current one, inserts `number+1` carrying the **same `locked_hash`** and the new `guidance_text`, `author_id`, `reason`, `diff`. Rows are immutable: the table has no update path in this repository, and a database trigger from NL-08 refuses UPDATE/DELETE.
Because DO-4's `PromptRepo` has no initializer, `PgPromptRepo` also has a repository-level (non-port) method `sync_locked_layer(locked_hash, tx)`: when the table is empty it inserts **v1** (`number 1`, `locked_hash`, empty `guidance_text`, `author_id null`, `reason "initial"`); when the current row's `locked_hash` differs from the files' hash it inserts a new version with the new hash and the current guidance carried over (so editing a locked file in a code change creates a new immutable version, never a mutation); when equal it does nothing. It is in DO-4 §3.5 `PgPromptRepo` (§13 R-6) and runs under `pg_advisory_xact_lock('prompt:sync')`, so two processes starting together insert v1 once.
**2. Service (`apps/web/src/server/services/prompt-service.ts`, DO-4 §5 `PromptService`).** Full DO-4 constructor `(prompts, audit, tx)`; `list(user)` (any signed-in role) → OpenAPI `PromptVersions{current_prompt_version_id, locked_layer{version_id, text}, guidance_versions[{version_id, number, author, created_at, reason, diff, pinned_by_runs}]}`: `locked_layer.text` is the locked files' text read through `packages/prompts` (NL-14), `locked_layer.version_id` is `locked-<first 12 hex of locked_hash>`, `author` is the author's name (`null` author → "system"), `pinned_by_runs` the run ids. `save_guidance` exists on the class and throws `NotBuiltYet("NL-88")`. The locked layer text is a response field only: no method accepts locked text.
**3. Route (`apps/web/app/api/prompt-versions/route.ts`)**: `GET` via `with_route` (any role, `listPromptVersions`). NL-88 adds the `POST` in the same file; this ticket exports no write handler and defines no `PUT`/`PATCH`/`DELETE`.
**4. Wiring (`apps/web/src/server/wiring/prompts.ts`, A0's stub; DO-4 `wire_prompts`)**: builds `PgPromptRepo`, `PgAuditLog`, `PromptService`; at construction calls `sync_locked_layer(locked_layer_hash(), tx)` once per process (NL-14's hash function; it is the same value as `RenderedPrompt.locked_hash`); returns `PromptWiring{prompts}`.
Must not: write the locked layer from any route or method; edit or delete a version; implement the guidance save (NL-88); re-implement the locked-layer hash; edit `container.ts`, DDL, `packages/prompts/**` (NL-14).
