### Story
US-24 — As a reviewer (P-1) I need Submit to freeze the lesson, so that the approver reads exactly what I sent. US-25 — As an approver (P-3) I need to approve one pinned version. US-28 — reopening asks for a reason and makes a new version. This ticket is the one rule table for those moves, shared by the web app (most moves) and the collaboration server (Submit, the editable-state guard).

### What to build
`packages/core/src/lifecycle/lesson-machine.ts` (A12a; pure; depends on `@ls/schema`).
**`decide_transition(i: TransitionInput): TransitionDecision`** (DO-4 §8) applying CON-18's order **role → state → missing input**: `ROLE_FORBIDDEN`, then `INVALID_TRANSITION`, then `NOTE_REQUIRED` / `REASON_REQUIRED` / `RATING_REQUIRED` (a blank or whitespace-only text counts as missing). The pin, four-eyes, blocking and dependency conditions are the services' (they need data), so this function never returns them. Moves:
| action | role | from | to | `writes_snapshot` | `collab_mode_after` | missing input |
|---|---|---|---|---|---|---|
| `start_review` | reviewer | `draft` | `in_review` | none | none | — |
| `submit` | reviewer | `in_review`, `changes_requested`, `reopened` | `submitted` | `submit` | `read_only` | — |
| `withdraw` | reviewer | `submitted` | `in_review` | none | `editable` | none (UXP-10: no reason) |
| `approve` | approver | `submitted` | `approved` | `approve` | none (already frozen) | `rating` → `RATING_REQUIRED` |
| `request_changes` | approver | `submitted` | `changes_requested` | none | `editable` | `note` → `NOTE_REQUIRED` (the `tag` is validated by the schema, not here) |
| `reopen` | approver | `approved`, `exported` | `reopened` | `reopen` | `editable` | `reason` → `REASON_REQUIRED` (UXP-4) |
A refusal returns `{allowed: false, to_state: null, refusal: <code>, writes_snapshot: null, collab_mode_after: null}`. A second approver approving an `approved` lesson, and `start_review` on an `in_review` lesson, are `INVALID_TRANSITION` (CON-18). No path leads to `generation_failed` or `exported` (the worker and CON-23 own those).
**`transition_roles(action): RoleName[]`** gives the roles allowed to ask, checked before the lesson is loaded so `ROLE_FORBIDDEN` precedes `NOT_FOUND`. **`is_editable(state, role): boolean`** is true only for the reviewer role in `in_review`, `changes_requested` and `reopened` (CON-12 write permission: authors and approvers never edit); `WriteGuard` and `apply_edit` both call it, so a new state is one edit here.
Must not: read a repository, clock or session, return the pin, four-eyes, blocking or dependency codes, or hold an editable-state list anywhere else.
