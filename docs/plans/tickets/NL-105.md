### Story
US-22 — As a reviewer I ask for a fresh draft without losing my edits (adopt a candidate); the same internal call serves standard decisions, slot fills and AI-assist accepts. Platform: every HTTP-started content change must reach lesson content through the one process that may write it, attributed to a named person (shared guarantee 3).

### What to build
Build the collaboration server's private HTTP command surface (`CollabCommands`, DO-4 §3.3) — everything except the Submit freeze (NL-106 fills `commands/lock-and-snapshot.ts`; the shell and its route are already mounted by NL-07 and `routes.ts` only dispatches to it).

- `commands/routes.ts` — `CollabCommandHandler` (the whole class and its DO-4 `CollabCommandHandler_ctor`, including the Submit dependencies `versions`, `loader`, `rules`, `policy`; NL-105 is its only builder) and the internal HTTP routes `POST {COLLAB_INTERNAL_URL}/lessons/{lesson_id}/{lock-and-snapshot|apply-edit|set-mode}`. **Every route first checks `Authorization: Bearer <COLLAB_INTERNAL_TOKEN>` with a constant-time compare (`timingSafeEqual`)**; no or wrong token → 401 with the Error envelope, no handler runs and no row is written. Bodies are the DO-4 records (`EditCommand`, `ModeCommand`) validated with Zod (`INVALID_REQUEST`); `X-Request-Id` is carried onto every audit and review row; refusals return the OpenAPI `Error` envelope with the `ApiErrorCode` (the web client maps them unchanged).
- `commands/apply-edit.ts` — `apply_edit(EditCommand) -> StoreAck`: refuses `LESSON_LOCKED` (with `details.state`) when `FrozenDocs.is_frozen` or the state is not editable; otherwise applies the edit as **one Yjs transaction with origin `{actor, tag}`** through a server-side direct connection (`openDirectConnection`) and stores **immediately** (no debounce) through `LessonPersistence.store`, setting the last editor to the actor (so four-eyes counts it). Edits: `StandardEdit` (`standard-decision`; `decision "undo"` sets the code's front-matter entry to `restore`, or deletes it when `restore` is null — DO-4 §3.3, §13 R-4), `SlotFillEdit` (`slot-fill`), `AdoptEdit` whole or section (`candidate-adopt`), `SuggestionAcceptEdit` (`ai-assist`): resolve the stored `anchor` against the **live** document, compare the text there with `expected_text` (the stored suggestion's `selected_text`; the browser's `anchored_text_now` is never trusted) and apply `replacement_text` only on equality, else `ANCHOR_CHANGED`, nothing applied. Unknown lesson/slot/candidate → `NOT_FOUND`.
- `commands/set-mode.ts` — `set_mode(ModeCommand) -> ModeResult`: idempotent; updates `FrozenDocs` **first**, then `AckBroadcaster.mode`; returns `connections_notified`.
- `wiring/commands.ts` — fills the command half of the collab composition: `CollabCommandHandler` built with the DO-4 `CollabCommandHandler_ctor` fields from `CollabDeps` (including `token` from `COLLAB_INTERNAL_TOKEN`).

**Must not:** expose these routes outside the Compose network or without the token; apply an edit to a frozen or non-editable lesson; trust any text the caller sends about what is under an anchor; edit `lock-and-snapshot.ts`, NL-80's files, or write DDL.
