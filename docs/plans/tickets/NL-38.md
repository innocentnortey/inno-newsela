### Story
US-12 — As a reviewer (P-1), I need to see that a lesson depends on another lesson and to be stopped from approving it before its source is ready, so the checks need the other lesson's stored text, the pending suggestions and the open safety flags. Three callers (the check worker, the Submit freeze and Approve) must build the same context, or the blocking set would differ between the issue list, Submit and Approve.

### What to build
**Module:** `packages/core/src/checks/context-loader.ts` — `CheckContextLoader` (DO-4 §6), constructor `(outlines, standards, graph, reader, suggestions, flags, alignment, clock)` with ports only (`OutlineRepo`, `StandardRepo`, `LessonGraphRepo`, `LessonDocReader`, `SuggestionRepo`, `SafetyFlagRepo`, `AlignmentRepo`, `Clock`); no `pg`, no SDK import (the boundaries lint from NL-01 checks `packages/core`). Callers: `CheckJobRunner` (NL-81), `CollabCommandHandler.lock_and_snapshot` (NL-106), `ApproveService` (NL-53), and `CompileCheckNode` (NL-29) at draft time.
`load(lesson_id, lesson, content_hash) → CheckContext`. The lesson content is **passed in** (the stored derived row for the worker, the freshly stored row at Submit, the frozen snapshot at Approve); the loader never reads the lesson itself from storage, so the same function checks exactly the content its caller names.
- `row`, `arc_header`: `outlines.row_context(outline_version_id, lesson_id, null)` (the version's stored choices, since this is outside a run). The outline version is the unit's `latest_outline_version_id` for the unit the lesson id belongs to (the lesson id minus its last segment). **Open item for the orchestrator (a DO-4 gap):** `load` has no outline-version argument, so a re-upload after generation changes the row the checks compare against; the clean fix is to pass the version (or read it from the lesson's version provenance) and is left to a `CHG`; until then this ticket resolves the latest version and states it in the code comment and AC-9.
- `allowed_codes`: the row's `focus_codes`, `eld_codes` and `msls_codes` expanded to their listed leaves with `standards.index().leaves_of`; `standards`: `standards.texts(allowed_codes ∪ the codes in lesson.front_matter.standards)`.
- `text_cards`: `lesson.text_cards`; `links`: the row context's `lesson_link` records.
- `linked_lessons`: for each `graph.dependencies(lesson_id)` entry and each `graph.dependants` lesson, `reader.latest_derived(id)` (the other lesson's **stored** row, R-28 as amended); a linked lesson with no stored doc is omitted.
- `pending_suggestions`: `suggestions.pending_for(lesson_id, clock.now())` (expired ones excluded); `safety_flags`: `flags.open_for(lesson_id)`; `confirmations`: `alignment.for_lesson(lesson_id)` rows whose `origin` is `narrowed` or `added`.
- A lesson with no outline row raises `InvariantViolation` with the lesson id (a data fault, never a silent empty context).
Must not: read or write the lesson being checked; hold state between calls; call `run_checks` (callers do); edit `registry.ts`, `policy.ts`, `gates.ts` (NL-20) or any repository.
