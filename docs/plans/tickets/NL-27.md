### Story
US-6 — As an outline author (P-2), I need to choose which rows to generate, see the prompt version the run will use, and set a spend cap, then start the run, so that a unit is generated once, under a ceiling, from a pinned prompt and a pinned set of intake choices.

### What to build
**1. Pure run machine (`packages/core/src/lifecycle/run-machine.ts`, DO-4 §8 *lifecycle*).** `derive_run_state(jobs, run: RunStateInput)`: `cancelled` flag → `cancelled`; `capped` → `capped`; `paused` → `paused`; plan not stored → `planning`; every lesson/candidate job terminal and all `ready` → `complete`; every job terminal with at least one `generation_failed` or cancelled → `partial`; otherwise `running`. `tile_state(job)`: `queued`→`queued`, `running`→ the job's stored step (`planning|drafting|checking|repairing`), `ready`→`ready`, `generation_failed`/`cancelled`→`failed` (OpenAPI `TileState`). `decide_run_control(current, action)` (CON-7): `cancel` from planning/running/paused → `cancelled`, `cancel_jobs true`; `retry_failed` only from `partial` → `running`, `requeue_failed true`; `resume` only from `paused` → `running`; anything else, and any action on `cancelled`, `capped` or `complete`, → `INVALID_TRANSITION`. Pure: no I/O, no clock.
**2. Run repository (`packages/db/src/repos/runs.ts`, DO-4 §3.5).** `PgRunRepo implements RunRepo` with every method of the port (NL-30, NL-31 and NL-78 use the others): `insert_run`, `get`, `find_by_idempotency_key(user_id, key, within_hours)`, `lock_for_update` (`SELECT … FOR UPDATE`), `set_state`, `mark_capped` (state `capped` + `capped_by`, one statement), `pinned_choices` (reads `run.choices_json`), `mark_plan_failed` (run → `paused`, `paused_check "unit_plan"`), `store_unit_plan` (sets `unit_plan.entries_json`, `state stored`, `run.plan_stored_at`, run `running`, in one transaction), `unit_plan`, `summary_rows`, `active_runs`. Tables `run`, `unit_plan` from NL-08.
**3. Service (`apps/web/src/server/services/run-service.ts`, DO-4 §5 `RunService`).** Create the file with the **full** DO-4 constructor `(runs, queue, outlines, states, prompts, spend, calls, audit, tx, ids, clock, settings)` so NL-78 adds `progress`, `control`, `plan`, `summary` without touching it (those methods throw `NotBuiltYet("NL-78")` here). `start(user, req, idempotency_key)` in this order (INTERFACE shared guarantee 11, then CON-5's list): author only; a repeated `Idempotency-Key` within `IDEMPOTENCY_WINDOW_H` (24) for the same user returns the first run and starts nothing (taken under `pg_advisory_xact_lock('run:start:'||user||key)`); `INVALID_REQUEST` for a trial without `lesson_id`, `rows` naming a row that is not a lesson row, `unfinished_of_run` naming a run of another outline version, `cap_usd <= 0`; `NOT_FOUND` for an unknown outline version or prompt version; `VALIDATION_INCOMPLETE` (`details.errors_unconfirmed`) from `generate_gate(outlines.generate_gate_inputs(...))`; `DAY_CAP_REACHED` (`details.scope` `user`|`project`, `details.remaining_usd`) from `spend.check_day_cap(user_id, cap_usd)`. Then **one** `tx.with_tx`: `insert_run` with the pinned prompt version, the copied intake choices and `choices_hash` (sha256 of their canonical JSON), the lesson links copied into the run's `unit_plan` row, `idempotency_key`; `states.ensure_lessons(rows_in_scope, unit_id)`; `queue.create_run_jobs` (a full run: one `unit_plan` job plus one `lesson` job per lesson in scope; a trial: one `candidate` job, no plan job) with each job's `idempotency_key = sha256(run_id, lesson_id, prompt_version_id, schema_version)`; one `audit_event` `run.start`. After commit it issues `NOTIFY lesson_job`. Returns the OpenAPI `Run` (`state "planning"`, `spent_usd 0`). The dialog's suggested cap comes from `run_cap_for` (NL-35) and is not computed here.
**4. Route (`apps/web/app/api/runs/route.ts`)**: `POST` via `with_route` (author, `StartRunRequest`, success 201), reading the `Idempotency-Key` header. The service object comes from `getWebServices().runs`; the wiring file `wiring/runs.ts` is NL-78's, so this ticket's route tests inject a service built from fakes.
Must not: start a lesson job before a plan exists (the queue enforces it, NL-28); write a spend row; call a model; edit `container.ts`, `wiring/runs.ts`, `package.json`, DDL, `prompt-service.ts`.
