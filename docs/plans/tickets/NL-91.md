### Story
US-33 — As an author or approver I see which standards the unit teaches, practises and assesses, so that I can see a standard that is never assessed before a state reviewer does. (Cut #4: if cut, the route is absent and the wiring returns `coverage: None`.)

### What to build
Write the coverage read.

- `apps/web/src/server/services/coverage-service.ts` — `CoverageService.coverage(user, unit_id) -> CoverageMatrix` (CON-22, DO-4 §5): **one query** over stored alignment links (`AlignmentRepo.coverage_rows(unit_id)`) joined to `standard` for the official text, never a model. Response `standards` (`code`, `official_text`, `never_assessed`), `lessons` (`lesson_id`, `number`) and `cells` (`code`, `lesson_id`, `roles` any of I / P / A, `confirmed_by` `person | judge_only | generator_only`, `source` `approved | working`). A lesson's cells read its latest approved snapshot where one exists (`source approved`), else its stored derived row (`working`). A code is `never_assessed` when no cell has role `A`.
- `apps/web/app/api/units/[unitId]/coverage/route.ts` (GET) through `with_route`; every role reads; unknown unit → `NOT_FOUND`.
- `apps/web/src/server/wiring/coverage.ts` — `wire_coverage` returns `CoverageWiring{coverage: CoverageService}`. It lives in its **own file**; it does not edit `BoardService` or `wiring/metrics.ts` (DO-4 §5, A18: this resolves the slice plan's `board-service.ts` coverage-method row in favour of DO-4; the dependency on NL-54 stays harmlessly).

Per-cell `source` (`approved` / `working`, CON-22) comes from `CoverageCell.source`, chosen inside `AlignmentRepo.coverage_rows` in its one query (NL-43; DO-4 §3.5, §13 R-11); the service groups cells by `(code, lesson_id)` into `roles` and passes `confirmed_by` and `source` through unchanged.

**Must not:** call a model; write anything; return minutes or reviewer names; edit repositories you do not own.
