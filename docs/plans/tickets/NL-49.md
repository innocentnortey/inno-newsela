### Story
US-36 — As the builder who must show the tool works, I need one runner that executes a named suite, stores one result per case with its source, and writes a report naming the code version, so later tickets only fill suites. Platform work: S1…S14 and the load scripts hang on this.

### What to build
**1. Evidence repository** — `PgEvidenceRepo` in `packages/db/src/repos/evidence.ts` (DO-4 §3.5): `start_eval_run(NewEvalRun)`, `add_case_result`, `finish_eval_run(id, passed, total, report_path)`, `insert_probe_run`, `insert_experiment_run`, `ops_event`, over `eval_run`, `eval_case_result`, `probe_run`, `experiment_run`, `ops_event` (NL-08's tables).
**2. Runner** — `evals/src/runner.ts` `EvalRunner(evidence, suites, clock).run(suite, opts) → EvalRunSummary` (DO-4 §9): starts an `eval_run` (suite, `git_sha`, `prompt_version_id`, models, `provider_mode`, `case_set`), scores each `EvalCase` through `EvalSuite.score`, stores one `eval_case_result` per case (provenance, source, guards, expected, actual, failure category), finishes with `passed`/`total`, writes `evals/reports/<kind>-<git-sha>.md` (kind `golden` for S1/S2/S3/S7, `grounding` for S4, `faults`, `full-run`, …) naming git SHA, prompt version, model ids and *n* (EV-R1).
**3. CLI** — `evals/src/cli.ts` behind the root scripts: `npm run eval:golden -- --suite intake,checks|drafts|safety [--repeat n] [--provider stub|real]`, `eval:grounding` (S4), `eval:faults` (S6), `eval:full-run`, `eval:seed`, `eval:heldout`, `eval:judge-calibrate`, `load:spike` mapped to suites per DO-3 §9; suite names `intake`→S1, `checks`→S2, `drafts`→S3, `safety`→S7. Exit code non-zero on any failed case in a suite whose acceptance floor is 1.00, and **non-zero for a suite with zero cases** (a shell must never report green).
**4. Shells** — `evals/src/suites/s1.ts … s14.ts`, each an `EvalSuite{name, cases() → [], score → throws NotImplemented}` registered in the runner; and `load/spike.ts` (`run_spike`), `load/http-mix.ts`, `load/yjs-mix.ts` exporting their DO-4 §9 signatures and throwing `NotImplemented` naming the filling ticket. Later tickets fill: s1, s7 NL-84 · s2, s4 NL-85 · s9, s13 NL-86 · s6 NL-107 · s3 NL-109 · s10 NL-92 · s12 NL-111 · s5 NL-125 · s8 NL-127 · s14 NL-118/119 (collision map W4–W7); this ticket never edits a suite body.
Must not: call a model or the network, store a provider key or a restricted-folder path in a report, write DDL, or edit another ticket's suite file once it is filled.
