### Story
US-35 / US-28 — As an approver I export a unit's approved lessons as a versioned JSON file in the published schema, and exporting twice with no change gives the same file, so Newsela can import what was approved and nothing else. Cuttable (PD-17 #5): if the cut fires the service is dropped and `wiring/exports.ts` stays a stub.

### What to build
Implement `ExportService` in `apps/web/src/server/services/export-service.ts` (DO-4 §5) and routes `apps/web/app/api/units/[unitId]/exports/route.ts` (`listExports` GET; `createExport` POST → 200 same or 201 new) and `apps/web/app/api/exports/[exportId]/download/route.ts` (`downloadExport`), role `approver` only. `wiring/exports.ts` is NL-102's.
**`list`**: `included[{lesson_id, approved_hash}]` from `LessonVersionRepo.approved_snapshots(unit_id)` filtered so a **dependent lesson is included only while every lesson it links to is approved** (`LessonGraphRepo`); `held_back[{lesson_id, reason, waits_on}]` (e.g. "Lesson 4 waits on Lesson 5"); `exports[{export_id, version_number, created_at, created_by, lesson_count, payload_hash}]` from `ExportRepo.all_for_unit`.
**`create`**: one `TxRunner.with_tx` under `pg_advisory_xact_lock('export:' || unit_id)` (two simultaneous calls serialize; the second sees the first's result): build the payload (`ExportBundleFile` from `packages/schema/src/export.ts`: approved snapshots' lesson JSON and hashes only, canonical key order) → `payload_sha256`; if equal to `ExportRepo.latest(unit_id).payload_sha256` return that export with `same_as_previous: true` (200) and write **nothing** (no row, no state change, no audit row); else `ExportRepo.insert` (next `version_number`, `lesson_versions`, `held_back`), move each newly included lesson to `exported` (`LessonStateRepo.set_state`; an `exported` lesson stays in later exports while its approved snapshot stands) and `AuditLog.append` (`export.create`), 201. The constructor's `states: LessonStateRepo` makes that move (DO-4 §5 `ExportService`, §13 R-6; CON-23 moves lessons to `exported` in the same transaction). The `approved → exported` move writes one `review_event` per newly exported lesson (actor = the caller), in the same transaction (DO-3 §6: every lesson move goes there; DO-4 §5 `ExportService`, §13 R-6).
**`download`**: `ExportRepo.payload(export_id)` → the JSON document; unknown id → `NOT_FOUND`. The payload must validate against `docs/contracts/lesson-export.schema.json` (emitted by NL-09's `npm run schemas:emit`; this ticket does not write that file).
Must not: read a draft, derived row, candidate or non-approved snapshot; include prompts, raw model output, provenance model fields beyond what the schema lists, emails, review notes or minutes; call the network.
