### Story
US-15 — As a reviewer I edit together with a colleague and know my time is counted fairly, so that two of us can finish a lesson together without losing each other's work. Platform: this is the only process that writes lesson content (R-26), and the one that refuses typing after Submit.

### What to build
Build the Hocuspocus server's behaviour (the socket on `lesson:<lesson_id>`, CON-12). The internal command routes and the Submit freeze are NL-105 and NL-106; `main.ts` and `health.ts` are NL-07 / NL-83.

- `frozen-docs.ts` — `FrozenDocs` (in memory, one process, PD-9): `is_frozen`, `freeze`, `unfreeze`, `seed(lesson_id, state)` (frozen unless `is_editable(state, "reviewer")`).
- `auth.ts` — `CollabAuthenticator.authenticate(SocketAuthRequest)`: reads the `ls_session` cookie (`SESSION_COOKIE_NAME`) from the upgrade request, `SessionRepo.resolve`; expired, revoked or unknown → `DomainRefusal(UNAUTHENTICATED)` and the connection is refused before the document loads; loads the lesson's state, builds `SocketContext{user, lesson_id, lesson_state, read_only}` from `WriteGuard.can_write`, seeds `FrozenDocs` on the document's first connection.
- `permissions.ts` — `WriteGuard.can_write(role, state, lesson_id)` at connect (read-only unless `is_editable(state, role)` and not frozen; **only `reviewer` connections write**, authors and approvers read) and `WriteGuard.on_update(ctx, frozen)` per message from Hocuspocus `beforeHandleMessage`: a frozen document or a read-only connection is refused **before the update is applied**; the caller sends `AckBroadcaster.refused(socket_id, LESSON_LOCKED, message, refused_from)` with the client's state vector before the refused update, then drops the update (SP-2 option A).
- `persistence.ts` — `LessonPersistence.load` (latest `lesson_doc`; an unknown `schema_version` fails loudly with the lesson id) and `store` (`onStoreDocument` after `STORE_DEBOUNCE_MS` 2000, max `STORE_MAX_DEBOUNCE_MS` 4000): `ydoc_to_lesson` → `content_hash` → `LessonDocStore.store` in **one transaction** (Y.Doc bytes, derived JSON, hash, state vector, coalesced `check_job`, last editor, audit; mints `store_id`) → `AckBroadcaster.stored`.
- `acks.ts` — `AckBroadcaster`: stateless messages `{type:"stored", content_hash, state_vector, stored_at}`, `{type:"mode", mode, state}`, `{type:"refused", code, message, refused_from}` exactly as CON-12's `x-collaboration-channel`.
- `wiring/server.ts` — fills the server half of the collab composition (auth, guard, frozen set, persistence, acks) from `CollabDeps` with `PgSessionRepo`, `PgLessonRepo`, `PgLessonDocStore`, `PgLessonDocReader`, `PgAuditLog` (the command-handler half is `wiring/commands.ts`, NL-105).

**Must not:** accept a write from a non-reviewer, an unauthenticated or a frozen document; persist an edit that was refused; start a model client or require a provider key (Metz S4); log cookies, tokens or lesson text; close connections to enforce the freeze (SP-2 rejected option B).
