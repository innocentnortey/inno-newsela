### Story
US-16/US-17/US-20 (with US-14, US-18, US-24, US-25) — As a reviewer I see a new blocking issue within seconds of an edit, so that what blocks Submit and Approve is always current. Platform: after every durable store, the deterministic suite runs in its own worker lane so checks never wait behind generation.

### What to build
Build the after-store check lane and fill its wiring.

- `apps/worker/src/checks/check-job-runner.ts` — `CheckJobRunner.run_once() -> CheckRunReport | null` (DO-4 §6): `CheckQueue.claim(lease_ms)` → `LessonDocReader.latest_derived` (the **stored derived row**, never the live Y.Doc; skip and `finish` if a newer hash is already queued) → `CheckContextLoader.load` → `run_checks(CHECK_RULES, CHECK_POLICY)` (NL-20/38/39/40/41) → in one `TxRunner.with_tx`: `IssueRepo.replace_for_hash` (carries resolutions to an identical finding; the rest `cleared_by "fix"`) + `AlignmentRepo.replace_for_hash` for that hash → `CheckQueue.finish` → `LessonGraphRepo.dependants(lesson_id)` and `CheckQueue.enqueue` for each dependant whose `cross_lesson_link` result may change. Returns `CheckRunReport{blocking, confirmation, advisory, dependants_requeued, duration_ms}`.
- The loop that calls it: polls every `CHECK_POLL_MS` (500), claims from its **own lane — independent of the generation semaphore** (`GENERATION_CONCURRENCY`), renews/expires leases like the generation lane, and on SIGTERM stops claiming and finishes the check in hand.
- `apps/worker/src/wiring/checks.ts` — `wire_checks` fills `CheckWiring{check_runner}` from `WorkerDeps` with `PgCheckQueue`, `PgLessonDocReader`, `PgIssueRepo`, `PgAlignmentRepo`, `PgLessonGraphRepo`, `CheckContextLoader`, `CHECK_RULES`, `CHECK_POLICY`, `TxRunner`.

**Must not:** call a model (checks are deterministic: zero `model_call` rows); write a partial issue set (one tx); write content; block on or share a slot with generation; edit rule modules (NL-20/39/40/41), `CheckPolicy` values or `CHECK_RULES`.
