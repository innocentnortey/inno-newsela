### Story
US-10 — As an author I change the guidance part of the prompt and try it on one lesson first, while the locked rules stay out of reach, so that I can improve drafts without breaking the rules that keep them safe. (Cut #7: if cut, the list and the locked layer remain, NL-34.)

### What to build
Add the write half of CON-24 to the `PromptService` NL-34 created (same file, **save path only**; the list path and wiring are NL-34's) and prove the trial path end to end.

- `PromptService.save_guidance(user, req: SaveGuidanceRequest) -> GuidanceVersion` (`saveGuidance`): role `author`; in one `TxRunner.with_tx`: validate `reason` non-empty (`REASON_REQUIRED` 422) and `guidance_text` ≤ 8,000 characters (`INVALID_REQUEST` 400 naming the field); `PromptRepo.insert_guidance(NewGuidanceVersion{base_version_id, guidance_text, reason, author_id}, diff)` where the repo row-locks and raises `STALE_BASE` 409 with `details.latest_version_id` unless `base_version_id` is the latest guidance version; compute the text `diff` against the base; `AuditLog.append`. The new version is immutable; running runs keep their pin (`pinned_by_runs`).
- `POST` handler added to `apps/web/app/api/prompt-versions/route.ts` through `with_route`.
- **Try on one lesson** is not a new endpoint: it is `startRun` with `kind "trial"` (NL-27) naming the new `prompt_version_id`, which creates one candidate job (CON-5 / CON-16): the candidate is a new version and never overwrites the current lesson. This ticket owns the test that proves the chain.

**Must not:** write the locked layer from any route (R-38, GR-18); edit a saved version; let a save change an already running run's pinned version; add a route other than POST on `prompt-versions`.
