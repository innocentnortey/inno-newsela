### Story
US-7 — As an author I watch the lessons being written (one tile per lesson with running cost) so I can see the run is healthy. US-8 — I recover from failures without paying twice (cancel, retry failed, resume). US-9 — I read the unit plan first. US-32 — I read the run summary (cost, retries, failures, calls lost, brakes fired).

### What to build
Add four methods to the `RunService` NL-27 created (`start` is NL-27's; **same file, methods plus wiring**) and fill the web wiring file `wire_runs` (DO-4 §12) so `services.runs` is a real object:

- `progress(user, run_id) -> RunProgress` (CON-6): one indexed read of the run's `lesson_job` rows (≤ 47) plus the run row; per tile `tile_state(job)` (DO-4 §8 *lifecycle*), `attempts`, `repair_used`, `truncation_retry_used`, `failure_reasons` (the OpenAPI `FailureReason.check` vocabulary), `cost_usd`, `openable` (true only for `ready`); run-level `state`, `paused_reason`, `capped_by` (`RunRow.capped_by`, same three values as CON-6, no mapping), `spent_usd`, `reserved_usd`, `cap_usd`, `concurrency_cap` (`GENERATION_CONCURRENCY`), `queued_ahead`, `counts_by_tile_state`, `updated_at`.
- `plan(user, run_id) -> UnitPlan` (CON-8): `UnitPlanRow` + the run's copied `lesson_links`; `state` `planning | stored | failed`.
- `control(user, run_id, req) -> RunControlResult` (CON-7): role `author`; in one tx `RunRepo.lock_for_update` (the row lock that stops two clicks both applying) → `decide_run_control(current, action)` (`INVALID_TRANSITION` with `details.state`) → `JobQueue.requeue_failed` / `JobQueue.cancel_run(run_id, "cancelled")` / resume (re-queues a failed plan, `RunRepo.set_state`) → one `audit_event`. NOTIFY `lesson_job` after commit when jobs were requeued.
- `summary(user, run_id) -> RunSummary` (CON-21): totals from `ModelCallLog.totals_for_run` and `RunRepo.summary_rows`; `cost_per_ready_lesson_usd` = total cost ÷ ready lessons (empty when none), `calls_lost_in_flight`, `brakes_fired`, `truncation_retries`, `p95_minutes_per_lesson`, `target_minutes_per_lesson 5`, `report_path`; a mismatch between run spend and call sums sets the *trace incomplete* flag (DO-6 completeness check 1).
- Routes under `apps/web/app/api/runs/[runId]/` (`progress` GET, `plan` GET, `actions` POST, `summary` GET) through `with_route`; `apps/web/src/server/wiring/runs.ts` builds `RunService` from `WebDeps` with `PgRunRepo`, `PgJobQueue`, `PgOutlineRepo`, `PgLessonRepo`, `PgPromptRepo`, `PgSpendLedger`, `PgModelCallLog`, `PgAuditLog`, `TxRunner` (all earlier-wave real objects) and `RunWiring.runs`.

**Must not:** stream (progress is polled, shared guarantee 9); recompute spend from anything but stored rows; add a "raise the cap" action (UXP-5); write any row on a read or on a refusal.
