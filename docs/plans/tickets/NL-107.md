### Story
US-8 — As an author I need a run that survives a killed worker, a rate limit or a spend cap without paying twice or losing lessons, so that I can trust a 47-lesson run to finish. This ticket proves it with a script on a stubbed provider (HP-7, S6).

### What to build
Build the HP-7 fault-injection script and the S6 suite module that records its results (A20, DO-3 §4 row `ops/faults/run-faults.ts`, DO-4 §9 `run_fault_suite`, `FaultSuiteReport`, `EvalOptions`).

- Files: `ops/faults/run-faults.ts` (+ helpers under `ops/faults/`), `evals/src/suites/s6.ts` (fills NL-49's shell), report `evals/reports/faults-<git-sha>.md` (generated). Command: `npm run eval:faults` (declared by NL-01).
- It drives the **real worker runtime** (NL-79 wiring: real claim loop, recorder, spend ledger, store) against Postgres and `StubModelClient` on a seeded 47-lesson run (CON-5 start via the real route, so the pinned prompt, cap and idempotency key are the real ones). Four tests, each its own stub run:
  1. **kill** — SIGKILL the worker process after at least 10 lessons are stored; restart it; the run resumes at the next unfinished lesson (R-16, SD-7.2).
  2. **429** — the stub answers `rate_limited` for its first 8 calls, then healthy; no lesson may be lost to the 429 alone.
  3. **truncation** — the stub stops one lesson's first call with `max_tokens` at 32,000; exactly one retry at the raised 48,000 (SP-1); a second truncation ends that lesson `generation_failed` with reason `truncated`.
  4. **cap** — the run cap is set below the stub run's total cost; settled spend never exceeds the cap and the run ends `capped` (PD-14).
- Each invariant is stored as one `eval_case_result` under one `eval_run` (via `EvidenceRepo`); the report names git SHA, prompt version, model IDs (the stub's), `n`, and the stub-versus-real flag. `FaultSuiteReport` fields are filled from the stored rows, not from process memory.
- Must not: call a real provider (`provider_mode` is `stub` only; the script refuses `real`), edit worker or recorder code (A9/A7 own it; a defect found is a failing invariant and a bug ticket, not a patch here), or write a key or password to a report.
