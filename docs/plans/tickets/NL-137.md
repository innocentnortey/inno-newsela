### What to build
Prove the release candidate and tag it. **Check and report; do not fix.** If anything fails, file a build-loop ticket and stop: this ticket changes no source, configuration, test or lockfile.

**Lane flag for the orchestrator.** The plan keeps this ticket `lane::direct`: it runs commands, takes a backup file and commits a Markdown record. If a check forces a change to config that code reads (Compose file, `render.yaml`, settings defaults, scripts), that change is a separate `lane::build-loop` ticket and this one resumes after it merges; do not edit it here.

Steps, in order, each stopping at the first red (`build-loop-test-scope.md`: cheapest first):
1. **Clean tree on `main`.** `git status --porcelain` empty; no unpushed commit: `git log origin/main..main` empty.
2. **Full suite (EV-R3).** `npm run lint`, `npm run typecheck`, `npm test` (all projects, not affected-only), `npm run eval:golden -- --suite intake,checks` (no model calls), `npm run test:e2e`. Record counts and wall time.
3. **Clean Compose up from the committed config.** `git clone . /tmp/nl137 && cd /tmp/nl137 && docker compose config -q && docker compose -p nl137 up -d --build`, wait for healthy, then run the migrations and seed (`npm run db:migrate`, `npm run db:seed` through the documented route). Tear down at the end with `down -v` (never touch other projects' containers).
4. **Start events (WF-38).** Each process (web, worker, collaboration server) wrote one `ops_event` start row with a non-empty `build_id` (the local git SHA, or `RENDER_GIT_COMMIT` on Render).
5. **Network exposure (OBS-10).** Postgres is not published outside the Compose network: `docker compose -p nl137 ps` shows no host port for it, and a connection to the host's 5432 from outside the network is refused.
6. **One backup (WF-40, PD-30).** On the real stack that holds the final full-run data (not the throwaway clone): `npm run ops:backup`; check the `ops_event` row (dump path, size, SHA-256) and `pg_restore --list` reads the dump. The dump file is git-ignored and stays on the VPS.
7. **Repository facts.** `LICENSE` exists at the root (GR-17: all rights reserved, evaluation use permitted); `render.yaml` is committed and no Render service was provisioned for it (PD-15 option D); no file under `docs/source/restricted/` is tracked (`git ls-files docs/source/restricted | wc -l` = 0).
8. **Tag.** `git tag release-<short-sha>` and push `origin main --tags` only (factory mode, PD-34). Write `docs/delivery/<YYYY-MM-DD>-release-check.md` with the SHA, command outputs (counts, not logs) and the backup row. Lane guard (`ticket-lanes`): before committing, `git diff --name-only` must list no file that code or tests read (source, tests, schemas, migrations, prompts, settings, lockfiles, fixtures, CI); if it does, stop, relabel the ticket `lane::build-loop` and report. Commit straight to `main` (factory mode, PD-34).
