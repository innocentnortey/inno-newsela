### What to build
Build the generator for the experiment kickoff page (zero-to-hero `ARTIFACT-MAP.md` §9 row 1).

- Files: `evals/src/kickoff/**` (`cli.ts`, `collect.ts`, `render.ts`, tests). Run: `npx tsx evals/src/kickoff/cli.ts --out docs/artifacts/<date>-experiment-kickoff.html`. The npm alias `eval:kickoff` needs a `package.json` line, which A0 owns: raise it to the batch merge agent; do not edit `package.json`.
- It reads only code and tracked docs, never the database or a model:
  1. **Flow:** the worker pipeline's node list from `apps/worker/src/generation/nodes/**` and the decision table of `route_after_checks` (DO-4 §6), drawn as inline SVG or an HTML list.
  2. **Prompts verbatim with versions:** every locked layer and renderer from `packages/prompts/**` (plan, draft, repair, assist, judge), each with its version string and SHA-256, and the guidance layer v1 as seeded.
  3. **Chosen approach:** the HP-1 card text and SP-1's settled values (model, effort, max_tokens, concurrency, per-run cap, timeout).
  4. **Failure types so far:** the FC-1…FC-14 table parsed from `docs/design/eval-plan.md` *Failure categories*, and any `FT-N` found in `docs/testing/error-analysis/` ("none yet" before NL-120).
  5. A footer: git SHA, generator version, generation time.
- Output obeys `html-files-not-artifacts`: a complete standalone HTML file (doctype, `lang`, charset, viewport, title), inline CSS, no external script, both light and dark readable; the report to Innocent gives the path and `open` command.
- **Registers WF-46** (class development-experiment) in `docs/design/observability.md`: the registry row was added at spec time (orchestrator note); this ticket keeps it true and keeps `design_outputs.py check-obs` at exit 0.
- Must not: read `docs/source/restricted/`, paste prompt text by hand (the page is built from the files), or touch any prompt or check (A7/A6 own them).
