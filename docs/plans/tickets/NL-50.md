### Story
US-23 — As a reviewer I select a passage, add a note and get a tracked rewrite suggestion held outside the lesson; nothing AI-written enters the lesson until I accept it, and an accepted change is attributed to me and tagged `ai-assist`. Cuttable (PD-17 #8): if the cut fires, the service is dropped and `wiring/assist.ts` stays a stub.

### What to build
Implement `SuggestionService` in `apps/web/src/server/services/suggestion-service.ts` (DO-4 §5) and routes `apps/web/app/api/lessons/[lessonId]/suggestions/route.ts` (`listSuggestions` GET, `requestSuggestion` POST → 201) and `…/suggestions/[suggestionId]/decision/route.ts` (`decideSuggestion`), role `reviewer` for the writes.
**`request`**: precedence role → lesson `NOT_FOUND` → `LESSON_LOCKED` (not editable; assist is never offered on approved lessons, GR-7) → render `PromptRenderer.render_assist(AssistPromptInput{prompt: PromptRepo.current, selected_text, note, section_name})` (only the selected text, the note and that lesson's context reach the model; the text is delimited data, never instructions) → `PaidCaller.call` (alias `ASSIST`, `run_id` null, `user_id` the reviewer, timeout `ASSIST_CALL_TIMEOUT_MS` = 20 s) → `SuggestionRepo.insert` with `expires_at = now + SUGGESTION_TTL_MIN` (30) and the `model_call_id` → `AuditLog.append` (`suggestion.request`) in one tx. `SpendRefused` and `ProviderError` both surface as `MODEL_UNAVAILABLE` (503; `details.reason` `spend_cap` for the first) with nothing stored. `selected_text` over 2,000 characters → `INVALID_REQUEST`.
**`decide`**: not `pending` (accepted, rejected, closed or expired) → `INVALID_TRANSITION` (409). `accept` → `CollabCommands.apply_edit(EditCommand{edit: SuggestionAcceptEdit{suggestion_id, anchor, expected_text = the STORED selected_text, replacement_text = suggested_text}, tag "ai-assist", actor = the acceptor})`; the collaboration server resolves the anchor against the live document and applies only if the text there equals `expected_text`; the browser's `anchored_text_now` is a hint and is never used for the check. `ANCHOR_CHANGED` → `decide(closed)` and 409; `COLLAB_UNAVAILABLE` → suggestion stays `pending`. Success → `decide(accepted)` + audit (`suggestion.accept`) and the new `content_hash`. `reject` → `decide(rejected)` + audit. `list_pending` excludes expired (a pending suggestion blocks Submit and Approve — NL-39's `suggestion_pending` rule reads it). Additive constructor change to record in the dev log: a `LessonDocReader` to resolve `section_name` from the stored derived row (DO-4 §5's constructor has none).
Must not: write lesson content from the web process (CON-G3), accept a suggestion by the browser's text, send student work or other lessons' text to the model, log `selected_text`, `suggested_text` or the prompt outside `model_call`, edit `wiring/assist.ts` (NL-116) or another route folder.
