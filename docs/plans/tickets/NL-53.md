### Story
US-24 — As a reviewer I submit a lesson when nothing is blocking, to freeze it, so that the approver reads exactly what I sent. US-25 — As an approver I approve one pinned version on its evidence, so that "approved" means a named person approved exactly that text. US-26/27/28/31 — send back with a reason, approve linked lessons in order, reopen without breaking dependants, rate the draft at Approve.

### What to build
Implement the server side of every lesson move and the approval gate, and fill the review wiring so all six review-area services are real objects.

- `apps/web/src/server/services/transition-service.ts` — `TransitionService.transition(user, lesson_id, req)` (DO-4 §5). Precedence (CON-18): `transition_roles(action)` (`ROLE_FORBIDDEN`) → `LessonStateRepo.get` (`NOT_FOUND`) → `decide_transition(action, role, from_state, note, reason, tag, rating)` (`INVALID_TRANSITION`, then `NOTE_REQUIRED` / `REASON_REQUIRED` / `RATING_REQUIRED`) → per action: `start_review` (one tx: `set_state(in_review, reviewer)` + `review_event`); `submit` → `CollabCommands.lock_and_snapshot` (NL-106 does the freeze; its refusals `NOT_STORED`, `BLOCKED`, `CONFIRMATION_OPEN`, `SUGGESTION_PENDING` pass through with the same code and `details`; unreachable → `COLLAB_UNAVAILABLE`, nothing changed); `approve` → `ApproveService.approve`; `withdraw` / `request_changes` / `reopen` → one tx with the lesson row locked (reopen writes a new `lesson_version` with `derived_from_version_id`) → `CollabCommands.set_mode(editable)` **inside the open tx** → commit (DO-4 §5 `TransitionService`, §13 R-10). `CollabUnavailable` → rollback → `COLLAB_UNAVAILABLE` (503), nothing changed (CON-18). If the commit itself fails after `set_mode` succeeded: best-effort `set_mode(read_only, from_state)`, one `InvariantViolation` log line, then the error envelope (a collab restart re-seeds `FrozenDocs` from the stored state). The `review_event` id is the response's `audit_id`.
- `apps/web/src/server/services/approve-service.ts` — `ApproveService.approve` (**the approval-integrity code**): one tx with the lesson row locked (`lock_for_update`): `decide_transition` re-checked on the locked row → `LessonVersionRepo.latest_snapshot` (kind `submit`) and the pin (`snapshot_hash` AND `snapshot_state_vector`) else `STALE_PIN` → `CheckContextLoader.load(snapshot.lesson, snapshot.content_hash)` + `run_checks(CHECK_RULES, policy)` on the **snapshot** → `merge_resolutions(findings, IssueRepo.resolutions_for(lesson_id))` → `GateState{pending_check false, pending_suggestions, open_confirmations, last_editor_id, approver_id, four_eyes_enabled, dependencies}` → `approve_gate` in order `FOUR_EYES → SUGGESTION_PENDING → BLOCKED → CONFIRMATION_OPEN → DEPENDENCY_UNAPPROVED` → `write_snapshot(kind approve, dependency_record)` + `set_state(approved)` + `append_review_event` + `MetricsWriter.write_first_approval` → commit. No collaboration hop (already frozen). A refused call rolls back and writes **no row of any kind**; one log line only.
- `apps/web/app/api/lessons/[lessonId]/transitions/route.ts` through `with_route` with `RouteSpec.request_schema = "TransitionRequestInput"` (NL-11's Zod mirror, DO-4 §5: `rating`, `note`, `reason` optional so the card's codes are reachable; do not edit it).
- `apps/web/src/server/wiring/review.ts` — `wire_review` fills `ReviewWiring {lesson_reads, issues, slots, candidates, transitions, approvals}` from `WebDeps` with the real `Pg*` repositories, `HttpCollabCommandClient`, `CheckContextLoader`, `CHECK_RULES`, `CHECK_POLICY`, `MetricsWriter`, `FOUR_EYES_ENABLED`.

**Must not:** let any role approve its own submit when `FOUR_EYES_ENABLED`; approve without a matching pin; trust the client's view of blocking issues; write content (only the collaboration server writes content); bulk anything (one lesson per call, GR-6); edit `packages/core/src/{lifecycle,checks}/**` or the collab server. Settled (DO-4 §13 R-10): `set_mode` runs inside the transaction, so a collaboration failure rolls the move back, as CON-18 promises.
