### Story
US-11 — As an author or reviewer I need to know which lesson to review next, so that I spend my time where a lesson is furthest from approvable. US-12 — I see that a lesson depends on another. US-30 — I see reviewer time per approved lesson honestly: with its n, the fast-approval guard, "approved k of N" and the caption, never by person.

### What to build
Write `BoardService` and fill the metrics wiring. `HeartbeatService`, `MetricsWriter`, the pure metrics code and `PgMetricsRepo` / `PgBoardReadRepo` are NL-48's (wave 3); this ticket reads them and owns:

- `apps/web/src/server/services/board-service.ts`: `board(user, unit_id, state?) -> UnitBoard` (CON-9) and `metrics(user, unit_id) -> UnitMetrics` (CON-10).
  - **Board:** `BoardReadRepo.board_rows(unit_id, state)` + `IssueRepo.counts_by_lesson(unit_id)`. Counts come from the stored `issue` rows of each lesson's latest *checked* hash; it never calls `run_checks`. `rollup` counts every lesson state over the whole unit even when `state` filters the rows. **Sort (UXQ-5):** `generation_failed` first as a group; then active lessons by `blocking_count` desc, `advisory_count` desc, `confirmation_count` desc, lesson order; `approved` and `exported` last in lesson order. `reviewer` is the reviewer who started the review (UXP-1); `send_back` (`tag`, `note`) from the latest `request_changes` `review_event`; `dependency_flags` from `lesson_link` rows: `waits_on` with status `slot_empty` or `waiting_for_source_approval` (UXP-2) and `source_reopened`. `judge_flag` is omitted until NL-110 supplies verdicts.
  - **Metrics:** `MetricsRepo.unit_metrics_rows(unit_id)` (frozen first-approval rows only) → `north_star`: `median_minutes` (empty when n = 0), `n`, `fast_approvals {count, of}` where a row counts when `active_minutes < g2_threshold_minutes` (the row's own stored threshold), `approved {k, total}`, the exact caption `No baseline yet (AQ-14). Measured with us as reviewers.`, `segment_label` such as `one reviewer, n = 3` when fewer than 3 distinct reviewers (GR-15). `quality` is the key present with value `null` while cut #6 is cut. Output never contains a person's name next to minutes.
- Routes `apps/web/app/api/units/[unitId]/board/route.ts` (GET, optional `state`) and `.../metrics/route.ts` (GET) through `with_route`; every role reads.
- `apps/web/src/server/wiring/metrics.ts` (`wire_metrics`, DO-4 §12): builds `BoardService`, `HeartbeatService` (NL-48's class, wired here) and `MetricsWriter` (consumed by NL-53 through `WebDeps`/review wiring) from `PgMetricsRepo`, `PgBoardReadRepo`, `PgIssueRepo`, settings; `MetricsWiring {board, heartbeats}`.

**Must not:** recompute a metric with a model or from live checks; return minutes joined to a name (GR-15, shared guarantee 8); edit NL-48's pure code or repos; add `coverage` (NL-91 adds one method later in this file; keep the class open for it).
