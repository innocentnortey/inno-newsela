### What to build
**Worker (`apps/worker`, DO-3 §2.4, §8, DO-4 §6 `build_worker_runtime`, `serve_health`).** `src/main.ts` exports `build_worker_runtime(settings: WorkerSettings): WorkerRuntime`: `Logger` → `WorkerDeps` (`apps/worker/src/deps.ts` + `deps-types.ts`, local structural `db`, `ids`, `clock`, `model_client` types, same reason and same NL-12 re-point as NL-06 §4) → `wire_generation`, `wire_checks`, `wire_judge` → health server → one `process.start` log line (`service: "worker"`, `build_id`). `src/wiring/{generation,checks,judge}.ts` are shells returning `{}` with a header naming the filler (NL-79, NL-81, NL-110). `src/health.ts` `serve_health(port)` answers `GET /healthz` 200 `{"status":"ok"}`; the Postgres check and the failure event are NL-83's (WF-39).
**Collab (`apps/collab`, DO-3 §2.5, DO-4 §7 `build_collab_runtime`).** `src/main.ts` builds `CollabDeps`, a Hocuspocus `Server` on `COLLAB_PORT` and mounts what `wire_collab` returns (nothing yet); `onRequest` dispatches by path: `/healthz` → `src/health.ts` shell (200), `/internal/*` → `src/commands/routes.ts` shell, everything else falls through to Hocuspocus. `src/wiring/collab.ts` and `wiring/commands.ts` are shells (fillers NL-80, NL-105); `src/commands/{routes,apply-edit,set-mode,lock-and-snapshot}.ts` are shells (`routes` NL-105, `lock-and-snapshot` NL-106, the other two NL-105). The `/internal/*` shell answers 503 with the error envelope code `COLLAB_UNAVAILABLE` and logs `internal.not_built`; it never returns 200 and never checks the token (NL-105).
**Both.** SIGTERM and SIGINT: stop accepting work, wait up to `DRAIN_GRACE_MS = 25000` [A] for in-flight handlers, close the server, exit 0; a second signal exits 1 at once. Collab never reads a model or spend setting (Metz S4).
Must not: implement a claim loop, a store, a guard or a command (their tickets do), add a route, touch `apps/web`, or write the `ops_event` start row (NL-23 passes the writer once NL-08 has merged).
