### What to build
Fill the two suite shells NL-49 created (`evals/src/suites/s1.ts`, `s7.ts`, each an `EvalSuite`, DO-4 §11) and add their cases. Both are **deterministic and model-free**; `EvalRunner` (NL-49) writes one `eval_case_result` per case and the report.

- **S1 intake golden** (`npm run eval:golden -- --suite intake`): for each case the normalizer, code resolver and `build_validation_report` (NL-15/16/17) run on the case input and the **expected fields** are compared exactly. Cases: the issued sheet (`docs/data/samples/g6-u4-lesson-outline.json` and the issued row samples; expected counts 47 teaching days, 1 unit conflict, 1 malformed code, 3 non-existent codes, 2 bad filenames, 7 ELD mismatches), SYN-2 (layout-shifted sheet, `synthetic-2026-10-24-syn2-layout-shifted.csv`), WP-5 (clean control: 0 errors, 0 warnings) and **one test per outline defect** (R-51 part 1). Two runs must be byte-identical; the suite also asserts no `model_call` row exists after it ran (HP-6).
- **S7 safety notes** (`npm run eval:golden -- --suite safety`): WP-4 four checks (the row-39 content warning is **proposed** as a safety note, **routed** to the teacher-only tip, **absent** from every student-facing block, and **Approve refused** until a named person clears the flag: via `run_checks` + `approve_gate` on the fixture lesson, no route needed); recall over the SYN-4+ planted warnings and decoys written by `docs/data/scripts/build_samples.py` or its successor (labelled synthetic, with *n*); false proposals over the issued sheet's 620 cells (≤ 1) and over WP-5 (0); every cleared flag carries user, note and time.
- Cases live under `evals/cases/s1/**` and `evals/cases/s7/**`, each with `provenance` (`issued`, `hand-written`, `synthetic`), `source`, `guards` (DO-5 *Case provenance*); expected values come from the authority in DO-5 (hand-counted sheet, HP-6, HP-9), never from the output being tested.

**Must not:** call a model; derive an expected value by running the code under test; use `docs/source/restricted/`; change intake or check code (a failing case is reported to its owning ticket).
