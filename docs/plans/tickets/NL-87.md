### Story
Platform ticket (no user story): the three spikes (SP-1 one-call draft, SP-2 freeze at Submit, SP-3 invention scans) ran before the database existed. Their results must land in `experiment_run` and `model_call` once it does, so build spend (M-29) and the spike evidence are queryable like any other record (R-48).

### What to build
Write `ops/import-spike.ts`: `import_spike_report(path: str) -> ImportReport{experiment_id, model_calls_imported}` (DO-4 §11) and the CLI `npm run ops:import-spike -- <report>`.

- Input: a spike report: the committed record `docs/analysis/spikes/SP-N-*.md` (its result tables) plus, for SP-1, the run ledger / per-call results exported from branch `spike/SP-1` (`git show spike/SP-1:spikes/sp1/...`). The importer parses the result tables into one `ExperimentRunRecord` (`experiment_id` `SP-1`/`SP-2`/`SP-3` plus a run suffix, `config`, `result`, `report_path`) via `EvidenceRepo.insert_experiment_run`, and for each recorded model call one `model_call` row (`purpose "spike"`, `experiment_id` set, tokens, `cost_usd`, `stop_reason`, `served_model`, no `run_id`) via `ModelCallLog`/`ModelCallStart` + `complete`, so M-29 (build spend against the ceiling) includes spike spend (G-5).
- **Idempotent:** keyed by `experiment_id` + call id; importing the same report twice writes nothing new.
- Fixtures under `evals/tests/fixtures/spike/` are trimmed copies of the three records (synthetic-free: they hold only the published result tables, no model output text beyond what the records already print).

**Must not:** call a model; invent a call that the report does not record; import prompt or output text from restricted content (GR-9); edit the spike records or branches.
