### Story
US-37 — As a reviewer, author or approver (P-1, P-2, P-3), I need to sign in with an allow-listed staff email and password and be recognised by every later request, so that I see and do only what my role allows. Without this none of the other 23 routes can tell who is asking.

### What to build
**1. Repository (DO-3 §2.2 `packages/db/src/repos/sessions.ts`, DO-4 §3.5).** `PgSessionRepo implements SessionRepo` built from `PgRepo_ctor{db, ids, clock}`: `find_user_by_email(email)` (case-insensitive on the stored lower-cased email; returns `AppUserCredentials` with the scrypt `password_hash`), `create_session(user_id, token_hash, expires_at, tx)`, `resolve(token_hash, now)` (null when unknown, `expires_at <= now` or `revoked_at` set), `revoke(token_hash, now)` (sets `revoked_at`; idempotent). Tables `app_user` and `app_session` exist from NL-08 (`0001_identity.sql`); this ticket writes no DDL.
**2. Passwords (`apps/web/src/server/http/passwords.ts`, DO-4 §5).** `hash_password(password)` → self-describing scrypt string (`scrypt$N$r$p$salt_b64$hash_b64`, random 16-byte salt, `node:crypto` only); `verify_password(stored_hash, password)` → boolean, constant time (`timingSafeEqual`), false on any malformed stored hash, never throws. Pure functions with no web imports, so NL-82 (seed) can import or relocate them (slice plan Open item 2: DO-3's path is used here; moving them is a DO-3 `CHG` that NL-82 raises, not this ticket).
**3. Service (`apps/web/src/server/services/session-service.ts`, DO-4 §5 `SessionService`).** Constructor exactly as DO-4: `(sessions, audit, tx, clock, ids, settings)`. `sign_in(req, meta)`: unknown email → `DomainRefusal(NOT_ON_ALLOW_LIST)`; wrong password → `INVALID_CREDENTIALS`; each of the two failures first awaits `clock.sleep(1000)` (CON-1: failed sign-ins wait ~1 s) and writes **no row** (shared guarantee 2): one application-log line with `request_id`, the error code and `email_hash = sha256(AUDIT_HASH_SALT + lower(email))`, never the email or the password. Success: a random 32-byte token (`crypto.randomBytes`), only `sha256(token)` stored, `expires_at = now + SESSION_TTL_HOURS` (12 h [A], fixed at issue: DO-4 has no touch method, so there is no sliding renewal), and in the same `tx.with_tx` one `audit_event` (`action "session.sign_in"`, `target_kind "session"`, `target_id` = the first 16 hex characters of the token hash, `details` ids only, `request_id`). Returns `SignInOutcome{session, cookie_token, expires_at}`. `require(cookie_token, request_id)` → `RequestUser` or `UNAUTHENTICATED` (this is the `SessionResolver` implementation NL-13's `with_route` calls). `get_session(user)` → OpenAPI `Session`. `sign_out(user, cookie_token)` → `revoke` plus an `audit_event` `session.sign_out` in one transaction.
**4. Routes (`apps/web/app/api/session/route.ts`)** thin, via `with_route` (NL-13): `POST` → `signIn` (public: the one route that runs without a session; the Origin check still applies), `GET` → `getSession`, `DELETE` → `signOut`. The `ls_session` cookie is set on sign-in with `HttpOnly; SameSite=Strict; Path=/; Max-Age = SESSION_TTL_HOURS×3600` and `Secure` whenever `APP_ORIGIN` is not `http://localhost`/`127.0.0.1`; cleared on sign-out. The request schema is the strict Zod mirror `SignInRequest` (email, password): an extra key such as `synthetic` is `INVALID_REQUEST` (`synthetic` is seed-only, CON-1). If the merged `with_route` has no public-operation switch for `signIn`, stop and raise it: do not edit `apps/web/src/server/http/with-route.ts` (NL-13 owns it).
**5. `apps/web/middleware.ts`** (Next.js): a page request without the `ls_session` cookie is redirected (307) to `/sign-in?next=<url-encoded path+query>`; matcher excludes `/sign-in`, `/api/**`, `/_next/**`, `/healthz`, `/favicon.ico` and static assets. It checks cookie presence only; the server decides validity on the first API call (a stale cookie lands on the UNAUTHENTICATED path of NL-24's client).
**6. Wiring (`apps/web/src/server/wiring/sessions.ts`, the stub NL-06 created; DO-4 names the function `wire_sessions`)**: builds `PgSessionRepo`, `PgAuditLog` (NL-12), `SessionService` from `WebDeps` and returns `SessionWiring{sessions}`. `container.ts` is not edited (slice plan *Composition-root wiring owners*).
Must not: store or log a raw token, password or email on a refusal; add any route that sets `synthetic` or changes a role; render any string as HTML; edit `with-route.ts`, `container.ts`, `package.json` or any DDL.
