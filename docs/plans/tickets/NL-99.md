### What to build
- Specs under `apps/web/e2e/integration/con-20/` on `startStack({ web: true })` (collab is not needed: lessons are seeded in states through repository helpers in `con-20/seed.ts`; three editable lessons from WP-1, WP-3 and WP-4's compiled stub drafts, plus one `submitted` lesson with its snapshot for the approval step). Accounts: two human reviewers, one approver who is not a last editor, one author and one synthetic reviewer (`createUser(role, { synthetic: true })`).
- The S8 script is a list of events `(tab, t, focused, visible, last_input_at)` replayed through the page's real sender under Playwright's `page.clock`; `con-20/oracle.ts` computes the expected merged active minutes from the script alone. The S8 case writes one `eval_case_result` row (suite S8, through NL-49's `EvidenceRepo` when merged; otherwise a JSON file under `evals/reports/` that NL-49's importer picks up).
- Approval step: the approver approves the submitted lesson through SCR-14 (the CON-18 route; its full matrix is NL-115) so the first-approval frozen metrics row is written.
- During its run this ticket alone may fix the heartbeat sender and approval-rating files in `apps/web/src/features/lesson-workspace/**` and `src/features/approval-review/**` (only the parts that send heartbeats or send the rating), each fix in the dev log.
- Must not: return minutes with a name anywhere, count author sessions, or edit a frozen row.
