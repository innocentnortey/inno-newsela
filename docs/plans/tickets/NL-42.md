### Story

### What to build
Implement `PgLessonRepo` in `packages/db/src/repos/lessons.ts`: one class implementing the three ports `LessonStateRepo`, `LessonVersionRepo` and `LessonGraphRepo` (DO-4 §3.5, `ports/lesson-state.ts`, `lesson-versions.ts`, `lesson-graph.ts`), over the tables NL-08 already created (`lesson`, `lesson_version`, `review_event`, `lesson_link`; no DDL here). It is built by `PgRepo_ctor{db, ids, clock}` (DO-4 §12) and every write method takes the caller's `Tx` so a service commits several repos at once.
**State port.** `get`, `state_of` (`LessonStateInfo{editable}` from `is_editable`), `lock_for_update` (`SELECT … FOR UPDATE` inside the caller's tx), `ensure_lessons(rows, unit_id, tx)` (idempotent: one `lesson` row per outline lesson row, id `G6.U4.L<n>`, state `draft`, returns the number newly created), `set_state(lesson_id, to_state, reviewer_id, tx)`, `append_review_event(NewReviewEvent, tx)` (one append-only `review_event` row with `request_id`; there is no update or delete method), `record_last_editor`.
**Version port.** `write_generated_version` (kinds `generated`/`candidate`; `idempotency_key` UNIQUE with `ON CONFLICT DO NOTHING`, returns the existing row and `created: false` on a repeat, HP-7 mechanic 3; a `candidate` has `adopted = false` and never changes `lesson.current_version_id`, R-29); `write_snapshot` (`submit`/`approve`/`reopen`: next `number`, **inherits** `outline_row_hash`, `prompt_version_id`, `schema_version`, `run_id` from the generated version it descends from, sets `derived_from_version_id`, leaves model fields null and `cost_usd` 0 — INTERFACE CON-19 system rule); `version`, `latest_snapshot`, `candidate(lesson_id, candidate_id)` (null for another lesson's id), `has_generated_version`, `approved_snapshots(unit_id)` (the latest `approve` snapshot of each lesson whose state is `approved` or `exported`; a `reopened` lesson is excluded until re-approved).
**Graph port.** `dependencies(lesson_id)` → `DependencyState[]` from `lesson_link` (`waits_on` / `depended_on_by`, `slot_id`, `source_state`, `source_approved_hash` from the source's latest `approve` snapshot, `slot_filled` read-only from the source's latest `lesson_doc.derived_json`; NL-36 owns `lesson_doc` writes) and `dependants(lesson_id)`.
**Board rows.** The plan gives `board rows` to this ticket although DO-4 §3.5 names `repos/metrics.ts` for `BoardReadRepo`; this ticket therefore adds `PgBoardReadRepo.board_rows(unit_id, state | null)` → `BoardRowRecord[]` (number, type, title, state, reviewer name, last change time, `dependency_flag`) to `lessons.ts`, with no minutes column and no person-level metric (GR-15); NL-54 imports it from here. Report to the orchestrator: DO-4 §3.5's file note changes to `lessons.ts`.
Must not: write DDL, edit `ports.ts` (NL-12; a missing method such as marking a candidate adopted is a `CHG-N`, see NL-47), write `lesson_doc` rows, or log lesson text. Tests use the real Postgres container (Postgres 16 test container); the in-memory twin of these ports is NL-12's.
