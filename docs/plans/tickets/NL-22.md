### Story
US-8 — As an outline author (P-2) I need failed lessons to say why they failed and to be retried on their own, and a run to stop cleanly at its cap or after repeated failures, so that a few failures leave the rest of the unit reviewable and nothing is billed twice. This ticket is the pure decision layer: what the worker does next, which reason a failed tile shows, and when a run pauses, kept apart from every model call and database write (rule `agent-architecture`: code decides what next and done).

### What to build
`packages/core/src/pipeline/` (A9; pure; `@ls/schema` only).
**`state.ts`.** `LessonJobState` as in DO-4 §6 (job reference with `unit_id`, `context`, `draft_call`, `call_ids`, `draft`, `schema_issues`, `compiled`, `compile_error`, `check_result`, `repair_rounds`, `truncation_retries`, `rate_limit_retries`, `brakes_fired`, `started_at`, `cost_usd`, `outcome`) with the heavy members as **type parameters** (`LessonJobState<Ctx, Compiled, Checked>`, default `unknown`), because `ClaimedJob`, `RowContext`, `CompiledLesson` and `CheckResult` come from NL-12, NL-18 and NL-20, which are not this ticket's blockers; NL-29 instantiates it. Pure helpers: `initial_state(job, now)`, `with_brake(state, brake)` (idempotent, immutable), `wall_clock_exceeded(state, now, limit_ms)` (true only when strictly over). `BrakeName`, `NextStep`, `RouteInput`, `FailureInput`, `FailureReasonRecord` as in DO-4 §2 and §6; `ProviderErrorKind` is declared here as a literal union identical to DO-4 §10.2's (NL-12's `ProviderError.kind` uses the same union; NL-29 asserts the two are mutually assignable).
**`route-after-checks.ts`: `route_after_checks(i: RouteInput): NextStep`.** First matching row wins: `schema_valid and compiled and check_passed` → `store`; `repair_rounds < max_repair_rounds` (any failure: invalid schema, `CompileError` or a blocking finding) → `repair`; otherwise `fail`. `max_repair_rounds` is 1 (R-19), so there is never a second repair.
**`failure-reasons.ts`: `failure_reasons_for(i: FailureInput): FailureReasonRecord[]`.** One reason per row that applies, in this order: brake `cancelled` → `cancelled`; brake `spend_run_cap` / `spend_day_cap` / `spend_project_cap` → `capped`; brake `job_wall_clock` → `timeout`; brake `truncation_retry` (truncated twice) → `truncated`; provider error `rate_limited` or `overloaded` after the retries (brake `rate_limit_retries`) → `rate_limited`; provider error `timeout` → `timeout`; any other provider error → `provider_error`; `compile_error` set → `compile_error`; `schema_valid` false → `schema_invalid`; `first_failing_kind` set → `check_failed` with `check_kind`. `circuit_breaker` adds no reason. `check` values are the OpenAPI `FailureReason.check` enum exactly. `message` comes from a fixed table of plain-English strings (`FAILURE_MESSAGES`), never from model output.
**`circuit-breaker.ts`: `should_pause_run(recent: Sequence[TerminalJobView], threshold): PauseDecision`.** Considers only `ready` and `generation_failed` jobs (a `cancelled` one is ignored), takes the `threshold` most recent by `finished_at` (ties by `lesson_id`), and pauses iff all of them are `generation_failed` with the same non-null `first_failing_kind`; returns `{pause, check, lesson_ids}` (`CIRCUIT_BREAKER_SAME_CHECK` is 3).
Must not: read a clock (times are passed in), call a model, repository or queue, or format a message from untrusted text.
