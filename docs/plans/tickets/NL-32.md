### What to build
**Modules (DO-3 §2.1):** `packages/llm/src/{model-client,anthropic,stub,prices}.ts`.
- `model-client.ts`: re-exports the `ModelClient`, `StructuredCallRequest`, `PromptBlock`, `ModelResponse` types and the `ModelAlias` literal from `@ls/core/ports/model-client` (NL-12 wrote them; DO-4 §13 R-19), replaces NL-14's local structural `PromptBlock` in `packages/prompts/src/inputs.ts` with `import type { PromptBlock } from "@ls/core/ports/model-client"` (same area A7; the one edit in `packages/prompts`), and `model_id_for(alias, settings)` mapping `GENERATION|REPAIR|ASSIST` to `MODEL_GENERATION_ID|MODEL_REPAIR_ID|MODEL_ASSIST_ID` (default `claude-sonnet-5-5`). No logic beyond that.
- `anthropic.ts`: `AnthropicMessagesAdapter implements ModelClient` from `AnthropicMessagesAdapter_ctor{api_key: SecretStr, model_ids, http_timeout_ms}`. **The only file in the repository that imports `@anthropic-ai/sdk`** (NL-01's boundaries lint enforces it). `complete(req)` makes exactly one Messages API request: `system_blocks` become the `system` array with `cache_control` on the last block whose `cacheable` is true (GP-33); `user_blocks` the single user message; `max_output_tokens` → `max_tokens`; `effort` is passed to the SDK's effort setting only when non-null; `temperature` only when non-null (SP-1 ran with the provider default); the per-request timeout is `req.timeout_ms`. `output_mode "schema_enforced"` sends `output_json_schema` through the SDK's structured-output option (UnitPlan, assist, judge); `"prompt_embedded"` sends no schema parameter, because the renderer already placed the schema in a `schema` system block (LessonDraft and repair, SP-1: the API's enforced mode rejected `LessonDraft`). The response is mapped to `ModelResponse`: `raw_text` = the concatenated text blocks verbatim, `stop_reason` mapped to the five-value literal (an API refusal stays a `stop_reason "refusal"`, not an exception), `usage` with all four token counts (cache read and write included), `requested_model` from the request, **`served_model` from the response body**, `provider_request_id` from the `request-id` header, `latency_ms`. Errors become `ProviderError{kind, retryable, http_status, retry_after_s, provider_request_id}`: 429→`rate_limited` (reads `retry-after`), 529→`overloaded`, other 5xx→`server_error`, abort→`timeout`, socket failure→`connection`, 400/422→`bad_request`, 401/403→`auth`. The adapter never retries (the recorder owns retries) and never writes a log line containing the key, a prompt or an output; the error `message` is the HTTP status text only.
- `stub.ts`: `StubModelClient implements ModelClient` — deterministic, no network. Scripted per `(alias, purpose)` queue or a function; can return text, `stop_reason "max_tokens"`, a `ProviderError` (429 with `retry_after_s`, 529, timeout), or wait on `FakeClock` for a given delay; usage is computed from text length (`ceil(chars/4)`) so costs are non-zero and repeatable; `served_model "stub-model"`; records every request (`calls`) and offers an `on_enter` hook so a test can assert state while the call is "in flight". `StubJudgeClient implements JudgeClient` (cut #2) returns scripted `yes|no` verdicts the same way.
- `prices.ts`: `PRICE_TABLE: PriceTable` with `confirmed_on "2026-10-25"` and one `ModelPrice` — `claude-sonnet-5-5`: input 2.00, output 10.00, cache read 0.20, cache write 2.50 (USD per million tokens, `Decimal`; SP-1 and the provider docs, PD-12); `price_for(model_id)` throws `InvariantViolation("no price for <model>")` for an unknown model so an unpriced call can never be settled at zero.
Must not: import the SDK anywhere else; log or return the key (the `SecretStr` prints as `[redacted]`); retry; read a prompt or output into any log; touch spend or model_call rows; make a live network call in any test (an optional live smoke call, if wanted, is a separate `gate::paid` action under PD-29 and not part of this ticket's evidence).
