### Story
US-37 — As a staff member I sign in and see only what my role can do, so that only an author starts a run and only an approver approves. Platform: the demo needs the official standards tables, the first prompt version and one account per role to exist on a fresh database (R-4, R-54).

### What to build
Write `ops/seed.ts`: `seed_reference_data(db: PgDatabase) -> SeedReport{standards, users, ops_event_id}` (DO-4 §11) and its `npm run db:seed` entry. Idempotent: running it twice leaves the same rows.

- **Standards (R-4, GR-5):** loads the official CDE tables prepared by NL-15 under `packages/core/data/standards/**` (CCSS ELA 6, ELD 6, MSLS 6) into `standard` (`code`, `set`, `text`, `parent_code`, `is_leaf`, `eld_strand`) through `PgStandardRepo`. It reads those files; it does not re-author them and never reads `docs/source/restricted/`.
- **Prompt v1:** inserts `prompt_version` number 1 (locked layer hash from `packages/prompts`, empty guidance) via `PgPromptRepo`/NL-34's seed function, once.
- **Demo accounts:** exactly one account per role (`author`, `reviewer`, `approver`) in `app_user` with `synthetic = true` (set only here; no API route can set it), emails on the allow list, and `password_hash` from `hash_password` imported from **`packages/core/src/auth/passwords.ts`** (scrypt via `node:crypto`; the orchestrator moved it there so the seed and the web app share one hasher without breaking dependency arrows; slice plan open item 2 is closed that way). The plaintext password comes from the `SEED_DEMO_PASSWORD` environment variable; if it is unset the script generates a 20-character random password and writes it **only** to the git-ignored `.demo/seed-credentials.txt` (mode 600), never to stdout, logs, `ops_event` or any table. Nothing in the repository holds a password.
- One `ops_event` (`kind "seed"`, counts per standard set, never a password or hash) via `EvidenceRepo.ops_event`.

**Must not:** import from `apps/web` (dependency arrows); commit credentials; create more than one account per role; mark a non-seed user `synthetic`; load anything that is not CDE standards text.
