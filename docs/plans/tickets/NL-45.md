### Story
US-16 / US-19 / US-20 / US-21 — As a reviewer I see exactly what is wrong with a lesson and what stops Submit or Approve, I clear a block with a named reason, clear a safety flag with a note, and confirm or remove an AI-proposed standard (with a short undo), so that every approval rests on a person's recorded decision.

### What to build
Implement `IssueService` in `apps/web/src/server/services/issue-service.ts` (DO-4 §5) and the routes `lessons/[lessonId]/issues/route.ts`, `issues/[issueId]/resolution/route.ts`, `safety-flags/[flagId]/clear/route.ts`, `standards/decision/route.ts` (collision map: `issues/**`, `safety-flags/**`, `standards/**`).
**`get_issues`** (`getLessonIssues`, any role): `IssueRepo.current` + `CheckQueue.pending_for` → `stored_hash` (latest stored), `checked_hash`, `checked_at`, `pending` (a newer stored hash is queued), `counts` over **unresolved** issues by level, and each issue with `blocks` (level `blocking`/`confirmation` → `[submit, approve]`, advisory → `[]`), `resolvable` (false for `suggestion_pending`, `standard_confirmation`, `safety_flag_open`, `safety_note_without_tip`, `safety_text_in_student_block`, `rights_to_clear`, `cross_lesson_link`) and `resolution{by, reason, at}`. UXP-2 reading, planner confirms: for each `LessonGraphRepo.dependencies` entry whose slot is filled but whose source is not approved, the list carries a `cross_lesson_link` entry with `blocks ["approve"]`.
**`record_resolution`** (`reviewer`): precedence role → lesson `NOT_FOUND` / issue not on this lesson `NOT_FOUND` → `LESSON_LOCKED` (not editable) → `REASON_REQUIRED` (blank reason, 422) → `NOT_RESOLVABLE` (422, `details.use` names the right action, e.g. `clearSafetyFlag`, `decideStandard`, `decideSuggestion`, `fillSlot`); then one tx: `IssueRepo.resolve` + `AuditLog.append` (`issue.resolve`, `version_hash` = the issue's hash, reason). **`clear_safety_flag`** (`reviewer` or `approver`): allowed on `submitted`; `LESSON_LOCKED` on `approved`, `exported` and a `draft` whose review has not started; blank note → `NOTE_REQUIRED` (flag stays open); one tx: `SafetyFlagRepo.clear` + audit (`safety_flag.clear`). Neither touches the document or its hash. **`decide_standard`** (`reviewer`): `confirm`/`remove`/`add` go to `CollabCommands.apply_edit(StandardEdit, tag "standard-decision")` first (`COLLAB_UNAVAILABLE` → nothing recorded; counts as an edit for four-eyes), then one tx records `AlignmentRepo.confirm` + audit; `undo` with `undo_of` (the `audit_id` of the caller's last decision on that code) within `UNDO_WINDOW_S` (60) and with no later decision on the code, else `UNDO_EXPIRED` (409). Open item for the planner: DO-4 has no undo path (`StandardEdit.decision` is confirm|remove|add; `AlignmentRepo` has no un-confirm) — raise an additive `CHG-N` (`decision "undo"` carrying `undo_of`) before implementing the undo branch; confirm/remove/add and the rest do not wait on it.
All writes in one `TxRunner.with_tx`; a refusal writes nothing, not even an audit row (one application-log line). Responses: `item_id`, `status`, `by`, `at`, `audit_id`, the lesson's new `counts`.
Must not: write lesson content itself (collaboration server only, CON-G3), edit `wiring/review.ts` (NL-53), or resolve a kind outside the resolvable list.
