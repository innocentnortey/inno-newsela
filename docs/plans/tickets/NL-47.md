### Story
US-22 / US-10 — As a reviewer I can ask for a fresh draft of a lesson without losing the one I have: the new draft arrives beside the current one as a candidate, I read it, and I adopt the whole thing or one section as a recorded edit under my name.

### What to build
Implement `CandidateService` in `apps/web/src/server/services/candidate-service.ts` (DO-4 §5) and routes under `apps/web/app/api/lessons/[lessonId]/candidates/**` (`regenerateLesson` POST → 202; `getCandidate` GET `…/{candidateId}`; `adoptCandidate` POST `…/{candidateId}/adopt`).
**`regenerate`** (`reviewer`): precedence role → `NOT_FOUND` → `LESSON_LOCKED` (state `submitted`, `approved`, `exported`, or a `draft` whose review has not started, UXP-3; `generation_failed`, `in_review`, `changes_requested` and `reopened` are allowed) → card conditions: if a candidate job for the lesson is queued or running, return that candidate (202) and spend nothing; else `SpendLedger.check_day_cap(user, cap_usd)` (`DAY_CAP_REACHED` with `details.scope` `user`|`project`, remaining) where `cap_usd` is one lesson's worst case (the draft, the truncation retry and one repair reservations at the pinned model price, from `max_call_cost`; it never draws on the original run's cap) → one tx: `RunRepo.insert_run` (kind `candidate`, `parent_run_id` = the lesson's run, the run's stored plan and pinned prompt reused, optional reviewer `note` carried as `NewJob.reviewer_note` to the draft prompt, DO-4 §3.4, §13 R-15) + `JobQueue.create_candidate_job` + `AuditLog.append` (`candidate.regenerate`); `NOTIFY` after commit. A race on the partial unique index returns the winner's candidate. The worker (NL-29) generates; the lesson row and current version are untouched; on `generation_failed` the candidate path stores v1 directly (the shared state table).
**`get`** (any role): the candidate version beside `current_content_hash` (unchanged), `status` (`queued`, `drafting`, `ready`, `failed`) from the job and version rows, `failure_reasons` in CON-6 vocabulary, `cost_usd`, `sections` when ready; a candidate of another lesson → `NOT_FOUND`. A failed candidate is a status, not an error.
**`adopt`** (`reviewer`): `INVALID_TRANSITION` (409) unless `ready` and not already adopted whole; `scope "section"` needs `section_address` (else `INVALID_REQUEST`); `CollabCommands.apply_edit(AdoptEdit{candidate_version_id, scope, section_address}, tag "candidate-adopt", actor)` — the adopter becomes last editor via the collaboration store; then one tx: for `whole`, `LessonVersionRepo.mark_adopted(candidate_version_id, tx)` (DO-4 §3.5, §13 R-5; zero rows → `INVALID_TRANSITION`), for `section` no flag change, + `AuditLog.append` (`candidate.adopt`, details `scope`, `section_address`); response `candidate_id`, `audit_id`, `last_editor`, new `content_hash`. `COLLAB_UNAVAILABLE` leaves everything unchanged.
Must not: overwrite or edit the current version, write lesson content from the web process, draw on the original run's cap, or fill `wiring/review.ts` (NL-53).
