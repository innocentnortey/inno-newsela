### Story
US-36 — every number in the demo needs its *n* and a source. After the experiments (NL-128…130) each change has to be scored against the same frozen set as before, and the final full-run report has to describe the prompt that will actually be shown (GP-21, GP-51).

### What to build
Score what the experiments changed, decide with a rule whether the whole unit must run again, and publish the final report.

1. **Score each experiment.** For every `XP-N` that landed (NL-128, 129, 130; a slot closed unused is recorded as closed), run its recorded score command on the **frozen set** named in its record (WP-1…WP-5 golden cases and the stated development set) with the pre-change and post-change prompt versions: `npm run eval:golden -- --suite drafts --repeat 3` for model-driven cases (WF-24) and the targeted suite for its `FT-N`. Write `docs/testing/experiments/XP-N-result.md`: the `FT-N`, the one variable, score before / after with *n*, cost before / after, the decision (**kept**, **reverted**), and the commit. A change is kept only if its named `FT-N` improved and no other suite fell (golden tier 100% stays 100%).
2. **The rerun rule.** Compare `prompt_version` (and model, schema, check set) of the NL-112 run with the version that will be shipped. **Unchanged:** do not rerun; refresh the report with the XP scores and the sentence "the shipped prompt version equals the one in run <run_id>". **Changed:** rerun the whole unit exactly as NL-112 (`npm run eval:full-run -- --unit G6-U4`, same settings; one run), after the headroom check against the PD-29 $75 ceiling (stop and ask Innocent if it does not fit, `gate::paid`). Never rerun to chase a better number with the same version.
3. **Final report.** `evals/reports/full-run-<run_id>.md` is the report the docs and video quote; the older one stays in the repo, linked as superseded. Reconcile the totals the same way as NL-112 (OBS-8). Update the S9 line in `docs/design/eval-plan.md` *Baselines* only through a dev-log-explained commit (the table says "none yet" until a run sets it).
4. Print total build spend against the $75 ceiling (M-29).

Lane guard (`ticket-lanes`): before committing, `git diff --name-only` must list no file that code or tests read (source, tests, schemas, migrations, prompts, settings, lockfiles, fixtures, CI); if it does, stop, relabel the ticket `lane::build-loop` and report. Commit straight to `main` (factory mode, PD-34).
