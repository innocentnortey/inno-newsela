### Story
US-24, US-25 — Submit freezes the lesson and Approve pins the exact version reviewed. S5 repeats the promise 20 times per assertion with three live browsers, so a race that shows up once in twenty is caught before the demo (HP-4, HP-5).

### What to build
Build the S5 integrity suite (A20; DO-5 S5; DO-6 WF-43).

- Files: `apps/web/e2e/integrity/**` (Playwright specs and a trial driver, 3 browser contexts), `evals/src/suites/s5.ts` (records results), report `evals/reports/integrity-<git-sha>.md`. Command: `npm run test:e2e -- integrity --trials 20`.
- One trial = a fresh clone of a WP-1 stub lesson and three contexts: A (reviewer, editing), B (second reviewer, co-editing), C (approver). Assertions per trial (each stored as one `eval_case_result` with its trial number):
  1. **stale approve**: B edits after C loaded the snapshot (via withdraw / resubmit) → C's approve gets `STALE_PIN` 409 and nothing changes (WF-15);
  2. **zero edits after lock**: after Submit, A types → refused, the editor drops the refused local edits and tells the typist (CON-12 `refused`, `refused_from`), and no `lesson_doc`/`audit_event` row appears (WF-9);
  3. **zero silent keystroke loss**: every keystroke before Submit either appears in the stored snapshot or in the refused notice;
  4. **four-eyes**: the last stored editor cannot approve (WF-15);
  5. **pending suggestion blocks Approve**: run only if NL-116 landed, otherwise recorded `not built (cut #8)`, never as a pass;
  6. **round-trip hash identity**: JSON → Y.Doc → JSON hash unchanged after reload; and export hash = snapshot hash only if NL-102 landed (else `not built`).
- Store p95 across trials is recorded (target ≤ 500 ms `[A] → SP-2`). All floor-1.00 assertions need 20 of 20.
- Must not: edit editor, collaboration or transition code; a failing assertion is a bug report to its owner, not a patch here.
