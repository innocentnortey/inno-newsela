### Story
US-37 — As a reviewer, author or approver I need to sign in and see only what my role can do. Platform work: every route in the app runs through this wrapper, so the server-side guard (R-54), the error envelope and the request id are written once and cannot be forgotten by a route.

### What to build
`apps/web/src/server/http/with-route.ts` and `refusal.ts` (A3; `passwords.ts` and `SessionService` are NL-25's).
**`with_route(handler: ServiceCall, spec: RouteSpec): RouteHandler`** (DO-4 §5). `RouteSpec{operation_id, roles | null, request_schema | null, success_status}` plus one additive field `public: boolean` (default false; `signIn` needs no session; **DO-4 gap, orchestrator to record**). Order (INTERFACE shared guarantee 11): **1** request id (accept the client's `X-Request-Id` if it matches the `RequestId` pattern, else mint `req_<ulid>`) → **2** session, through an interface owned here, `SessionResolver{require(cookie_token, request_id): Promise<RequestUser>}` (cookie `ls_session`; NL-25's `SessionService` satisfies it structurally), and, on `POST/PUT/PATCH/DELETE`, an `Origin` check against `APP_ORIGIN` (absent or foreign → `UNAUTHENTICATED`; DO-4 open item 2) → **3** Zod parse of path, query and body by the named `@ls/schema/api` mirror (`INVALID_REQUEST`, `details.fields` lists each failing path, never the value) → **4** role (`ROLE_FORBIDDEN` when `roles` excludes the caller's) → **5** the service call (its `DomainRefusal`s pass through) → **6** envelope. `PoolExhausted` (`@ls/db/pool-exhausted`) → 503 `SERVICE_BUSY` with `Retry-After: BUSY_RETRY_AFTER_S`. Any other throw → 500 with body `{"request_id": …}` (not an envelope; the client shows "can't load"), log `route.unhandled` with the error class only. Every response carries `X-Request-Id`; every refusal body carries `details.request_id`.
**`to_error_response(refusal, request_id): ErrorResponse`** and a generated status table: `npm run gen:error-status` reads `x-error-catalog` of `docs/contracts/interface.openapi.yaml` and writes `apps/web/src/server/http/error-status.generated.ts` (code → HTTP status, 36 codes); a contract test regenerates it and diffs.
**Logging.** Exactly one `route.done` line per request: `operation_id`, `status`, `duration_ms`, `request_id`, `role` (never name, email, body or cookie); a refusal also logs `route.refused` with the code. A refusal writes **no audit row** (guarantee 2).
**Wiring.** `with_route` reads its dependencies lazily from `getServices()` (`sessions` resolver, `logger`, settings, clock, ids); `make_with_route(deps)` is the test seam. Routes call `with_route`; this ticket adds no route.
Must not: implement sign-in, passwords or sessions (NL-25), import `SessionService`, add a route, or return an unnamed error code.
