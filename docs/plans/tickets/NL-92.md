### Story
US-34 — As the builder I read the seeded-error result next to the quality page: about five errors planted by someone other than the reviewer, hidden from them, and how many were caught before approval, so that I can judge the review as well as the drafts. (Cut #6.)

### What to build
Build the tool (`npm run eval:seed -- --plan <hidden key>`), the S10 suite shell fill and the report. Claude plants; Innocent reviews through the **normal flow** (NL-53 transitions); this ticket scores.

- `evals/src/seed/plant.ts` — reads a hidden **key file** (`evals/local/seed-key-<run>.json`, git-ignored; entries `{plant_id, lesson_id, kind, locator, marker}`; kinds include the required **wrong standards code** plant, an invented quote, an out-of-range page, a safety warning in a student block, a missing section) and applies each plant to a **copy** of a generated lesson stored as a lesson in a separate seeded unit through the same seeding function as v1 (`LessonDocStore.seed_initial`), attributed to a dedicated synthetic planter account (never the reviewer); writes one `audit_event` per plant (`planted_by`) and one `eval_run` for the run. The key's contents are never printed or stored in a table readable by the reviewer's routes.
- `evals/src/seed/score.ts` + `evals/src/suites/s10.ts` — after the review, scores each plant from stored rows: **caught before approval** = (a) an `issue` of the matching kind was raised on the planted hash (by a check) or (b) the planted text no longer appears in any later stored version, or the lesson was sent back with a note naming it (by the reviewer); **missed** = the plant is still in an `approved` snapshot or the lesson was approved with it. Writes one `eval_case_result` per plant (`provenance hand-written`, source = the key id) and `evals/reports/seeded-<run_id>.md`: each plant, caught or not, by check or reviewer, labelled "our reviewers", with *n*.
- Thresholds (DO-5 S10): ≥ 90% caught; below 70% fails the guard; the wrong-code plant must be caught (floor); with *n* ≈ 5: 5/5 meets the aspiration, 4/5 is reported, ≤ 3 fails.

**Must not:** plant into a lesson any reviewer is working (only the seeded unit); let any API response, board row, issue message or log name a plant; commit the key; edit check rules (a missed plant is a finding, not a change here).
