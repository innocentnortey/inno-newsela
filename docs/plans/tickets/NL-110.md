### Story
Platform work for R-23: a second provider reads each (activity, standard) claim of a stored lesson and says yes or no, so a reviewer sees a provisional "judge says no" flag beside the deterministic checks. It is advisory; it never blocks Approve. Cuttable (#2): if cut, the docs say the judge was not built.

### What to build
Wire the judge into the worker as its own claim loop and prove it end to end on the stub (A19; DO-4 §6 `JudgeJob`, `JudgeRunReport`; §3.1 `JudgeClient`, `StubJudgeClient`).

- Files (this ticket owns): `apps/worker/src/wiring/judge.ts` (fills NL-07's shell: builds `JudgeJob`, the claim loop and registers it on `WorkerRuntime.judge`), `apps/worker/src/judge/claim-loop.ts` (new), tests, and the capture test. NL-89 owns `judge-job.ts`, `openrouter-judge.ts`, `repos/judge.ts`; do not edit them.
- **Trigger:** the loop claims stored `(lesson_id, content_hash)` pairs that have no `judge_verdict` rows yet, with `FOR UPDATE SKIP LOCKED` over existing tables (no new table; DDL is NL-08's. If a table proves necessary, stop and raise a `CHG`). It never shares a lane with generation or checks (a slow judge cannot delay a draft or a check). One pass per hash: re-running is idempotent.
- For each pair `JudgeJob.run(lesson_id, content_hash)` reserves, calls `JudgeClient.verdict`, settles or releases, stores one `judge_verdict` per pair and, for a `no`, an **advisory** issue of kind `judge_no` (`blocks: []`, labelled provisional in its message) through `IssueRepo`.
- **Never blocks:** `submit_gate` and `approve_gate` ignore `judge_no`; an unavailable judge (provider error, timeout, spend refusal) leaves the lesson untouched and logs one line.
- The prompt carries only the activity, the standard's official text and the rubric (R-23). Real OpenRouter calls happen only in NL-111/NL-122; every test here uses `StubJudgeClient`.
- Must not: add a gate, change a check rule, or let a verdict set an alignment link's `asserted_by` to a person.
