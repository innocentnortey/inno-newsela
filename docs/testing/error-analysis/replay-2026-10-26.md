## What blocks a paid run

1. **Flex Day codes.** A Flex Day row with no focus codes forces a model-invented CFU `standard_code`, and since slice D that is a blocker. Needs a decision: allow an empty `standard_code` on code-less rows, or tell the prompt what to write. 3 of 6 Flex lessons are affected on first draft.
2. **Checker strictness questions to settle before spending** (changes would be code, not prompts): whether `callout_say` teaching counts as teaching text; whether ELD codes count toward the two-code limit; whether Quick Write can check a writing code. Each decides how many lessons need a repair.
3. **The new prompt is untested on a model.** Three instructions must land together (heading tags, at most two codes per Pulse Check, exact Part A/B). Editing `lesson-shape.md` changes `locked_hash`: a new prompt version at start (NL-134 rerun rule).
4. **Expect a lower first-pass rate than attempt 3's 40%** and more repairs. Slice C gives the repair prompt the findings, so the repair success rate is the number to watch, not first pass.

### 9. Output selection and what the stored data can show

Selections: **original** = the last usable `lesson_draft` call (even if truncated); **effective** = what `DraftNode` accepted (the draft, or the single `truncation_retry` when the draft stopped at `max_tokens`); **last_repair** = the last usable repair; **final** = last repair, else effective; or **none** with a reason (`no_draft_call`, `draft_call_has_no_output`, `truncated_without_completed_retry`, `retry_truncated`, `no_repair_call`, `repair_has_no_output`). Usable = `status = completed` and output present. Order = `sent_at`, then `attempt`, then id (every row has `attempt = 1`, so attempt cannot order calls). This run has 47 `lesson_draft`, 28 `repair`, 1 `unit_plan` and **0 `truncation_retry`** calls, so the truncation-retry path is covered by unit tests only and **no number in this report depends on it**; the old `initial` columns equal `effective` here because no first draft stopped at `max_tokens`.

### 10. Omissions, with timestamps

Recorded in each JSON as `provenance.omissions` (timestamp = database time of that run, e.g. 2026-10-26T17:14:03Z for `45a2a63`): (1) cross-lesson links, linked lessons and dependency states are cleared (affects `cross_lesson_link`, `linked_text_changed`, the waiting phase); (2) reviewer state: emptied in generation_time mode, today's values in current mode (affects `safety_flag_open`, `suggestion_pending`, `standard_confirmation`, coverage kinds); (3) standards texts come from today's database, not versioned; (4) the prompt is not re-rendered: drafts were written under the run's prompt version (locked hash `c8fb9306`); the current locked hash differs from the run's at every commit after base (the two are equal only at `e7e72a3`); (5) no model call, no spend, no repair re-executed. **This replay does not establish lifecycle equivalence: no cross-lesson links, no reviewer state at generation time, no re-run repairs, no prompt rendering, standards texts as of the replay time.**
