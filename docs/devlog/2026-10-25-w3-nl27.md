# NL-27 build (W3): start a run, run repo, run state machine

**Changed.** Pure `run-machine.ts` (derive state, tile state, control matrix), `PgRunRepo`, `RunService.start` (full DO-4 constructor; other methods throw `NotBuiltYet` for NL-78), `POST /api/runs` with a local Next-to-HttpRequest adapter, in-memory fakes and tests.

**Why.** One transaction writes the run, its jobs and the audit event, so a refusal leaves nothing behind. Decisions: flag order cancelled > capped > paused; `pg_notify` inside the transaction (delivered at commit); a retried key replays the first run, and an expired holder gives its key up (`~id` suffix); `model_call.status` values completed/failed/lost.

**Checked.** Lifecycle, repo (real Postgres), service and route tests pass; eslint and typecheck clean.

**Remaining.** NL-78 wires `wiring/runs.ts` (passes `idempotency_window_h`, removes the cast in `route.ts`) and builds the other methods. NL-25 can hoist the adapter.

**Review fix.** A repeat with the same Idempotency-Key returns the ORIGINAL run unchanged: the scope is rebuilt from the stored run and its jobs (parent run, lesson jobs), never from the retry body; a changed body is not an error (no IDEMPOTENCY_CONFLICT code exists in the OpenAPI). The repeat answers 201, the same status as the first call (choice, not a 200). `start` holds two pool slots while it waits on the advisory lock and runs repo reads (lock connection plus the transaction's); size the pool for two per concurrent start.
