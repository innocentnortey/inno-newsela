**Why / decisions.**
- *Ticket command cannot run as written* (S-125-1): `npm run test:e2e` is wired by `scripts/script-targets.json` (not owned) to the mock config and Playwright rejects `--trials`. Working command from `apps/web`: `npx tsx e2e/integrity/run.ts --trials 20 [--grep token] [--fault-fixture]`.
- *Lesson content is the compiled WP-3 flex-day draft*, not WP-1: WP-1 is flawed on purpose and can never be approved (con-18 seed note), but stale-pin, four-eyes, round-trip-export and suggestion-lifted all need an approve that can succeed. Trial starting document is therefore WP-3 (`seedFlex`), a deviation from the plan's "WP-1 Lesson 4" wording.
- *Submit swaps the submitter's page to the read view.* The ticket's "A types after Submit" is therefore done with a page that has not heard about the lock: in `zero_edits_after_lock` B presses the real Submit button while A's socket frames are held (`hold-bridge.ts`), A types a real keystroke, the frames are released, and A shows the refused notice, `Removed text`, `aria-readonly=true` and `read_only`. A raw socket write is refused `LESSON_LOCKED`; lesson_doc, audit_event, lesson_version, review_event counts are unchanged.
- *`no_silent_loss`* counts a token as typed only if the editor was editable and focused before and after its keystrokes; tokens typed while the editor turned read-only are reported as `ambiguous`, not counted. B types across the lock (A presses Submit 250 ms in, retrying on NOT_STORED); the oracle is `typed subset of (snapshot union refused notice)`.
- *Suggestion half* (NL-116 landed): created and rejected through the real routes (`POST /suggestions`, decision); Submit is refused `SUGGESTION_PENDING`; the Approve gate on a submitted lesson uses the same SQL-inserted pending row the NL-116 spec uses (the route refuses a locked lesson).
- *`ids`* asserts `review_event.request_id` equals the response header, web-written `audit_event` rows carry a request id and `lesson.store` rows carry the store id.
- *Store p95 basis (O-1):* verdict on the figure net of the 500 ms collab debounce, raw shown beside it.
- *No product code, collab fault hooks or package.json touched.* The AC-7 fixture is a test-side stray `lesson_doc` row for that trial's own lesson (trial `ceil(n/2)` of `zero_edits_after_lock` only).
- `availability.ts` lives in `evals/src/suites/s5-support.ts` (it is read by the suite, and apps/web is CommonJS, evals is ESM); `run.ts` imports the ESM helpers dynamically.
