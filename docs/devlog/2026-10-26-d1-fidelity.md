# D1 Clear Ledger fidelity fix (layout, theme default) and the visual gate

**Changed.** The built UI kept D1's tokens but not its layout, and followed the OS into dark mode. Fixed in `apps/web`:
- app shell: the 60 px icon rail of `design.md` §4 (was a 220 px text sidebar at `lg`), product mark, tooltips, gear at the foot;
  top bar with chevron breadcrumb, a status slot (presence and save state portal into it, SCR-9), role pill and an account menu
  (name, theme, Sign out);
- theme: light is the default whatever the OS says (`design.md` "Light is the default theme"); Light / Dark / Match system in
  the account menu, stored per viewer (`ls-theme`), applied before first paint (`src/lib/theme.ts`, `app/layout.tsx`).
  Recorded as DQ-4a in `design.md`;
- SCR-9 workspace (look sheet M3): stepper centred on one line; outline · page sheet · evidence rail; the formatting toolbar as
  one strip at the top of the sheet; the lesson as one document (label rows over hairlines, no boxed fields, read view too);
  compact issue cards with their actions inside; one sticky footer bar under outline and page, the blocking count once;
  below `xl` the outline is a "Sections" disclosure;
- SCR-14 approval (M4): one page sheet (header, banners, checklist rows on hairlines, frozen text) beside the decision card
  with full-width buttons; SCR-8 board (M2): segmented state filter; SCR-4 validation report (M1): full-width sheet
  (`PageSheet measure="full"`, also the unit plan) and a stat-list summary; approval and history breadcrumbs moved into the top bar;
- shared components: `Banner` icons at the look sheet's size (level word kept for screen readers); `Button` has no blank
  leading slot when idle, and while loading lays the spinner over the label so its width never changes; `Stepper` one line.

**Why.** Innocent, 2026-10-26: "why doesnt our current ui follow this? … that means something went wrong in our stages", and
"the ux colors on clear ledger vs what we have now is completely different" (his Mac runs in dark mode). The stages were
right; the FW template defined the visual check as "palette and radius tokens", every UX-5a slice compared tokens and
deferred the rest as NEEDS_HUMAN_REVIEW, and the §8 gate closed over those deferrals. The process fix is in the workspace
skills (zero-to-hero 2.0.2, ux-pipeline `scripts/look_compare.mjs`, `ui-typography-and-color.md` *Apps open in the picked
direction's theme*); this project pins its own workflow copy and adopts that through its own mechanism.
