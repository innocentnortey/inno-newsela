**Why / decisions.** (1) Worker process path not covered: `startStack({worker:true})` takes no per-test scripts and global-setup starts web only, so `drive-worker.ts` runs the real `wire_generation` claim loop on `StubModelClient` against the stack DB (child `tsx`). S-8 stays open for NL-96/NL-112. (2) Runs are started through the real `POST /api/runs`. (3) Wire type: `cost_usd` and `cost_per_ready_lesson_usd` are JSON numbers, not decimal strings (AC-2 wording); compared as Decimal, **CHG request for Innocent**. (4) Canary rides in the stub reply (stored `raw_output`), not the prompt: the prompt is rendered from the outline and has no scripted part. (5) Completeness mismatch: the finalizer uses its own pool, so the call row is deleted and restored in a try/finally (the reservation link is cleared and put back) instead of a rolled-back transaction. (6) `report_path`: no writer links a finished run to its S9 report, so the spec inserts `eval_run` and sets `run.eval_run_id`. (7) Loading state has no `role=status` (aria-busy plus sr-only text): asserted that instead. (8) Failure message markup cannot reach SCR-17 (it shows reason names only), so that check is true but cannot fail today.

**Defects found, not fixed (outside owned paths), requests.** R-1: run start pins `confirmed_by` as the user's display NAME; `PgRunRepo.pinned_choices` parses it as `usr_<ULID>`, so any run started after real confirmations dies in the unit-plan job with a ZodError. Specs use a user whose name is id-shaped. R-2: p95 prints unrounded (`0.11908333333333333 min`), clipping the card at 1280 and overflowing at 390 (`format.ts` says nothing rounds, R-57); needs a display-precision decision. R-3: stale `claim_loop` after a lost call needs a never-answering call in the driver (a late answer is fatal for the old loop).
