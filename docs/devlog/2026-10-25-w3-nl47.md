# NL-47 CandidateService and candidates routes (2026-10-25)

**Changed.** `CandidateService` (regenerate / get / adopt), `routes/candidate-{routes,default}.ts`, three `candidates/**` route files (using the shared `next-adapter`), in-memory fakes, and a new read seam `PgCandidateLookup` (`packages/db/src/repos/candidate-lookup.ts`) behind a small `CandidateLookup` interface (plan R1, approved by Innocent).
**Why.** DO-4 section 5's ports cannot find a lesson's in-flight candidate job, the version a run wrote, the lesson's own run or the next version number. `candidate_id` is the candidate run id (exists from the 202 on). The web process writes only a run, a job and audit rows; adopt is one `apply_edit` then `mark_adopted` (whole only).
**Checked.** Service, route and lookup int tests; eslint, prettier, typecheck.
**Remaining.** NL-53 must construct `CandidateService` with `lookup` (`new PgCandidateLookup({ db, ids, clock })`), `prices` (NL-33 PriceTable) and `cost` (NL-35 `max_call_cost`), and set `candidates` in `wiring/review.ts`. Output-cap constants mirror worker defaults (R3).
