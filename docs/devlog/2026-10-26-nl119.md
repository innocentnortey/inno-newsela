## Why
The capacity doc needs remote-edit p95, stored p95, lost updates and reconnect time for the collaboration server. Each editor is a real Hocuspocus provider with a real session cookie, so the run exercises auth, the write guard and the `lesson_doc` store path. A defect found by a run is a finding, never patched here.

Decisions inside the plan: the load unit is `G6.U9`, lesson ids `G6.U9.L9<NN>` (no collision found in `ops/` or `docs/design`); `assert_load_lesson` runs before every seed and socket open, so the demo unit cannot be touched. Token names carry a per-run tag (`[<tag>-e<i>-<seq>]`) so a second run against the same load lessons never counts an earlier run's text as its own duplicates. The probe id uses the `pr` prefix.

`p95_json` keys: `remote_edit` (ms), `stored` (ms), `reconnect_p95_s` (seconds), `duplicate_tokens`, `unacknowledged`, `socket_errors`, `editors`, `lessons`, `incomplete`, `evidence {git_sha, prompt_version: null, models: [], provider_mode: "stub"}`. `event_loop_lag_p95_ms` and `max_db_connections` are written as 0: the HTTP half owns them (this script measures only the socket side). "Incomplete" has no column, so it lives in `p95_json.incomplete` and the `wf=WF-30` log line; NL-127 reads it from there.
