# NL-119b: spike call site for the Yjs probe, plus two review fixes

## Changed
- `load/cli.ts`: `--collab-url` (or `COLLAB_URL`). Required with `--socket-editors > 0`; must be `ws:`/`wss:`; non-local host refused without `--allow-remote`. All refusals exit 2 before any request.
- `load/spike.ts`: `main` runs the HTTP half and, when `--socket-editors > 0`, the Yjs half (`run_socket_half`, dynamic import of `yjs-mix.ts`) concurrently. Two rows (`kind=http`, `kind=yjs`), never merged. The JSON summary stays the last stdout line; exit is 1 if the Yjs half is incomplete, lost updates, or failed. The password is never passed to the Yjs half.
- F-1 (`load/yjs-mix.ts`, `load/yjs-stats.ts`): remote-edit samples taken across a dropped socket (per-editor `epoch`, pure `is_clean_sample`) no longer enter `remote_edit`; they are reported as `remote_edit_during_drop` and counted. New `p95_json` keys: `remote_edit_n`, `remote_edit_during_drop`, `remote_edit_during_drop_n`.
- F-2: tokens still unacknowledged after the drain make the run incomplete (`incomplete_reason: unacknowledged_after_drain`, exit 1). `incomplete_reason` is in `p95_json` (null when complete; also `connect_timeout`, `socket_down`, `error`).
- `load/report.ts`: the socket-editors note now points to the separate yjs row.
- Test harness: `start_probe_stack({ unit_id })` (default `G6.U9`); `load/src/testing/collab.ts` (`start_collab`), shared by `yjs-mix.int.test.ts` and the new `load/spike-yjs.int.test.ts`.

## Why
The call site was the only thing blocking AC-6 and R-1 after NL-118 merged. The stack seeds unit `G6.U9`, which is also the Yjs load unit, so the HTTP half would have discovered the load lessons; the new test uses `G6.U1` for the web stack. Halves run concurrently because the capacity doc's load is one mixed load. `max_db_connections` in the http row now includes the Yjs half's and the collab server's connections (one database).
