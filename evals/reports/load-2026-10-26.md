## Misses (AC-7)

- **M-24 stored p95: 6,008 ms against < 3,000 ms (n = 22,533).** Not tuned. The capacity doc's scale path has no step keyed to store latency. The nearest is step 3 (a second Hocuspocus process with pub/sub fan-out, trigger: socket messages lag > 500 ms), but remote-edit lag was 6.7 ms, so step 3's own trigger did not fire. The store path is Postgres write plus the check refresh; the worker logged 1,310 `check.failed InvariantViolation` lines in the same window (F-4), which is the first thing to look at. Recommend: diagnose the store path before any scale step.

## Findings that qualify the passes

- **F-1 Seed data deviation.** NL-112 (the real-key unit run) has not run, so no generated unit existed. The HTTP half read a synthetic unit `G6.U1` with 40 lessons built from the committed WP-1 fixture padded with repeated filler to about 3,300 words (about 31 KB of lesson JSON each); the setup script was throwaway and is not committed. The Yjs half used its own fixture lessons (`G6.U9.L9xx`, 47 lessons, the small WP-1 document), so its documents are much smaller than a real lesson. Both facts make the numbers optimistic against real content.
- **F-2 No generation run progressed during the plateau.** A stub run over the issued sheet (48 jobs) was started 06:05, but its first job (`unit_plan`) failed with a generic `Error` (`error_kind: unexpected`) at 06:07:31, the run stayed in `planning`, one job stayed `running` and 47 stayed `queued` for the whole test, and the worker was idle. The worker and the polls therefore did not compete as in real use. The probe also took `run_id` from the discovered unit (`G6.U1` has no run), so it reported "progress poll skipped" and the poll class is the board only (20% of users at 1 poll / 2 s still ran as board polls). The stub unit-plan failure is a defect to file; I did not investigate it here.
- **F-3 Recovery reading.** The probe computes the 100 s from its windows after the plateau, which overlap the 2-minute ramp down; it does not add the 5 minutes of extra sampling the ticket asks for. Recovery is "met" only in that sense.
- **F-4 Check failures.** 1,310 `check.failed` / `InvariantViolation` worker log lines, all on the Yjs load lessons (the smoke run's and the real run's), none from the HTTP unit. Either the fixture clones violate a lesson invariant or the checker rejects the typed-token edits. The log is `docker compose logs worker` on project `ls-nl127`.
- **F-5 Contention.** See header: another agent was using the machine.
